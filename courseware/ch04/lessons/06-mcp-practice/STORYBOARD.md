## 本节内容

### 从读一份需求，转向日常怎么用工具

4.5 已经把规格基线交给第 5 章。这一节不再改 JSON Diff，也不接着写规格。开头顺着学员可能的追问：4.2 只用飞书 MCP 读过一份需求，日常要处理资料时，还能怎么把工具交给 Agent？MCP 是其中一种方式；飞书这边先做一段「飞书 CLI 主演示」：先讲清两种接入，再现场接上，然后用一句话加链接来读文档，接着更新和上传云文档、改电子表格、创建多维表格。随后三页是「实用 MCP 工具推荐」：AntV、高德，以及 12306、Playwright、Context7、Blender，仍用 MCP 做短演示。这一节偏重演示：开场只作很短的铺垫，口播只点出该看什么、怎样判断，不单独开很长的知识页。学员以看懂为主，按自己的需要选做即可。

### 先讲清两种接入，再把两套都接上

4.2 只讲清了 MCP 是什么，并且只用飞书 MCP 开放了两个读取工具。当时说过，接入放到这一节补上。接入飞书现在有两种方式。按官方文档的用法：飞书 CLI 本质上是一组技能（Skill），安装后要重启 AI 工具让技能加载，Agent 通过技能调用命令行，适合个人使用；在团队环境里，需要搭建 Agent 工作流时，飞书 MCP 更适合。两种不要混为一谈，也不要把命令行工具说成 MCP。

p60 只讲清区别和后面怎么演示，不写成逐步点击教程，也不在画面上列出命令细节或凭证。p61 再把两套接入都做一遍，让学员看见「怎样登录、怎样接上」。飞书 MCP：从创建应用讲到安装并配置 lark-mcp。飞书 CLI：从官方 CLI 文档链接开始，把链接交给本地 Agent，让它自助安装 Skill，再返回授权链接，由讲师手动完成授权。凭证、密钥和应用密钥不进入公开材料，也不出现在画面或录屏里。配置过程里如果弹出应用凭据或授权状态细节，及时避开或事后裁掉。没接上的学员，也可以看后面的演示。

后面 p62–p65 的读写演示仍用更适合个人使用的飞书官方 CLI，不再把命令行工具说成 MCP。官方说明里，云文档的创建、读取、更新和评论，以及电子表格、多维表格和知识库，都在能力范围内，但仍要演练后按实际结果讲，做不到就保留实际范围。

### 飞书 CLI 主演示：读、改、上传，再到表格

接上之后，用四个短演示把常用使用方式走一遍，不要再以「开发者分享会」的分类整理、来源核对、创建整理稿作为这几页的主线。已上传的教学文档和表格仍可作为演示材料使用，但公开仓库不提交需登录的演示链接。p62 的读文档演示不要改写 4.2 的需求笔记；如需更新或上传，改用本节准备的教学文档和目录，不要覆盖原来的需求笔记。

先做读取。用一段很短的话加一个文档链接，例如：「请阅读 <活动方案链接> 这个飞书文档，告诉我这个文档中写了什么。」让本地 Agent 读出文档内容。先看见这句请求，再发出去，再打开实际文档，核对 Agent 转述是否对得上原文。不预写文档正文或转述结果。

再做更新和上传。除了读取，还要让学员看见：怎样指定要改的文档和改动范围，让 Agent 更新已有云文档；怎样把本地文件或新文档上传、创建到指定目录。两次都要打开实际云空间检查位置和内容，不能只看对话里的「已完成」。不向群聊发消息。不预写更新后的正文或上传结果。

然后单独演示电子表格。用一段 prompt，请 Agent 修改指定工作表里的一处内容，再打开实际表格检查。不要用云文档里的普通表格代替电子表格。已有的「分场次报名统计」可以继续用作这一页的材料。短演示即可，不是飞书产品课。

最后演示创建多维表格。用一段 prompt，请 Agent 在指定位置新建一张多维表格，用来追踪团队任务计划：例如追踪分摊到各个团队成员的任务，以及创建时间、任务优先级、当前任务进度。打开实际多维表格，检查是否建在指定位置，以及字段和示例记录是否符合请求。这一页是创建，不要改用已有的「主题与跟进」表来顶替。哪一步做不到，就按实际完成范围讲，不改用别的工具装作做完。

### 实用 MCP 工具推荐

p66–p68 三页作为「实用 MCP 工具推荐」，沿用原来的三个短演示，课上仍实跑，不改成只放清单或只放公开演示画面。

先做工具接续。从已有教学数据里取出三个主题和人数（40、25、15，来自活动方案里的普通表格，不是电子表格）。先核对要交给绘图工具的输入，再用 AntV Chart MCP 生成柱状图。打开结果，检查类别、数值、中文标签和标题是否对应源表。不把图表自动回写到飞书当作必须完成的环节。AntV 默认使用远程渲染，本机启动 MCP 并不等于数据只留在本机。图表和中文显示以实跑为准。

再换一个日常场景，用高德做短演示：周末从杭州东站出发，安排两个适合步行串联的景点，区分车站到景点的交通段和景点之间的步行段，并生成能在高德打开的专属地图。地点和路线以真实查询为准，不预先写好成功结果。讲师分别核对文字行程、地图结果和 APP 是否打开，按实际完成范围讲解。模型写了一段行程，不等于已经生成地图；返回一个链接，也不等于手机已经打开。百度地图只作为替代说明，不再单独做一遍。

其余四个推荐的 MCP，放在同一页分段揭示，各做一个能看见结果的短演示。12306-mcp 查一次具体车次或中转，说明这是社区实现、依赖上游接口，不是购票或抢票工具。Playwright 在浏览器里完成一项能看见的操作，例如打开指定页面并核对页面上的一项内容。Context7 针对一个具体的库或接口查文档，打开返回结果，看清版本和内容是否对得上当前问题。Blender 在本机做一个很小的三维操作，例如创建一个简单物体并在 Blender 里看到结果。这些短演示都先实跑；账号、网络、本机环境和插件等条件，讲的时候一并交代。哪一个当时做不到，就按实际完成范围讲，不换别的工具顶上。

### 其他推荐、学员判断与交接

实用 MCP 工具推荐之后，再用一页介绍三个课上没有展开的 MCP：GitHub 官方 MCP、MiniMax 官方 MCP，以及 FreeCAD 社区 MCP。各配一张能看见结果的公开演示画面（动图或截图），并标明来源是项目公开演示，不是这一节已经实跑的结果。不要求学员装齐。口播顺带收住选用条件：要分清官方实现和社区实现，账号、网络和本机软件条件都要看清。再进入自检和小结。
