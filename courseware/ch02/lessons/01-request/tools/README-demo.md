# 2.1 请求演示的复现入口

`demo.sh` 是 p08/p09 实验的准备与启动来源，不依赖讲师电脑的绝对路径。它在备课仓库之外准备个人主页，检查规则，再运行主页或 Codex；不自动发送 Prompt。脚本对应初始请求实验，不负责后续内容迭代或发布。

## 前置条件

- Git、Node.js、npm、uv、Codex CLI 已安装；Codex 冻结为 0.163.0，不一致时停止，需另行核验。
- 主页快照的 `.nvmrc` 声明 Node 22.19.0；脚本使用当前 Node 并打印版本，不自动安装或切换。2026-10-23 实际准备与构建使用 Node 26.12.0 / npm 11.20.0，通过；不能将其写成 Node 22.19.0 已实测。
- 在终端配置 `MINIMAX_API_KEY`，不要写入项目或脚本。准备项目不需要 Key，启动 Codex 才需要。
- macOS 已实测；Agent Lab 的 Linux/WSL 路径尚未实测，原生 Windows 暂不支持。另一台机器仍须核对实际请求，模型回答、调用选择及 token 数不保证相同。

## 使用

在拿到课程仓库代码后，于仓库根目录运行：

```sh
sh courseware/ch02/lessons/01-request/tools/demo.sh prepare
```

该命令克隆 `course-starter` 的 `ch02-start-v1`，校验实际提交为 `8e9a323174411a011f87e230450b9115d09b7dea`，运行规则检查、`npm ci` 与构建。已有目录只核对，不重置或清理；内容已变更时另选目录。

两个终端均从课程仓库根目录启动：

```sh
sh courseware/ch02/lessons/01-request/tools/demo.sh homepage
```

```sh
sh courseware/ch02/lessons/01-request/tools/demo.sh codex
```

也可将同一份 `demo.sh` 复制到便捷位置，以绝对路径运行；它不依赖脚本所在目录，故无需下载整份备课仓库才能执行。课程仓库中的脚本是维护来源，分发时固定其提交版本，本机副本随之同步，不另改一套逻辑。

默认目录为 `$HOME/course-demos/personal-homepage`；专用课程 HOME 为 `$HOME/.local/share/agent-lab-ch02-recording/codex`。可在所有终端一致设置 `CH02_DEMO_ROOT`（项目父目录）和 `AGENT_LAB_HOME`（专用环境父目录）。不放在备课仓库或其他带规则的项目内。`audit` 子命令可单独检查：

```sh
sh courseware/ch02/lessons/01-request/tools/demo.sh audit
```

检查覆盖项目起点、工作区改动、项目及上级的 `AGENTS.md` / `AGENTS.override.md` / `.agents/skills`，以及专用课程 HOME 的全局规则和保存的批准规则。发现影响实验的内容时报告路径并停止，不删除它们。真实个人 HOME 的 Skills 不等于专用课程 HOME 的 Skills，最终仍需从实际请求确认来源。

## 固定来源与操作

- 项目来源：`https://github.com/prompt-to-harness/course-starter.git`，标签与完整提交见脚本。
- Agent Lab 来源：与 p06 相同的源码包提交 `691d15c58a3b89abc36bfcf90bc6b7072423ad4c`；依赖固定 claude-tap 0.1.146，模型及配置由该启动器固定。脚本不会更新本机 Codex。
- 首次启动可能需要信任项目；准备阶段完成，不把信任界面当作请求内容。
- 发送“你好，用一句话介绍你能帮我做什么。”，回答结束后打开终端给出的查看器地址。用末句辨认第一份主请求，不凭捕获顺序选择；会话标题请求可能先出现。
- 展示第一份主请求中的原句、工具定义、Skills 列表、环境、权限和系统/协作指令。若模型调用工具，保留记录，初始请求与工具返回后的后续请求分开讲，不承诺问候必然不读文件。
- 记录留在专用课程 HOME，可能包含路径和代码，不提交公共仓库；上屏前脱敏。原始鉴权配置与 Key 不上屏。

## 查看器的请求编号与标题请求

2026-10-23 的 claude-tap 0.1.146 记录中，三次 API 请求显示为轮次 2、1、3。原因是代理原始编号按请求到达顺序分配，查看器显示编号却按记录入库顺序重新编排，再按原始编号排序；并发请求先后完成时，两套编号可能不一致。这里的“轮次”不能直接当成人发送 Prompt 的次数。

该次实验的对应关系是：

| 查看器显示轮次 | 代理原始 turn | 用途 |
| --- | --- | --- |
| 2 | 1 | 第一份主请求，末句是问候；响应提出读文件调用 |
| 1 | 2 | Codex 自动生成会话标题，末句以 Generate a concise, single-line task title 开头 |
| 3 | 3 | 主流程带上工具返回，给出最终介绍 |

英文标题指令在已安装的 Codex CLI 0.163.0 二进制中可查到，与实际捕获请求吻合；它不是项目 `AGENTS.md`、用户额外输入或代理临时添加的提示。它要求模型为会话起一个简短名称，引用原始问候作为素材，与回答问候是两个任务。

录制时通过末句和响应辨认任务；主请求与后续工具返回连起来讲，标题请求只简短解释来源。本次显示编号不能作为其他机器或下一次运行的固定定位方式；“用户输入”分组也是查看器对请求内容的归类，不表示人又输入了一句话。
