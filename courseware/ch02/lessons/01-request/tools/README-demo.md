# 2.1 请求演示的复现入口

`demo.sh` 是 p08/p09 实验的准备与启动来源，不依赖讲师电脑的绝对路径。它在备课仓库之外准备个人主页，检查规则，再运行主页或 Codex；不自动发送 Prompt。脚本对应初始请求实验，不负责后续内容迭代或发布。

## 前置条件

- Git、Node.js、npm、uv、Codex CLI 已安装；Codex 冻结为 0.163.0，不一致时停止，需另行核验。
- 主页快照的 `.nvmrc` 声明 Node 22.19.0；脚本使用当前 Node 并打印版本，不自动安装或切换。2026-10-23 实际准备与构建使用 Node 26.12.0 / npm 11.20.0，通过；不能将其写成 Node 22.19.0 已实测。
- 在终端配置 `MINIMAX_API_KEY`，不要写入项目或脚本。准备项目不需要 Key，启动 Codex 才需要。
- macOS 已实测；Agent Lab 的 Linux/WSL 路径尚未实测，原生 Windows 暂不支持。另一台机器仍须核对实际请求，模型回答、调用选择及 token 数不保证相同。

## 使用

在拿到课程仓库代码后，于仓库根目录运行：

```sh
sh courseware/ch02/lessons/01-request/tools/demo.sh prepare
```

该命令克隆 `course-starter` 的 `ch02-start-v1`，校验实际提交为 `8e9a323174411a011f87e230450b9115d09b7dea`，运行规则检查、`npm ci` 与构建。已有目录只核对，不重置或清理；内容已变更时另选目录。

两个终端均从课程仓库根目录启动：

```sh
sh courseware/ch02/lessons/01-request/tools/demo.sh homepage
```

```sh
sh courseware/ch02/lessons/01-request/tools/demo.sh codex
```

也可将同一份 `demo.sh` 复制到便捷位置，以绝对路径运行；它不依赖脚本所在目录，故无需下载整份备课仓库才能执行。课程仓库中的脚本是维护来源，分发时固定其提交版本，本机副本随之同步，不另改一套逻辑。

默认目录为 `$HOME/course-demos/personal-homepage`；课程环境由 Agent Lab 按项目目录自动选，放在项目外面（`agent-lab home` 查看，C2-110），新的项目目录就是新的环境。可设 `CH02_DEMO_ROOT`（项目父目录）；`AGENT_LAB_HOME` 仍可手动指定环境。不放在备课仓库或其他带规则的项目内。`audit` 子命令可单独检查：

```sh
sh courseware/ch02/lessons/01-request/tools/demo.sh audit
```

检查覆盖项目起点、工作区改动、项目及上级的 `AGENTS.md` / `AGENTS.override.md` / `.agents/skills`，以及专用课程 HOME 的全局规则和保存的批准规则。发现影响实验的内容时报告路径并停止，不删除它们。真实个人 HOME 的 Skills 不等于专用课程 HOME 的 Skills，最终仍需从实际请求确认来源。

## 数据与运行的做法（其他章可沿用）

2.1 在 2026-10-24 整组重跑（C2-90）时定下这些做法，其他章做请求记录、实测对照时照此办。

- **原始记录放私有仓库。** claude-tap 数据库、解码后的完整请求、Codex 会话、终端输出和驱动脚本放进 [prompt-to-harness/lab-runs](https://github.com/prompt-to-harness/lab-runs)，按 `章/节-日期/` 存放并写 README（条件、命令、结果）。只提交课件实际采用的那一组；不放进 ai-coding-resources 或本地忽略目录（换机器会丢）。提交前用 Key 片段 grep 一遍。
- **公开数据不删结构。** 只去掉鉴权请求头、缓存与会话标识、推理的加密部分和本机路径（含 `ls -l` 的账户列），消息正文、工具定义、可读的推理文字、调用与返回全部保留，不做“教学删节”。删节会改变数据结构，而结构本身常常就是要讲的东西：旧记录删了推理，曾让我们把“每轮追加三条”误读成两条（C2-89）。导出脚本里写断言自动检查，做法见 [run-20261024 的 export-public.py](../../../materials/request/run-20261024/export-public.py)。
- **一次运行，多页复用；数字从一份数据生成。** 尽量用同一次运行支撑一组页面（2.1 用一个交互会话供 p08、p08a、p09、p07-loop、p07），页面上的数字从同一份 `summary.json` 读取或核对。同一个数字散写在十几处，换数据时很难改干净。
- **真实结果会变，讲法提前留分支。** 同一句问候，10-23 先读了 package.json，10-24 直接回答。分镜里按“实际结果是 A 时这样讲、是 B 时那样讲”写，换数据时只改数字和一两句口播；不为凑旧结果反复重跑。
- **回答里的引用逐条对照源码。** 模型给出的文件和行号，对照当次快照逐行核对；额外的判断（如“dist 未落后于 src”）没核对就写“未核实”。
- **驱动交互界面先看屏幕再按键。** 用 PTY 驱动 Codex TUI 时，每次按键前先渲染屏幕确认当前提示。Codex 启动可能弹出“有新版本”，Enter 会直接全局升级 Codex，要选 Skip；2026-10-24 曾因此被升到 0.164.0，当即装回 0.163.0。新建的课程 HOME 首次启动还会问是否信任项目。

## 录制采用的查看器

第二章统一使用启动器固定的原版 claude-tap 0.1.146，不加载本地用途分类、统一编号或命名整链归组补丁；本地试用版仅保留作研究备查。录制前核对打开的是本次终端给出的原版查看器地址，不使用旧的本地补丁预览页。

每个新会话先手动 `/rename ch02-demo`，确认名称已更新，再发送首句问候。录制主流程时保持模型目录等辅助路径未选中；差异对比前核对两侧均为目标主请求，遇到压缩单独标记边界。手动命名的效果依据下述冻结版本的实测，不承诺消除所有辅助请求。

## 固定来源与操作

- 项目来源：`https://github.com/prompt-to-harness/course-starter.git`，标签与完整提交见脚本。
- Agent Lab 来源：课程仓库 main 的 `tools/agent-lab`（2026-10-24 起；此前的实测用提交 `691d15c58a3b89abc36bfcf90bc6b7072423ad4c`，两者该目录内容一致）；依赖固定 claude-tap 0.1.146，模型及配置由该启动器固定。脚本不会更新本机 Codex。
- 首次启动可能需要信任项目；准备阶段完成，不把信任界面当作请求内容。
- 每个新会话在首句问候前，先在 Codex 输入 `/rename ch02-demo`，确认名称已更新，再发送“你好，用一句话介绍你能帮我做什么。”。`/rename` 是客户端命令，不是发给模型的自然语言 Prompt；不能用一句“不要自动命名”替代。启动脚本不自动代输命令，`demo.sh codex` 在启动前打印要输入的那一行（会话名用 `CH02_SESSION_NAME`，`record` 按标签给出 `ch02-<标签>`）。原因（2026-10-25 核对 Codex 0.163.0 源码 `tui/src/app/thread_routing.rs`、`thread_title.rs`，C2-99）：会话没有名字时，每条用户消息完成后 TUI 都会另开一个临时会话请模型起标题，标题请求走的是单独的临时会话，在 claude-tap 里另成一组；标题没能生成时名字保持为空，下一句还会再发（MiniMax 下是否常出现未核实）；没有配置项能关掉；`codex "<初始输入>"` 会把 `/rename` 当普通消息发给模型，不会执行。模拟键盘往 TUI 里打字会和信任项目、升级提示抢输入，不采用。
- 手动命名作为第二章录前准备，用来减少自动命名请求干扰；不是关闭全部辅助请求的开关。该效果受冻结的 Codex 版本与配置约束，当次仍需检查记录。已有旧记录保留，不删除其中的标题请求。
- 回答结束后打开终端给出的查看器地址。用原句、上下文和响应辨认第一份主请求，不凭捕获顺序、固定 Turn 编号或面板累计 token 选择。若仍有标题请求，单独辨认，不计作人工输入。
- 展示第一份主请求中的原句、工具定义、Skills 列表、环境、权限和系统/协作指令。若模型调用工具，保留记录，初始请求与工具返回后的后续请求分开讲，不承诺问候必然不读文件。
- 记录留在专用课程 HOME，可能包含路径和代码，不提交公共仓库；上屏前脱敏。原始鉴权配置与 Key 不上屏。

## 模型目录读取、压缩与对比

- 当前 Agent Lab 配置使用随包提供的本地模型目录（`model_catalog_json`）。若另一次记录出现 `GET /v1/models`，它是服务读取请求，没有本次用户 Prompt，不能当成模型回答或一轮人工对话。
- claude-tap 0.1.146 有主对话路径时，默认仅选主路径；模型目录路径收在顶部的“更多”中。要查看，展开路径筛选并点选 `/v1/models`，看方法、URL、请求体和返回 JSON。录制主流程时保持该路径未选；不要因编号相邻把目录读取拿来做对话差异比较。
- 压缩会影响之后发送的历史，不能把它当作目录查询那样一律忽略。2.1 不专门触发或讲解压缩；若运行中发生，标记当前请求属于压缩前还是压缩后，需要展示时留到 2.2。它可能使用相同的 `/v1/responses` 路径，不能只靠 URL 判断；自动对比也可能选中压缩请求作前一份，因此须核对两侧用途与压缩前后边界。
- 用途分组和自动对比是不同逻辑：本地试用版可分类命名、维护和服务请求，但仅折叠后台组不会约束“对比上次”的候选。对比前核对两边均属于同一主流程；没有可信上一份时不强行比较。用途试用版尚未纳入这里的固定 claude-tap 分发，不把它当作学员或另一台机器的前置依赖。

实测与录制决策登记在[第 2 章 LOG](../../../LOG.md)，不能将本机一次的请求编号当作复现步骤。

## 未手动命名的旧记录：请求编号与标题请求

2026-10-23 的 claude-tap 0.1.146 记录中，三次 API 请求显示为轮次 2、1、3。原因是代理原始编号按请求到达顺序分配，查看器显示编号却按记录入库顺序重新编排，再按原始编号排序；并发请求先后完成时，两套编号可能不一致。这里的“轮次”不能直接当成人发送 Prompt 的次数。

该次实验的对应关系是：

| 查看器显示轮次 | 代理原始 turn | 用途 |
| --- | --- | --- |
| 2 | 1 | 第一份主请求，末句是问候；响应提出读文件调用 |
| 1 | 2 | Codex 自动生成会话标题，末句以 Generate a concise, single-line task title 开头 |
| 3 | 3 | 主流程带上工具返回，给出最终介绍 |

英文标题指令在已安装的 Codex CLI 0.163.0 二进制中可查到，与实际捕获请求吻合；它不是项目 `AGENTS.md`、用户额外输入或代理临时添加的提示。它要求模型为会话起一个简短名称，引用原始问候作为素材，与回答问候是两个任务。

录制时通过末句和响应辨认任务；主请求与后续工具返回连起来讲，标题请求只简短解释来源。本次显示编号不能作为其他机器或下一次运行的固定定位方式；“用户输入”分组也是查看器对请求内容的归类，不表示人又输入了一句话。

## 补充记录：问候后 fork 的另一套对照

下面保留已完成的另一套实验，供需要控制前置问候历史时参考，不是当前 p14a 展示数据的生成步骤。它使用 workspace-write 并继承问候历史；累计输入为 84,879/46,084。不能将其步骤或数字混用到上面的全新 read-only 会话对照。本次只整理两套说明，不重跑模型。


2026-10-23 已实际验证。完成一次问候后，保存这个 **Codex 会话 ID**（不是 claude-tap 代理会话 ID）。为了让两组获得相同历史，用 `codex exec fork` 分别从这份未继续追加问题的问候会话开始；点名组不接着不点名组的答案。fork 只是录前控制条件，学员无须跟做机制对照。

先运行本脚本 `audit`，再到个人主页项目根目录操作。把下列 `ch02_seed` 替换为本机的问候 Codex 会话 ID，并保持与问候时相同的 `AGENT_LAB_HOME`。会话 ID 可从专用课程 HOME 的 `.codex/sessions/` 对应问候记录的 `session_meta.payload.id` 核对；不要凭“最新会话”选择，否则可能把别的实验历史带进来。

```sh
ch02_seed='替换为本机问候的 Codex 会话 ID'
ch02_agent_source='git+https://github.com/prompt-to-harness/prompt-to-harness.github.io#subdirectory=tools/agent-lab'
export AGENT_LAB_HOME="${AGENT_LAB_HOME:-$HOME/.local/share/agent-lab-ch02-recording}"
cd "${CH02_DEMO_ROOT:-$HOME/course-demos}/personal-homepage"
ch02_question='只读任务，不修改任何文件。
这个个人主页的项目区现在显示什么？数据写在哪个文件里？
请说明依据来自哪个文件的哪几行；
不确定就写“不确定”，不要猜。'

# 不点名组：第一次 fork
uvx --from "$ch02_agent_source" agent-lab codex --tap -- exec -s workspace-write fork "$ch02_seed" "$ch02_question"

# 点名组：仍从同一 seed fork，只增加一个文件提示
ch02_named_question="$ch02_question
请重点查看 src/App.tsx。"
uvx --from "$ch02_agent_source" agent-lab codex --tap -- exec -s workspace-write fork "$ch02_seed" "$ch02_named_question"
```

这里显式保留问候的 `workspace-write` 配置，两个 Prompt 都要求只读；它不是系统级只读沙箱实验。源码确认本快照的数据与渲染均在 `src/App.tsx`，因此才提示这个路径，不把答案预先写入 Prompt。更换项目后须先核对相关路径。录前 `prepare` 留下的 `dist/`、依赖和其他文件也属于运行现场，不为制造数字差异临时删改。运行后再次 `audit` 确认项目未改。

核验顺序：先看回答内容与源码行号是否相符，再看读了哪些文件、是否遗漏必要依据，最后比较本题主流程的请求与输入量。模型工具调用按响应里的调用项计数；一个 exec 内的多个 shell 命令段不重复算成模型调用。输入量以各次 API `usage.input_tokens` 求和，排除种子问候、标题等其他任务；它含重复历史，不是新增文字量或费用。fork 后 CLI 的 `turn.completed` 累计量可能包含继承会话的历史，不直接作为本题 API 累计量。

本次不点名/点名分别为 7/4 次主请求、6/3 次模型工具调用、84,879/46,084 输入 token。两组都正确指出数据 1–6 行、项目区渲染 19–31 行，但也都查了额外文件；点名只是引导，没有限制只能读该文件。各一次不构成普遍节省结论，别的机器或另一次运行按实际结果讲。
