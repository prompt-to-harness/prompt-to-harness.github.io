## 两步 Prompt（草稿）

两个 Prompt 都事先设计，保证稳定触发要展示的内容（2026-10-19 讲师确认分两步）。

**p08 第一步（与项目无关）**：

```text
你好，用一句话介绍你能帮我做什么。
```

目的：不触发工具调用，只看 context 的基本组成。录制前确认这一句在冻结版本下不会触发读文件；若触发，换成更短的问候并记下原因。

**p07 第二步（与项目相关、只读）**：

```text
只读任务，不修改任何文件。
这个个人主页的项目区现在显示什么？数据写在哪个文件里？
请说明依据来自哪个文件的哪几行；
不确定就写“不确定”，不要猜。
```

目的：让 Codex 自己去找产品代码（项目区的数据和渲染所在的文件），在记录里看到工具调用和返回。不提示文件名。2026-10-22 按章文件 C2-54 改问法：答案在当前代码里，正好是 2.2 要改的地方，不再依赖第 1 章留下的 `PROMPT_V1.md`；原问法“当初定了哪些要求和完成标准”见 Git 历史。**新问法还没重跑**，p07、p14、p14a 的画面仍是旧问法的记录，重录后按实际改。不问“项目卡为什么不跳转”：这条决定只在 2.5 用到时就地复述（2026-10-19 讲师确认）。

## p14 按实际记录选择讲法

| 实际结果 | 讲法 |
| --- | --- |
| Codex 读取了 `src/App.tsx` 等文件，说出了项目区显示的内容和数据所在的行 | 在记录中指认那次读取文件的工具调用：对照工具返回、后续请求和回答，检查来源与理解是否相符 |
| Codex 没读文件，凭目录名或代码猜 | 核对完整请求与工具返回后指出依据缺失；这正是 Prompt 要求“说明依据”的原因 |

还可能出现“读到了但理解错了”或“没有找到依据，回答不确定或继续查找”。均按实际结果讲解，保留原始记录，不重跑凑结果。
