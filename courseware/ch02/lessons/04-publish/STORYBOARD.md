## p45 推送前检查命令（2026-10-12 改为检查完整历史）

```bash
git log --stat HEAD
git log -p HEAD
git log --format='%an <%ae>' HEAD | sort -u
```

2026-10-12 讲师确认先直接克隆课程模板、发布前再建个人空远端，首次推送会公开当前分支的全部历史，所以检查范围是 `HEAD` 而不是 `origin/main..HEAD`。换 origin 后，旧的 `origin/main` 引用可能仍在本地，按它做增量检查会漏掉课程模板带来的提交和其中后来删掉的文件（Git 2.56.0 临时仓库验证）。`--stat` 会列出历史中出现过、后来又删除的文件，它们推送后同样公开。

## p47 部署 Prompt（草稿）

```text
Goal：用 GitHub Actions 把这个 Vite 项目发布到 GitHub Pages。
Context：仓库名是 <我的仓库名>，Pages 地址是 https://<用户名>.github.io/<仓库名>/。
Constraints：只新增工作流文件和必要的 Vite 配置；不推送，这一轮不改仓库设置；
说明每个权限为什么需要。
Done when：本地 npm run build 成功；我能逐项解释工作流做了什么。
```

## 事实边界与待实测

- Pages 来源设置界面按录制时 GitHub 版本核对。
- 首次部署若自然出错，保留真实失败；不准备错误 `base` 分支（C2-05）。
- 启动必须带 `CLEAN_CODEX_GH=1`（讲师录制再加 `--tap`）；不带时 `gh` 报未登录，Codex 会自己申请运行 `gh auth login --web`，要人拒绝。
- 学员前置：course-starter 环境检查单里有 GitHub CLI 一行，本人运行 `gh auth login --scopes workflow`；`gh` 默认登录不含 `workflow`，Git 用它推送 `.github/workflows/` 会被拒绝（2026-10-07 实测）。
- 默认沙箱没有网络，`gh` 调用逐条申请到沙箱外运行。Prompt 里的“先告诉我再执行”停不住它，停住它的是批准框，所以批准框是本节的人机边界。
- p49 的 Prompt 写明“没有 Pages 站点就用 POST 创建，已有就用 PUT 修改”，避开 PUT 404 后自己改用 POST 的弯路。
- 凭据边界：token 不放环境变量、不贴进对话（预检中 Codex 检查环境变量的命令会把 token 原文打印出来）。

## p45–p46 检查边界

先用文件统计定位，再展开补丁查看新增、修改和后来删除的实际文字；截图等二进制文件须另行打开核对。统计列表不能证明内容可公开。若准备把已有内容的私有仓库改为公开，还须检查远端已有的内容与历史。待公开范围未查清时，保留私有状态并暂停发布。部署工作流生成并提交后，在 p49 补查实际待推送提交，再设置 Pages 来源并推送（GitHub 要求先为仓库启用自定义工作流）。
