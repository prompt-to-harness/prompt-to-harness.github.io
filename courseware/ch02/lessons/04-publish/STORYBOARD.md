## p45 推送前检查命令（草稿，2026-10-02 用本地裸仓库模拟实测通过）

```bash
git fetch origin
git log --stat origin/main..HEAD
git log -p origin/main..HEAD
git log --format='%an <%ae>' origin/main..HEAD | sort -u
```

2026-10-03：为使本节不依赖之前各章的证据文件，示范例子由第 1 章环境记录中的系统用户名改为提交作者邮箱（修订提案决定 18，内部大纲已同步）；作者命令同日在本地裸仓库实测。

远端已有 GitHub Template 生成的初始提交；`origin/main..HEAD` 只列出本地新增、即将公开的提交。course-starter 默认分支为 `main`。`--stat` 会列出历史中出现过、后来又删除的文件，它们推送后同样公开。

## p47 部署 Prompt（草稿）

```text
Goal：用 GitHub Actions 把这个 Vite 项目发布到 GitHub Pages。
Context：仓库名是 <我的仓库名>，Pages 地址是 https://<用户名>.github.io/<仓库名>/。
Constraints：只新增工作流文件和必要的 Vite 配置；不推送、不修改仓库设置；
说明每个权限为什么需要。
Done when：本地 npm run build 成功；我能逐项解释工作流做了什么。
```

## 产出与验收映射

- 跟做：推送前检查记录；公开 URL；三项发布检查结果；`ch02-homepage-live` tag。

## p45–p46 检查边界

先用文件统计定位，再展开补丁查看新增、修改和后来删除的实际文字；截图等二进制文件须另行打开核对。统计列表不能证明内容可公开。若准备把私有仓库改为公开，还须检查远端已有的内容与历史，不能只检查 `origin/main..HEAD`。待公开范围未查清时，保留私有状态并暂停发布。部署工作流生成并提交后，在 p49 补查实际待推送提交，再设置 Pages 来源并推送（GitHub 要求先为仓库启用自定义工作流）。

## 2026-10-07 提议：Pages 来源由 Codex 用 gh 设置（待讲师确认，课件未改）

讲师提出：让学员看到网页上的设置多数也能交给 Codex 用命令完成。预检见 [`materials/pages-source/`](../../materials/pages-source/README.md)：Codex 用 `gh api` 查询、切换、改回 Pages 来源均成功，网页刷新可见。

建议放法：不做“改过去再改回来”的演示，而是把 p49 本来就要做的“设置 Pages 来源为 GitHub Actions”交给 Codex。人先读它要执行的命令再批准，执行后在 Settings → Pages 刷新确认。推送仍由人执行。理由：这一步是发布的真实需要，不额外加内容；来回切换只有在期间不推送时才无害，作为演示容易让学员忘了改回（改回后线上也不会自动恢复）。

与现有设计的冲突，需讲师定夺：

1. p47 的部署 Prompt 写着“不推送、不修改仓库设置”，p47 讲稿说“推送与启用 Pages 由人执行，回扣 1.6”。采用后改为“设置可以交给 Codex，命令由人审，推送仍由人做”，并说明 Codex 改的是仓库之外的状态。
2. 新增前置：安装 `gh` 并由学员本人 `gh auth login`；course-starter 的环境检查单要加一项。没装 gh 的学员走网页设置，课件要给两条路。
3. 默认沙箱没有网络，交互界面会弹出权限请求，这一步未实测；录制前要在交互界面跑一遍。
4. 凭据边界：token 不放环境变量、不贴进对话（预检中 Codex 检查环境变量的命令会把 token 原文打印出来）。
