# 2.4 逐页分镜：发布上线，看 Codex 怎么用 gh

本节范围、时长和验收见[章文件](../../README.md)的 2.4 一行；页型、方式、层与讲透问题这几栏的含义也在章文件“全章约定”里。[课件](index.html) · [逐步讲稿](speaker.html)。决策和实测见 [LOG.md](../../LOG.md)。

## 本节内容

### 从 homepage-v2 开始，第一次推送

上一节参考 Hyperspace 改了两轮风格，让 Codex 提交了 homepage-v2。到现在为止，所有提交都只在自己电脑上。这一节第一次推送，把主页发布成一个公开 URL。推送以后公开的不只是页面，还有当前源码和整段提交历史，推出去就收不回来。本章最后一个问题也在这里回答：这一列内容，最后发到了哪里？答案有两个去处，要分开看：推送，是我们决定把仓库公开给所有人；context，早在每一次请求里就发给了模型服务。

### 推送前，看清即将公开的历史

先在自己的 GitHub 账号下建一个空仓库，把本地 origin 从课程模板改成它，暂时不推送、不公开。首次推到空仓库，当前分支的全部历史都会过去，所以检查范围是 `HEAD`，不是“比课程模板多出来的提交”。用 `git log --stat` 看每次提交动过的文件（包括后来删掉的），`git log -p` 读实际文字，再列出所有作者。会看到三类容易漏的东西：每个提交都带着作者的姓名和邮箱；课程模板带来的提交，作者是别人，克隆时就在历史里，其中后来删掉的文件推送后照样能看到；我们自己放进去的个人信息，`profile.md` 本身就在 homepage-v1 里。`-p` 的输出往往很长，大半是依赖锁文件，可以先排除它再读。文件列表只回答“有什么”，能不能公开要由人逐项判断：有没有 secret、他人信息、截图里的隐私，首屏是不是自己的名字，借来的风格出处还在不在，本人愿不愿意公开。有一项不行就先停下。改写历史不进主课，指向 GitHub 官方文档。

### 推送之前，context 早就发出去了

推送前查这么多，是因为推送是公开。但 Codex 读过的文件、命令的输出，每次请求都原样发给模型服务：Codex 的请求不在服务端接着上一次，每次都带上全部内容（OpenAI 的文章写了原因）。放个人信息时读的 `profile.md`，早就随请求到了模型服务那里，不用等推送。所以 secret 和别人的信息，不只是不推送，也别让它读进 context。服务端怎样保存数据看各家条款，本节不展开。

### Codex 写部署配置，我们逐项审

部署要两样东西：一个 GitHub Actions 工作流，在 GitHub 的机器上构建并发布；Vite 的 `base`，让资源路径对上仓库名。Prompt 沿用四要素，写清自己的仓库名和地址，约束里写明不推送、这一轮不改设置、说明每个权限。审四项：`base`、build 后的资源路径、权限是否只要发布所需、触发分支。

文件要审，它在报告里说的话也要核对：某个 action 的默认行为、最新版本是什么，它可能没查就凭记忆说，说得很确定，也可能是错的。问一句“依据是什么”，看请求里有没有能支撑它的内容。它去查网页时，网页是模型服务那边打开的，不弹批准框；打开的网页都算进这一次的输入，正文作为引用附在它的回答后面，之后每次请求都带着。查得多，context 一下子就撑大，超过窗口的九成，Codex 会在下一轮之前自动压缩，只留我们说过的话和一份交接摘要。外面的信息要进到请求里才算数，进来也有代价。审过让 Codex 提交，和前两节一样在批准框里看清文件和提交说明。

### Pages 来源交给 Codex 用 gh，推送由我们来做

提交后再跑一遍推送前检查，看最终要公开的提交；需要时这时才把仓库改成公开。Pages 来源交给 Codex 用 gh 设为 GitHub Actions：默认沙箱没有网络，每条 gh 命令都会申请到沙箱外运行，弹出批准框。批准框是这一节的人机边界：Prompt 里的“先告诉我再执行”停不住它，停住它的是批准框；它要做请求外的事（例如补跑部署，或者 gh 没登录时去用环境外的登录信息），就在这里说不。改完在网页上刷新确认，它自己看不到网页。推送由我们执行。回到请求记录看这次调用：模型发出的工具调用里是完整命令，带着“要在沙箱外运行”的标记和理由；返回进入下一次请求，模型据此决定下一步；我们点的同意不在记录里。这还是本章一开始看到的那个循环。同样是外面的信息，gh 的输出是在我们电脑上执行、经批准后作为工具返回进来的，网页是模型服务自己去打开的，两条路不一样。

### 证明页面可用，只推送一个 tag

Actions 成功不等于页面可用。用未登录窗口打开公开 URL、看 Network 没有 404、停用缓存后刷新仍正常，三项都过才算发布成功。给这个版本打 `ch02-homepage-live`，只推送这一个 tag，不用 `--tags`。最后三道自检题都只考机制：推送之前个人信息去了哪里，gh 的输出和网页分别怎样进到请求里，谁在哪一步说了算。

### 和本章主线的关系

2.1 认识一次请求里有什么，2.2 看它变长、被清空和压缩，2.3 问依据在哪一块、哪些不在里面；2.4 指着同一列问它发到了哪里：每次请求发给模型服务，推送才公开；外面的东西要进到请求里才算数（gh 的输出是工具返回，网页由模型服务打开），动作经 gh 送出去，每一条经人批准。

### 内容分层（ED-020）

| 层 | 本节内容 | 用在哪 |
| --- | --- | --- |
| 机制 | 首次推送公开当前分支全部历史；context 每次请求都带全部内容发给模型服务，和推送是两回事；它的说法要在请求里找依据，没有就是凭记忆；gh 输出是工具返回、执行前要批准，网页由模型服务打开、不经批准、正文随回答进 context；用量超过窗口九成自动压缩；工具调用里有完整命令和批准申请，人的同意不在记录里；Actions 成功不等于页面可用 | 页标题、转场、自检、小结 |

### 事实边界与待实测

- 推送前检查用 `HEAD` 而不是 `origin/main..HEAD`：换 origin 后旧的 `origin/main` 引用可能还在，按它做增量检查会漏掉模板提交和其中后来删掉的文件（2026-10-12 讲师确认先克隆模板、发布前再建个人空远端；Git 2.56.0 临时仓库验证）。`--stat` 会列出历史中出现过、后来又删除的文件。先用统计定位，再用 `-p` 读实际文字；二进制文件另行打开。若把已有内容的私有仓库改公开，还要查远端已有内容。
- GitHub 文档（2026-10-03 查阅）：从命令行推送的提交用本地 `user.email`；改配置只影响之后的提交；noreply 地址格式按录制时设置页核对，画面不写格式。不做改写历史配套页（2026-10-05 讲师确认），p46 指向官方文档。
- 先为仓库启用自定义工作流再推送（2026-10-05 查阅 Using custom workflows with GitHub Pages）；先推送导致失败时在 Actions 对失败的运行 Re-run。Pages 设置界面按录制时 GitHub 版本核对。首次部署若自然出错，保留真实过程，不准备错误的 `base`（C2-05）。
- 启动方式：Agent Lab 默认复用本机 `gh` 登录，10-25 排练用全新的 AGENT_LAB_HOME 直接可用，不用 `CLEAN_CODEX_GH=1`。gh 没登录时（10-25 实验：`GH_CONFIG_DIR` 指向空目录、另开 AGENT_LAB_HOME，发同一句设置请求，记录在 lab-runs 同目录 `nologin/`）：它没有申请 `gh auth login`，而是查环境变量（只看有没有）、找到环境外真实的 `~/.config/gh` 并遮盖令牌读了 hosts.yml，再申请用 `GH_CONFIG_DIR=…/.config/gh gh api user` 联网；拒绝并说明后，它停下给出登录和执行步骤。那份登录是实验里藏起来的，真没登录的学员不会有；能说明的是：受阻时它会去找别的凭据，读取几乎不受沙箱限制，批准框里要看清用的是谁的登录。用 `clean-codex.sh` 且不带开关时，Codex 会自己申请 `gh auth login --web`（2026-10-21 实测）。
- 学员前置：course-starter 环境检查单里有 GitHub CLI 一行，本人运行 `gh auth login --scopes workflow`；默认登录不含 `workflow`，Git 用它推送 `.github/workflows/` 会被拒绝（2026-10-07 实测）。
- p49 的 Prompt 写明“没有就用 POST 创建，已有就用 PUT 修改”，避开 PUT 404 后改用 POST 的弯路（2026-10-20 讲师决定）。凭据边界：令牌不放环境变量、不贴进对话（预检中检查环境变量的命令会把 token 原文打印出来）。
- 能力目录开时每次调用是 `exec` 工具里的一小段 JavaScript，调 `tools.exec_command`，`sandbox_permissions: require_escalated`、`justification`、`prefix_rule` 写在这段代码的参数里（2026-10-20、10-25 实测）。批准后命令可能超过等待时间，返回先是“Script running with cell ID …”，结果在随后的 `wait` 调用返回里。
- 网页搜索：请求的 tools 里有 `web_search`（由服务端执行），调用出现在模型返回的 `web_search_call` 里，Codex 不弹批准框。
