# 2.3 逐页分镜：参考一个主页改风格：它看到了什么

本节范围、时长和验收见[章文件](../../README.md)的 2.3 一行；页型、方式、层与讲透问题这几栏的含义也在章文件“全章约定”里。[课件](index.html) · [逐步讲稿](speaker.html)。决策和实测见 [LOG.md](../../LOG.md)。

## 本节内容

### 从 homepage-v1 开始，只动样子

上一节结束时，主页已经放进了自己的个人信息、教育、经历和项目，看过页面、构建通过，并让 Codex 提交为 homepage-v1。这一节内容不再变，只动样子：找一个喜欢的主页作参考，改出自己的风格，讲师改两轮。不满意随时能回到 homepage-v1，回退靠提交，不靠对话。一个问题贯穿这一节：我们在浏览器里看得到参考长什么样，Codex 看得到吗？它改风格的依据，只能来自这一次请求里的内容。

### 挑一个参考，用四要素交给它

同一份个人资料可以做成很不一样的样子。先看几个公开的主页或模板，选一个和现在差别明显的（讲师示例用 Hyperspace），说清想借鉴什么。学的是风格，不照搬别人的代码和文字，按各自的许可注明出处。Prompt 沿用第一章的四要素：目标是参考它改风格；背景给出参考网址，点明用 curl 取 HTML 和 CSS，结合当前代码先给计划；约束是保留个人内容、不加依赖、不引远程资源；完成标准写清 build 通过、页脚注明出处、页面效果由人在浏览器里看。用 Plan 模式，先看计划再放行。

### 它拿到的是代码片段，不是页面

给了网址，进入请求的并不是我们看到的页面。它用工具把参考取回来，通常先存进临时文件，再一段一段挑着读；进入“工具返回”的是这些代码片段。它说出的风格判断能在片段里找到依据，但那是从代码推出来的，不是看到的渲染效果：取回来，不等于看到了。读完它往往会问几个偏好，我们的回答是提问工具的返回；它写的计划进了对话历史，之后每次请求都带着，它改的时候照着。计划不越界就放行。

### 第一轮改完，哪里和想的不一样

改完先在浏览器里和参考并排看。会有做到的，也会有和想的不一样的地方，具体是什么取决于当次运行。这个差别我们一眼就能看到，它看不到：渲染出来的页面不在 context 里，build 通过也回答不了像不像。它自己通常也想看，会去起预览服务或截图，这正说明页面不在它手里。

### 把看到的样子带进请求

还在同一个会话里，把当前效果和参考的首屏截图贴进去，再用一句话说清哪里不满意、想要什么样，其他部分先保持。图给出我们看到的页面，话说出这次的偏好。这一条就是新的 Prompt：图片作为输入进了请求，之后每次请求都带着；前一轮的任务和计划也仍在对话历史里。改完回到同一位置看变化。它看见了我们贴的图，自己做出来的页面它仍然看不见；让它自己看页面，要把浏览器接进它的运行环境，留给后面的章节。学员第二轮按需要进行。

### 审过再提交，接到发布

像不像只能由人在浏览器里判断。diff 很大，不逐行读，只看新加了什么（脚本、动画、借用素材的出处）和范围对不对。满意就让 Codex 提交，在批准框里看清文件和提交说明；不满意，用 `git restore` 放弃还没提交的改动。最后用三个问题自检：依据在请求的哪一块，贴的图在哪一块，像不像由谁判断。下一节把这个主页发布上线。

### 和本章主线的关系

2.1 认识了一次请求里有什么，2.2 看到它怎样变长、被清空和压缩；2.3 指着同一张图问：改风格的依据在哪一块，哪些东西不在里面。三点都是机制，换一次运行也成立；排练里出现的具体问题只是例子（编辑规范 ED-020）。

### 讲师提示（不上屏）

- 交互题按自己的想法选；录制当天题目、计划、第一轮的问题和 PPT 不同是正常的，口播按现场说。
- 它可能想把参考文件下载进项目目录：拒绝，说“参考文件不要放进项目目录，放到 /tmp 下就行”，免得之后被一起提交。
- 它可能在沙箱里后台起服务（不弹框），或要用无头 Chrome 截图（弹出批准框）：拒绝，说“不用截图，页面我自己在浏览器里看”。10-25 这次 Done when 写了不用起预览服务，第一轮没起，第二轮画完想截图。
- 提交时 `git add` 先在沙箱里失败，它会说明 .git 只读并申请提权；`git add`、`git commit` 各批准一次。
- 第二轮贴图：拖进终端或 Ctrl+V，输入框出现 `[Image #1]`、`[Image #2]` 再写那句话。贴自己的页面，是因为它看不见自己做的页面；只贴参考也能做，但差别出在我们页面上时它就没有依据。
- 五次排练都没出现输出截断，“长输出会被截断”只在追问时提一句。
