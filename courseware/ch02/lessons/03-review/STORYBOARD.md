## 内容分层（ED-020）

| 层 | 本节内容 | 用在哪 |
| --- | --- | --- |
| 机制 | 给网址不等于给页面，进 context 的是工具返回的文字；交互题的答案是工具返回，计划进对话历史；渲染出来的页面不在请求里；贴的图在新的 Prompt，之后每次请求都带着；第二轮带着第一轮的历史；像不像由人判断，回退靠 Git | 页标题、转场、小结、自检 |
| 稳定现象 | curl 把参考存进 /tmp、挑着读 CSS；Plan 里先问偏好；实施完想起服务或截图看页面（10-24 四次排练都出现） | 口播说“通常会”“几次排练都出现过” |
| 某次细节 | 密集小箭头（来自参考 CSS 里下拉框的图标，计划里就写了）；交互题内容；沙箱里第一次联网失败；滚动高亮脚本 | 只在 PPT 里当例子，标“排练这次” |

## 讲师提示（不上屏）

- 交互题按自己的想法选；录制当天题目、计划、第一轮的问题和 PPT 不同是正常的，口播按现场说。
- 它可能想把参考文件下载进项目目录：拒绝，说“参考文件不要放进项目目录，放到 /tmp 下就行”，免得之后被一起提交。
- 实施时它在沙箱里后台起服务不弹框；要用无头 Chrome 截图时弹出批准框，拒绝，说“不用截图，页面我自己在浏览器里看”。
- 第二轮贴图：拖进终端或 Ctrl+V，输入框出现 `[Image #1]`、`[Image #2]` 再写那句话。贴自己的页面，是因为它看不见自己做的页面；只贴参考也能做，但差别出在我们页面上时它就没有依据。
- 10-24 四次排练都没出现输出截断，“长输出会被截断”只在追问时提一句。
