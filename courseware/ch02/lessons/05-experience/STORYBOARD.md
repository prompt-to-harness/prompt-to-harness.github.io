本节范围、时长和验收见[章文件](../../README.md)的 2.5 一行；页型、方式、层与讲透问题这几栏的含义也在章文件“全章约定”里。[课件](index.html) · [逐步讲稿](speaker.html)。决策和实测见 [LOG.md](../../LOG.md)。

## 本节内容

### 从项目中的请求，看到更多使用条件

个人主页已经上线。前面几节，我们跟着这个项目看了请求组成、历史变化、参考材料和远端状态。现在把视角拉开一点：界面上只问了一次，背后这些请求一共花了多少；换会话时，除了让工具压缩历史，我们还能留下什么；同一句话交给不同工具、不同模型服务，或者同一工具的不同版本，请求又有哪些差别。

这些问题仍然围绕“这一次请求里有什么”，但关注的是前面没有展开的代价和使用条件。先看费用和交接两个短例子，再依次改变工具、模型服务和版本，观察那些不是由我们输入的一句话直接决定的内容。

### 一次提问，要把多次请求放在一起看

一次提问不一定只产生一次模型请求。工具调用之后还会继续请求模型，因此估算这一次任务的费用，要看这一段过程的累计用量。拿已有的一段独立实验记录，把几次请求的输入、其中的缓存命中部分，以及输出用量放到一起，再按所选价格口径换算。

这里多得到了一层认识：请求中的内容不仅影响回答，也有实际的计费代价。一次请求有多长、整个任务累计用了多少、最后花多少钱，是三个不同的问题。缓存让符合条件的重复输入按不同价格计费，不能把缓存命中量在总输入之外再重复加一次；具体怎样拆分，以这份记录的用量字段和对应计费说明为准。

这个例子让我们对一次任务的花费有个量级感。缓存原理和历史怎样增长，前面已经讲过，接下来看看我们能怎样主动选择下一轮带走的信息。

### 换会话时，可以自己决定留下什么

前面见过工具压缩出来的摘要。需要换一个新会话继续做时，也可以自己留几行交接：这轮要做什么、已经做到哪、还剩什么，以及相关文件在哪里。

把一段已有交接与新会话的第一次请求放在一起，就能看到我们选择的信息怎样成为新一轮的输入。它给下一轮一个起点，相关文件和当前状态仍可继续读取、核实。长期规则与本轮进度各有用途，这里只用这个短例子说明人的选择，不再展开一套交接流程。

到这里，看过的是任务累计用了多少信息，以及人能选择带走哪些信息。请求里另外一些内容，则来自我们使用的工具和配置。

### 换一个工具：同一句话之外，还带了什么

在已有的一组对比中，Codex 和 Claude Code 接同一个模型服务，各收到同一句问候。先比较它们发出的系统指令，再看工具定义：用户输入相同，并不意味着发给模型的整份请求相同。系统指令写了什么、工具怎样描述，都是理解差异的具体入口；字符数和工具数只帮助看出规模，不用于判断哪一个更好。

这里把 2.1 的“这些东西是谁放进去的”向外扩了一步。原来只在 Codex 里拆开看，现在换一个 coding agent，就能比较不同工具组织请求的方式。对比能说明这两次请求有何不同；它们怎样影响具体任务，还要回到任务表现核对，不能仅凭长度下结论。

### 工具不换，换一个模型服务

刚才改变的是 coding agent。接下来保持 Codex 不变，看它分别连接两种模型服务的已有记录。

先看发送出去的部分：这两次请求里的系统指令和工具表示有什么区别。这是客户端面对不同服务配置时，实际组装出来的请求差异。仅仅看到请求不同，还不能把每一项变化都归因于服务端在处理请求时做了什么。

再看返回的部分。已有实验记录中，一边能读到推理正文，另一边的推理条目呈现为密文；这一处让我们看到服务返回形式也有差别。它说明本次记录中哪些内容可直接观察，不用来比较推理质量，也不展开加密机制。至于网页搜索在哪里执行、压缩由哪一侧完成，需要各自的证据，不能从系统指令的长短顺带推出。

这次比较的收获是：换模型服务时，值得同时留意请求和返回；变化可能不止是模型给出的答案。客户端组装和服务端返回分别看，才能说清眼前的差异发生在哪一侧。

### 工具不换，只看版本变化

除了换工具和模型服务，还可以看同一个工具的不同版本。用 Phistory 现有的两版系统指令对比，只挑一处具体修改：对外发送消息的授权表述怎样改变。

前面看到的系统指令，原来也是会被维护和修改的内容。Phistory 提供了一个查看历史快照的入口，让我们不用自己安装每一个旧版本，就能查看它收录的指令差异。这组快照有自己的模型与配置背景，要和本课实验记录分清。

如果升级以后遇到不同表现，这种对比能提供一条排查线索。但指令发生变化，不等于已经证明某个行为由它导致；当前配置、实际请求和运行表现仍要一起看。这里留下一个有用的观察入口，不要求每次升级都逐行检查指令。

### 回到这一章

从一次任务的累计费用，到自己选择交接内容，再到工具、模型服务和版本带来的差异，我们把同一张请求图放进了更多使用条件里。用户写下的一句话始终只是其中一部分。

项目上，我们补上了个人信息，参考主页改了风格，并完成发布。机制上，2.1 看清组成，2.2 看历史怎样变化，2.3 分辨依据与可见范围，2.4 看查询返回怎样支持下一步判断；这一节再补上五个扩展观察。最后用章文件的七个问题回顾，再进入下一章的小游戏。
