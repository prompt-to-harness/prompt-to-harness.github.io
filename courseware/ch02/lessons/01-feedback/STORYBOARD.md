**本节一句话**：只发一句话，就能看到 Codex 实际发出的请求里远不止这句话；这些加在一起就是 context。

## 两步 Prompt（草稿）

两个 Prompt 都事先设计，保证稳定触发要展示的内容（2026-10-19 讲师确认分两步）。

**p08 第一步（与项目无关）**：

```text
你好，用一句话介绍你能帮我做什么。
```

目的：不触发工具调用，只看 context 的基本组成。录制前确认这一句在冻结版本下不会触发读文件；若触发，换成更短的问候并记下原因。

**p07 第二步（与项目相关、只读）**：

```text
只读任务，不修改任何文件。
这个个人主页 v0 当初定了哪些要求和完成标准？
请说明依据来自哪个文件的哪一段；
不确定就写“不确定”，不要猜。
```

目的：让 Codex 自己去找第 1 章 1.4 留下的 `PROMPT_V1.md` 等文件，在记录里看到工具调用和返回。不提示文件名。不问“项目卡为什么不跳转”：这条决定只在 2.5 用到时就地复述（2026-10-19 讲师确认）。

## p14 按实际记录选择讲法

| 实际结果 | 讲法 |
| --- | --- |
| Codex 读取了 `PROMPT_V1.md` 等文件，说出了要求和完成标准 | 在记录中指认那次读取文件的工具调用：对照工具返回、后续请求和回答，检查来源与理解是否相符 |
| Codex 没读文件，凭目录名或代码猜 | 核对完整请求与工具返回后指出依据缺失；这正是 Prompt 要求“说明依据”的原因 |

还可能出现“读到了但理解错了”或“没有找到依据，回答不确定或继续查找”。均按实际结果讲解，保留原始记录，不重跑凑结果。

## 产出与验收映射

- 跟做：重启开发服务器，确认首页 v0 可用（p02）。
- 自检：能从讲师记录中指出至少四类非用户内容，并说出缺了其中一类会怎样；能指出一次工具调用和它的返回在记录里的位置。
- claude-tap 与 p15 的隔离环境对比，学员可自主尝试，不计入验收。本节不写记录文件（第 2 章不设固定记录文件，2026-10-19）。

## 事实边界与待实测

- 请求记录只用统一脱敏记录；截图检查本机路径、用户名、个人 Skills 列表；标注“一次运行”。
- p08、p16 的字符数与 token 数原来来自 2026-10-02 一份“读标题”任务的记录，第一步 Prompt 改了以后要重录，旧数字不沿用。
- 录制用隔离环境启动，使请求内容接近学员基线。Codex 0.160.0 源码显示：个人 Skills 读自 `$HOME/.agents/skills`，旧位置 `$CODEX_HOME/skills` 仅兼容保留，项目 Skills 读自仓库 `.agents/skills`；因此只设 `CODEX_HOME` 不够，需同时隔离 HOME（复制所需配置与登录）。步骤写入配套页。
- p10 的基础指令目录取自 Codex 开源仓库，与实际发出的指令有差异，画面以实际请求为准、仓库文件作对照。
- 已核实：环境信息与 `AGENTS.md` 都以 user 角色注入，p09 不能只按消息角色划分“我写的 / Harness 加的”；Skills 列表与权限说明是 developer 角色。
- 本地会话记录里的基础指令是删减前的全文，与实际发出的不同；画面一律用代理记录。
- p16a 引用的官方解释未选定；不自造定义，不大段引用。
