# 2.1 逐页分镜：先听听别人怎么说

> 依据：第 2 章提案与分段分镜的 2.1；草稿，未试讲。内部大纲 2.1 已按提案修订（2026-10-02）。

**本节一句话**：熟人给了三条建议，先分清哪些是真问题、谁来决定，再动手。

| 页面 | 页型 | 学员问题 | 画面证据与揭示顺序 | 讲稿要点 / 预期判断 | 方式 |
| --- | --- | --- | --- | --- | --- |
| p01 | 章节开篇 | 第 2 章要做什么？ | 本章地图 → 圈出 2.1 → 一句话主线 | v0 只在自己电脑上；本章做出能拿给熟人看的 v1 并发布 | 看懂 |
| p02 | 切到实操 | 昨天的页面怎么打不开了？ | 浏览器打开本地地址失败 → 终端启动开发服务器 → 页面恢复 | 只操作，不解释；“为什么要重启”留到 2.2 | 跟做 |
| p03 | 漫画开场 | 熟人给了三条建议，都要改吗？ | 第一格：给熟人看首页 → 第二格：三条建议 → 第三格：“我”准备直接让 AI 全改 | 先停一下：建议不等于问题 | 看懂 |
| p04 | 正反对照 + 证据清单 | 三条建议各是什么性质？ | 左：反馈卡三条原话（标“课程示例反馈”）→ 右：空的核对表（复现条件 / 期望 / 实际 / 证据） | 学员可换成自己收集的建议；分支表在配套页 | 跟做 |
| p05 | 切到实操 | 怎样核对？ | 观察清单：第 1 条切手机 360；第 2 条桌面点击项目卡并按 Tab；第 3 条看项目区 | 每条只看相关视口，不全量巡检 | 跟做 |
| p06 | 带解读的操作记录 | 三条核对出了什么？ | 三行：动作 → 结果 → 能说明什么；第 1 条两种结果都列出 | 第 1 条复现与否都要如实写；第 2 条“点了没反应”是事实，但它是不是问题还没判断 | 跟做 |
| p07 | Prompt ↔ 回复对照 | 这三条分别对应哪些代码？ | 只读 Prompt（见下）→ Codex 回复，逐句贴标签 → 高亮它对第 2 条的判断 | 只读，不修改文件；Prompt 不提示 `PROMPT_V1.md` 的存在，让揭示是真的 | 跟做 |
| p08 | 可见 / 不可见对照 | Codex 怎么知道 1.4 的决定？ | 左：我们输入的一句话（约 70 字）→ 右：这一句实际发出的请求（实测第一次请求约 1.15 万 token） | 抛出两个问题：它怎么知道的？我们只写了一句，请求里为什么有这么多东西？ | 看懂 |
| p09 | 分层模型图（循环） | 请求里都有什么？ | 上排：Harness 的组成（系统指令、工具、上下文）→ 下排：本次记录逐块标注：系统指令、工具定义、Skills 列表、环境信息、权限说明、我们那句话 | 这张图是本节的“请求解剖地图”，下面逐块回答“如果没有它会怎样” | 看懂 |
| p10 | 正反对照 + 证据清单 | 如果没有系统指令？ | 左：模型只会续写，不知道自己是写代码的 Agent → 右：Codex 开源基础指令的章节目录：工作方式、性格、`AGENTS.md` 规范、任务执行、验证、汇报 | 产品的大部分行为写在这里；同一个模型换一个 Harness 表现就不同；注意目录里有一节专门讲 `AGENTS.md`，所以 Codex 会去找它 | 看懂 |
| p11 | 带解读的操作记录 | 如果没有工具定义？ | 一个工具的 JSON schema（名字、说明、参数）→ 实测：模型调用了不存在的 `read_file` → 报错 → 改用 `cat` | 模型只能“说”，做事靠 Harness 执行工具；模型只能可靠地调用被描述过的工具；Harness 也会让指令和工具保持一致：没开计划工具时，指令里讲计划的章节会被删掉 | 看懂 |
| p12 | 可见 / 不可见对照 | 装了那么多 Skills，都塞进去了吗？ | 左：请求里的 Skills 列表（只有名字和一句描述）→ 右：某个 Skill 的完整文件 | 列表只是指针，用到才读全文（渐进披露）；装得越多，每次请求越重 | 看懂 |
| p13 | 正反对照 + 证据清单 | 模型知道它在哪台电脑、今天几号吗？ | 左：环境信息（当前目录、系统、日期）→ 右：权限说明（沙箱模式、审批策略的文字） | 模型有知识截止，不注入就不知道；回扣 1.6：权限说明只是文本，真正的限制由本地沙箱执行 | 看懂 |
| p14 | 可见 / 不可见对照 | 同一句话，换一台“干净”的电脑会怎样？ | 两份记录对照：日常环境 / 隔离环境 → 个人 Skills 列表消失（实测约 1.24 万字符降到约 2 千，剩 Codex 自带的 4 个）、第一次请求约 1.15 万 token 降到约 9 千 → 三层来源图：个人（`~/.codex` 的配置、登录、全局 `AGENTS.md`；`~/.agents/skills` 的个人 Skills）/ 项目（仓库里的 `AGENTS.md` 与 `.agents/skills`）/ 本次（目录、日期、权限） | 请求是 Harness 按“你是谁、在哪个项目、这次怎么配置”现场拼出来的；`CODEX_HOME` 只搬走 `~/.codex`，个人 Skills 跟着 HOME 走；讲师录制也用隔离环境，让画面接近学员基线 | 示例（选做） |
| p15 | diff 对比 | 同一句话，换个权限会怎样？ | 只读与可写两次请求的权限说明 diff（实测约 340 与 670 字符，可写时环境信息也多出可写范围）→ 对应 Codex 仓库里按沙箱模式分开的模板文件 | 权限说明是按配置拼装的文本；回扣 1.3 的权限选择与 1.6 | 示例（选做） |
| p16 | 带解读的操作记录 | 它到底是怎么“知道”的？ | 回到钩子：工具调用 → 返回内容 → 下一次请求带上返回（分支见下） | “记得”其实是“读到了”；数字只说明结构，随版本和环境变化 | 看懂 |
| p17 | 权衡矩阵 | 哪些要改，谁来决定？ | 四类标签：视觉现象、行为事实、个人偏好、既有决定 → 三条逐条归类 → 第 2 条交给人 → 选定第 3 条 | 第 2 条要不要改是人的决定，不是 AI 的；第 3 条是内容缺失，必然成立 | 跟做 |
| p18 | 暂停自检 | — | Q1：从请求记录中指出四类不是你写的内容，并说出缺了其中一类会怎样；Q2：第 1 条在你的页面上不复现，该怎样记录？ | Q1 回到 p09–p15；Q2 回到 p06 与分支表 | 看懂 |
| p19 | 涂鸦小结 | — | 反馈四要素、四类标签、“记得＝读到了”、请求解剖地图 → 课件站“请求解剖”页入口 → 预告 2.2：多次请求之间发生了什么 | 产出写入 `CH02_VIBE_ITERATIONS.md` | 跟做 |

## p07 只读 Prompt（草稿）

```text
只读任务，不修改任何文件。
下面是别人对我首页的三条建议，以及我的核对记录：
（粘贴反馈清单）
请逐条说明：
1. 它对应哪些文件和代码；
2. 它是否和项目里已有的决定或文档冲突；
3. 你的依据是哪个文件的哪一段。
不确定就写“不确定”，不要猜。
```

## p16 的两个分支

| 实际结果 | 讲法 |
| --- | --- |
| Codex 读取了 `PROMPT_V1.md` 等文件，认出“项目卡不跳转”是 1.4 的决定 | 在记录中指认那次读取文件的工具调用：它不是记得，是读到了 |

## 事实边界与待实测

- 请求记录只用统一脱敏记录；截图检查本机路径、用户名、个人 skills 列表；标注“一次运行”。
- 录制用隔离环境启动，使请求内容接近学员基线。Codex 0.160.0 源码显示：个人 Skills 读自 `$HOME/.agents/skills`，旧位置 `$CODEX_HOME/skills` 仅兼容保留，项目 Skills 读自仓库 `.agents/skills`；因此只设 `CODEX_HOME` 不够，需同时隔离 HOME（复制所需配置与登录）。具体步骤待实测，写入配套页。
- p10 的基础指令目录取自 Codex 开源仓库，与实际发出的指令有差异（见提案实测记录），画面以实际请求为准、仓库文件作对照。
- 已核实：环境信息与 `AGENTS.md` 都以 user 角色注入，p09 不能只按消息角色划分“我写的 / Harness 加的”；Skills 列表与权限说明是 developer 角色。
- 本地会话记录里的基础指令是删减前的全文，与实际发出的不同；画面一律用代理记录。
