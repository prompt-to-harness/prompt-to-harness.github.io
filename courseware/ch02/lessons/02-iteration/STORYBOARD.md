# 2.2 逐页分镜：只改一处，并证明改好了

> 依据：第 2 章提案与分段分镜的 2.2；草稿，未试讲。

**本节一句话**：先选对会话，再用当前证据让 Codex 只改一处，并用三种视口、键盘和构建证明没弄坏别的。

## p29 本轮 Prompt（草稿）

```text
Goal：在项目区呈现我提供的项目经历，解决反馈清单第 3 条“看不出你做过什么”。
Context：反馈清单见 docs/evidence/CH02_VIBE_ITERATIONS.md；
1.4 已决定项目卡不跳转，本轮不改。
项目内容（原文照用）：
（由人提供）
Constraints：只使用上面的文字，不补写、不润色事实；不加链接、不加依赖；
只改项目区相关文件；先说明计划和要改的文件，等我确认后再改。
Done when：三种视口内容完整可读；Tab 焦点顺序与改前一致；
npm run build 成功；diff 只含项目区相关改动。
```

## 本章记录模板（草稿）

```markdown
## 第 N 轮

- 问题证据：
- 本轮目标：
- 会话选择与理由：
- 改动文件：
- 验证结果（三种视口 / 键盘 / build）：
- 剩余问题：
- 回退点：
```

“会话选择与理由”和“剩余问题”两项是本节验收需要，比提案中的五项多两项。

## 产出与验收映射

- 跟做：第 3 条对应的内容补充已呈现（原内容完整时记录为新批准的补充，示例练习单独标注）；三种视口与键盘无回归；本轮记录完整；会话选择理由引用具体状态。
- 自检：能解释“恢复对话不等于恢复文件或服务”；能说出压缩后模型不再看到哪些原始信息；能区分输入量、缓存记录和实际费用，不能仅凭对话长度断言每次费用增加。

## 事实边界与待实测

- p25–p26 的仓库数据见提案实测记录（核对于 2026-10-02），录制前按冻结版本复核。
- 已核实（0.160.0，MiniMax 配置）：`/compact` 走本地压缩，用一段“交接摘要”提示让模型写摘要，保留最近用户消息；`codex exec resume` 恢复后按当前目录与配置追加新的环境信息和权限说明；`--last` 默认只在当前目录的会话中挑选。
- p22–p24 的数字与“每次重发完整历史”只在 MiniMax 自定义 provider + Responses API 下实测过。

## 内容已完整时的跟做分支

先记录第 3 条未发现缺口，再由人确认一条值得补充的项目事实；Prompt 的 Goal 改为呈现这条新增内容，不追认原页面有缺陷。没有实际补充需求时，在独立练习副本使用课程合成示例：原文“学习笔记：记录课程练习”，补充为“学习笔记：整理三次课程练习的目标、页面截图和修改记录”。这些是虚构练习内容，不当作学员真实经历发布。

p25–p26 的对比只帮助理解版本与模型配置会影响请求；讲完回到 p28 的具体选择，不从指令长度推导哪个模型更好。p27 保留在主讲时，p33 才考该页内容；若移到配套材料，须同时移走对应自检并提供实际入口。
