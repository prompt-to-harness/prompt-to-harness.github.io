**本节一句话**：对话每多一轮，前面的内容都会被重发；清空和压缩之后还剩什么，在同一份请求记录里看得到。项目上，把自己的项目经历加进首页，并证明没弄坏别的。

**页序**：先讲清 context 怎样变长和清空（p21–p27a），再选会话、做本轮修改并验证（p28–p31），最后在这次真实的长会话上看压缩（p27）。id 不按页序。

```text
Goal：在项目区呈现我的项目经历。
Context：首页 v0 的项目区目前只有占位内容；
项目卡不跳转，本轮不改。
项目内容（原文照用）：<每行一条：项目名称：一句描述>
Constraints：只用上面的文字，不补写；不加链接、依赖；
只改项目区；先说计划，等我确认再改。
Done when：我在浏览器查 360/768/1440 宽可读、
```

2026-10-19：去掉“解决反馈第 3 条”和对 `CH02_VIBE_ITERATIONS.md` 的引用；Context 改为直接写项目区的现状。“项目卡不跳转，本轮不改”是约束，不展开讲这条决定（只在 2.5 就地复述）。此前的改动：2026-10-03 压缩到 8 行，使 1280×900 演示画面不必滚动；2026-10-05 去掉“1.4 已定”，视口写出具体宽度；2026-10-06 写明视口与 Tab 由人检查、build 与 diff 交给 Codex（讲师用 `materials/mainline/run-v1.sh` 试跑三轮，其中两轮 Codex 没有浏览器工具却自行验证视口，执行多花 14–16 分钟）；讲师演示把尖括号一行换成 `courseware/ch02/materials/README.md` 中两位讲师经历聚合的三条。

## p27 压缩对比的素材

主讲用本节真实会话。录制时若会话太短，压缩前后看不出差别，就改用 `materials/compact/` 的独立实验，并在画面和口播里如实说明“这是另一次专门做的实验”，不把它说成主线会话。原独立实验里实际丢掉的证据：grep 原文只剩“共 10 处匹配”，追问答不出；人写的决定以用户消息原文保留。

## 内容已完整时的跟做分支

学员的项目区已经有完整经历时，由人确认一条值得补充的项目事实，Goal 改为呈现这条新增内容。没有实际补充需求时，在独立练习副本使用课程合成示例：原文“学习笔记：记录课程练习”，补充为“学习笔记：整理三次课程练习的目标、页面截图和修改记录”。这些是虚构练习内容，不当作学员真实经历发布。

## 产出与验收映射

- 跟做：项目经历已呈现，内容由人提供；三种视口与键盘没有回归，`npm run build` 通过；能说出本轮会话选择的理由，并引用 context 的具体状态（p33 Q4）。
- 自检：能解释“恢复对话不等于恢复文件或服务”和“`/clear` 不清文件”；能说出压缩后模型不再看到哪些原始信息；能区分输入量、缓存记录和实际费用，不能仅凭对话长度断言每次费用增加。
