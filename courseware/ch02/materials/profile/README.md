# 2.2 讲师演示用的个人信息文件

> 状态：草稿（2026-10-22），按第 2 章决策 C2-55 准备，未录制。内容待 MiaoDX 本人过目后冻结。

`profile.md` 是 2.2 讲师演示的输入。录制时把它复制到个人主页项目的根目录（排练用 [`../mainline/run-2.2.sh`](../mainline/run-2.2.sh) 自动放入），2.2 的 Prompt 只写“内容见 `profile.md`，原文照用”，不把内容贴进 Prompt。这样 Codex 要自己读这个文件，请求记录里能看到一次读文件的工具调用和它的返回（2.1 讲过的“工具返回也进 context”在 2.2 再出现一次），2.3 审 diff 时也能对照“页面上的每一句是不是都来自这个文件”。

## 内容来源

- 取自 [miaodx.com](https://miaodx.com/) 首页和在线简历的公开内容（2026-10-22 查阅，简历标注更新于 2026-10）。
- 只挑了主页用得上的四块：基本信息、教育、工作经历、项目与开源。每条压成一行，不写数字指标、奖项、论文和技术栈，页面放得下，diff 也审得完。
- 不放联系方式（邮箱、电话、社交账号）。项目不放链接：沿用“项目卡不跳转”的约定。
- 取代 [`../README.md`](../README.md) 里“两位讲师经历聚合的三条项目”，那三条留作历史记录。

## 学员怎么用

学员照同样的四块写自己的 `profile.md`，只写愿意公开的内容；也可以用虚构人物。这个文件会和页面一起提交，2.4 推送前检查历史时要一并看。
