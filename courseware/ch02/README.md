# 第 2 章：Vibe Coding - 迭代并发布个人主页

> 状态：第 2 章的**唯一来源**。本文写讲透问题、各节要点、验收和全章约定；每页讲什么写在各节分镜；决策和实测记录追加在 [LOG.md](LOG.md)。内部大纲第 2 章只留摘要并链接到这里。本章按[章设计方法](../../docs/outline/proposals/2026-10-22-chapter-design-method.md)试点（C2-51 至 C2-54）。
> 负责讲师：MiaoDX。对外描述见[平台交付版](../../docs/course-outline.md)第 2 章。时长为暂估，内容未试讲。本文不是课程承诺。

## 本章主线

**一句话**：把个人主页补成真正能用的样子（个人信息、经历、项目，再参考一个喜欢的主页改出自己的风格）并发布上线；一路打开 Codex 实际发出的请求，看清 context 长什么样、怎么变。

**主知识点**：Context，本章要讲透。每节一个项目动作，配 context 的一种状态：组成 → 变化 → 后果（依据与看不见的、发到了哪里）。

**锚点图**：“这一次请求里有什么”，画成一列方块（系统指令、工具、环境、规则、对话历史、工具返回、这一句）。全章都回到这张图：2.1 认识它，2.2 看它变长、被清空、被压缩，2.3 指着它问依据在哪一块、哪些东西不在里面，2.4 指着它问它发到了哪里。数字只做旁注。

**起点**：项目连续，证据不连续。讲师演示从第 2 章起点快照开始；课件只引用当前的产品代码和本章任务卡，不引用第 1 章的过程记录（C2-54）。

## 各节要点

主线跟做，计入验收；深入只要求看懂，每一条回答主线引出的一个追问，只收机制类内容（每次运行都一样的）。时长合计约 95 分钟。

| 节 | 项目动作 | 主线（跟做） | 深入（看懂）：回答的追问 | 验收 |
| --- | --- | --- | --- | --- |
| 2.1 只说了一句话，模型收到了什么（25 分钟） | 重启开发服务器，问两句 | 一次请求里有什么；工具调用和返回进入 context；点名文件和让它自己找，代价差几倍。第二问问“项目区现在显示什么、数据在哪个文件”，答案在当前代码里，正好是 2.2 要改的地方 | **这一列是谁定的？** Codex（这层 Harness）按个人、项目、本次三层来源组装；同一句话在不同权限、能力目录开或关时的请求并排一页；子代理有自己的 context，只露出一句 | 跟做：开发服务器重启，个人主页可用。看懂：从讲师请求记录中指出至少四类非用户内容，说出缺了其中一类会怎样；指出一次工具调用和它的返回 |
| 2.2 补上个人经历，看对话怎么变长（25 分钟） | 写两三行 `AGENTS.md`；学员先自己在项目根目录写一份 `profile.md`（基本信息、教育、工作经历、项目，只写愿意公开的），`/clear` 后让 Codex 读这个文件放进页面（讲师一轮，学员可分几轮） | 每次请求都重发前面的内容，代价是 token 和注意力；失败的返回也一直留着；`/clear` 清对话不清文件；压缩后只剩摘要；会话和文件是两回事 | **能不能少发一点、留下想要的？** `AGENTS.md` 在清空和压缩后重新进入；缓存为什么便宜却不省注意力；`/status` 看还剩多少，到窗口 90% 自动压缩 | 跟做：个人信息、经历和项目已呈现，内容都来自人写的个人信息文件、没有 AI 编造；在浏览器里看过页面，`npm run build` 通过；能说出本轮会话选择的理由，依据是 Codex 界面里看得到的“这个会话读过哪些文件、做过哪些事”（不装 claude-tap 也能做到） |
| 2.3 参考一个主页改风格：它看到了什么（20 分钟） | 先快速审 2.2 的内容（范围对不对、每一句是不是都在 `profile.md` 里），提交 homepage-v1 作检查点；再找一个喜欢的主页改出自己的风格：第一轮参考一个主页整体改风格（配色和版式都可以改，文字不变、不加依赖），第二轮说清哪里不像再改；审完接受就提交，不接受就 `git restore` 回到 homepage-v1 | 风格改动的依据在请求里的哪一块：给了参考地址，它怎样取、取到了什么（2026-10-22 排练：它用 web_search 工具在模型服务一侧打开了地址，只拿到首页摘要，缺的部分用描述和自己的记忆补；取回的内容不在请求记录里，C2-62）；我们看到的参考页面、浏览器里的效果，都不在 context 里；第二轮的请求带着第一轮的对话历史。参考的是风格，不照搬别人的代码和文字。审查只看范围、出处和新增的行为（动画、脚本），不逐行走读 | **它看全了吗？** 长输出会被截断，它说“检查过了”时追问看全了没有；截图直接进 context，模型能读（2026-10-22 实测）；模型生成的 SVG 图它自己看不见渲染效果（待实测） | 跟做：homepage-v1 提交，范围对、每一句都有出处，提交说明写本轮目标与改动文件，能说出回到它的命令；至少一轮风格改动，审过后提交或 `git restore`。看懂：能指出这次风格改动的依据在请求里的哪一块，说出它看不见的一样东西 |
| 2.4 发布上线，看 Codex 怎么用 gh（15 分钟） | 推送前看清整段历史，部署 GitHub Pages | 推送前看历史，发布，做三项检查；对外动作由人确认 | **这一列发到了哪里，外面的东西怎么进来？** context 每次都发给模型服务，和推送公开是两回事；网页搜索的结果进 context；`gh` 把动作送出去，要经批准 | 跟做：URL 未登录可访问、Network 中没有 404 资源、刷新后仍可用；推送前看过完整历史，公开内容与历史里没有 secret、他人信息或不愿公开的个人信息（自检）；推送、改设置这类对外动作都经人确认。看懂：context 发给了谁 |
| 2.5 用好 context 的四个做法（10 分钟） | 无，另一位讲师分享 | — | 重发换算成费用；换会话时自己写交接；换一个工具看同一句话的请求；同一个工具换一个模型服务，看服务端替它做了什么（C2-65） | 看懂即可，不设练习和自检题 |

**不放进本章**：系统指令的版本历史（配套页，第 7 章讲“规则会过期”时再用）；`gh` 调用在记录里的位置细节（讲师提示）；`git revert` 的完整演示（复现按钮）；只在某一次运行里出现的现象（只放讲师提示，见[可讲点清单](../../docs/outline/proposals/2026-10-21-ch02-teachable-points.md)的稳定性列）；统一检查入口（本章只建立包含 build 的最小部署流程，第 7 章在独立 dependency-cruiser 仓库建立）。

## 全章约定

- **全章基线**：`tools/clean-codex.sh` 默认的 MiniMax-M3.1-Flash、MiniMax 官方模型能力目录开、推理档位 max。能力目录开时系统指令只有一句加多代理团队说明，主要用法写在 code mode 的 `exec` 工具描述里。课件数字按这套配置录；2.4 也用它，加 `CLEAN_CODEX_GH=1` 使用本机 `gh` 登录（C2-39）。
- **请求记录**：全章用同一套配置下的请求记录，各节可以分开录。画面不说成同一次运行，每段标“一次运行”；录制时冻结、统一脱敏，画面数字以当段记录为准。
- **claude-tap**：讲师演示的必要内容，固定 0.1.146。PPT 上写清启动方式并录屏演示，说明它是本地代理、会经手 API 密钥、只看得到经过代理的内容。学员自己运行算选做，不计入验收；不另做分系统的排障文档。ChatGPT 登录下能否使用，不作为主演示内容。
- **演示与实测范围**：macOS 上的 Codex CLI + MiniMax 自定义 provider。ChatGPT 登录、Windows、OpenAI 官方 provider 下的行为不作为本章核实项。
- **章节独立**：本章只依赖第 1 章留下的个人主页；没做完第 1 章的学员可从第 1 章参考快照开始（见 course-starter `CHECKPOINTS.md`）。引用前面章节时就地复述决定或做法本身，检查点写“本轮开始前的最后一次提交”，不依赖之前各章的证据文件或 tag 名。
- **少用跨章引用**：不用“1.4 的决定”“回扣 1.2”这类节号当钩子，学员和讲师都记不住那段上下文。需要前面的内容时，直接说出内容本身，例如“项目卡点了不跳转，是做个人主页时定下的”。
- **Harness 的两个意思**：本章只用第一个意思，即 Codex 这层 Harness：包在模型外面、组装请求、调用工具、管权限的那一层。2.1 拆开请求时先用一句话说明，并点明课程第四层要为项目搭的 Harness 是另一层意思，第 7 章再讲。之后正文写“Codex（这层 Harness）”，不单写“Harness”。
- **记录方式**：本章不设固定记录文件，学员按自己的习惯记笔记或截图。本轮目标和改动文件写进提交说明；检查点就是提交本身；推送前检查结果学员自己看过即可；公开 URL 和三项发布检查放进自检清单；会话选择理由答在暂停自检题里。
- **页面检查**：本章由人在浏览器里看一眼页面、跑一次 build，不再列屏幕尺寸和键盘检查；想看手机上的样子，只在 2.2 p31 的操作提示里一句（设备工具栏切到 360×800）（C2-45、C2-48）。第 3 章讲 Skill 时，把页面检查做成 Codex 能自己跑、结果能回到 context 的检查（跨章安排，待第 3 章确认）。
- **对外动作由人确认**：推送、改 Pages 设置、触发部署都是对外动作。可以人自己执行，也可以交给 Codex、人在批准框里看清命令再确认；不能不经人确认就送出去（C2-47）。
- **方式**：跟做＝学员暂停视频完成，计入验收；看懂＝机制演示，以自检为准；示例（选做）＝讲师演示，学员可按配套页自主尝试，不计入验收。学员跟做只覆盖一轮内容迭代、Review 与发布。
- **不构造失败**：2.3 不准备坏 diff，2.4 不准备错误的 `base`。用到准备好的教学材料时标明是教学材料，不说成一次真实运行。
- **演示只走正常路径**：录屏演示一条走通的路；分支情况（没装 `gh`、空仓库暂时不能启用 Pages 来源等）写在操作提示和配套页，口播不展开。自然出现的失败照常就地处理。
- **各节厚度不要求均匀**：2.2 的改动若很小，2.3 就以演示回到检查点为主，不为加厚 2.3 而扩大 2.2 的需求。
- **模型名**：课件与讲稿以录制时实际使用的具体型号为准，录制前冻结。
- **对外措辞**：平台交付版只写工具中立的能力描述，不写请求查看工具、模型或请求次数这类会变的细节。
- **分镜写法**：页面 id 全章连续、稳定，规则见[课件制作流程](../../docs/agents/courseware-workflow.md)。页型用[视觉设计规范](../../docs/production/visual-design-system.md)第 6 节的名称，不新增页型。分镜不做页面级时长估算，节奏由讲师录制时调整。“层”一栏是主线（跟做或看懂，计入本节主线）或深入（只看懂，只收机制类内容）；“讲透问题”一栏对应上面的 1–7，项目动作页对应验收，不对应问题。开篇页都放锚点图，按本节高亮其中几块。

## 常见错误与风险

- 让 AI 为解决一个 CSS 问题重写全部组件或引入大型 UI 依赖；
- 让 AI 替自己编写项目经历，或把不愿公开的内容写进公开仓库；
- 只看 Codex 的完成报告或截图，自己不在浏览器里看一眼页面、不跑 build；
- 把请求记录里的 token 数、请求次数或指令长度当成固定值；
- 以为清空或压缩对话会撤销文件改动；
- 会话中途写好 `AGENTS.md` 就以为 Codex 已经看到，没有 `/clear` 或开新会话；
- 2.4 启动时没加 `CLEAN_CODEX_GH=1`，Codex 发现 `gh` 未登录就自己发起登录，人没有拒绝；
- 硬编码讲师仓库名，导致学员的 Vite `base` 或 Pages 路径错误；
- 把 GitHub Actions 成功等同于页面已经可用；
- 在公开站点或提交历史中暴露个人敏感信息、未授权图片或 secret。
