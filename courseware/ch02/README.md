## 本章主线

**一句话**：把个人主页补成真正能用的样子（个人信息、经历、项目，再参考一个喜欢的主页改出自己的风格）并发布上线；一路打开 Codex 实际发出的请求，看清 context 长什么样、怎么变。

**主知识点**：Context，本章要讲透。每节一个项目动作，配 context 的一种状态：组成 → 变化 → 后果（依据与看不见的）→ 伸到外面（用本机的命令行工具读写 GitHub）。

**锚点图**：“这一次请求里有什么”，画成一列方块（系统指令、工具、环境、规则、对话历史、工具返回、新的 Prompt）。系统指令是 Codex 给的全部说明（身份、协作、Skills 列表、权限说明），规则只指项目里的 AGENTS.md（C2-88）。全章都回到这张图：2.1 认识它，2.2 看它变长、被清空、被压缩，2.3 指着它问依据在哪一块、哪些东西不在里面，2.4 指着工具和工具返回问：工具列表里没有的 gh 是怎样用上的，GitHub 上的状态怎样进来。数字只做旁注。

**起点**：项目连续，证据不连续。讲师演示从第 2 章起点快照开始；课件只引用当前的产品代码和本章任务卡，不引用第 1 章的过程记录（C2-54）。从 2.2 起每节做完留一个快照分支，命名 `ch02/<节>-done-<排练日期>`（如 `ch02/2.2-done-20261024` 就是 2.3 的起点），内容是 lab-runs 里归档的这一节结束状态，推到 course-starter 前问讲师；排练和课件证据从本节快照起跑，重跑一节不用重跑前面几节，`demo.sh` 用 `CH02_START` 从快照起跑（C2-104）。

## 各节要点

主线与深入划分教学重点：主线回答本章讲透问题并推进项目；深入回答主线引出的机制追问，不把某一次运行的偶发现象当成通用结论。跟做与看懂划分参与方式，主线中既有跟做，也有只需看懂的机制演示。时长只粗估到 5 分钟档，合计约 90–100 分钟；录播可以剪辑，不按它排练核算，也不当作改动的依据（C2-79）。

| 节 | 项目动作 | 主线（按验收区分跟做与看懂） | 深入（看懂）：回答的追问 | 验收 |
| --- | --- | --- | --- | --- |
| 2.1 只说了一句话，模型收到了什么（25 分钟） | 重启开发服务器，问两句 | 一次请求里有什么；一句 Prompt 引出多次请求，每轮在上一轮末尾追加工具调用和返回；点名文件和让它自己找，先核对回答依据与读取范围，再比较实际代价，不预设节省倍数。第二问问“项目区现在显示什么、数据在哪个文件”，答案在当前代码里，正好是 2.2 要改的地方 | **这一列是谁定的？** Codex 按个人、项目、本次三层来源组装；系统指令首句与 MiniMax 官方说明对照，说明一部分来自模型配置，不展开配置教程、权限对照、字段和数量记忆（C2-81）；子代理有自己的 context，只露出一句 | 跟做：开发服务器重启，个人主页可用。看懂：从讲师请求记录中指出至少四类非用户内容，说出缺了其中一类会怎样；指出一次工具调用和它的返回 |
| 2.2 补上个人经历，看对话怎么变长（25 分钟） | 讲师演示写两三行 `AGENTS.md`（学员选做，不计入验收）；学员先自己在项目根目录写一份 `profile.md`（基本信息、教育、工作经历、项目，只写愿意公开的），`/clear` 后用 Plan 模式（`/plan`）让 Codex 读这个文件、先出计划，人审过计划的范围再放行（越界时留在 Plan 修订），放进页面（讲师一轮，学员可分几轮）；看过页面、build 通过后，让 Codex 提交 homepage-v1 作检查点 | 每次请求都重发前面的内容（回答交互题、确认执行这样补一句，前面的资料和计划随之重发），代价是 token 和注意力（前面原样重发才能命中缓存，缓存只省 token，不省注意力）；失败的返回也一直留着；`/clear` 清对话不清文件；压缩后只剩摘要；会话和文件是两回事，回退靠提交，不靠对话 | **能不能少发一点、留下想要的？** `AGENTS.md` 在清空和压缩后重新进入；`/status` 看还剩多少，到窗口 90% 自动压缩 | 跟做：个人信息、经历和项目已呈现，内容都来自人写的个人信息文件、没有 AI 编造；在浏览器里看过页面，`npm run build` 通过；homepage-v1 已提交，提交说明写本轮目标与改动文件，能说出回到它的命令；能说出本轮会话选择的理由，依据是 Codex 界面里看得到的“这个会话读过哪些文件、做过哪些事”（不装 claude-tap 也能做到） |
| 2.3 参考一个主页改风格：它看到了什么（20 分钟） | 从 homepage-v1 开始（没跟上的从本节起点快照开始），找一个喜欢的主页改出自己的风格。讲师演示两轮：第一轮参考一个主页整体改风格（配色和版式都可以改，个人内容不变、不加依赖），第二轮在同一会话贴当前效果和参考两张截图，说一句哪里不满意、想要什么样；学员至少完成一轮，第二轮按需要进行；审完接受就让 Codex 提交，不接受就 `git restore` 回到 homepage-v1 | 参考主页的样子它看不见。三点，都是机制，不押在某一次运行上（ED-020）：① 取回来不等于看到了：给的是网址，进入“工具返回”的是它挑着读的 HTML/CSS 片段；交互题的答案是工具返回，计划进对话历史；② 页面的样子不在 context 里：第一轮哪里和想的不一样，我们一眼看到，它看不到（它想自己起服务看，正说明这一点）；③ 看到的样子要靠我们带进去：截图加一句话放在“新的 Prompt”，之后每次请求都带着；它看见了贴的图，仍看不见自己做出来的页面。第二轮带着第一轮的历史（2.2 讲过，一句带过）。参考的是风格，不照搬别人的代码和文字。审查只看浏览器里像不像、新加的行为（脚本、动画）、范围对不对，不逐行走读 | **它拿到的代码看全了吗？** 命令输出过长会被截断（2026-10-21 实测）；10-24 四次排练都是它自己挑着读 CSS，没有出现截断，只留讲师提示 | 跟做：至少一轮风格改动，审过后让 Codex 提交或 `git restore`。看懂：能指出这次风格改动的依据在请求里的哪一块，说出它看不见的一样东西，说出贴的截图进了哪一块 |
| 2.4 发布上线，看 Codex 怎么用 gh（15 分钟） | 推送前看清整段历史，部署 GitHub Pages | 推送前看历史；Codex 写部署配置，人审过让它提交；Pages 来源交给 Codex 用 `gh` 设置，人批准、人推送；推送后让 Codex 用 `gh` 读这次部署的状态和日志；人自己做三项检查，只推送一个 tag | **工具列表里没有 gh，它是怎样用上的？GitHub 上的状态怎样进来？** 请求的工具里只有 `exec` 这类通用工具，`gh` 是本机装的命令，经 `exec` 运行，会不会用靠模型自己的知识；调用里是完整的 `gh` 命令和沙箱外运行的申请，返回是 GitHub 给的文本，作为工具返回进入下一次请求。Pages 设置、部署状态本来都不在 context 里，`gh` 查过才进来（和 2.3 页面的样子不在 context 里同理）；改设置的调用经人批准，批准本身不在记录里 | 跟做：URL 未登录可访问、Network 中没有 404 资源、刷新后仍可用；推送前看过完整历史，公开内容与历史里没有 secret、他人信息或不愿公开的个人信息（自检）；推送、改设置这类对外动作都经人确认；让 Codex 用 `gh` 读到这次部署的结果。看懂：在请求记录里指出一次 `gh` 调用和它的返回 |
| 2.5 用好 context 的五个做法（10 分钟） | 无，另一位讲师分享 | — | 暂留五条候选：重发换算成费用；换会话时自己写交接；换一个工具看同一句话的请求；同一个工具换一个模型服务，看服务端替它做了什么；用 Phistory 看各工具系统指令怎样随版本变（C2-76，取代原“系统指令版本对比”配套页）。由讲该节的讲师排练后定取舍，暂按 10 分钟；若超时，先把第三条和第五条合并（都是跨工具看系统指令），再压缩其余，仍放不下则移到配套材料 | 看懂即可，不设练习和自检题 |

**不放进本章**：系统指令的版本历史（2.5 只用 Phistory 做一条展示；第 7 章讲“规则会过期”时再展开）；`gh` 调用在记录里的位置细节（讲师提示）；`git revert` 的完整演示（复现按钮）；只在某一次运行里出现的现象（只放讲师提示，见[可讲点清单](../../docs/outline/proposals/2026-10-21-ch02-teachable-points.md)的稳定性列）；统一检查入口（本章只建立包含 build 的最小部署流程，第 7 章在独立 dependency-cruiser 仓库建立）。

## 交付物与退出门禁

- 1 轮必做的内容迭代，形成评审过、可回退的 homepage-v1 提交，提交说明写明本轮目标与改动文件；
- 至少 1 轮参考主页的风格改动，审查后提交接受的改动，或用 `git restore` 放弃；第二轮按需要进行，不要求必须接受风格结果；
- 推送前看过完整历史，以及一个可公开访问的 GitHub Pages 个人主页；
- 学员能用公开 URL、Network 面板和 Actions 日志验证发布结果，不把 Actions 成功当作页面可用；

## 全章约定

- **全章基线**：`tools/clean-codex.sh` 默认的 MiniMax-M3.1-Flash、MiniMax 官方模型能力目录开、推理档位 max。能力目录开时系统指令只有一句加多代理团队说明，主要用法写在 code mode 的 `exec` 工具描述里。课件数字按这套配置录；2.4 也用 Agent Lab，它默认复用本机 `gh` 登录，不用另加开关（C2-112，取代 C2-39 的 `CLEAN_CODEX_GH=1`）。
- **请求记录**：全章用同一套配置下的请求记录，各节可以分开录。画面不说成同一次运行，每段标“一次运行”；录制时冻结、统一脱敏，画面数字以当段记录为准。
- **claude-tap**：讲师演示的必要内容，固定 `0.1.146+pr475`，即 0.1.146 加上已提交上游的查看器改动 [liaohch3/claude-tap#475](https://github.com/liaohch3/claude-tap/pull/475)（文字按文字显示、显示推理、显示 namespace 子工具），Agent Lab 与课件静态查看器用同一个 wheel（C2-103、C2-108）；p06-tap 页面和口播交代一句这处调整。录下来的请求是 0.1.146 抓的，抓取部分两版相同。PPT 上写清启动方式并录屏演示，说明它是本地代理、会经手 API 密钥、只看得到经过代理的内容。学员自己运行算选做，不计入验收；不另做分系统的排障文档。ChatGPT 登录下能否使用，不作为主演示内容。
- **演示与实测范围**：macOS 上的 Codex CLI + MiniMax 自定义 provider。ChatGPT 登录、Windows、OpenAI 官方 provider 下的行为不作为本章核实项。
- **章节独立**：本章只依赖第 1 章留下的个人主页；没做完第 1 章的学员可从第 1 章参考快照开始（见 course-starter `CHECKPOINTS.md`）。引用前面章节时就地复述决定或做法本身，检查点写“本轮开始前的最后一次提交”，不依赖之前各章的证据文件或 tag 名。
- **少用跨章引用**：不用“1.4 的决定”“回扣 1.2”这类节号当钩子，学员和讲师都记不住那段上下文。需要前面的内容时，直接说出内容本身，例如“项目卡点了不跳转，是做个人主页时定下的”。
- **锚点图的读法**（C2-86）：全章只有一种读法。粗框高亮是这一页要看的块；这次请求里没有内容的块画成灰色虚线，写“这次没有”；其余块照常在请求里，只是这一页不看，画得浅；不在请求里的东西画在列外的虚线框里。底部一句写给学员：这一页为什么看这几块，不写制作说明。整列都要看时整列高亮。由 `tools/lessonkit.py` 的 `anchor()` 统一画，不在页面里手写。只用在 2.1 p16a（第一次拼起来）和 2.1–2.4 四个开篇（C2-88；2.3 p40b 改成证据页后不再放，C2-105），不在其他页面另加。
- **Harness 的说法**：2.1 不单讲 Harness 的两个使用层面（C2-82）。正文写具体执行者 Codex，需要强调术语时写“Codex（这层 Harness）”；课程第四层围绕项目建设的知识、工具、约束、检查与反馈环境，第 7 章展开。
- **记录方式**：本章不设固定记录文件，学员按自己的习惯记笔记或截图。本轮目标和改动文件写进提交说明；检查点就是提交本身；推送前检查结果学员自己看过即可；公开 URL 和三项发布检查放进自检清单；会话选择理由答在暂停自检题里。
- **页面检查**：本章由人在浏览器里看一眼页面、跑一次 build，不再列屏幕尺寸和键盘检查；想看手机上的样子，只在 2.2 p31 的操作提示里一句（设备工具栏切到 360×800）（C2-45、C2-48）。第 3 章讲 Skill 时，把页面检查做成 Codex 能自己跑、结果能回到 context 的检查（跨章安排，待第 3 章确认）。
- **对外动作由人确认**：推送、改 Pages 设置、触发部署都是对外动作。可以人自己执行，也可以交给 Codex、人在批准框里看清命令再确认；不能不经人确认就送出去（C2-47）。
- **方式**：跟做＝学员暂停视频完成，计入验收；看懂＝机制演示，以自检为准；示例（选做）＝讲师演示，学员可按配套页自主尝试，不计入验收。学员必做一轮内容迭代、至少一轮风格改动，以及相应的审查、检查点和发布；风格第二轮按需要进行。写 `AGENTS.md` 与自己运行 claude-tap 为选做，不计入验收。
- **PPT 与现场演示**：按[课程共识“PPT 与现场演示”](../../docs/design/course-design-principles.md#7-录制形态与公开材料)（全课适用）：PPT 自包含、证据来自排练并标明哪一次；每段先讲 PPT，再切现场讲相同和不同，当天结果不同不替换 PPT。故事线只押在机制和稳定现象上（编辑规范 ED-020）。
- **Git 操作交给 Codex**：本章的暂存、提交、`git restore` 让 Codex 来做，人在批准框里看清命令再确认，提交前看它列出的 `git status`；回退靠 Git，不靠对话。Codex 0.163.0 在 workspace-write 下 `.git` 只读，提交会申请到沙箱外运行（10-24 排练实测）（C2-104）。
- **不构造失败**：2.3 不准备坏 diff，2.4 不准备错误的 `base`。用到准备好的教学材料时标明是教学材料，不说成一次真实运行。
- **演示只走正常路径**：录屏演示一条走通的路；分支情况（没装 `gh`、空仓库暂时不能启用 Pages 来源等）写在操作提示和配套页，口播不展开。自然出现的失败照常就地处理。
- **各节厚度不要求均匀**：内容改动的审查在 2.2 的计划和页面检查里做完，2.2 结尾提交；2.3 只讲改风格，不为加厚审查而扩大 2.2 的需求（C2-104）。
- **模型名**：课件与讲稿以录制时实际使用的具体型号为准，录制前冻结。
- **对外措辞**：平台交付版只写工具中立的能力描述，不写请求查看工具、模型或请求次数这类会变的细节。
- **分镜写法**：页面 id 全章连续、稳定，规则见[课件制作流程](../../docs/agents/courseware-workflow.md)。页型用[视觉设计规范](../../docs/production/visual-design-system.md)第 6 节的名称，不新增页型。分镜不做页面级时长估算，节奏由讲师录制时调整。“层”一栏是主线（跟做或看懂，计入本节主线）或深入（只看懂，只收机制类内容）；“讲透问题”一栏对应上面的 1–7，项目动作页对应验收，不对应问题。开篇页都放锚点图，按本节高亮其中几块。

## 常见错误与风险

- 让 AI 为解决一个 CSS 问题重写全部组件或引入大型 UI 依赖；
- 让 AI 替自己编写项目经历，或把不愿公开的内容写进公开仓库；
- 只看 Codex 的完成报告或截图，自己不在浏览器里看一眼页面、不跑 build；
- 把请求记录里的 token 数、请求次数或指令长度当成固定值；
- 以为清空或压缩对话会撤销文件改动；
- 会话中途写好 `AGENTS.md` 就以为 Codex 已经看到，没有 `/clear` 或开新会话；
- 2.4 时本机 `gh` 没登录，Codex 自己申请运行 `gh auth login`，人没有拒绝；
- 硬编码讲师仓库名，导致学员的 Vite `base` 或 Pages 路径错误；
- 把 GitHub Actions 成功等同于页面已经可用；
- 在公开站点或提交历史中暴露个人敏感信息、未授权图片或 secret。
