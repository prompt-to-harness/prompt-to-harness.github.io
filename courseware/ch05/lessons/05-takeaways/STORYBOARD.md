## 本节内容

### 前四节把功能做完了，这一节换一件事

5.4 结束后，留下的是通过本章验收的 JSON Diff、Review 结果、可解释的 diff、本地检查点及已知缺口，以及更新后的 `CH05_IMPLEMENTATION.md`。JSON Diff 的实现和验收到这里就停。第 6 章才批准「明确提示当前图是上次有效结果」的 CR-01；本节不把它设为完成条件，也不再补实现或验收。本节也不是进入第 6 章的判断门禁。

本节从另一个问题开始：做着做着，还有哪些招数可以带走？这是第五章的工程经验分享，围着 Vibe Coding，先有趣、再实用。看懂即可，不新增练习和自检题，不设学员判断，不改本章代码，不要求学员安装任何插件。时长按工程经验预算 15 分钟，允许在 10–15 分钟内试讲调整。增补两页之后，15 分钟会偏紧，试讲时可以压缩各段时长，但不为了卡在 15 分整而删减已确认的内容。地图短标题为「可带走的招数」。

**一句话**：前四节已经把功能往前推完，这一节把课程主线里还没展开、但马上能用的 Vibe Coding 招数拿出来看一眼，做着做着就能带走。

全节分成两段：先看一组不必额外安装的官方技巧，加上一个「按画面改」的入口；再只深看一个官方插件。官方依据见 [Slash commands](https://learn.chatgpt.com/docs/reference/slash-commands)、[Developer commands](https://learn.chatgpt.com/docs/developer-commands)、[Plugins](https://learn.chatgpt.com/docs/plugins)。

### 一组官方技巧，外加一个按画面改的入口

1. **侧聊，不冲乱正在做的事**
   使用 `/side`（CLI 里也写作 `/btw`）。主会话正在实现时，把一句报错或某个 API 问到侧聊里，主记录保持连续。这是本节最实用的机关，也最先演示。

2. **想换一种做法，把对话分出去**
   使用 `/fork`，把当前对话复制到新会话（或新的工作副本入口）里试另一种实现，原来的记录还在。用来回答「不如换个写法看看」。官方桌面版说明：`/fork` 可以把本地对话复制到新的本地对话或 worktree；`/worktree` 是在新的 Git worktree 里跑对话。这里只补这一句，不把 `/worktree` 做成演示页，也不展开工作区隔离，那是第 7 章的正课。

3. **把界面截图贴进对话，让它按画面改**
   这是第三个技巧。讲的是实现做到一半时怎么用：对着当前界面截一张图，让它按画面修改，而不是把截图、文件交给 AI 看的入门用法。那个门槛更低的讲法留给第 1 章。

4. **会话变长了，压缩当前对话的上下文**
   使用 `/compact`。官方说明是：Compact the current chat’s context（压缩当前对话的上下文）。讲的是实现做到一半、对话已经很长时，怎样继续往下推，不另开新功能。不预写压缩后的摘要长什么样。

5. **先给当前项目生成脚手架，再改**
   使用 `/init`。官方说明是：Generate an `AGENTS.md` scaffold for the current project（为当前项目生成 `AGENTS.md` 脚手架）。第 2 章已经讲过怎么写这份文件，这里只看「先生成再改」，不再重讲写法。同一页带一句 `/project`：官方说明是 Choose a project for new chats（给新对话选择项目）；不把 `/project` 单开一页。

`/review` 不作为演示项。5.4 后半已经是整体验收与 Review；本节只在口播里提一句：产品自带的 `/review`（需要看具体文件改动时再配 `/diff`）可以检查未提交改动，官方说明是聚焦行为变化和缺测，并且不改工作区。要讲清它不能代替本章验收，也不重讲 5.4 的规格回环。

`/memories` 也不做演示页。官方说明是：Configure whether the chat can use or generate memories, when Memories is available（在 Memories 可用时，配置这次对话能否使用或生成记忆）。只在收束口播里提一句；若录制版本尚未核验，标明尚未核验，不现场猜测记忆会怎样工作。

在这些技巧之后，若录制版本的 ChatGPT 桌面版或 CLI 已核验，可用很短一句补上语音口述，或从 CLI 用 `/app` 把当前会话接到桌面版。未核验的 App 能力只留官方说明，不现场猜测，也不占用正片技巧的位置。桌面版的 `/pet` 如需出现，只作约 10 秒的趣味收尾，不占正片。课程规定 Codex App 为可选入口，项目操作与模型接入须单独核验；对学员应使用「Codex App」这一名称。

### 一个好玩的官方插件：Remotion

技巧讲完后，用 `/plugins` 打开官方目录，只深看一个插件：[Remotion 的官方 Codex 插件](https://www.remotion.dev/docs/ai/codex-plugin)。用代码做视频，和前面做网页、改开源仓库的感觉都不同，负责本节的「有趣」。演示预先审查过的官方示例或短片段，说明它提供了哪些 Skill 或工作流；用 `$技能名` 显式调用即可，点到为止。具体技能名以录前审查结果为准，不在这里预先写定。

不要求学员安装，也不在课上新建 Remotion 项目。若录制时该插件在教学账号中不可用，改用 [openai/plugins](https://github.com/openai/plugins) 里的 Build Web Apps 作为备选：只展示它在界面设计上的指导，避开第 4.6 节已经提过的浏览器测试类能力。Figma 官方插件需要额外账号，不作为本节首选。

演示选用独立的小副本或预录片段，避免改动第 5 章的 JSON Diff 工作区。现场不跟做安装；以课前准备的短片段或截图为主，避免把时间花在下载和登录上。命令、截图改界面、插件和 App 能力须按录制版本核验；缺失项从本节拿掉，不现场改用未证实的替代操作。
