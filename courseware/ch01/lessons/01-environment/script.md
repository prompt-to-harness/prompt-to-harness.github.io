> 从演示内容源导出。逐页时长预算见 `lesson.js` 的 `seconds`，口播与操作均未试录；演示分支按录制时的实际情况选择。

## 第一章开场口播

你好，欢迎来到第一章。从这一章开始，我们要动手做一个自己的个人主页。你可以先想一个很简单的画面：有人打开这个页面，能看到你是谁、你在做什么，以及你想展示的作品。我们会从这个想法出发，一步一步把首页原型做出来。

如果现在让你对 AI 说“帮我做一个个人主页”，它可能马上就开始写代码。不过，这句话里还有不少事情没有说清楚：页面要放哪些内容，哪些文件可以修改，做到什么程度才算完成？这一章，我们就围绕这个小项目，练习怎样把这些要求讲清楚，再检查它交回来的结果。

工具与环境在零点二准备。本章从一次很小的修改开始。接着，回过头看 AI 是怎样读取文件、执行动作的，以及什么时候需要我们确认。等这些环节看明白了，再把首页的需求整理成一份明确的请求，交给它执行，最后一起看页面、检查代码改动，并验证项目能否构建。

你可以跟着视频暂停操作，也可以先看完一遍，再用自己的项目练习。遇到报错或者结果和预期不一样，我们就把具体问题找出来，带着证据继续修改。现在先从一个容易看清结果的任务开始：请 AI 帮我们换掉页面上的一句欢迎语。

## P04 先交任务，再看计划，最后确认

[对应课件](index.html#p04)

### 口播

【操作提示｜停留课件 p04 第 1 步，展开并阅读完整请求；此页讲解请求，暂不发送，统一在 p04-live 实操】

我们先把要发的请求看一遍。第一句限定读取范围：只读 setup-check/index.html 和必要的仓库状态。接下来写清楚目标，要改的是 h1#welcome-message，也就是刚才找到的那个标题元素。

目标文案直接给出完整的一句：“你好，欢迎来到 Vibe Coding 课堂！”这样后面检查时，就有一份可以逐字对照的标准。

再往下看，其他内容、结构、样式都不改，也不安装依赖、不发布。因为今天要做的事情只有替换欢迎语，增加这些动作会超出当前任务。

【操作提示｜推进第 2 步，指向“先复述目标、非目标和小计划，等我确认后再修改”；仍留在课件】

注意这一句：先复述，再给小计划，等我确认后再修改。我们希望先听一听它准备怎么做。

计划不需要很长。读到目标文字，只替换这句欢迎语，然后说明怎样检查页面和改动，就够了。你要看的是，这个计划有没有对应刚才的任务。

如果它说“顺便调整配色”，或者“先安装一套前端框架”，就指出这一项超出了范围，让它先改计划。今天把这些环节分开，是为了看清楚每一步；小任务不用写成一份很长的方案。

【操作提示｜推进第 3 步；下一页再发送请求与确认，不在此处预读一份虚构的 AI 回答】

等目标、范围和计划都对上，我们再明确回复：同意按这个计划，只修改指定文件里的欢迎语，其他内容保持不变。

这次确认对应的是这一次修改。如果后面出现额外动作，还要看它是否在范围里。具体的工具权限提示，我们会在一点三专门讲。

接下来切到真实操作。你可以对照刚才这份请求，看它怎样读取文件、怎样回复，以及什么时候开始写入。

## P05 页面正确，还要查改动范围

[对应课件](index.html#p05)

### 口播

【操作提示｜课件 p05 第 1 步 → Chrome 已有“练习页面”标签页，刷新 http://localhost:4174/setup-check/；与修改前截图比较，不新开另一份文件】

先检查页面。地址还是刚才那个地址，服务也还是同一份副本。我们刷新后，拿任务卡的完整文字来对照：你好，欢迎来到 Vibe Coding 课堂！空格、文字和最后的标点都看一遍。

再看看周围的页面。标题以外的内容有没有变化，布局有没有明显移动。把这个画面和修改前的截图放在一起，就更容易发现差异。

如果刷新后还是旧文字，先核对服务目录、文件是否已经保存，以及打开的地址。确认检查对象没找错，再决定要不要让 AI 修正。

【操作提示｜切 Terminal 的“仓库检查”标签页，依次运行 git status --short、git diff --stat、git diff；补看 git diff --cached，以覆盖暂存区。若 status 出现未跟踪文件，切 VS Code 检查其内容。对照修改前记录】

然后看代码改动。先用 status 看有哪些文件变化，再用 diff 看里面具体改了什么。带减号的一行表示删除，带加号的一行表示新增。

我们要找到原来的欢迎语被替换成目标文案的地方，也要继续往下看完整输出，确认有没有附带修改其他内容。

普通 git diff 显示的是尚未暂存的修改。已经暂存的部分要另外看，新增但还没被 Git 跟踪的文件也要从状态列表里检查，不能因为某段 diff 很短就跳过去。

最后对照开工前的记录，把原来就有的变化与这次修改区分开。

【操作提示｜回课件 p05 第 3 步；依实际结果选择结论：全部符合则说明通过；有问题则指出具体位置，并保留给 p06 修正】

现在可以回答开头的问题了。浏览器帮助我们确认用户实际看到的文字和布局，完整差异和文件状态帮助我们确认改动范围。

再回看操作记录，它是否等到确认后才修改。三个问题都有对应证据，才可以接受这次结果。
