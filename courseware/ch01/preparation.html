第 1 章 · CLI 协作实践

课前准备与排障

CLI 为主演示和完整验收入口。先改独立环境页欢迎语；React + TypeScript + Vite 应用在 1.5 课堂创建。

取得独立练习项目

起点为 course-starter：项目说明、欢迎语任务卡、环境记录单。按项目说明创建自己的仓库，再克隆到课程仓库之外；以下以同级 projects/personal-homepage/ 为例，在课程仓库根目录执行，将地址替换为自己的仓库地址：

git clone 你自己的仓库地址 ../projects/personal-homepage
cd ../projects/personal-homepage
git rev-parse --show-toplevel
git rev-parse HEAD
git status --short

已有目录时不要覆盖原有工作；可使用其他新目录。记录课程来源版本和自己仓库的完整 SHA。编码工具和下方 4174 服务都在同一练习项目根目录启动；本机已有同级 course-starter/ 时，也可在该目录核对材料。临时试讲另放同级 experiments/。

课程统一发布 commit 仍待录制冻结，本地初始提交不等于统一发布基线。起点没有 package.json 或正式首页，这是预期状态；1.4 材料见项目根目录的 PROJECT_BRIEF.md 与 PLACEHOLDER_CONTENT.md，工具链说明见 docs/setup/TOOLCHAIN.md。

安装与模型接入

按官方 Codex CLI 安装说明选择系统路径。在独立练习目录启动 codex，核对登录、实际读写与审批边界。

课程主用 MiniMax M3，教学接入仍待实测；工具安装与模型服务认证分别核对。Claude 观察对象的正式名称与定位待核验，不作未经验证的能力或性能结论。不要展示密钥。

Node.js 与 npm 在 1.5 前按固定教学工具链准备。1.1 的独立 HTML 不依赖 Node；不要提前创建 React 应用来掩盖环境问题。

记录环境与起点

git --version
codex --version
codex --help
pwd
git rev-parse --show-toplevel
git branch --show-current
git rev-parse HEAD
git status --short

记录实际版本、目录、分支、提交与工作树状态，并核对权限。已有未知改动时保留现场、辨认来源，不能直接清空。Node/npm 检查记录为已就绪或待补做。

浏览器与演示页

用浏览器直接打开独立练习项目的 setup-check/index.html。若要在课件 P04 内嵌查看，在 projects/personal-homepage/ 根目录另开终端运行：

python3 -m http.server 4174 --bind 127.0.0.1

打开 环境检查页。只启动一个 4174 服务，确认展示与 CLI 修改的是同一副本。Python 服务为内嵌演示所用，不是直接打开 HTML 的前置条件。

首次任务与验收

按 P04 请求只改 h1#welcome-message 为“你好，欢迎来到 Vibe Coding 课堂！”。先复述、计划、确认，再修改；不改其他内容、布局、文件，不安装、不发布。

刷新浏览器核对文字与布局，再检查 diff 和 git status；记录问题、限定修正、复验。没有真实问题时明确本轮通过；教学故障样例须另行标注，不捏造错误或修正成功。

失败与继续条件

  • CLI 不可用：仅经核验的临时桌面入口可完成同一任务，标记临时通过；1.3 结束前必须补齐 CLI 基线。
  • 登录或模型不可用：保留脱敏错误，可先观察回放，恢复后补实际操作。
  • Node 未就绪：可以先完成 1.1，1.5 前补齐。
  • 页面不更新：检查文件路径、服务目录与刷新；不修改别处源码伪装成功。
  • CLI 基线未完成：可以继续 Prompt 讨论，暂停依赖 CLI 的实操。回放和其他智能体不能记作 CLI 通过。

保存首次闭环记录

按环境单保存环境、目标复述、小计划、人工确认、前后截图、diff、Review 和修正记录，形成 docs/evidence/CH01_ENVIRONMENT_AND_FIRST_LOOP.md。教学证据文件的写入范围须单独确认，不混入欢迎语单文件任务。

首次闭环交给 1.2 分析；1.3 完成 CLI 与权限记录；1.4 确认 Prompt；1.5 才初始化正式网站。
