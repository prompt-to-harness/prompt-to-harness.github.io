第 0 章 · 课前准备

课前准备

开始第 1 章之前，按这一页取得练习项目、装好 Codex CLI 并登录。命令都在终端里运行（macOS 的“终端”、Windows 的 PowerShell，或 VS Code 里的终端都可以），每个命令块上方写着在哪个目录运行。

第 1.1 节里讲师会把这些检查完整演示一遍，你可以暂停视频跟着做。这里提前准备好，上课时就不用在安装上卡住。

取得练习项目

课程模板是 course-starter 仓库，里面有项目说明、欢迎语任务卡和环境记录单。先按项目说明，用模板创建你自己的仓库，再克隆到本地。下面以课程仓库旁边的 projects/personal-homepage/ 为例，把“你自己的仓库地址”换成实际地址后运行：

后三行依次确认：当前在练习项目的根目录；当前提交的完整编号（SHA）；有没有未提交的改动。目标目录已经存在时，不要覆盖里面的内容，换一个新目录名。把课程模板的版本和你自己仓库的提交编号写进环境记录单。

刚创建的项目里还没有 package.json，也没有正式的个人主页，这是正常的。写个人主页任务（1.4）时要用的材料在项目根目录的 PROJECT_BRIEF.md 与 PLACEHOLDER_CONTENT.md，工具版本说明见 docs/setup/TOOLCHAIN.md。

安装 Codex CLI 并登录

按官方 Codex CLI 安装说明选择你的系统安装。然后在练习项目目录里运行 codex 启动它，登录课程所用模型服务的账号，确认它能读取练习文件，并看清哪些操作需要你批准。

课程主要使用 MiniMax M3 模型。安装 Codex CLI 和登录模型账号是两步，分别确认。截图或录屏时不要露出密钥。

Node.js 与 npm 在创建个人主页（1.5）之前装好即可，版本以 docs/setup/TOOLCHAIN.md 为准。1.1 只改一个 HTML 文件，用不到 Node；不要为了绕开环境问题提前创建 React 项目。

记录环境与起点

把输出的版本、目录、分支、提交编号和改动状态填进环境记录单。看到不认识的改动时，先保留、弄清来源，不要直接清空。Node/npm 还没装好，就记为“待补做”。

遇到问题时

  • Codex CLI 用不了：可以先用图形界面完成 1.1 的任务，记为临时通过；最晚在 1.3 节（工具与权限）结束前补上 CLI。
  • 登录失败或模型不可用：记下报错（去掉密钥等敏感信息），先看课程视频，恢复后再补做。
  • Node 没装好：不影响 1.1，创建个人主页（1.5）之前补齐。
  • CLI 一直没装好：可以继续看 Prompt 相关的内容，需要 CLI 的实操先暂停。只看视频，或者用其他 AI 工具完成，都不算 CLI 这一步通过。

1.1 实操时的检查和排障（页面服务、第一次修改、保存记录）见 1.1 实操备忘。
