## 一、改了什么

**1. `templates/styles.css`（第 7 区重写 + 第 8c 区参数化）**
- 把「场地容器」拆成三种语义清晰的容器：
  - `.board-wrap` —— 只负责居中，**与场地类型无关**（保持原样）；
  - **`.stage`（新增）** —— 通用非网格场地容器：纵向 flex + 水平居中，宽度上限 `var(--stage-max, 100%)`，不加列宽约束；配 `.stage__tip`（场地内提示文字）；
  - `.board` —— 保留原行为，但注释明确它是**网格/棋盘专用容器**，自带 `display:grid` 和按列算的宽度上限；把硬编码的 `108px` 提成变量 `--cell`（默认仍 108px，**渲染结果与原来完全一致**）。
- `.stage-canvas` 的宽度上限改为 `var(--stage-max, calc(var(--cols,8)*64px))`、长宽比改为 `var(--stage-ratio, 4/3)`——**默认值不变**（512×384、4/3），但以后任何玩法都能用自己的数值覆盖，而不必改模板。

**2. `SKILL.md`（正文 + 骨架 + 清单 + 反模式 + 验证）**

- 新增一节「**场地容器怎么选（网格 / 画布 / 自由布局）**」：`.board-wrap` 通用、`.board` 仅网格、`.stage` 非网格，**两个类不得挂在同一元素上**，并写明「不要把某一款游戏的像素尺寸/比例写进模板」；
- 骨架示例加上「二选一」注释；frontmatter description 点明三种场地容器；

## 二、为什么能减少同类问题

- **根因是"把网格场地当通用结构"**。改法不是给画布加一条专用规则，而是把「场地容器」在 Skill 里**显式建模成两个互斥选项**，并把选择表写进正文、模板注释、检查清单、参考资料四处——AI 在生成时的**每个读取点**都会撞到这条信息，不再需要自己推断「`.board` 是不是万能容器」。
- **消除了"自己造轮子"的诱因**：上次 AI 自造 `.arena`（几乎逐条复制 `.stage-canvas`），说明它没把现有场地件当成正式接口。现在画布类玩法有现成、受支持的 `.stage` + `.stage-canvas`。
- **宽度/比例不再硬编码**：`--cell`/`--stage-max`/`--stage-ratio` 让"布局随玩法调整"成为默认路径，同时默认值保持原样，不破坏既有网格与画布玩法的观感。
- **补上了"静默覆盖"这一类通用坑**（同特异度后写规则赢），并把「量一次宽度」写进验证清单——这类塌缩没有报错，只有量尺寸才抓得住。
- 没有引入当前游戏的任何具体数值（640/480、4:3 之外的值都没写死成要求；4:3 只是 `.stage-canvas` 的**既有**默认值，且可覆盖）。
