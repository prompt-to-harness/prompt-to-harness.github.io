# 3.3 逐页分镜：挑一个缺陷，按证据修

> 依据：第 3 章故事线提案第五版；草稿，未试讲。调查与修复排练见 `courseware/ch03/materials/mainline/debug-3.3.sh`。

**本节一句话**：先复现，再让 Codex 只调查，再由人定规则，最后最小修改；调查常常比报告看得更深。

| 页面 | 页型 | 学员问题 | 画面证据与揭示顺序 | 讲稿要点 / 预期判断 | 方式 |
| --- | --- | --- | --- | --- | --- |
| p15 | 章节开篇 | 挑哪一个？ | 3.2 的问题清单 → 圈出“翻错步数不变”（最先看到的现象） | 先挑能稳定复现、影响明确的 | 看懂 |
| p16 | 操作记录 | 能稳定复现吗？ | 三步复现 → 连做三次 → 每次步数都是 0 → 写成缺陷报告 | 不能稳定复现就先别修 | 跟做 |
| p17 | Prompt ↔ 回复 | 先让 Codex 只调查 | 只读请求：复现步骤、期望、实际、三个要求 → Codex 的回答：两个独立缺陷，第二个让第一个无法单独验证 | 只读权限，回答里不许改代码 | 跟做 |
| p18 | 代码讲解 | 根因在哪？ | 词表 12 个词各不相同、每词只生成一张 → 配对分支永远走不到 → 步数只在配对分支里加 | 表面现象（步数）下面还有一层（牌组）；用代码位置验证，不靠“听起来合理” | 跟做 |
| p19 | 正反对照 | 我的报告哪里不对？ | 报告里“只有配对成功时步数才加 1” → Codex 反问：观察到的，还是从代码推的？ | 观察和推断分开写；推断要标出来（讲师自己的报告就混了一句） | 看懂 |
| p20 | 正反对照 | 改之前，先定什么？ | 两个问题：用哪 6 个词？步数怎么算？→ 人定：6 个词；两张算一步，成功失败都算 | 这是两条规则，不是代码问题；Codex 也说“文案取舍是你的决定” | 跟做 |
| p21 | diff + 证据清单 | 改对了吗？ | 最小 diff → 原场景复验 → 相邻场景（配对、完整一局、重开、最佳成绩）→ build | 修复只处理根因；相邻场景都要再看 | 跟做 |
| p22 | 涂鸦小结 | — | 复现 → 只读调查 → 人定规则 → 最小修改 → 复验 → 下一节：经验有人打包好了吗 | 记忆翻牌 v1 提交 | 看懂 |

## 产出与验收映射

- 跟做：缺陷记录（复现步骤、假设、根因、修复、复验）；定下的规则写进 `CH03_MEMORY_GAME.md`；记忆翻牌 v1 提交。
- 验收沿用大纲：修复前稳定复现；修复只处理根因；原场景和相邻场景复验；不伪装成现场随机发现。
