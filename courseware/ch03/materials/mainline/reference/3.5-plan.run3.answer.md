## 一、技术选型与理由

**结论：React 19 + 原生 CSS + `requestAnimationFrame`，零新增依赖，不引入 Phaser。**

game-studio 的路由规则默认 2D 走 Phaser，这里我建议偏离，理由按重要性排序：

1. **仓库已有既定惯例**：`MemoryGame.tsx` + `memory-game.css` 就是「React 组件 + 作用域 CSS + 零依赖 + 纯几何图形」。第二个游戏沿用同一形状，改动最小、评审最容易。
2. **Phaser 的能力在这个玩法里用不上**：Brief 要求的是圆形 + 矩形 + 键盘移动 + 圆形碰撞，没有精灵图、图块、摄像机、场景编排。插件自己列的 Phaser 适用场景（sprite/tile-based、camera跟随）一条都不命中。
3. **体积代价**：当前构建产物 gzip 61 KB；Phaser 完整包量级在 1 MB / gzip 300 KB 上下（以实际安装为准），对个人主页是数量级负担，和 Brief 的「只用简单几何图形或 CSS」相悖。
4. **环境限制**：这个沙箱里 npm registry 不可达（`npm view phaser version` 20 秒超时），装 Phaser 也只能 vendor 进仓库，更糟。

**照搬插件的架构规范**（这些是重点，不是套话）：
- **模拟与渲染分离**：碰撞/计时/生成逻辑放在 `src/game/dodge/` 的纯函数里，不碰 React 和 DOM；React 组件只负责输入、帧循环、渲染和 HUD。
- **帧循环不触发 React 重渲染**：实体位置存在 ref 里，每帧直接写 `style.transform`；只有整数秒、分数、生命变化时才 `setState`。这是性能的关键——60fps 的 `setState` 会把页面拖垮。
- **HUD/菜单用 DOM**：计时、分数、生命、开始/结束覆盖层都是真 DOM 文字，带 `role="status"`；只有场地是图形。
- **输入映射集中在一处**：`move-up/down/left/right` 四个动作，WASD 和方向键各绑一套。

## 二、玩法与参数（默认值，可调）

| 项 | 值 |
| --- | --- |
| 场地 | 逻辑坐标 800×500，CSS `aspect-ratio` 自适应，实体用百分比定位 |
| 玩家 | 圆，半径 15，速度 300 单位/秒 |
| 收集物 | 圆，半径 11，同时存在 3 个，+10 分，约 1.0 秒后重生 |
| 障碍 | 6 个：3 个巡逻条（撞墙反弹）+ 3 个漂移块，矩形 |
| 时限 | 60 秒倒计时 |
| 生命 | 3 条，受击后 1.2 秒无敌（闪烁）+ 击退 |
| 难度 | 障碍速度在 60 秒内从 1.0× 线性升到 1.5× |
| 碰撞 | 圆 vs 矩形，取矩形最近点算距离 |
| 存档 | 最高分存 `localStorage`（key 与翻牌的 `BEST_MOVES_KEY` 同风格） |

**交互流程**：`idle`（覆盖层「开始游戏」）→ `running` → `over`（覆盖层显示结果 + 重新开始）。
键盘监听挂在**场地元素**上而不是 `window`：开始后自动聚焦场地，`blur` 时清空按键并自动暂停（点场地继续）。这样你在页面上滚动或点别处时不会被方向键劫持，也不会「人不在、玩家还在原地送命」。

## 五、需要你拍板的 3 点

1. **零依赖 DOM+CSS（推荐）还是一定要 Phaser？** 选 Phaser 的话我需要你提供网络访问或接受 vendor 进仓库。
2. **障碍要不要漂移块？** 我推荐「巡逻条 + 漂移块」两种（碰撞代码复用同一套）；只做巡逻条也行，更简单但60 秒可能偏单调。
3. **最高分存 localStorage 要不要？** 翻牌游戏存了最佳步数，我倾向保持一致；不想要我就不存。
