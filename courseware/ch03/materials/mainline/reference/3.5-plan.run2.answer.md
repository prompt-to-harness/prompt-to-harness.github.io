# 计划：60 秒躲避与收集（DodgeGame）

## 1. 技术选型

**选：Canvas 2D + `requestAnimationFrame` + 纯 TypeScript 模拟层，HUD 用 React DOM。新增运行时依赖为 0。**

理由（按 game-studio 的路由顺序：先 `game-studio` 分类 → 2D → 本该走 Phaser 默认，但引擎选型表的前提不成立）：

- **不引入 Phaser 的理由**：引擎选型表里 Phaser 的适用条件是「精灵/图块为主」「需要相机与场景原语」。本 brief明确「只用简单几何图形或 CSS，不用图片、音频和外部资源」，是固定相机、单场景、圆形+矩形的纯数学碰撞——精灵管线、tilemap、相机、场景编排、asset manifest **全部用不上**，等于为一个约 300 行的数学循环背1MB+ 的运行时。
- **接进现有 React 应用的额外成本**：`main.tsx` 用了 `<StrictMode>`，effect 会双调用，Phaser 的 `new Phaser.Game()` 与 canvas 挂载需要额外处理销毁与重建；而 MemoryGame 已确立「单组件 + DOM HUD」的房间内写法，沿用它更一致。
- **替代方案（如果你更看重插件默认路径）**：也可以做 Phaser 版，但需要新增依赖 + `src/dodge/` 场景目录，HUD 仍是 DOM，收益主要是「用了一个引擎」。**我建议不做**，除非你要的就是引擎实践。

**保留 game-studio 的架构约束**（`web-game-foundations` 第 1/2/5 条），这些与引擎无关，照做：
- 模拟与渲染分离：规则、碰撞、计时在纯 TS 模块里，不碰 DOM。
- 输入映射集中一处：`WASD` + 方向键 → 一个方向向量。
- HUD 走 DOM（`game-ui-frontend`：文字密集的 UI 不要塞进 canvas）。

## 3. 玩法与规则（拟定数值，可调）

- **场地**：固定逻辑坐标 `720×480`，canvas 按 devicePixelRatio 放大 backing store 保证不模糊，CSS 侧等比缩放。碰撞始终在逻辑坐标里算，**与窗口大小无关**（避免 resize 时碰撞错位）。
- **玩家**：半径 14 的圆，速度260 px/s，斜向归一化。
- **收集物**：半径 10 的圆，**+10 分**，吃到后立刻在空白处随机重生。
- **障碍**：移动的矩形，碰到 **扣 1 条命** + 约 1.5s 无敌闪烁 + 回到场地中央。3 条命。
- **难度**：60 秒内障碍生成间隔从约 1.6s 压到 0.5s，速度同步上升。
- **结束**：倒计时归零 或命数归零 → 显示结果 + 「重新开始」。最高分存 `localStorage`（沿用 MemoryGame 的 try/catch + 校验写法，独立 key `homepage-dodge-best`）。

## 4.几个必须处理的实现细节

- **计时用时间戳而非 `setInterval`**：60 秒倒计时按真实经过时间算，掉帧也不会不准。
- **不让 React 每帧重渲染**：模拟状态放 ref，rAF 直接画；只有分数/命数/每秒一次的倒计时才同步进 React state。
- **输入清理**：`keydown`/`keyup` 监听 window，按键存 Set；对方向键 `preventDefault` 防止页面滚动；`blur` 时清空按键，避免切窗后角色卡住。
- **页面切走自动暂停**：监听 `visibilitychange`，避免你在试玩时切到别的标签页，回来发现已经 game over。
- **重开时清空按键状态**，否则会出现「按着方向键重开后角色一直往一边跑」。
