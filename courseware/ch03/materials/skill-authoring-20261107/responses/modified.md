# 最小翻牌记忆游戏 — 开发方案

## 1. 分类与路由

| 判定 | 结果 |
|---|---|
| 2D 网格 + 翻牌补间 + 指针输入 | 2D 默认轨道 → **Phaser**（非 Three.js / 非 R3F / 非裸 WebGL） |
| 文本型 HUD、结算面板、按钮 | **DOM 覆盖层**（不放进 canvas） |
| 素材 | 无角色动画，**不走 sprite-pipeline**；牌面程序化绘制 |

**技术栈**：Phaser 3 + TypeScript + Vite，`src/ui/` 放 DOM HUD，画布只负责牌阵。
*（纯 DOM/CSS 翻牌是可行的更轻量变体，但偏离本插件 2D 默认路径；除非你明确要零依赖，我按 Phaser 走。）*

## 2. 玩法定义- **幻想**：一张小桌面上摊开的记忆牌阵，找齐所有对子。
- **玩家动词**：`flipCard`（点/触摸一张牌）、`restart`（重新开始）。
- **棋盘**：4×4，8 对 = 16 张牌，牌面 8 个符号。
- **回合规则**：每次翻两张 → 比对
  - 一致：两张牌**保留面朝上**、锁定不可再翻，配对数 +1
  - 不一致：停留 ~800ms 让玩家看清，然后同时翻回背面
- **锁定规则**：判定动画期间输入锁定；第一张翻开时第三张不可点。
- **结束条件**：8 对全部配对 → 停止计时、禁止翻牌、弹出结算面板。
- **失败状态**：无失败，只有"重开"。

## 3. 架构边界（simulation / render 分离）

```
src/
  game/simulation/    # 纯 TS，可单测，不 import Phaser
    state.ts          # 牌阵、阶段枚举、配对/步数/计时
    systems/deck.ts   # 洗牌（种子随机 mulberry32，可复现）
    systems/match.ts  # 翻牌、比对、锁定、胜负判定
  game/input/actions.ts        # 动作表：flipCard / restart
  game/assets/manifest.ts      # 稳定 key：card.back / card.face.symbol
  phaser/scenes/BootScene.ts   # 仅加载
  phaser/scenes/GameScene.ts  # 薄场景：读 simulation，产出 sprite
  phaser/view/                 # 翻牌补间、匹配闪光
  ui/hud/ ui/overlays/        # DOM：步数/配对数/计时/重开/结算
```

- 状态机阶段：`idle → awaitingFirst → awaitingSecond → resolving → won`（`restart` 从任意阶段回到 `idle`）。
- 场景只做状态→sprite 的映射和补间播放；规则变更不得依赖补间时长。
- 计时器由 simulation 拥有，DOM HUD 每帧从中读数渲染。

## 4. 视觉与 UI 方向

- **材质语言**：哑光纸牌 + 圆角卡背；一主色调（深蓝桌布）配高对比符号。
- **HUD（常驻，仅一处）**：顶部一条窄状态条 —— 步数 / 已配对 x/8 / 计时 / 「重新开始」按钮。
- **结算面板**：居中一次性出现，含用时与步数 + 重开按钮；不使用全屏标题卡。
- **动效**：翻牌为 scaleX 1→0→1 的单次补间；匹配时轻微高亮，失误时轻微左右抖动。尊重 `prefers-reduced-motion`：降为淡入淡出、无抖动。
- **响应式**：桌面 4×4 居中；窄屏缩放卡牌尺寸，必要时降到 4×3 换行，保持牌面可点面积 ≥44px。
- **可访问性**：重开按钮是真实 `<button>`，可键盘操作；牌面带 `aria-label`。

## 5. 素材工作流

- 卡背：一张程序化生成的 PNG（或纯 Graphics 绘制）。
- 牌面：8 个符号用 Graphics + Text 生成图集，运行时按 key 取用。
- 清单只有 `card.back`、`card.face.*` 若干 key；代码中不出现文件路径。
- 无3D 资产、无 GLB流程。

## 6. 实施顺序

1. **M1** 脚手架 + simulation 纯函数 + Vitest 单测（洗牌唯一性、比对、胜负、重开归零）
2. **M2** GameScene 接入 simulation：翻牌补间、输入锁、失配回翻
3. **M3** DOM HUD + 结算面板 + 重开（完整状态重置：重新洗牌、计数归零、面板隐藏、解锁）
4. **M4** 响应式 + reduced-motion + 键盘可达5. **M5** 浏览器 playtest，按下面清单逐项核对

## 7. 检查计划（**待执行**，非已通过结果）

每项含「前置状态 / 用户操作 / 预期可见结果」。

| # | 前置状态 | 用户操作 | 预期可见结果 |
|---|---|---|---|
| 1 | 首次加载完成 | 无 | 16 张牌全部背面朝上平铺；HUD 显示步数 0、配对 0/8、计时 0 |
| 2 | 初始状态 | 点击任意一张牌 | 该牌翻至正面并停住；HUD仍为 0/8（未判定） |
| 3 | 已翻开第一张 | 点击另一张牌 | 第二张翻开；两张同时可见，出现匹配/不匹配结果 |
| 4 | 两张牌不匹配 | 等待 | 约 800ms 后两张同时翻回背面；步数 +1 |
| 5 | 两张牌匹配 | 等待 | 两张**保持面朝上**，配对计数 +1，该对不可再点击 |
| 6 | 判定动画进行中 | 快速点击第三张牌 | 无响应（输入锁定生效），不改变任何牌面 |
| 7 | 同一张牌已翻开 | 再次点击该牌 | 无响应，不重复计入步数 |
| 8 | 全部8 对已配对 | 无（自动触发） | **游戏结束**：计时停止、翻牌锁定、结算面板出现并显示总步数与用时 |
| 9 | 结算面板可见 | 点击「重新开始」 | 面板关闭、全部牌翻回背面并重新洗牌布局、步数与配对数归零、计时从 0 重新开始 |
| 10 | 任意进行中状态 | 点击 HUD 的「重新开始」 | 同 #9 的完整重置，无残留计时器/动画回调 |
| 11 | 桌面视口 | 缩放到手机宽度 | 牌阵缩放不错位，牌面可点，HUD 不遮挡牌阵 |
| 12 | 系统开启 reduced motion | 翻牌 | 无抖动、无缩放补间，改为快速淡入淡出，功能不受影响 |

自动化部分：simulation层的单测（无浏览器）+ Playwright 走通「翻牌 → 配对 → 结束 → 重开」主链路并在结束/重开两个状态截图。视觉问题（牌面可读性、HUD 遮挡）以截图判定，不靠 DOM 断言。

## 8. 风险与取舍

- **Phaser 相对纯 DOM 的开销**：为最小游戏引入引擎。保留理由是补间、场景编排与后续扩展（关卡/计时赛）；若最终只做这一页且不加特效，纯 DOM + CSS 3D transform 是更省的方案 —— 需要的话我改轨道。
- **输入锁与补间时序**：最易出 bug 处，用单一阶段枚举 + 定时器随 reset 清理来兜底。
- **无失败/无存档**：不引入存档与难度系统，保持"最小"边界。
