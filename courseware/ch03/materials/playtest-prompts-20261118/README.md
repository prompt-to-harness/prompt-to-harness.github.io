### E 的核对结果与边界

E 没有在请求中指定读 Reference、调用其他 Skill、截图、重开、窄屏或减弱动画检查。实际记录中，game-playtest 正文先进入上下文（原生日志第 12 行），模型又主动读取正文（17→21）；随后读取完整清单（37→41），并说要查看 UI 指导，读取 game-ui-frontend（54、55→59）。这些均为实际取用，不代表另起了 Agent 或发生了程序式调用。

模型通过 Playwright 完成启动、点击、失败配对、提前通关、重开、键盘与视口检查，并多次用图片工具查看截图。报告按严重程度列问题，每项包含玩家现象、复现、影响与归属；正文要求的是交付内容，没有规定该报告的标题与表格模板。

正文提供的流程、工具建议、检查方向和报告要求均能找到对应行为，因此 E 比 C 更适合讲“任务给具体目标，Skill 给工作方法”。这仍是本次行为与指导的对应，不是无 Skill 对照实验，不能证明每个行为都由 Skill 单独导致。

报告须人工取舍：

- 配齐三对就提前通关：点击日志与截图可互相核对，可选用。
- `npm run build` 缺 tsconfig：本轮起点继承的是 11 月 11 日重建的试玩副本，其中没有 tsconfig；这是实验副本的构建条件，不能回写为 3.1 原生成项目的缺陷。不选作游戏缺陷讲解。
- 卡片翻到侧面变成细线、必须一屏显示全部牌等：报告包含主观判断，不能直接当成已确认缺陷。
- “修完即可上线”等表述超出本轮验证范围，不沿用。

E 完整运行仍较长，含服务启动处理、脚本生成、构建检查等支线。主讲应定位正文、资料读取、代表性操作结果和一条报告；完整记录保留供回看，不逐条讲脚本代码。本轮未改正式讲稿。

### 建议的讲解对应（候选，未替换正式讲稿）

1. 请求只给试玩目标与当前项目，先核对正文怎样进入上下文。
2. 对着正文的 References 看文件路径，再看读取工具及返回内容。E 中可以额外核对另一份 Skill 的读取；是否主讲仍沿用讲师的知识取舍。
3. 对着 Preferred Workflow 与 Tooling Guidance，看模型怎样编写并运行浏览器检查，再看截图工具返回。本次 `evidence/` 的 Python 脚本是模型现场生成的，不能讲成 Skill 自带的 Scripts。
4. 选“三对就提前通关”这一条，核对操作结果与画面，再对照 Reporting Standard 看报告里的现象、复现、影响与归属。

读过的指导不意味着全部适用或每项都执行。桌面/窄屏与报告内容能对应到原文；其他 Skill 特有的 3D 指导不强行套到本例。新日志仍有脚本与环境处理支线，正式页需聚焦取段，不能直接作为无需剪选的逐条讲述材料。

### F 的结果与最终建议

F 使用与 E 相同的四要素文本，仅去掉 `$game-playtest`。模型在本次自然语言请求下自行读取 game-playtest（原生日志 46→50）和完整清单（57→62），没有观察到读取另一份 Skill。后续通过 Playwright 操作游戏并查看截图，最终报告包含按严重程度排序的问题、现象、复现说明及可能原因。原始脚本与补充验证曾出现重复执行和检查状态错误，模型又修正脚本并重新取证；`verify2.log` 确认三对即通关且剩余牌无法翻开。游戏源文件指纹保持一致。

因此采用**短四要素请求**作为后续改稿候选，E 优先用于正文、资料、工具及报告的对应，F 可用于核对不点名时的选用与后续执行。两轮的细节分别归属，不拼接成一次运行，不预设后续现场必然读取同样文件。若继续沿用 3.2.1 的自然语言同轮主线，F 也有主要证据，但需要在讲述设计中处理脚本修正支线；本轮不直接替换已存在的讲稿。

C、E、F 已通过现有转换器导入独立的 Inspect AI 回放，保存在私有实验根目录的 `review/`；转换脚本为 `build-review.py`，来源行映射为 `review/manifest.json`。可用现有 Inspect Python 环境重新生成，浏览器已核对请求与消息视图入口。正式讲述页的定位、高亮和页序尚未接入。

最终取舍：缩短请求，将操作方法留给 Skill；优先用已核对的提前通关问题串起指导、操作、证据与报告。没有进行课堂试讲，也没有无 Skill 对照，不能据此宣称教学效果或因果收益已验证。
