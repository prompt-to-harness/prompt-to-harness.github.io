## 实验设计

模型与执行入口：MiniMax-M3.1-Flash、Codex CLI 0.163.0、claude-tap 0.1.146；每次使用独立 HOME、工作区与新会话，关闭模型网页搜索。启动器的默认插件同步仍会访问上游；不能把本实验说成操作系统级断网隔离。原始事件与请求记录可核验实际模型及工具行为。

先让 AI 根据原作提炼正文初稿。初稿扩入翻牌网格、3D、音效与存储，且夹带代码；保留原稿，再将明确的范围问题反馈给 AI，生成无代码块的共同正文。最终共同正文约 102 行，按冻结指纹用于两组，不手工分别优化。

| 条件 | 调用时可访问什么 | 不提供什么 |
| --- | --- | --- |
| A：只有正文 | 同一份冻结的 SKILL.md | 原游戏截图、源码、编写聊天与随包示例 |
| B：正文加示例 | 相同正文，末尾多一段读取指引，加原作视觉 CSS 节选 | 原游戏截图、完整项目和编写聊天 |

B 的新增内容是“代码示例及读取指引”这个整体，不能把结果单独归因于代码文件的存在。节选覆盖原作 token、背景、工具栏/按钮/统计块、浮层与响应式/减少动效规则，保留原行内容及行号；没有复制翻牌逻辑、牌阵 CSS 或整款游戏作为模板。完整来源范围见 example-source.json。

两种任务均各跑 A/B 一次：开始界面；游戏中 HUD 与暂停面板。每个任务的请求两版逐字相同，原生 HTML/CSS/少量 JS，无外部依赖。开始界面与 HUD 是局部原型，不是完整躲避游戏。检查点在运行前保存，所有产物均保留，没有按美观程度挑选某一轮。

## 观察与待讲师判断

以下是本轮产物的观察，不是两版的统计效果结论：

- 两个开始页均保留了深蓝紫背景、浅色文字、半透明面板及紫色主按钮。只有正文也能迁移这些特征，加代码不意味着每个任务都有明显增益。
- HUD 的 B 版背景光晕与原作的关系更直接，A 版实屏几乎没有上部光晕：A 将渐变放在负层级背景元素，同时 body 有不透明背景。它在代码中写了所需配方，实际层叠仍影响结果。用“数值写对了”不能代替看实际画面，也不能据一个实现缺陷证明正文表达无效。
- 两版都保留了玩家、奖励和障碍的色彩/形状区分，没有生成翻牌玩法。B 中可见斜纹障碍等设计来自共同正文也可能包含的纹理说明，不能仅凭外观断言来自外部代码示例。
- B 的代码节选已有玻璃面板与按钮等实现，实际读取有证据；哪些声明被原样采用、哪些由模型改写，可对照各页 styles.css 与示例。布局差异同时包含模型自行选择，不把更宽、更紧凑或更漂亮当作唯一判据。
- 初稿将原游戏的局部实现扩成泛化要求，并纳入 3D、音效、存储；收敛版仍较长，且对部分原作反馈持续时间的叙述值得继续审阅。这里交付的是待改进的实测 Skill，不是已定稿教学规范。

## 编写过程、修改责任与轮次（2026-11-10 补核）

本表中的一轮指一次人的请求到 AI 完成回复，不把工具读取、文件写入或 AI 自行返工作为新的用户反馈轮。两次编写是独立会话，不是同一聊天连续续写。

| 步骤 | 谁执行什么 | 用户请求轮数 | 实际产物 |
| --- | --- | --- | --- |
| 初次提炼 | 协调者提供截图、完整前端源码与[原始提示词](prompts/author.txt)，MiniMax 自行读材料、提炼与写文件 | 1 | 269 行 SKILL.md、authoring-notes.md；Skill 有 name/description 和编号 0–15 的 16 个正文小节，含内嵌代码，无随包源码示例目录 |
| 范围收敛 | 协调者根据实际初稿提出[修订请求](prompts/refine.txt)，MiniMax 在独立会话读取原初稿和同一份素材后改写 | 1 | 102 行、9 小节的正文；移除代码块、收敛玩法/工程要求，保留视觉数值与迁移判断；另有 revision-notes.md |
| A/B 组装 | 协调者脚本冻结 A 的正文，给 B 追加读取指引，原样摘取原作 CSS | 0（没有再让 AI 生成 Skill） | A 102 行；B 107 行，另附 244 行 CSS 节选（含来源注释与空白）。实际差异见 variant.diff |

因此 Skill 编写与修订共 2 次用户请求、2 次独立模型调用；后面四次模型调用用于生成局部界面，不计入 Skill 编写轮数。初次调用有 13 次已完成 shell 调用、1 组文件变更；修订调用有 17 次 shell 调用、5 组文件变更。后者包含 AI 在同一轮内自行删写和压缩篇幅，不是人追加了五轮修改。

人的修订要求包括：去掉翻牌网格、3D、音效和存储等过宽内容；区分瞬时反馈和持续语义；删除代码块以建立本次对照的正文基线；保留真实色值、材质、层级、控件反馈和可读性；允许新玩法布局与语义配色；区分原作值和迁移建议。具体文字改写由 AI 完成，协调者没有手工重写 A/B 的共同正文。

“无代码块”和“约 60–100 行”是本次实验的表达控制要求，不是 Skill 的通用产品限制或教学定律。B 的新增部分也不是第三轮 AI 优化，不能把 B 的效果当成再次询问模型的效果。

**AI 自述的核验纠正**：revision-notes.md 将原始初稿写成 154 行，并说 102 行在 60–100 行区间内，均不准确。实际输入初稿与保存原稿 SHA-256 一致，按文件 splitlines 统计为 269 行；154 行是本轮修订内部曾出现的中间稿。最终是 102 行，不在 60–100 的严格区间内。AI 说明原样保留供复查，以本表和文件指纹为核验事实。
