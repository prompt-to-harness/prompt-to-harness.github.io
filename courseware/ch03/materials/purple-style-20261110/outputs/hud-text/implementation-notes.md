## 3. 三处风格实现与对应依据

### ① 色彩角色 token 化 + 页面底双光晕 + 玻璃面板层级

**依据：** SKILL §1〔原作值〕“先定义语义 token 再在组件里引用，不要在组件里散写色值”与色彩角色表；§2〔原作值〕页面底三层叠加与三种材质、四级层级。

**实现：**

- `:root` 中集中定义角色 token：`--bg-deep #0c1022` / `--bg-lift #171e3d`、`--glow-blue #2a3170`、`--glow-purple #3b2a63`、`--primary #7c8cff`、`--primary-2 #9a6bff`、`--focus #56d6c6`、`--reward #4ade80`、`--danger #fb7185`、`--text-1 #eef1ff`、`--text-2 #a3abcf`，以及玻璃层 `rgba(255,255,255,.07) / .14 / .12 / .18` 与凹槽底 `rgba(0,0,0,.28)`；组件里只引用 token，不散写色值。
- `.page-bg` 按 §2 叠三层：左上 `radial-gradient(1100px 620px, #2a3170)`、右上 `radial-gradient(900px 600px, #3b2a63)`、再叠 `linear-gradient(160deg, #0c1022 → #171e3d)`；用 `position:fixed` 保证底色固定不随滚动。
- HUD 与舞台是**玻璃面板**：7% 填充 + 1px 14% 描边 + 10px 背景模糊 + 16px 圆角 + `0 18px 40px rgba(0,0,0,.35)`；统计块与游戏区是**凹槽底**（28%）；页脚/说明文字用次级色 `#a3abcf`。
- 层级顺序与 §2 一致：页面底 → 玻璃面板层（HUD / 舞台）→ 交互实层（主按钮、玩家、晶体、危险物）→ 浮层（暂停面板）。

### ② 玩家 / 收集物 / 障碍物：持续语义配色 + 形状冗余

**依据：** SKILL §5〔迁移建议〕“语义状态要分两类用”“持续存在的危险物靠稳定颜色与形状表达存在感，不用抖动”“三者同屏时除颜色外至少再给一项冗余信息（形状、图标或文字标签）”“危险与奖励在色相上明确分离”。

**实现：**

| 元素 | 颜色（持续语义） | 形状 / 冗余信息 | 依据 |
| --- | --- | --- | --- |
| 玩家 | 主色家族 `#7c8cff`（中性偏亮，与危险/奖励异色） | 圆形 + 中心亮点 + 朝向箭头 + 身上“你”标签 | §5「玩家单位用中性亮色或主色 `#7c8cff` 家族」 |
| 收集物 | 成功绿 `#4ade80` | 六边形晶体（顶面高光） | §5 玫红 / 绿在色相上分离 |
| 障碍物 | 危险玫红 `#fb7185` | 三角形 + 45° 斜纹 + “!” 标记 | §2 斜纹纹理（45° 白色 8%）借用为危险纹理 |

- 三者除颜色外还各有一个形状差异（圆 / 六边形 / 三角），并在 HUD 下方加了**图例行**（色块 + 文字），形成“颜色 + 形状 + 文字”三重冗余，颜色不是唯一语义通道。
- 持续存在的危险物只使用稳定填充色与稳定形状，**不做抖动**；§5 的“瞬时反馈（改面色 + 2px 描边/外发光 + 0.42s 抖动）”在本原型中不出现，因为没有命中判定逻辑。
- 生命值用“数字 3 + 3 个心形图形”双通道表达（心形为玫红，与危险色一致，但不参与危险/奖励判定）。

### ③ 暂停浮层：与游戏画面区分 + 唯一主行动 + 焦点管理

**依据：** SKILL §8 浮层（遮罩 + 有色玻璃面板 + 内容节奏 + 焦点行为）、§2 四级层级最上层、§4 按钮三态、§1“主色只给当前唯一的主行动”。

**实现：**

- **与游戏画面区分**：暂停时在**游戏区范围内**加遮罩 `rgba(6,9,22,.72)` + 6px 背景模糊（游戏网格与元素被压暗、模糊），中间浮出**有色玻璃面板**：`linear-gradient(165deg, rgba(42,49,112,.96) → rgba(30,24,60,.96))`、1px `rgba(255,255,255,.14)` 描边、22px 圆角、`0 18px 40px rgba(0,0,0,.35)` 阴影 —— 比页面底更亮更饱和，读作“浮出”。
- **内容节奏**（§8）：图标 → 标题（1.45rem“已暂停”）→ 说明（次级色、行高 1.7）→ 一行按钮（主行动“继续游戏” + 次行动“重新开始”）。面板里另有一行把剩余 / 生命 / 分数三个数值用**主色**标出（§8“关键数字提为主色”）。
- **唯一主行动**（§1）：游戏中，HUD 上的「暂停」是**主按钮**（140° `#7c8cff → #9a6bff`、白字、`0 8px 20px rgba(124,140,255,.32)`）；进入暂停后主色**让给浮层里的「继续游戏」**，HUD 按钮降级为次级玻璃按钮（此时按钮文案变为「继续」），保证同一屏只有一个主色实心块。
- **焦点行为**（§8）：打开时焦点移到浮层主行动「继续游戏」；关闭时焦点归还触发它的按钮；Esc 关闭；Tab 在面板内循环（Shift+Tab 反向）；按钮用 `aria-pressed` 表达暂停状态，颜色不是唯一状态通道。

### 其他已落实项（不计入上面 3 处）

- §4：hover 只提亮度（`brightness(1.08)`）不换色；active 下沉 1px 并缩放 0.99、0.12s；焦点环 3px `#56d6c6` + 2px 偏移，只在 `:focus-visible`（键盘可见焦点）时出现。
- §6：数字用 `tabular-nums`；标题为 92° 渐变文字（`#fff 10% → #b9c2ff 60% → #7ce7d8 100%`）、字号 1.7–2.4rem、字距 0.5px；副标题 0.9rem 次级色；统计数值 1.25rem / 字重 650；标签 0.74rem、字距 0.5px；字体栈用 Skill 原栈。
- §6：`prefers-reduced-motion: reduce` 时动画与过渡时长归零、迭代次数为 1。
- §7：单列居中、最大宽度 960px、横向页边距 12–24px；≤520px 时工具栏改纵向拉伸、操作按钮均分（暂停按钮满宽，统计块仍为三等分网格）。
- §9：牌阵、翻牌、图案、计分口径等原作专属内容已全部替换为本游戏的 HUD / 竞技场 / 三类元素。

## 4. 自行决定的部分（Skill 未规定）

1. **版式骨架**：沿用 §7 的“标题 → 工具栏/数据条 → 主舞台 → 页脚”关系，但把 §7 的数据条与工具栏合并为一条 HUD；主舞台换成竞技场凹槽而非牌阵（§7 允许）。
2. **游戏区形态**：网格底纹 + 视晕（`inset 0 0 70px rgba(0,0,0,.45)`）+ 顶部内发光、8 个元素的百分比坐标、三种具体形状与“!” 标记，均为自拟；Skill 只规定“视觉语言”，未规定盘面结构。
3. **遮罩范围**：§8 的浮层示例是全屏结算遮罩。为了让 HUD 上的「继续」按钮**可点击**（题目要求“按钮变为继续，点击继续返回原状态”），本原型把遮罩限制在**游戏区**范围内，HUD 保持可见可操作；这是对 §8 的一次自行取舍。
4. **暂停态的主色让位规则**（见 ③）：属于依据 §1 角色规则推导出的设计决定，Skill 未明说“暂停时按钮要降级”。
5. **浮层未声明 `aria-modal="true"`**：因为 HUD 按钮在暂停态仍可交互，声明 modal 会与实际行为矛盾；改用 `role="dialog"` + `aria-labelledby`/`aria-describedby` + 焦点陷阱。
6. **「重新开始」按钮行为**：把示意数值复位为 01:00 / 3 / 0 后回到游戏（只复位显示值，不含真实游戏逻辑）。
7. **空格快捷键**：页面空白处按空格可暂停 / 继续（附加便利功能）。
8. **文案与口径**：副标题、图例文字（“收集物 · +10 分”“障碍物 · 碰到扣 1 命”）、页脚操作提示、浮层说明文字均为自拟；Skill 明确把“计分口径与文案”交给新游戏决定。
9. **HUD 数值为固定示意值**（00:42 / 3 / 120），没有做实时倒计时 —— 题目要求的就是这个示意状态。
10. **“你”标签与朝向箭头**、心形图标的具体路径、晶体/三角的 SVG 坐标，均为自绘。

## 5. 实际做过的验证 与 未验证项

### 实际执行过的验证（全部通过）

1. **交互逻辑验证（30/30 通过）**：用 Node 内置 `vm` + 一个从**真实 `index.html` 解析出来的**最小 DOM stub，执行**真实的 `output/app.js`**，断言：
   - 初始：面板 `hidden`、按钮文案「暂停」、HUD 为 00:42 / 3 / 120、生命为 3 个心形、游戏区含 1 玩家 + 4 收集物 + 3 障碍物；
   - 点「暂停」→ 面板出现、按钮文案变「继续」、`aria-pressed=true`、焦点移到浮层主行动「继续游戏」、HUD 按钮降级为次级、HUD 数值不变；
   - Esc → 面板关闭、文案恢复「暂停」、焦点归还触发按钮、HUD 按钮恢复主按钮；
   - Tab / Shift+Tab 在面板内循环（焦点陷阱）；
   - **题目主流程**：点暂停 → 按钮变「继续」→ 点「继续」→ 面板关闭并**回到原状态**（00:42 / 3 / 120，舞台 `is-paused` 已移除）；
   - 浮层内「继续游戏」按钮同样生效；空格可开/关；「重新开始」复位为 01:00 / 3 / 0。
2. **静态一致性验证（35/35 通过）**：CSS 花括号配平、`node --check` 通过 app.js、HTML 标签闭合计数配平、**无任何 http/CDN/外链**、JS 无 import/require、app.js 引用的 id 全部存在、ARIA 引用目标全部存在、无重复 id、所有 `var(--token)` 均已在 `:root` 定义、HTML 中每个 class 都有对应样式、关键色值与 Skill 原作值逐条一致、焦点环/hover/active/玻璃层/浮层遮罩与面板/tabular-nums/92° 渐变标题/`prefers-reduced-motion` 均命中规范。
3. **布局算术验证**：按 CSS 声明值（配合保守字宽模型）在 1280×900 与 390×844 下计算 →
   - 无横向溢出（手机内容宽 366px ≤ 390px，舞台 346px）；
   - HUD 三个统计块内的标签与数值文字宽度都在可用宽度内（手机每块内容宽 89.3px）；
   - 8 个游戏元素的图形框与玩家标签全部落在游戏区内；
   - 暂停面板估算高度 317px(桌面) / 320px(手机) ≤ 可用 512px / 334px，不需滚动即可完整显示（面板另设 `overflow-y:auto` + `margin:auto` 兜底）。

### 未能验证 / 仍然存在的风险

- **没有做浏览器渲染验证，因此没有真实截图。** 本环境里 Chrome 一启动就 `SIGABRT`（`--headless=new`、`--headless=old`、`--no-sandbox`、`--single-process` 等组合均崩溃且无 stderr），系统无图形会话（`screencapture` 失败）、Quick Look 预览被沙箱拒绝。所以**实际像素效果未经确认**，包括：真实字体度量下的换行与截断、`backdrop-filter` 毛玻璃与模糊的渲染差异、SVG 渐变 / 图案与 `clip-path` 的表现、iOS Safari 上的表现、`prefers-reduced-motion` 的实际降级效果、屏幕阅读器的朗读顺序。
- 上述“布局算术”用的是**保守字宽估算**，不是真实字体测量；真实字体更宽时，暂停面板与 HUD 文字仍有余量（面板已设可滚动兜底），但极端系统字体（如最小字号设置 + 粗体）下未逐一验证。
- 移动端面板与游戏区高度接近（320 / 334px），在极小视口（如 320px 宽或横屏）下未专门验证；此时面板会变为面板内滚动而不是被裁切。
- “重新开始”后的 01:00 / 0 是自定的示意值，未与题目要求的 00:42 / 120 状态混淆：初始与“继续”之后始终是 00:42 / 3 / 120。
- 验证脚本放在 `/tmp`（`dom-test.mjs`、`static-check.mjs`），**不属于交付内容**，也未写入项目目录。
