## 2. 三处风格实现及其依据

### 实现一：语义 token 化 + 「同屏只有一个主色主角」

**依据**

- SKILL §1：「先定义语义 token 再在组件里引用，不要在组件里散写色值」；角色规则「主色只给『当前唯一的主行动』或『当前选中的选项』，避免同屏多个主色实心块互相抢戏」。
- SKILL §9 复用检查清单第 1、3 条：底色双光晕且固定；面板用半透明玻璃；主色只出现在当前主行动 / 选中项。
- 原作 CSS `source-visual.css` 的 `:root` token 清单与 `.btn--primary` / `.btn--ghost` 规则。

**落地**

- `styles.css` 的 `:root` 集中定义全部色值与形状 token：`--bg-0/--bg-1/--glow-a/--glow-b`、`--panel/--panel-strong/--panel-strong-hover/--border/--groove`、`--text/--text-dim/--accent/--accent-2/--accent-text/--ink-player/--focus/--good/--bad/--pause-hue`、`--radius-*` 与两级阴影。组件规则里不写裸色值（仅标题渐变 `#fff / #b9c2ff / #7ce7d8` 沿用原作 §6 的 92° 标题渐变原文）。
- 主色 `#7c8cff` 的实心块全屏唯一：进行中时只有 HUD 的「暂停」按钮是主按钮；点击暂停后浮层里的「继续游戏」成为唯一主行动，HUD 上的「继续」由 `btn--primary` 切换为 `btn--ghost`（JS 中 `classList.toggle`），避免两块主色实心按钮同屏抢戏。
- 关键数值不用主色实底，而在深底上改用主色浅调 `--accent-text: #b9c2ff`（取自原作标题渐变中段，既不改色相又能满足对比度）：HUD 分数 `120` 与浮层里的「42 秒」。焦点色 `--focus: #56d6c6` 只出现在 `:focus-visible` 焦点环，不做按钮填充。

### 实现二：三种材质 + 四级层级，浮层与游戏画面明确分层

**依据**

- SKILL §2：玻璃面板 / 实体表面 / 斜纹纹理三种材质；层级四级「页面底 → 玻璃面板层 → 交互实层 → 浮层」；浮层面板改用有色玻璃 165° 渐变，「比页面底更亮更饱和，读作『浮出』」；层级靠「亮度 + 模糊度 + 不透明度」表达。
- SKILL §9 清单：「底色双光晕且固定；面板用半透明玻璃」「遮罩层永远压得住下层内容」。
- 原作 CSS 的 `body` 背景三段式、`.toolbar/.stat` 玻璃规格、`.overlay` 浮层规格。

**落地**

| 层级 | 本次实现 |
|---|---|
| 页面底 | 左上 `1100×620 #2a3170`、右上 `900×600 #3b2a63` 两团径向光 + 160° 线性渐变 `#0c1022→#171e3d`，`background-attachment: fixed`（固定底色） |
| 玻璃面板层 | HUD 与主舞台面板：`rgba(255,255,255,.07)` + 1px `rgba(255,255,255,.14)` + `blur(10px)` + 16px 圆角 + `0 18px 40px rgba(0,0,0,.35)`；凹槽底 `rgba(0,0,0,.28)` 用于游戏区 `.arena`、HUD 数值槽与浮层里的冻结数值槽 |
| 交互实层 | 玩家用「实体表面」材质：近白渐变 `rgba(255,255,255,.96)→rgba(226,230,255,.9)` + 1px `rgba(255,255,255,.55)` 描边；危险块用「斜纹纹理」材质：45° 白色 16% 实线 6px 与透明 6px 交替，叠在 140° 玫红渐变上 + `rgba(255,255,255,.22)` 描边 + 顶边 `rgba(255,255,255,.28)` 内高光 |
| 浮层 | 遮罩 `rgba(6,9,22,.72)` + `blur(6px)`；面板 `165°` 有色玻璃 `rgba(42,49,112,.96)→rgba(30,24,60,.96)` + 1px `rgba(255,255,255,.14)` + 22px 圆角 + 同款阴影 —— 亮度与饱和度都高于页面底，暂停面板读作「浮出」而不是游戏画面的一部分 |

另外，浮层内外还有多重「区分」手段，避免只靠颜色说明状态：遮罩压暗 + 模糊下层、面板换成更亮更有色相的玻璃、面板内给出暂停图标 / 「已暂停」标题 / 冻结数值条；同时 HUD 的数值槽在暂停时降到 0.62 透明度，状态芯片从「进行中」变为琥珀色「已暂停」。

### 实现三：危险 / 奖励 / 玩家的持续语义 + 冗余编码 + 可编程语义与焦点管理

**依据**

- SKILL §5：语义配色分「瞬时反馈」与「持续语义」两类；危险与奖励在色相上明确分离；玩家单位用中性亮色或主色家族，与危险 / 奖励不同色；三者同屏时除颜色外至少再给一项冗余信息（形状、图标或文字标签）；持续存在的危险物靠稳定颜色与形状表达存在感，不用抖动。
- SKILL §4：「语义状态要有可编程语义（开关用 aria-pressed 一类），颜色不能是唯一的状态通道」；焦点环 3px 实线 `#56d6c6` + 2px 偏移，仅键盘可见焦点时出现。
- SKILL §8：浮层「打开时焦点移到主行动按钮，关闭时焦点归还触发它的按钮，Esc 关闭，Tab 在面板内循环」。

**落地**

- 持续语义：玩家 = 近白圆形 + 靛紫环 + 「你」字（中性亮色，与危险 / 奖励都不同色）；收集物 = 奖励绿 `#4ade80` 菱形 + 白色内芯；障碍物 = 危险玫红 `#fb7185` 三角（「!」角标）+ 玫红斜纹块。危险与奖励是玫红对绿，色相明确分离；玩家近白且圆形，三者形状两两不同，图例另给文字标签（「玩家 / 收集物 / 障碍物」），构成颜色之外的冗余通道。
- 障碍物常驻用稳定颜色与稳定形状，不抖动、不闪烁；收集物只有 3.2s 的轻微上下浮动（且每个关键帧重复写出 `rotate(45deg)`，避免位移动画覆盖静态旋转）；瞬时反馈只用在「重新开始」上（0.5s 数值槽高亮 + 状态芯片短暂显示「已重新开始」）。
- 可编程语义：暂停按钮 `aria-pressed` / `aria-expanded` 随状态翻转；状态芯片 `data-state="running|paused"` + `aria-live="polite"`；浮层 `role="dialog"` + `aria-modal="true"` + `aria-labelledby` / `aria-describedby`；游戏区 `role="img"` + 中文 aria-label 概述三类元素。焦点环 3px `#56d6c6` + 2px 偏移，只用 `:focus-visible`（鼠标点击不亮圈）。
- 浮层行为：打开时焦点移到「继续游戏」，关闭时焦点归还触发它的按钮，Esc 关闭，Tab / Shift+Tab 在面板内两个按钮之间循环。

## 3. 自行决定的部分（技能未规定，由本次自行取舍）

1. **布局**：HUD 独立成条放在舞台上方（不覆盖游戏区），以满足「HUD 不妨碍观察」；游戏区用百分比定位的静态元素表示「示意」，未做画布坐标系。
2. **暂停态专用色 `--pause-hue: #f6c453`（暖金）**：技能只给了成功绿与危险玫红，暂停需要第三种可区分色；暖金与玫红、绿在色相上分离，也不与主色靛紫冲突。
3. **两个派生 token**：`--accent-text: #b9c2ff`（沿用原作标题渐变中段）用于深底上的关键数值；`--ink-player: #2a3170`（与左上光晕同值）用于近白玩家表面上的「你」字。两者都是为了在不改色相的前提下保证文字可读。
4. **文案与计分口径**：副标题、图例说明（「每枚 +10 分」「碰到障碍扣除 1 生命」）、浮层说明均为自拟，技能不规定玩法与计分口径。
5. **元素数量与摆位**：4 枚收集物、2 处尖刺 + 1 段危险块、1 名玩家，位置为百分比锚点，属示意布局。
6. **浮层遮罩点击不关闭**（避免游戏中误触即恢复），只能通过「继续游戏」/ HUD「继续」/ Esc 关闭。
7. **「重新开始」是空壳动作**：原型没有游戏逻辑，它只复位 HUD 数值槽（0.5s 瞬时高亮）并让状态芯片短暂显示「已重新开始」；由于示意数值固定为 00:42 / 3 / 120，数值本身看不出变化，这一点在界面上以「已重新开始」的状态文字说明。
8. **倒计时固定为 00:42**，不推进（符合「只做界面示意」）；数字统一用 `tabular-nums`，为将来接真实计时预留不抖动。
9. **窄屏策略**：沿用原作 `≤520px` 断点，HUD 纵向拉伸、操作按钮均分；舞台比例桌面 16:9、窄屏 4:3。
10. **预览钩子**：`index.html#paused` 带该锚点载入即进入暂停态，方便走查与截图（非必需功能，可直接删掉 `app.js` 末尾两行）。
