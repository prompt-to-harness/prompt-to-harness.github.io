## 3. 三处风格实现及其依据

### 3.1 色彩角色与材质层级（依据 §1 色彩角色、§2 背景/材质/层级）

- `output/styles.css:7`（`:root`）先定义全部语义 token：`--bg-0/--bg-1`（底色 `#0c1022 → #171e3d`）、`--glow-cool/--glow-warm`（光晕 `#2a3170` / `#3b2a63`）、`--primary/--primary-2`（靛紫 `#7c8cff` / `#9a6bff`）、`--focus`（焦点色 `#56d6c6`）、`--success`（`#4ade80`）、`--danger`（`#fb7185`）、`--text-1/--text-2`（`#eef1ff` / `#a3abcf`）、`--glass/--glass-btn/--glass-btn-hover/--hairline/--groove`（玻璃层四值）、圆角 5/9/11/13/16、阴影阶梯四档。组件层一律引用变量，未在组件里散写色值。
- `output/styles.css:76`（`body`）：页面底按 §2 叠三层——左上 `1100×620` 径向光晕（冷蓝）、右上 `900×600` 径向光晕（暖紫）、底层 `160deg` 线性渐变 `#0c1022 → #171e3d`，并用 `background-attachment: fixed` 使底色不随滚动。
- `output/styles.css:158`（`.panel`）：玻璃面板 = `rgba(255,255,255,0.07)` 填充 + 1px `rgba(255,255,255,0.14)` 描边 + `blur(10px)` 背景模糊 + `16px` 圆角 + `0 18px 40px rgba(0,0,0,0.35)` 阴影；工具栏、数据条、主舞台都复用这一材质，靠「亮度 + 模糊度 + 不透明度」区分层级，而非堆叠阴影。
- 语义色的持续态用法见 `output/styles.css:340/346`：危险用玫红、奖励用绿（色相分离，§5），图标同时带形状差异，文字标签再给一层冗余信息。

### 3.2 控件三态、焦点环与开关语义（依据 §4 控件与反馈、§9 复用检查清单）

- `output/styles.css:196`（`.btn`）：常规过渡 `0.18s ease`、按下 `0.12s ease`，`active` 下沉 1px 并 `scale(0.99)`；`:hover` 只用 `filter: brightness(1.08)` 提亮，不换色。
- `output/styles.css:245`（`.btn--primary`）：`140deg` 渐变 `#7c8cff → #9a6bff`、白字、阴影 `0 8px 20px rgba(124,140,255,0.32)`——全屏唯一的实心主色块（开始按钮）。
- `output/styles.css:257`（`.btn--secondary`）：`rgba(255,255,255,0.12)` 底 + 1px `rgba(255,255,255,0.14)` 描边，hover 提到 `rgba(255,255,255,0.18)`，用于音效开关与「返回标题」。
- `output/styles.css:233`（`:focus-visible`）：焦点环 `3px solid #56d6c6` + `2px` 偏移，用 `:focus-visible` 保证只在键盘可见焦点时出现，鼠标点击不亮圈；主色只留给主行动，焦点色专用。
- `output/styles.css:274`（`.btn--toggle[aria-pressed="false"]`）：音效开关的关闭态 = 透明度 `0.5` + 文字删除线，**不**换另一种主色；开启/关闭同时写进 `aria-pressed` 与可见文案「音效：开 / 关」，颜色不是唯一状态通道（§4 〔迁移建议〕）。

### 3.3 标题渐变、数值排版与动效降级（依据 §6 动效与排版、§7 版式骨架）

- `output/styles.css:134`（`.game-title`）：标题用 `92deg` 渐变文字 `#fff 10% → #b9c2ff 60% → #7ce7d8 100%`，字号 `clamp(1.7rem, …, 2.4rem)`、字距 `0.5px`；副标题 `output/styles.css:147` 用 `0.9rem` + `#a3abcf`。
- `output/styles.css:352`（`.stat__value`）：统计数值 `1.25rem` / 字重 `650` / `font-variant-numeric: tabular-nums`（等宽数字，后续计时与分数跳动不会左右抖动）；标签 `0.74rem` + 字距 `0.5px`。
- `output/styles.css:550`（`@media (max-width: 520px)`）：工具栏改纵向拉伸、主行动按钮整行铺满（§7「≤520px 工具栏改纵向拉伸、操作按钮均分」）；数据条保持等宽三列网格、间距 10px。
- `output/styles.css:602`（`@media (prefers-reduced-motion: reduce)`）：动画与过渡时长归零、迭代次数为 1（§6 硬性要求）。
- `output/styles.css:389/405`（`.stage__state`）：待开始 ↔ 预览中的切换用 `0.22s` 淡入 + `0.45s` `cubic-bezier(0.4,0.15,0.2,1)` 位移（§6 结构性变换档位）。

## 5. 自行决定的事项

1. **版式骨架取舍**：Skill §7 的骨架是完整游戏序（标题 → 工具栏 → 数据条 → 主舞台 → 页脚）。本次保留该顺序，但把「主舞台」降级为开始界面的占位区（待开始 / 预览中两态），不引入玩法。
2. **内容最大宽度取 760px**（Skill §3 给的是「≤960px」上限 + 关系式建议）；沿用的是「单列居中 + 窄屏可拉伸」的关系，不沿用原作的列数与列宽。
3. **「预览中」的表现方式**由本次自定：主按钮改为该文案并置 `aria-disabled`（避免重复触发）、舞台标题复用同款 92° 渐变文字、`role="status"` 区域播报。按钮仍是全屏唯一实心主色块，主色没有出现第二处抢戏。
4. **额外加入「返回标题」次按钮**：Skill 与需求均未要求，为的是让「待开始 ↔ 预览中」两态可来回对比。
5. **额外加入「场上语义图例」**（危险 / 奖励 / 玩家）：用「颜色 + 形状 + 文字」三重冗余演示 §5 的语义配色要求，属自行加入的信息层。
6. **规则摘要的文案措辞**（单局时长 / 初始生命 / 得分来源）为本次自拟；数值严格按需求取 60 秒、3 点、收集得分。
7. **材质取舍**：斜纹纹理（卡背/占位块材质）本次未使用——开始界面没有卡背或封面；浮层与结算材质也未使用——不在本次范围。
8. **音效开关只反映 UI 状态**，仓库内没有音频文件，切换不会产生真实声音（原型边界，非遗漏）。

## 6. 未验证 / 已知限制（如实说明）

1. **没有做过浏览器渲染核对**：本环境里 Google Chrome 一启动即 SIGABRT（退出码 134、无日志），`qlmanage` 报 sandbox 初始化失败，环境无 jsdom / playwright 且不允许联网安装。因此 **390px 与桌面宽度的最终视觉、像素级效果未做截图核对**。
2. **窄屏适配是静态估算**：用盒模型脚本估算 390px 下各关键文案的宽度（可用宽 365px）：标题 ≈217px、副标题 ≈331px、统计块内「收集得分」≈65px（列内可用 99px）、舞台标题 ≈288px、图例三项 ≈263px、页脚 ≈350px，均小于可用宽度，判定为不溢出。这只是估算，不能替代真实渲染。
3. **交互逻辑用最小 DOM shim 验证，非真实浏览器**：把页面内联脚本放进 Node 的 DOM 桩里执行，断言「点击开始 → 主按钮文案=预览中 + `aria-disabled=true` + 舞台切到 running 态 + 旧态置 `inert`」「再次点击开始保持预览中」「音效开关在 开/关 间来回切换 `aria-pressed`、文案与图标」「返回标题 → 回到待开始态」全部通过。真实浏览器中的事件与焦点行为未验证。
4. **以下细节未在真实浏览器/辅助技术中验证**：`:focus-visible` 的触发时机与 `:focus` 的浏览器差异、`backdrop-filter` 在旧版 Safari 的回退表现、`prefers-reduced-motion` 降级是否真的归零、`role="status"` 在真实屏幕阅读器中的播报、`inert` 在旧浏览器的支持（已另用 `visibility:hidden` 兜底）。
5. **字体与字重**：字体栈按 §6 原样声明，实际命中依赖平台（本机 macOS 为 PingFang SC）；`font-weight: 650` 在缺少可变字重的字体上会被合成或回退，跨平台观感未对照。
