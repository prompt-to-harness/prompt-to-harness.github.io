我们定的是一条**「等待翻回期间的点击锁定」**规则（2026-10-06 你明确要求记住的）：

- **场景**：记忆翻牌里玩家连续翻开两张牌。
- **规则**：一旦这两张牌**不匹配**，进入「等待翻回」状态；该状态期间玩家的**所有点击一律忽略**，不允许翻起第三张牌。
- **生效窗口**：从**判定为不匹配的那一刻起**，一直到**这两张牌翻回背面为止**的整个等待过程。
- **落地要求**：用一个**显式的锁定/忙碌标志位**（如 `isResolving` / `isLocked`）表示该状态，在点击处理函数入口拦截，窗口结束时清零解锁；**不要依赖延时回调（setTimeout / 动画结束）去推断状态**。
- **定性**：这是**长期行为契约**，不是实现建议——后续改这个游戏的回合/点击处理时默认按它走，不重新讨论。
- **踩过的坑**：不加显式 gate 就会出现「两张不匹配的牌还亮着，第三张却被翻开」；锁/解锁绑在动画时序上则会出现「翻回还没结束就能点」或「点太晚被误吞」。

补充一点：当前工作区 `repo/` 里搜不到 `isResolving` / `isLocked` 等任何相关实现，这条规则目前只存在于记忆中，还没有落到代码里。需要的话我可以按这个规则实现出来。
