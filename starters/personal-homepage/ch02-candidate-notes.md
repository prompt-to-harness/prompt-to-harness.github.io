> 状态（2026-10-06）：讲师备课用的 **v1 冻结候选**，不是录制版，也不是标准答案；未发布到 GitHub Pages，未经另一位讲师复现。Codex 输出不确定，学员的 v1 与这里不同是正常的。

> 本笔记和日志放在快照目录之外：快照可能被整个复制进学员仓库，笔记若在目录里，Codex 会直接引用其中的结论（见 [ch01-complete 笔记](ch01-complete-notes.md) 开头）。

[`ch02-candidate/`](ch02-candidate/) 是一次按第 2 章课件跑完 2.1–2.3 后，练习仓库在 `记录第 1 轮` 提交时的全部已跟踪文件（不含 `node_modules/`、`dist/`）。过程由 [`courseware/ch02/materials/mainline/run-v1.sh`](../../courseware/ch02/materials/mainline/README.md) 自动驱动，是该脚本 2026-10-06 第 5 次运行的产物。用途：

- 第 2 章录制前的起点：2.3 讲的 diff、2.4 要发布的 v1、2.5 的重构基线都应以真实 v1 为准；
- 学员落后时对照（与 `ch01-complete` 相同，带回需要的改动，不整仓覆盖）。

## 过程

1. **2.1 p06**：人写下三条课程示例反馈与对 v0 的核对，不提 1.4 的决定。
2. **2.1 p07（只读）**：Codex 读了记录文件和 `src/`、`PROMPT_V1.md`、`PLACEHOLDER_CONTENT.md`、`PROJECT_BRIEF.md`、`CHECKPOINTS.md`。第 2 条指出“点了没反应”符合 `PROMPT_V1.md:11` 的人工决定，又指出 `PROJECT_BRIEF.md:21`“没有实际入口时如何展示”从未回答；第 3 条指出增加项目是新的内容决定，要人先拍板。
3. **2.1 p17**：人补上性质标签，选定第 3 条。
4. **2.2 p29–p30**：新会话。Codex 先出计划：只改 `src/App.tsx` 的项目数据；人回复“确认，按计划执行。”。
5. **执行**：改完跑 build，用 4 条命令核对，没有尝试自己打开浏览器；回答里请人用 `npm run preview` 查三种宽度。用时约 2 分钟。
6. **2.2 p31（脚本代人）**：build 成功；360、768、1440 无横向溢出，三条经历原文都在；Tab 仍只停在“查看项目”。
7. **2.3**：范围只有 `src/App.tsx`（+10 −2），评审“接受”；代码与记录分两次提交，代码提交打 `homepage-v1`。

## 多次运行的对照

同一脚本共跑 6 次，前 3 次用旧版 p29（Done when 未写明由谁检查），后 3 次用新版。6 次最终的 `src/App.tsx` 逐字相同；2.1 都读了 `PROMPT_V1.md` 并认出“项目卡不跳转”是既有决定。执行步骤用时：旧版 56 秒、14 分钟、16 分钟（两次 Codex 没有浏览器工具却自行验证视口），新版 2–3 分钟。详见 [主线重跑说明](../../courseware/ch02/materials/mainline/README.md)。
