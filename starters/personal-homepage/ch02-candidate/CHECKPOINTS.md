## 1.5 保存本地检查点

确认验收通过后，检查 `git status --short`、完整 diff，以及新建但尚未跟踪的文件。按人工审阅结果暂存文件，用 `git diff --cached` 检查待提交内容，保存提交后再创建标签：

```bash
git tag ch01-prompt-baseline
git rev-parse HEAD
git rev-parse ch01-prompt-baseline
```

标签已存在时先核对它指向的版本，不强制覆盖。未通过的项目记录为待补做，不创建成功检查点。创建本地提交和标签不等于发布网站或推送到远端。

## 从第 2 章开始

没做完第 1 章、或想直接学第 2 章时，不需要切换分支或覆盖文件。在自己的仓库里让 Codex 对照课程的第 2 章参考起点，补齐第 2 章需要的前提：

1. 按 README 用 Template 创建自己的仓库并克隆（已有就跳过）；先提交当前的工作。远端会有一个 Template 生成的初始提交，2.4 的推送前检查以它为基准。
2. 在仓库根目录启动 Codex，粘贴课件第 2 章开头“从这一章开始”里的 Prompt。参考起点是本仓库的 `ch02-start-v1` 标签。
3. Codex 申请联网、把参考起点克隆到临时目录时，看清整条命令再同意；不要选“以后不再询问”。
4. 读它的逐条判断，只确认补齐前提所必需的改动；你的个人内容和已有的决定保持不变。
5. 改完后运行 `npm install` 和 `npm run build`，在浏览器里看一遍，确认后提交。

不想用 Codex 时，可以在 GitHub 上打开 `ch02-start-v1` 标签下载 ZIP，解压到另一个目录对照，再把需要的改动带回自己的仓库。

这仍是你自己的仓库和历史，之后的章节照常在里面继续。

## 想重新练习时

1. 保留整个当前项目，包括尚未提交的内容；不能只保存个人文字而遗漏代码、样式和证据。
2. 从课程仓库选择一个已发布的版本，下载 ZIP 并解压到另一个目录，记录来源 commit。
3. 按该版本 README 初始化 Git 并运行对应阶段的项目。第一章原始起点没有 npm 应用；章节完成态才有。
4. 逐项对照和带回需要的改动，再检查 diff、页面和构建，不整仓覆盖。

GitHub Template 生成的仓库拥有自己的历史；不需要添加课程 upstream、合并讲师分支或执行 reset/cherry-pick。切换分支也不能代替保存未提交工作。
