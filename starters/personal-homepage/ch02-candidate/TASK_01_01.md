# 1.1 任务卡：修改环境检查页的欢迎语

## 输入与目标

输入：独立的个人主页练习仓库、浏览器、已可用的 Codex CLI，以及课前环境记录。此任务不修改课程资料库的 `courseware/` 课件或 `starters/` 模板。

- 文件：`setup-check/index.html`。
- 元素：`<h1 id="welcome-message">`。
- 原文：`你好，欢迎来到我的练习页面。`
- 目标文案：`你好，欢迎来到 Vibe Coding 课堂！`
- 保持页面标题、其余文字、HTML 结构、样式和布局不变。

这是课程编写的练习文案，不是一次已经执行的 AI 修改记录。

## 给 Codex 的任务

```text
只读取 setup-check/index.html 和必要的仓库状态。
请把 h1#welcome-message 的文字从“你好，欢迎来到我的练习页面。”
改成“你好，欢迎来到 Vibe Coding 课堂！”。
保持其余文字、HTML 结构、样式和布局不变。
不修改其他文件，不安装依赖，不发布。
先复述目标、非目标和小计划，等我确认后再修改。
如果需要超出上述范围，请停止并说明原因。
完成后说明实际改动，给出浏览器和 Git diff 的检查方法。
```

任务文本限定本次操作意图，不代表环境已经实现单文件技术隔离。实际权限仍须按授课版本核验。

## 操作与验收

1. 记录实际工具版本、项目路径、分支与初始工作树状态；保存修改前截图。
2. 发送任务，人工核对目标、范围和计划，确认后再执行。
3. 刷新浏览器，逐字核对目标文案，确认其余内容和基本布局保留。
4. 查看 `git diff -- setup-check/index.html`，再看 `git status --short`，确认没有其他意外修改。
5. 如果有偏差，引用实际证据提出限定范围的修正，再重复检查；没有偏差就如实记录通过，不制造虚假故障。
6. 由学员整理证据到 `docs/evidence/CH01_ENVIRONMENT_AND_FIRST_LOOP.md`：环境状态、目标与计划、人工确认、前后截图、diff、Review 结论及修正或剩余问题。该文件由学员另行创建，不包含在上述源码修改授权中。

首次结果全部正确时，课程可另外准备并明确标注教学故障样例，用于练习修正。本 Starter 未附故障样例，不能把未做过的修正写成已完成。

通过标准：目标文字完全一致，其他内容与布局保持，实际 diff 仅含必要的欢迎语修改，证据与人工判断可追溯。环境或登录失败应记录待补做，不用页面能够显示冒充 Codex 实操通过。
