# 个人主页项目 Brief

## 1.4 的任务

把“帮我做一个好看的个人主页”澄清为可执行的首页任务。先阅读本文件、[占位内容](PLACEHOLDER_CONTENT.md)、[工具链说明](docs/setup/TOOLCHAIN.md)及必要仓库状态；材料已有的答案直接引用，缺失且会影响实现的决定向学员提问。本节只读、提问和规划，不创建应用、不安装依赖。

## 已确定的目标与范围

- 项目载体是个人主页，第一版只完成首屏和项目展示区。
- 正式应用使用 React + TypeScript + Vite，在当前仓库根目录创建，不另建嵌套项目。
- `setup-check/index.html` 仅用于首次环境练习，不是正式主页，也不进入发布产物。
- 使用可公开的文字与本地素材；可以全程使用虚构身份。本任务无需照片、图标包或远程素材。
- 不做账号、后端、数据库、发布或小游戏；后续章节再按任务推进。

## 需要人工确认的决定

占位内容是可选素材，不代表已经批准的需求。根据学员自己的决定补齐：

- 主页给谁看，希望访客首先了解什么？
- 姓名、简介和项目名称、描述使用哪些文字？是否采用给定的虚构素材？
- 首屏按钮的文案与目标是什么？项目卡是否跳转？没有实际入口时如何展示？
- 是否有必须遵循的视觉要求？没有指定时，先提出简单建议供人确认，不自行扩展功能。
- 本次允许创建的具体文件、小计划和检查方法是什么？

课件 P22–P23 展示了一组合成人工作答。学员可以明确确认采用这组示例，也可以提供自己的答案；未作出的决定不能记录为已确认。

## 1.5 的实现范围

人工确认后，创建根目录 `index.html`、`package.json`、`package-lock.json`、`vite.config.ts`、`tsconfig*.json` 和 `src/` 中必要文件。具体文件清单由计划列出并确认，保留已有材料及 1.1 的改动。不修改 `setup-check/`，不清空仓库，不在未确认的范围内创建其他项目或增加依赖。

## 首页 v0 的验收依据

- 显示的文字与已确认内容逐项一致，按钮和项目卡行为与人工决定一致。
- 可以启动页面，实际执行 `npm run build` 成功，无明显浏览器控制台错误。
- 能说明应用入口、主要组件和样式的位置；完整 diff 与批准范围一致。
- 正式应用与构建产物不包含环境检查页、密钥或私人资料。
- 保留请求、决定、截图、构建输出、Review 和未解决事项；通过后保存本地提交及 `ch01-prompt-baseline`。

这只是第一章 Prompt 原型的完成标准，不将当前视觉和行为冻结为后续正式产品规格。缺材料、工具链未核验、关键问题未回答或需要越界时，先说明阻塞并停止相关执行。
