# 课程参考进度

第 1–3 章在自己的同一个仓库中连续完成，不在下一章开始时换回讲师代码。

## 起点与检查点

| 参考 | 所在仓库与用途 | 创建时机 |
| --- | --- | --- |
| 课程发布基线 | course-starter：环境检查页、Brief、占位材料与环境说明；没有正式 React 应用 | 录制冻结时记录并发布完整 commit，当前待发布 |
| `ch01-prompt-baseline` | 学员仓库：第一章首页 v0 的本地检查点，对应课件 P30–P31 | 学员完成页面、构建、diff、产物检查后创建 |
| `ch01-complete` | 课程仓库：供第二章对照或重新练习的讲师参考快照 | 尚未发布，不能当作现有起点 |
| `ch02-complete` | 课程仓库：完成反馈迭代与 GitHub Pages 发布后的参考快照 | 尚未发布 |
| `ch03-complete` | 课程仓库：加入本章小游戏后的参考快照 | 尚未发布 |

学员本地 `ch01-prompt-baseline` 与讲师参考 `ch01-complete` 用途不同，不要求提交 SHA 相同，也不要求每小节建立标签。`course-run` 是讲师演示历史分支，不作为学员首次克隆的入口。

## 1.5 保存本地检查点

确认验收通过后，检查 `git status --short`、完整 diff，以及新建但尚未跟踪的文件。按人工审阅结果暂存文件，用 `git diff --cached` 检查待提交内容，保存提交后再创建标签：

```bash
git tag ch01-prompt-baseline
git rev-parse HEAD
git rev-parse ch01-prompt-baseline
```

标签已存在时先核对它指向的版本，不强制覆盖。未通过的项目记录为待补做，不创建成功检查点。创建本地提交和标签不等于发布网站或推送到远端。

## 想重新练习时

1. 保留整个当前项目，包括尚未提交的内容；不能只保存个人文字而遗漏代码、样式和证据。
2. 从课程仓库选择一个已发布的版本，下载 ZIP 并解压到另一个目录，记录来源 commit。
3. 按该版本 README 初始化 Git 并运行对应阶段的项目。第一章原始起点没有 npm 应用；章节完成态才有。
4. 逐项对照和带回需要的改动，再检查 diff、页面和构建，不整仓覆盖。

GitHub Template 生成的仓库拥有自己的历史；不需要添加课程 upstream、合并讲师分支或执行 reset/cherry-pick。切换分支也不能代替保存未提交工作。
