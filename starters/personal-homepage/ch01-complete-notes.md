[`ch01-complete/`](ch01-complete/) 是一次按第 1 章课件跑完 1.1、1.4、1.5 后，练习仓库在 `ch01-prompt-baseline` 时的全部已跟踪文件（不含 `node_modules/`、`dist/`）。用途：

- 第 2 章备课与录制的起点；
- 学员落后时对照：把需要的改动带回自己的仓库，不整仓覆盖（见 `CHECKPOINTS.md`）。

## 过程

1. **1.1**：提交课件 Prompt，Codex 先复述计划，确认后只改了 `setup-check/index.html` 的欢迎语一行。
2. **1.4**：只读模式下提交 P22 Prompt。Codex 列出已有答案和四个待确认问题，并指出 Node 版本不符、1.1/1.2 证据文件缺失。人工作答后，它整理出需求条目和文件清单。`PROMPT_V1.md` 由人按 P23 写成。
3. **1.5**：新会话提交 P23 任务。Codex 发现沙箱不能联网、无法 `npm install`，于是停下来问怎么办。人选择“它写源码，人来安装和构建”。
4. 人运行 `npm install` 和 `npm run build`，都成功；在浏览器里核对时发现一处偏差，见下节。
5. 两轮修正后复验通过，提交并打 `ch01-prompt-baseline`。
6. 排练结束后人工追加 rollup 的 `overrides`，重新 `npm install` 并构建通过。`ch01-complete/` 的 `package.json` 与 `package-lock.json` 是追加后的版本，不是 Codex 当时生成的原样。

## 排练中发现的问题

| 发现 | 处理 | 对课程的影响 |
| --- | --- | --- |
| Codex 默认沙箱不能联网，`npm install` 失败 | 人在自己的终端安装 | 1.5 要讲清楚依赖由谁安装、在哪里安装 |
| 1440 视口下内容列只有 200.6px（计划 860px） | 第 1 轮 Codex 判断错原因，并说“按 CSS 推算应已修好”，复验仍是 200.6px；把证据交回后第 2 轮修好（原因是 React 挂载点 `#root` 被收窄） | AI 没有验证就说完成，可作为 1.5 或 2.3 的真实素材 |
| 360 视口下不挤，Codex 主动加了 600px 断点 | 无 | 2.1 第 1 条反馈在这份 v0 上不复现 |
| 页面不满一屏，点“查看项目”时页面不动（地址栏变为 `#projects`） | 未改 | 和 2.1 第 2 条“点了没反应”混淆，需要决定怎么处理 |
| `npm run build` 约 2 分 30 秒 | 原因是间接依赖 rollup 4.64.0（2026-10-02 发布）。排练结束后在 `package.json` 加 `overrides` 固定为 4.63.6，重装后约 0.5 秒，产物哈希相同 | course-starter 的 `TOOLCHAIN.md` 已同步要求这段 `overrides`；本目录的 `docs/setup/TOOLCHAIN.md` 是更新后的版本 |
| `body` 的 `gap: 48px` 实际不生效（Codex 自己指出） | 不在本次范围，未改 | 剩余问题 |
| npm 11 提示 esbuild 安装脚本未批准 | 未处理；构建成功 | 与 `TOOLCHAIN.md` 的已知提示一致 |

## 验收结果

- 文字与已确认内容一致；按钮链接到 `#projects`；项目卡是 `li`，不可点击，也不在 Tab 顺序里。

- `npm run build` 退出码为 0；`dist/` 不含环境检查页。
