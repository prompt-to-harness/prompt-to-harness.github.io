# Screen Studio 剪辑与渲染

使用仓库工具 `tools/screenstudio-edit/`，先读该目录 [README.md](../../../tools/screenstudio-edit/README.md) 了解计划格式、命令和支持版本。该工具适配已验证的项目格式，不是官方 API，也没有命令行渲染能力。

本课程已确认的人像、镜像、放大、节奏和留痕要求统一见 [review-policy.md](review-policy.md)，执行课程录屏任务时读取；后续用户指示优先。

## 确定剪辑内容

复用已有转写、原逐字稿和剪辑清单。没有转写时用相邻的 `screenstudio-transcript` skill；已有成功转写不重复识别。课程主线发生变化时按 `lesson-polish` 路由；只按已确认内容删录错、重复、口水词，不自动改课件。

沿用本次用户已确认的视觉与交付偏好，写入任务私有目录中的 JSON 计划，不把某一位讲师的偏好写成所有录制的默认值。缺失且影响结果时，合并询问：人像位置和大小、镜像、固定／跟随／关键细节放大、点击提示、剪辑节奏、字幕、清晰度。用户要先看示例，就先做示例，不直接导整节。

只剪不补录时，保留原意思和操作先后；删口误分句或可独立删除的旁支，不拼造新结论。技术词／数字识别错误先核对，ASR 出错不等于讲师说错。口水词是候选，不按命中词批量全删；留换气、必要的阅读和操作停顿。文字审读不能冒充听音校对。

清单的“定位时间范围”不一定是实际切点。用源词定位句内边界，把已决定的 `keep`、`cut` 及理由写进计划。大段重复先删，再细剪保留段内的口水词；不同删除条目不要重叠。不依赖含糊自然语言让脚本推断要删哪句。

## 放大与删除的审阅记录

本课程已确认的放大原则（2026-10-25）：**以帮助读清小字为主；仅在判断非常重要时，少量用来强调重点。** 概念图、课程地图、循环关系先保持全景；角色字段、文件名和行号、源码依据、请求新增内容等确需阅读时才放大。目标确定后进入，停住供阅读，讲完返回全景；不追着鼠标走，人像位置与大小保持稳定。不能只因发生点击就放大。

每次放大在 `zooms` 中记 `purpose`（`reading`／`emphasis`）、`target_label`、`reason`、范围、倍率和目标点；区分“已配置”“已渲染”“已人工确认”。未放大的重要候选也在任务备注记取舍，不用“所有地方都放大”代替设计。审阅时核对目标是否真能读清、是否丢失文件名／行号／轮次等必要上下文。

每条删除在 `cut_details` 留范围、内容原话／摘要、原因、类型、源段 ID、校对状态；同一片段不要只写一个总备注。`keep` 间隙若代表删除，同样逐条登记。秒数、占比、成片接缝位置由脚本计算，不能估填。删除依照什么清单条目、重讲时保留哪一段，要写清楚；ASR 待核不得写成已听辨。

用 `build_review.py` 生成 HTML、JSON 和 TSV 审阅记录，命令见工具 README。审阅页同时展示源范围、成片接缝、放大事件和理由，可回听被删原音。**示例外未覆盖内容不等于删除，暂停空档不等于删掉的媒体**；三组独立示例不是三个可相加的最终成片版本。正式输出前用 `--strict` 检查每条删除／放大是否都有说明；历史资料缺失先标待补，不能伪造原因或听校状态。

整节制作使用 `scope: lesson`、一个 clip，输出一个完整工作项目和连续视频，不能把已有示例当作分片再拼接。用 `chapters` 记录讲述段落以便成片跳转；完整审阅页支持事件类型和关键词筛选。保留一次必要的阅读／操作证据，不为压时长删空主线。

## 生成与渲染

1. 明确未剪原项目和新的输出版本目录。先用 `edit_project.py --dry-run` 检查，再生成副本。工具不覆盖已有目录、不在源项目里输出，遇未知版本、已剪／变速源项目等拒绝继续；保留失败信息，不绕过格式检查硬写。
2. `recording-wall` 是转写使用的原录制时间线，包含暂停空档；素材的 source 时间则去掉暂停。让脚本从录制元数据换算，不能直接把字幕秒数填进 slices，也不能用剪后时间设置源 zoom。
3. 脚本统一设置实际生效的 `defaultLayout`、`mirrorCamera`、固定 `manual` zoom、鼠标和画幅。只镜像人像，不镜像屏幕；缩放时人像保持大小。不在源项目或正在打开的旧副本上改配置后期待自动重载，生成新版本再打开。
4. 在 Screen Studio 逐个打开 `render-queue.json` 的项目。通过允许的电脑操作工具，核对人像方向、位置与尺寸、小字可读性、局部放大目标、切点与画面；不必再逐项手调已生成的配置。应用窗口有时先显示未定位的初始帧，短暂播放后再判断实际片段。
5. 按队列路径导出 MP4：默认导出与验证规格为 1080p、30 fps、Studio 压缩；用户另有要求时同步修改验证规则。本课程普通课件、代码讲解默认 30 fps；只有用户明确指定，或游戏／大量动画演示确需更顺滑时使用 60 fps，并用 `--fps 60` 验证。不用将已有 MP4 二次转码代替原项目渲染。只改帧率时复用现有完整工作项目，另存 MP4，不为此再复制素材。只本地导出，不用共享链接。导出完成后再检查文件，不能把按下导出按钮当作成功。

## 验证与交付

运行 `verify_exports.py render-queue.json --frames`，核对实际时长与队列预期、分辨率、音轨及开头／中间／结尾解码。检查镜像时比较背景物体或左右手，不能只看布尔配置。查看放大前／中／后、人像尺寸和所有删剪接缝；实际执行了哪些听看检查，就报告哪些。

长片仍对全部接缝检查解码，但默认最多保存 24 张 PNG（`--frame-limit` 可调），优先覆盖首中尾、放大中间与分散接缝；不为一百多处细剪保存数百张全尺寸图片。人工检查与自动解码分开记录，未逐接缝听音不得写成全部质检通过。

导出异常先看具体日志和单个样片，保留源录音与失败副本，不用重新转写或破坏源文件来掩盖问题。Skill 或脚本改动后运行该工具目录的测试；原有转写代码受影响时同时跑原测试。

交付链接到视频、编辑计划及工作项目，说明每组验证的效果及未核对项。媒体、真实录音、个人路径和录制细节留在用户指定的私有目录或忽略目录，不加入公开课程仓库。工具与 Skill 可以公开，项目生产计划不硬编码进脚本。
