# 离线 H.265 交付流程

## 母版与编码

先完成 Screen Studio 原生导出及剪辑检查，再转换当前采用的连续成片。多项目小节先无重编码拼接成一节，再转码一次。保留原生 H.264 母版、可编辑工程和剪辑记录，不在母版路径上覆盖写入。

本课程采用 MP4 容器、HEVC／H.265（同一种编码）、1080p、30 fps；以 1,500,000 bps 为起点，压缩音频直接复制。2.4 的对照实验中，体积约减少 46%，代表性代码、终端、课件与人像帧未见明显可读性下降；这不是对其他视频的无损保证。小字或动态画面出现明显损伤时，提高码率重新生成新版本，不通过再次转码 H.265 修复。

已检查 Screen Studio 3.5.1-4051 的导出界面，没有可选 HEVC 编码项。因此当前使用离线转换；换应用版本时重新核实，不能把此结论推广到所有版本。

## 执行与核验

在仓库根目录运行（需要 macOS 与 Xcode Command Line Tools，不依赖 ffmpeg）：

```sh
python3 tools/screenstudio-edit/offline_hevc.py "/path/native-master.mp4" "/path/2.4-1080p30-h265.mp4"
```

工具拒绝覆盖，先写临时文件，通过核验才发布输出，生成同名 `.hevc-validation.json` 内部报告。报告已有时也拒绝覆盖。已有成功试验产物可用 `--verify-only` 核验后采用，不重复有损编码。`--bitrate` 指定新目标码率。

自动核验实际视频编码为 `hvc1`／`hev1`、1080p30、时长差小于 0.12 秒、源文件 SHA-256 未变、压缩音频 payload 哈希及包数一致，并解码首中尾。首次使用新参数先做代表性样片对照；每节抽查代码小字、终端、课件、人像和动态放大，比较同一时间的母版与转换版，记录人工检查范围。转换不改变切点，不要求重剪已经认可的成片。保留原剪辑队列的接缝解码核验；自动检查不代表已完整回看或已证明视觉无损。

## 命名、交付与清理

- 对外命名 `<lesson>-1080p30-h265.mp4`，每节只放一份连续视频。改版用新批次目录，避免同一个文件夹混放 H.264、H.265 和试验候选。
- 交付包默认仅根 README、各节视频和简短 `edit-notes.md`。从内部采用清单生成目录及相对链接，检查实际编码、文件数、大小和复制哈希；用独立 APFS clone 或完整复制，不用软链接／硬链接。
- README 明确批次范围、格式、时长和反馈方式。制作日志、校验 JSON、样片、对照图、工程和母版留内部，不塞入外发包，不默认增加 PDF、表格或网页。
- 新批次核验完成后，把旧交付批次移到内部归档并更新唯一的当前交付入口。保留母版、工程及必要实验依据；仅清理已结束任务产生的临时编码文件和可重建缓存，不按通配符删除真实媒体。实际删除或移动的范围写入内部批次记录。
