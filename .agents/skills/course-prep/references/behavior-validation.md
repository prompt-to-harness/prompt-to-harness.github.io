# Skill 的行为验证与反馈维护

修改 course-prep 的共用原则、任务路由或环节方法时读取本文。普通备课执行当前产物的方法与检查即可，不额外运行整套验证。修改 Skill 须有讲师明确授权。

## 维护顺序

1. 从实际失败中定位原因：任务没有加载适用方法、方法未进入执行步骤、检查识别不了偏差，或方法本身与任务不适配。不能只从产出有错推断“缺一条规则”。
2. 按下表修改唯一维护位置。共用原则应短而稳定；操作方法进入对应环节，具体事例保留为依据；已有规则失效时修正原处及引用。
3. 按影响范围选择下面的典型任务。共用原则或路由改变覆盖四类任务；单一环节的方法改变检验该类任务及受影响的上下游。只修链接或措辞时做相应静态检查即可。
4. 核对结构与链接，再执行可用的行为验证。记录实际产出、判断依据和未验证范围；格式校验通过不能报告为行为已验证。

| 反馈归属 | 唯一维护位置 | 更新结果应体现什么 |
| --- | --- | --- |
| 跨环节的教学判断 | SKILL.md 的“所有任务共用的判断” | 各任务都会取得的取舍依据；与仓库编辑规则保持引用关系 |
| 任务漏读或误读方法 | SKILL.md 的任务路由 | 请求如何对应执行与检查方法 |
| 某环节反复出现的错误 | 对应 reference 的执行步骤及检查 | 在错误发生前指导决策，在产出中能发现偏差 |
| 帮助辨别做法的具体样例 | 对应 reference 的样例；PPT 逐步样例归 ppt-examples.json | 能看见误做、正确关系与迁移条件 |
| 某课的取舍、状态或局部要求 | 该课现有内容源与记录 | 保留有效决定，不升级为全课规则 |
| 工具或环境问题 | preparation.md 或对应工具说明 | 可定位的处理方法及适用条件 |

## 怎样验证

以下任务用于复现典型问题，输入材料逐项注明是教学假设还是实际备课材料。维护者可用真实失败替换输入，保留原请求、原材料与评价依据。执行时只给请求和输入材料，评价依据留给核对者。

在独立上下文中提供当前 Skill、任务请求和输入材料，生成实际产出后再按评价依据检查。可用新会话或本环境支持的独立执行方式；不要求特定模型、工具或并行代理。只有获得相应授权才启动会增加成本或外部副作用的执行。无法独立执行时可以进行作者走查，但应明确标为作者走查。

比较修订前后时保持任务、输入、模型与工具条件尽量一致，并保留差异。单次改善只说明该样本上的表现，不能据此宣称稳定生效。除修改目标外，还检查保留事实、讲师决定与任务范围是否受损。

## 典型任务

### 0. 按目标产物路由并保持独立维护

使用相同主题分别走查以下请求，记录实际加载的方法和修改目标，而不仅检查最终文字。

| 请求 | 评价依据 |
| --- | --- |
| “修改 Discussion，整理每一步的画面和知识点” | 只进入 Discussion 方法；用四列讲解表，知识列不混操作，纯 PPT 行第四列留空；不加载 HTML 方法或生成页面。 |
| “先在聊天讨论讲什么知识、用什么画面，暂不写文件” | 默认 Discussion 方法与相应表格；不以“画面”路由到 HTML，不落盘。 |
| “修改 speaker.html 对应 screen-plan.json 的切换提示” | 按所属讲述页加载讲述方法；读取 Discussion 仅作内容参考，不加载其维护规则或改写它。 |
| “只修讲述页的评论定位” | 只加载 HTML 实现方法，保留教学内容。 |
| “为 Discussion 核对 Plugin 的组成” | 资料准备结束返回 Discussion；不自动安排 PPT 页数或生成讲述线。 |
| “修改 Discussion，并同步受影响的讲述页” | 分别加载两种方法、按各自职责维护；同步的是教学决定，不复制段落或强制相同结构。 |

修订前后须保持请求与输入一致。没有独立运行条件时只记录静态或作者走查，不宣称路由稳定性已经验证。


### 1. 用专业案例讲入门概念

**执行请求**：为初级开发者安排“读懂 Skill 正文”的讲解顺序，使用下面的游戏验收 Skill 摘录，在对话中给出具体讲法，不修改文件。

**输入材料**：本部分目标是识别正文常见内容及其用途；学生不需要学会完整游戏验收。案例摘录：“先启动游戏，再检查核心操作；画布渲染应保存截图，因为 DOM 信息不足以判断画面；报告写清复现步骤与影响。”

**评价依据**：讲法是否通过原句解释步骤、条件与理由、输出要求；是否额外展开缺陷分级、测试覆盖设计等独立课程；能否从安排中直接看见本节收获。原文件顺序可用于观察，不要求强套分类数量或固定模板。

### 2. 润色讲师原稿

**执行请求**：保留原意和推导顺序，把下面这段稿子改得适合照读，并给出修改结果。

**输入材料**：“我们先看到页面里的牌没有翻过来。刚才的检查为什么说通过了？它查的是内部状态。我们再看截图，卡片背面还在这里。所以这次状态检查回答了配对状态有没有变，截图让我们看到了实际画面。”画面顺序是游戏页面、状态检查记录、截图。

**评价依据**：现象、追问、检查对象差别和判断依据是否保留；是否把具体推导压缩成“应结合多种验证方式”；是否添加记录不支持的因果结论；口播是否仍对应画面顺序。允许多种表达，不按字面匹配。

### 3. 把讲述线做成 PPT

**执行请求**：根据以下讲述线给出可制作的画面与推进设计，解释为什么这样安排；不必生成最终课件。

**输入材料**：学生需要理解用户要求如何转成检查条件。用户原话：“做六对相同图案的翻牌，全部配对后显示胜利。”讲述依次对应十二张牌、每种图案两张、完成六对后出现胜利状态。材料是该原话与对应游戏截图，均作为教学假设提供。

**评价依据**：是否把原话、具体对象和检查条件建立可见对应；是否仅剩“需求—分析—验证”三个框；精简时是否丢掉完成条件；是否据此声称已有真实运行结果。若实际生成页面，还需用该环节的方法检查渲染和推进。

### 4. 局部修改已有课件

**执行请求**：下面是既有讲述安排。只补充第二段截图的定位说明，保留其他内容。

**输入材料**：第一段展示用户要求“全部配对后胜利”；第二段展示完成配对后的截图，讲述“最后一对配上后，胜利提示出现在画面上”；第三段回到原要求核对完成条件。截图材料名为 `win-state.png`，应定位胜利提示所在区域；不提供实际图片，本次只写定位说明。

**评价依据**：是否只调整第二段定位；原顺序、讲述和完成条件是否保留；是否无依据地声称已经看过截图或验证布局；是否以优化为由重做整段教学结构。

### 5. 合并备课入口并保留未成稿内容

**执行请求**：整理某章的备课入口，只合并和移动位置，不改教学正文。

**输入材料**：一份章级讨论稿；两个小节，其中一节有两份分部分讲师页和唯一口播源，另一节仅有讨论工作稿；第一节另有一个待补口播部分，章末保留经验分享占位；旧页存在评论与材料链接。

**评价依据**：是否保持全章唯一设计源、有讲述线的小节是否使用现有讲述页与 PPT 入口；只有 Discussion 的小节是否链接原文；工作稿、待补和占位是否可达且状态准确；是否保留原文、评论及材料定位；是否复制正文或无授权补写；历史是否明确区分。另走查四类既有任务，确认结构整理没有替代其教学取舍、口播、PPT 和局部修改方法。

### 6. 从 Discussion 产出讲述线与 PPT 逐页安排

使用 3.2.1 的「自然语言选用 Skill」做两次交接。第一次的产物经核对后作为第二次的输入。两次均沿用同一份运行记录。

**阶段 2 执行请求**。根据 3.2.1.5 和同次运行记录，推进这段的讲述设计。以聊天交付工作稿，并给出本课保存位置。

**阶段 2 输入与评价**。提供 Discussion 条目、回放材料和本节源文件名。现有 PPT 和口播留作核对参考。先看同一条讲述线是否给出 PPT 总页数和每页对应的讲述内容，再核对各画面的证据和解释是否区分描述匹配、实际读取和返回清单。清单只提供待执行的计划。读完回放后，返回 PPT 的位置及此时新增的证据须明确。 [Discussion](../../../../docs/outline/ch03-discussion.md#321-安装主动调用语言触发与描述调整) · [真实运行回放](../../../../courseware/ch03/lessons/02-rules/selection-evidence.html#implicit-request)

**阶段 3 执行请求**。接收上一步的讲述线和同次运行材料，为其中的 PPT 提供可查看的制作结果，并写出对应的口播。选择第二章或第七章一个同类成品作参照，指出借鉴了它的哪一处信息组织或视觉处理。交付可编辑源和实际展示入口。

**阶段 3 输入与评价**。提供已核对的讲述线、运行材料、视觉规范和 PPT 样例入口。检查实际画面能否同时指认请求与描述的对应，读取摘要是否按已定顺序出现，返回后能否继续推进。核对手绘线条、语义色、字号、对比和主次，并检查口播是否保留证据能支持的结论。用浏览器实点材料入口、返回和下一步。 [PPT 样例与制作方法](ppt.md#按表达难点选择样例)

### 7. 检查备课入口和定稿入口

在同一节的三个状态分别交付，沿用已存在的编号与源文件。

| 状态 | 实际核对 |
| --- | --- |
| 只有 Discussion | 从交付链接进入对应条目。入口不自动生成讨论稿正文的 HTML 副本。 |
| 已开始讲述设计 | 打开讲述页的实际段落链接，再点本段 PPT 和材料。确认画面、切换与讲法对得上，页面能在备课中继续使用。 |
| 备课成果交付讲师确认 | 打开授课画面、录制讲稿及操作入口，核对讲述顺序与唯一稿源一致、教学安排适合学生；不把学生独立使用材料列为本阶段默认产物。讲师确认后按独立交接说明启动后续制作。 |

### 8. 准备结果改变讲法，而非复制案例模板

**执行请求**：Discussion 计划用报表导出任务讲“通用要求怎样变成验收”。请决定还需准备什么，并给出讲述线和必要的 PPT 安排；不运行新任务、不修改文件。

**输入材料（教学假设）**：只有一次导出记录。文件已生成，抽样打开后发现部分中文显示错误；项目要求中文可读，没有指定编码。现有记录没有原因排查，也没有修后复验。

**评价依据**：是否预看输入、文件与结果后区分“生成文件”和“内容可用”；是否把编码原因保留为待核实而非已有结论；是否尊重不运行的范围，提出针对缺口的准备建议；是否根据解释需要选画面，避免照搬三个任务、一页三态或两份 Skill；是否明确每次切换新增的理解，保留结果与推断的边界。

再用“只调整既有页面的一句转场”和“已有充分证据的概念小结”作范围走查：前者不启动全套预跑，后者不为了遵守流程新增任务。独立生成未执行时仅报告作者走查。

### 9. 实际生成讲述页并检查浏览器结果

模板固定数据检查通过后，在独立上下文中只提供候选 Skill、自然任务请求和原始材料，让执行者实际生成一个可打开的讲述页。请求不重复排版规则，也不提供做好的目标页面；复用 Skill 自带模板是预期行为。输入应覆盖分步 PPT、操作与口播交替、同一材料两次定位、Prompt 与附件、动态演示及条件备用，以及成稿／仅设计／占位共存。已有逐字稿和材料保持唯一源，未写的稿件不补造。

分三层核对：实际读取的方法与模板；产出中的内容、设计、时序、材料与未完成状态；浏览器里的连续阅读、导航、折叠、复制、定位和展开态布局。保留原请求、输入、候选版本、首次完整产物与检查证据。未接真实编辑或评论后端时只验证节点与接口，不报告持久保存通过。一次页面通过不代表教学效果或稳定生成能力已经验证。

若失败，先区分输入、规则、路由、模板或适配问题；保留失败产物，修对应源后从独立上下文复验失败任务及受影响任务。不能手工修好测试页面后宣布 Skill 通过。只有文字制作稿时，不把它计作实际 PPT 或 HTML 验收。

### 10. 制作中的调整与上游缺口

用同一 Discussion、材料和阶段二首次产物，在新的独立上下文接续制作。检查是否保留当前有效设计，PPT 是否表达对象与关系，操作和材料是否仍只维护一次；分合页、改变展示方式等实际调整是否说明理由并回写正确源。输入不必每次从零设计，可复用已有交接测试。

另用一项上游设计与证据存在矛盾的小任务，检查执行者是否指出具体条目、按授权修正或标明受影响缺口，并继续不依赖该缺口的部分，不能把矛盾润色成成功台词。再以不同题材的小样例检查迁移，避免方法仅贴合某一章。共用原则改动仍覆盖前述入门安排、原稿润色、PPT 讲法与局部修改四类任务；路由隔离应使用各自独立上下文，不用同一上下文里先后读过多种方法来证明不会误加载。

## 记录与继续改进

验证记录沿用本项目已有的维护或检查记录位置，不放入课程正文，不要求每次另建报告。至少保留方法版本或快照、任务与原始输入、执行条件、实际产出、具体问题及判断依据、验证身份与未完成项。未执行的任务写“未执行”，作者对照阅读写“作者走查”，独立生成产出后才写实际行为结果。

失败时回到维护顺序定位原因。修复后复验失败任务及可能受影响的其他任务；检查通过后不为增加次数反复运行，也不为得到预期结果挑选性保留输出。
