## 适用范围与读取规则

本文用于跨阶段协调、目录与历史入口整理、新环境起步和交接，按当前问题读取对应小节；局部编辑不要求先通读本文。任务选择按 [Skill 入口](../SKILL.md#按任务读取方法)，资料与预跑按 [材料方法](materials.md)。本仓库按 docs/agents/sources-of-truth.md 定位内容依据，其他项目使用其对应规则。

下文保留第 2、7 课的真实案例作为方法依据。提到“讨论板”“课次卡片”时，指本课现有的内容设计载体；只有使用 harness-board 的任务才使用其字段（segments、screen、text、pending、draw、design_route、learning）、评论和编号机制。其他课沿用自己的内容设计与讲述线源，不为使用本方法另建讨论板。具体产品、评测次数、课次路线和某轮保留原话的要求只约束原任务，不自动推广。下文仓库命令与路径只适用于本课程环境；其他项目按其对应工具执行，不能将本项目路径当成通用 Skill 的安装依赖。

## 阶段入口与产物位置

需要跨阶段定位或交接时，沿 [Skill 入口的整体路线](../SKILL.md#先确定任务与阶段)与本课源文件说明找到当前产物。交付时给出可打开入口、源文件位置和未完成项；源文件与显示页面分别说明，不把 HTML 当作第二份内容源。

课程按“章 → 小节 → 节内部分 → 具体画面与讲述段落”组织，如 N、N.1、N.1.1、N.1.1.1；编号沿用本课有效设计。交接列全本轮范围内的小节及其部分，分别说明已有口播、仅有讲述设计和占位状态，不把局部完成当全节完成。以下用第 N 章的 N.1 小节示意路径，实际工作沿用项目现有目录和文件名：

| 阶段 | 查看入口与修改位置 | 交接时核对的准备程度 |
| --- | --- | --- |
| 1. 内容设计 | 本章 `docs/outline/chNN-discussion.md`，以 `N.1`、`N.1.1` 等编号定位。目标、学生收获、章级分工、知识依据与部分表格写回同一份 Discussion。 | 关键知识有可核对的依据，讲解顺序和画面职责明确，未定项已标记。具体模板与检查见 [Discussion 方法](discussion.md)。 |
| 2. 讲述设计 | 从本节 `speaker.html` 查看讲法、画面和切换，修改本节讲述线源。交付 PPT 总页数及每页对应的讲述段与内容，材料接入实际使用的步骤。 | 解释、证据与切换明确；影响当前讲法的材料缺口已处理，其余保留工作稿状态。完整逐字稿和正式版式可后补，见 [讲述设计](narration-html.md#怎样判断可读)。 |
| 3. 课件制作 | 对照本节 `index.html` 与讲述页，修改 PPT 源与唯一口播源。完成正式画面、可照读口播和操作入口；制作中的调整回写同一讲述线，不另存操作版本。 | 实际渲染支持已定关系与递进，符合课程视觉规范；口播可照读，画面、状态和入口可顺序走查。各自按 [PPT 方法](ppt.md)与[逐字稿方法](spoken-script.md)检查。 |
| 4. 检查、定稿与交接 | 按录制顺序实际打开 PPT、讲述页及演示，修正写回对应源。备课阶段完成授课和录制所需入口；讲师确认后再启动学生独立使用材料，按 [交接边界](../../../../docs/production/student-materials-handoff.md)另定交付范围。 | 本轮范围内的内容与操作已核对，机器检查、实际操作、讲师审阅与试讲状态分别说明，未完成项明确。完整路线按 [录制核对与复验](recording-alignment-workflow.md)。 |

此表用于定位各阶段的工作位置，不表示示例课次已经完成对应产物或通过审阅。讨论以当前有效版本为准；尚未同步的新设计写回对应设计源，材料缺口和待检查项随本轮交付说明。

### 目录与正式入口

备课设计维护 Discussion 与讲述线两层，并持续维护对应 PPT。提前准备事项写入 Discussion，网页、日志与运行记录按讲述需要接到对应步骤。推荐目录如下；已有章节采用其他文件名或内容设计载体时沿用其位置并明确职责，不为符合命名另建副本。

```text
docs/outline/chNN-discussion.md   # 全章有效内容设计稿
courseware/chNN/
├── index.html                   # 学生交付阶段按确认范围确定导航
├── materials/                   # 材料、证据与演示资源
└── lessons/
    ├── 01-topic/
    │   ├── speaker.html         # 本节讲述页，定稿后可开放讲师视图
    │   ├── script.json          # 本节唯一口播源
    │   ├── index.html           # 本节完整 PPT 入口
    │   └── …                    # 讲述线源、画面映射和构建文件
    └── 02-topic/
        ├── speaker.html        # 节内部分在同一页面中定位
        ├── script.json
        └── index.html
```

每章一个有效内容设计源，每小节一个讲述页及完整 PPT 入口；“一个”指一套有效内容及正式入口，不限制底层物理文件数量。节内部分与单页深链定位同一套课件，不另建分部分版本。真实案例链接保留原始定位。

只有内容设计时交付 Discussion 位置；有讲述线后从讲述页进入对应步骤。已有设计、仅有 Discussion、口播待补和占位状态如实呈现，具体接入按[尚未成稿的部分怎样接入](narration-html.md#尚未成稿的部分怎样接入)。备课时从同源讲述线与口播提供可用的录制视图。学生材料另行确定载体与内容组织，不默认公开备课源或沿用阅读模式。

### 历史与模板边界

小节 README、LOG 与旧制作记录供查阅；`STORYBOARD.md` 只读取材，使用其中独有有效信息时先接入当前 Discussion 或讲述线，不新建或同步独立分镜。

历史方案移至明确标识的取材入口或通过 Git 追溯。旧链接按需要重定向，不因参数或锚点不同而无提示地进入另一套方案。整理或合并页面时保留原文、已保存修改、评论坐标和材料定位；只获入口整理授权时不改教学正文。

Discussion 模板由 `discussion.md` 维护；具体讲法与逐页安排归 `narration-html.md`；页面布局、交互、模板和构建归 `narration-implementation.md`。独立 HTML 样例展示通用结构与状态，实际课页只作实例，不把某章段数、内容或临时状态固化为通用规则。


## 新环境的起步与质量校准

第一次给另一位讲师、另一台电脑或没有历史上下文的会话使用时，先检查以下条件。复用现有备课记录，不另建课程结构。

| 条件 | 实际要拿到什么 | 缺失时怎样处理 |
| --- | --- | --- |
| 内容依据 | 本课目标、受众基础、已定范围、事实材料与取舍 | 缺少会改变结构的输入，先问最少的关键问题；其余工作继续 |
| 质量参照 | 能打开的具体页面、全部推进状态、对应口播及设计说明 | 使用导出包 `assets/course-reference/guide.html`；没有则找本项目可用成品，不能只凭“简洁、好看”定标准 |
| 制作底子 | 字体、样式、可编辑图示、输出格式与预览方式 | 沿用可用实现；HTML 示例不等于 PowerPoint 模板，交付格式不同先核对可保留的关系与推进 |
| 验收能力 | 能实际渲染、截图、逐步推进、打开材料并对照口播 | 工具不足时完成可检查部分，明确未检查范围；不把阅读代码当作看过画面 |
| 版本 | 方法、规范、样例来自哪一批文件 | 导出包检查 manifest.json；本仓库检查当前文件，不能只凭提交号判断未提交内容是否同步 |

**先做一个代表性片段，再铺开整节。** 在本课已确认范围内，选能暴露主要难点的连续片段，例如原话与材料对应、两种方案比较、流程随问题展开。通常两三页已经足够，但不规定每课页数。先按当前阶段做出页面草图、推进和讲述要点，已有口播直接复用；进入逐字稿阶段后再展开口播，按 [PPT 视觉、信息逻辑与技术检查](ppt-review.md)核对；发现共性问题先改这一组，避免整节复制同一缺陷。已有授权允许继续制作时，作者自查后继续，不新增一轮形式审批；讲师尚未审阅的状态如实保留。

记录要具体：参考页哪一步的什么关系被迁移到本课、自己页面哪些对象与之对应、实际截图发现什么、修改后怎样复验。不要以“沿用手绘风”“符合规范”“无溢出”代替判断。样例的配色、数字和页数不直接决定新课内容。

交接任务可以这样写，括号内容换成本课真实信息：

> 使用 course-prep。受众与学习目标见（大纲），本轮范围为（小节），已定内容见（源文件），证据见（材料）。先实际打开包内样例及对应口播，说明本课可借鉴的表达关系；选择一个连续片段做成可预览页面和口播，逐步截图、对照并修正，再继续完成已授权的小节。缺少影响结论的材料时指出具体缺口。交付可编辑源、成品入口、四层检查证据和未检查项。

导出包的 `assets/course-reference/` 是制作参照，不是完整课件工程。它保留 [PPT 样例清单](ppt-examples.json) 中页面的原有画面、完整步骤及配套口播，附逐步观察、历史误做和迁移说明。无限画板所需的一张历史公开网页截图经逐项查看后随包附带，保留出处和文件指纹；不递归复制其他私有材料，不包含完整产品运行或本仓库的 `make check` 环境。自带字体是课程子集，新内容仍须查缺字。检查工具、字体覆盖和课程事实要在目标项目重新核对。

分享失败的检查顺序：先对照实际文件与版本，再检查能否渲染样例和运行检查，最后对照新成品的内容、关系与讲述。模型、工具权限与任务输入也可能影响结果，但没有同条件成品对照前，不把它们写成已证实的原因。

## 按产物协调工作

整体路线与共用判断由 [SKILL.md](../SKILL.md#先确定任务与阶段)维护，各阶段完成条件在对应方法落实；上面的阶段表用于交接定位。这里处理多产物之间的继承、调整与协作。

从 Discussion 推进时，把主题展开为待讲清的关系或判断，再预看原文、对象与记录；对影响讲法的未知项做最小预跑。根据观察修订选材与解释，沿实际顺序走查后再完善口播。已有材料足够或只是局部调整时，复用有效设计和原稿，不重跑整套准备。

上游目标、范围、事实依据、关键递进与讲师要求作为约束，具体呈现继续用实际材料检验。发现更好的表达时说明理由与影响，在授权范围内回写；涉及上述约束变化时先对齐。展示方便的点击顺序与教学递进分别判断，不能笼统任意调序。

同步针对目标、范围与关键教学决定的一致，不要求表格、文字或步骤逐项复制。仅修改一方时列出对另一方的实际影响，授权包含时再维护；没有影响就不为同步重写。材料缺口阻塞的片段保留待处理，其余不受影响的部分继续。

### 阶段三制作与交接

阶段三接收已具备制作条件的讲述线、PPT 逐页安排与主讲路线、已定输入及可用证据。制作前按[讲述设计完成标准](narration-html.md#怎样判断可读)核对本轮范围。比较对象、解释依据或关键切换仍不明确时，先补对应讲述设计；任务条件、材料用途或结论改变时回到 Discussion。沿用可用成品和讲师修改。

以下方法是阶段三及后续修改共用的制作规范。3a 通过这里取得逐段组织、两种视图、画面与口播对应、Prompt 展示、样式和检查方法，只另维护反馈与接续流程。已有讲述页在内容深化时按[渐进迁移](narration-implementation.md#随内容深化逐段迁移)替换当前环节，允许新旧结构并存。

按实际产物进入以下方法，制作时用成品反查设计。视觉、文案或交互调整保留关键教学递进，影响画面安排时在同一讲述线回写。

| 制作对象 | 执行与自查的唯一位置 | 交接时应具备的成果 |
| --- | --- | --- |

涉及演示工具时，使用录制环境实际安装的版本和日常启动命令核对。检查工作目录、输入材料、服务入口、链接出现时机及必要的等待状态。演示包含实时更新或多轮交互时，实际验证更新及后续一轮的发送和继续操作；按已定异常安排验证所需恢复方式。已有同版本、同入口的有效检查可复用，依赖或启动方式变化后复查受影响行为。具体命令与版本保存在本课现有准备位置。

阶段三完成意味着本轮范围的实际画面、口播、材料和操作入口已实现，并通过对应制作自查，调整已回写讲述线。交付可打开入口、可编辑源、实际检查依据及遗留项，明确哪些片段可进入[阶段 3a 逐段协作改稿](spoken-script.md#逐段协作改稿)。讲师完成本轮反馈后，说明哪些片段已共同审阅。阶段四在当前版本上综合核对真实录制顺序、全段解释和前后承接，并处理修正后的复验。局部制作自查与整节综合核对分别报告，已有有效结果可以引用。

## 和讲师沟通

- 使用当前课程可见的章、节、部分编号与标题定位，例如“第 N 章 N.1.1”；页号、步骤号和试跑编号另行说明，不把历史课程的命名当作通用禁令。
- 改了讲述顺序或讲法后，先自己从头到尾顺一遍。回复给出完整的讲述线（每一段讲什么、怎么接到下一段），再说一句改了哪里，不只列改动。
- 先查清再下结论：说现状前查本课当前内容源；讲师提到前几课的工具或说法，先到对应课件里查，查不到就问，不猜。2026-10-24 的两个例子：说“workflow 版没有循环”，其实 P3 第 4 步写着“校验不过，带着错误回到模型重写一次”；“第 2 课的 Context Tab”其实是讲上下文工程时用的 claude-tap 面板。
- **改动范围以讲师这一次说的为准**：讲师让做 PPT 时只改 PPT 条目和页面，不改讨论板上“讲什么”“讲述”的文字；讲述需要配合改，先单独提出，讲师明确同意再动（2026-10-24：第 7 课第 1 节的“讲什么”被整节改写，讲师要求撤回，P1 恢复到提交 53f2d7b 的版本）。别的会话按讲师授权改的具体数据（如评测题数），默认以最新的为准。
- 讲师给的是方向，不是逐条指令（“我给你的回答只是一个方向，我需要你自己深度思考”）。讲师说“想清楚了再来”时，先自己比较几种方案，只交一个推荐方案；定不下来，就列出可选方案和各自的取舍，不要边想边改讨论板。不同意时直接说，给理由和更好的做法；要讲师拍板的事放在最后，越短越好。
- 汇报准备好的素材，开头先给一张表：素材、做什么用、多大、状态、链接。核对过程不用讲，没准备好的写清还差什么。
- 几个会话并行时，按文件分工，提交前先同步。两个会话各做一版同一节时，讲述路线和素材只能成套选一版，再吸收另一版的个别做法，不逐页拼（第 2 课 2.2 两组重构的审查结论）。
- 时长不是备课阶段的重点，录播可以剪辑。不因为加了内容就提议挪时间。
- 没有试讲就不写教学效果已验证；没检查的如实标明。


讲师拍板的决定按该课现有记录保存依据与重开条件；未满足条件不主动重提。阶段状态回到该课记录，不写进通用方法。

## 交给其他窗口

交接沿用当前内容源和已有编号，给出本轮范围、当前阶段、有效设计与待改源、实际产物入口、材料及未完成项。只发一个 localhost 地址不足以跨机器复用；源码与文件路径随仓库交接，预览服务按当前环境启动。

从 Discussion 接续时，指向具体条目，并读取所属部分思路、小节目标与深度；章级分工影响取舍时再向上读取。当前教学决定、已选材料与输入、任务关系、证据限制和缺口应在对应源可找到；引用已有入口，不复制一份完整设计作为交接稿，也不因读取上游而获得编辑授权。已有材料足够时直接复用，未知项按其影响补充准备，不因换窗口或换阶段重跑全部实验。

跨阶段的约束与可调整安排按 [跨阶段继承与检验](../SKILL.md#跨阶段继承与检验)处理；变化写回其职责对应的内容源，受影响但未授权的产物列为待处理。实际运行、作者自查、技术检查、讲师审阅和试讲分别说明，不能把输入齐全视为已经验证。运行中的窗口须重新读取已更新的方法，不假设自动获得本次决定。

可复制以下说明，并补上本次课次与范围：

> 请读取 course-prep/SKILL.md，按当前任务选择对应 reference。当前范围为（章/节/部分），所处阶段为（阶段），有效设计、待改源文件、产物入口和材料分别为（路径及编号）。接续 Discussion 时一并读取对应部分思路和小节目标；已定输入、证据限制与缺口见（现有位置）。保留当前稿件与讲师修改；按本轮授权修正，并检查受影响的上下游。交付时说明已完成、已核验和未完成项。

## 已知的坑

- **独立分发要检查资源闭合（2026-11-09）**：只复制方法文件仍会留下规范与样例的仓库外链接。来源工作区曾用 `tools/export-course-prep.py` 导出（本仓库未包含该脚本），接收方应检查包内链接和字体，再从只服务导出目录的浏览器环境逐步播放。Markdown 代码块里的 `href/src` 是原项目用法示例，不应当成文档的活动资源；首轮导出因此误报 `parts.md`，已在导出器排除代码块，并把随包的零件链接重写到实际位置。其他未提供的历史材料明确标为仓库参考路径。
- **受限环境中的验证工具（2026-11-09）**：`uv` 缓存锁写入失败与本机 HTTP 端口无法绑定，都是权限问题，不等于包缺依赖或页面损坏。本次在获得相应执行权限后，`make setup`、Skill 格式校验和隔离浏览器检查成功；按环境的授权机制处理，不为通过检查更改课程内容或跳过浏览器。

- **维护 Skill 后运行格式校验（2026-11-06）**：`skill-creator/scripts/quick_validate.py` 依赖 PyYAML；本仓库默认 uv 环境未提供时，直接运行会报 `ModuleNotFoundError: yaml`。使用 `uv run --with pyyaml python <实际的quick_validate.py路径> <Skill目录>` 临时补齐依赖即可，无需修改课程项目依赖。该校验只检查 Skill 格式，读取入口与方法内容仍须分别核对。

以下保留原问题与成功做法，具体工具 API 和源文件使用时仍按当前环境核对；特定课次的共享脚本与讨论板编号问题查该课工具说明。

- **openai.com 文章用 WebFetch 打不开（403）**：改用调研资料库里已抓的原文，或找 developers.openai.com 上的对应文档；找不到就明说（2026-10-24 P1 的 “Codex harness” 出处）。
- **Anthropic 文章里的图**：原文 markdown 里是 `/_next/image?url=…` 的代理地址，外链时取 `url=` 参数解码后的 `https://www-cdn.anthropic.com/images/…png` 直接地址。小节锚点用页面里标题的 id（如 `#workflow-prompt-chaining`），先 `curl` 页面确认存在。
- **改了 `index.html` 或 `plan.json`，页面看起来没变**：浏览器缓存了旧文件，`location.reload()` 强制刷新后再判断。
- **CUA 连续报 `browser.user is unavailable`，但标签页仍在**：2026-11-03 复用连接和按 ID 重绑都失败后，重置 `cua_repl`，再以同一 IAB 标签页 ID 绑定，读取和刷新恢复。重置只清理工具变量，不关闭标签页；不要把这个连接错误误判为本地服务停了，也不要转去操作被工具禁止访问的桌面应用。
- **本机没有 uv，`make check` 跑不起来**：按 `Makefile` 开头的注释装 uv。
- **本地预览服务（8841）停了，截图连不上**：用 `sh tools/edit-courseware.sh` 重启；后台使用 `sh tools/edit-courseware.sh --background 8841`；前台可用 `make serve PORT=8841`，均须确认编辑接口就绪（2026-10-27）。
- **heredoc 里写含中文弯引号的 Python 报 Non-UTF-8**：脚本先用 Write 写成文件，再 `python3 -I 文件` 运行。文件里有含中文的长 f-string 时，系统的 Python 3.9 照样报 Non-UTF-8（文件本身是合法的 UTF-8），改用 `uv run --no-project python -I 文件`（2026-10-29）。

### 通用知识的归属与分享（2026-11-06 讲师纠正）

通用 Skill 会由其他课的讲师使用，因此通用知识必须随 course-prep 文件夹保存，不能反向依赖第 7–9 课 Skill 的参考文件。专属 Skill 引用通用 Skill；分享时传整个目录。原路径只可保留迁移提示，不再追加知识。
