# 资料、证据与演示预跑

按编号读取完整正文：从仓库根目录运行 `python3 tools/read-editorial-rules.py ED-编号 ...`；合并去重，已读且未变的不重读，缺号或截断时补取并核对结束标记。 核对运行材料与结论读 ED-020；选材影响内容范围读 ED-006、ED-021；接入画面证据补 ED-008，来源标注补 ED-018，状态交付补 ED-015。

从 Discussion 的方向建立备课上下文，或查找资料、核对事实、准备快照与运行演示时读本文。这里维护准备方式、预跑与取证；准备结果返回发起任务的产物；服务 Discussion 时按其知识、选材与四列表规则整理，服务讲述页时才接入具体讲法。局部改稿只补影响当前解释的缺口。

## 产物与保存位置

提前准备的任务、条件和缺口写入 Discussion；可用材料按当前授权接到 Discussion 的选材位置或讲述线的对应步骤。沿用本课材料目录与必要索引，保存来源、版本、实际输入输出和可定位入口。完整日志、第三方全文及大文件遵守公开/私有边界。日常自查与构建结果在本轮对话交付，不另建制作日志。

## 执行路径

**输入**：当前学习目标、Discussion 的相关条目及所属部分思路与小节深度、已有材料和不确定问题。沿已定材料登记接续版本、实际请求、附件、上下文及任务起点；明确独立或接续关系、现场或预存身份。登记与原文保持一处维护，讲述线引用所需片段。

1. **把主题变成准备问题。** 写清学员需要理解的关系或判断，以及当前还不知道什么。例如“讲 Reference”需要查清它补充哪种知识、怎样被当前任务使用；先形成候选解释，不预定运行结论。
2. **预看相关上下文。** 先查已有材料，再阅读原文及必要引用，体验实际对象，查看请求、关键过程和结果。先理解来源本来的任务与条件，再决定哪些片段适合教学；不从一张截图或摘要推断完整过程。
3. **按缺口决定是否预跑。** 已有证据足够时直接取材；关键行为未知、环境变化或需现场操作时，按[预跑步骤](#预跑步骤)执行能回答问题的最小任务。不同讲述内容的准备方式见下表，可以组合使用。
4. **将观察转成教学决定。** 明确选用哪些事实、它们支持什么认识、需要补哪层解释，哪些细节应舍弃。若结果不支持候选讲法，修订结论、调整任务或补测；材料引出的专业知识超出本节目标时收回必要范围。
5. **返回原任务。** 为 Discussion 准备时，返回知识安排、选材及任务取段；为讲述页准备时，接入具体画面、解释与切换。准备完成不自动推进阶段或加载另一产物的方法。缺口按其影响记录：改变解释或结论的缺口指出受影响环节，尚未取得证据的结果不写成已验证；不影响讲法的制作细节可以后补。只处理本轮授权的内容源，其他影响交接给对应产物。

### 按讲述内容选择准备方式

| 讲述内容 | 建议动作 | 准备完成的判断 |
| --- | --- | --- |
| 概念、结构与系统小结 | 读清定义、组成、边界与使用关系；回看实例；画关系草图并用实例检验 | 能解释对象之间怎样联系、图帮助解决什么问题；不能只有术语或文件分类 |
| 原文、规范或方法解读 | 预读相关章节及必要引用；选代表性片段，核对条件与例外；实际定位原页 | 知道指哪句话、解释什么作用、怎样连接当前例子，无需临场通读 |
| 通过任务讲知识 | 体验对象，查看请求和完整记录；对知识是否落实的疑问做最小预跑；逐项对应事实与知识 | 能指出哪项事实支持哪条认识及其中理由；执行步骤不直接充当教学段落 |
| 操作演示或跟做 | 从预定起点操作一次；检查环境、输入、等待、结果与恢复方式；保留必要状态 | 能按提示到达结果，知道等待期间讲什么、现场结果变化时怎样继续 |
| 比较、排错或反例 | 确定比较问题与共同条件；检查版本或完整失败记录；必要时控制变量补测 | 能区分观察与原因推断，不把不同起点造成的差异当作方法效果 |

这些类型可以组合，完成条件不要求另填表。比如讲 Reference，既需原文阅读，也可能需任务预跑；准备结果共同服务一条解释。完整推导见 [Reference 案例](narration-cases.md#reference从预看到任务讲法)。

## 预跑步骤

1. **明确要解决的不确定性。** 跑前列出影响讲法的问题，以及可能需要的材料。例如是否读取清单、通用条目被展开成什么检查、哪些画面能支持解释。
2. **确定最小范围与真实输入。** 固定起点、版本和必要条件；需要比较时说明变化项。Prompt 写真实需求及本课已定约束，不夹带事后实现答案；既有记录能回答的问题不重复运行。
3. **执行并保留解释所需的上下文。** 保存请求、回复、关键读取和操作、实际输出、异常与截图；完整记录与公开节选分开。必要时保留阶段快照供后续任务起跑。
4. **核对结果与证据范围。** 区分实际发生、原因推断和教学示意。否定“没有做某事”前检查完整记录及工具通道；发现越界先检查请求约束。需要补测就针对缺口，不为凑预期结果反复运行。
5. **回到教学问题作取舍。** 写清这次观察改变了什么：选哪段、讲多深、哪层关系需同屏、哪些结论要收窄。无新决定时检查是否跑了与教学问题无关的任务，不以增加运行次数替代思考。

**停止与继续**：关键问题有可定位证据即可返回原任务；不可复现或不能访问的部分保留缺口。现场演示的结果可能变化时准备观察与判断方法、必要的历史回放入口，不把预跑成功写成现场必然成功。一次运行不能支持稳定效果或普遍机制的结论。

下面保留不同材料的具体要求；知识、画面与切换的组织不在此重复维护。

## 参考资料

- **课程内容里不提吴恩达**：讲述、PPT、打开给学员看的资料都不提他，也不链接他的课；同样的思想用 Anthropic 等其他来源或自己的话讲。这里和 `DECISIONS.md` 里引他的课当依据可以，进课程不行（2026-10-30 讲师重申：之前已经说过一次，第 7 课第 4 节又写进去了）。

- **网站讲解素材默认保留官方原页（2026-11-03 讲师确认）**：后续同类博客、文档按第三节 `materials/workflow-patterns.html` 的方式准备：保留官方原文、原图与版式，只叠加按讲述顺序定位的“下一步”按钮。逐字稿单独维护，不把课程解释、适用任务或产品联系另做版面塞进原页。需要本地快照时明确标识，第三方全文只存私有资料库，公开仓库只保留入口、导航与重建方法。

- **资料融进讲述，为讲解服务**：讲到“什么是 Harness”时打开那篇文章看那张图，不要把“Anthropic 怎么说、OpenAI 怎么说”单独拎成一个小点，也不要讲完自己的再拿别人的证据重讲一遍。一个知识点只挑最合适的一份资料（2026-10-23 P1 改了五六轮才定下来）。
- 每句“某某文章说……”都要有能打开的原文。找不到原文的说法，改成能核实的来源，或者在汇报里明说找不到。
- 找新资料先查本项目已有材料索引；来源工作区曾用 `p2h-research-library`，当前环境可用时才使用，不将其作为 Skill 的必需依赖。核对原文而非只看摘要；第三方完整内容只放私有目录。
- 引用原文每处不超过 15 个词，其余用自己的话转述。
- 正式课件里的第三方图按讲透问题选材，截图读不清就重画，原文链接显示在画面最下一行。外部佐证在定知识主干时就选，不等 PPT 做完再找图塞进去（第 2 课 C2-63）。来源链接实现查 `docs/production/lesson-authoring-playbook.md`；第三方内容在 `THIRD_PARTY_NOTICES.md` 声明许可，不发布的宣传截图放 `promo/`。历史引用的 `external-sources` 文档或 skill 使用前先确认存在，缺失不能当成已读依据。

## 素材：数据、评测集、事实数字

- **日志快照保留日志查看器原页（2026-11-06 讲师明确）**：需要展示日志系统时，用其原生查看器加载完整原日志并制作本地快照；不把日志摘录、归类或总结后重排的HTML当成原页。定位按钮用独立、可收起的浮层，只调用原页导航、展开和滚动，不改变原页面结构、布局和内容。保存日志与查看器版本、来源指纹；完整记录仍遵守私有材料边界。产品体验页与日志查看器是不同材料，按讲师指定选择。

- **产品快照保留产品体验页（2026-11-03 讲师纠正）**：讲师要查看问题、回答和运行链路时，在原产品 UI 上增加课程案例选择与具体步骤／输入输出定位，载入对应运行的原记录，绑定当时的产品版本或明确可核对的运行来源。不得把自己整理的“输入—输出—SQL”报告改叫产品快照。产品具体实现与版本维护按本课记录定位。局部实验按实际运行范围展示，缺少的完整产品阶段不补造；模型思考只展示接口实际保存的原文。完整私有记录与公开核对摘录分开保存。

- 画面和口播里用到的数字都由脚本从快照算出，每项附可复查的计算过程；数据库统计附 SQL（例如 `courseware/ch07/materials/opening/facts.json` 和 `make_opening_facts.py`）。快照换了就重跑脚本，不手抄数字。
- 素材目录的 README 用表格写：素材、做什么用、多大、状态、链接。大文件和第三方数据不进 git，写清怎样重建。

## 运行材料的使用边界

- 每阶段快照只携带后续需要的代码、数据和任务说明，不把前课完整过程文件无差别带入新任务，避免引出无关支线。
- 给讲师核对时提供 Prompt 和回复原文及定位，理解与判断另写；公开或上屏版本保留支持结论的必要上下文，不因节选改变含义。
- 真实运行、回放、示意图与人工植入的故障明确区分；快进等待说明省略时长。

## 官方页面快照的历史排障例

来源工作区静态化官方页面时，曾遇到初始 `visibility:hidden` 导致首屏标题和元信息为空白。若使用经授权的私有原页快照，应检查动画完成后的实际可见状态并标明快照身份；此记录不要求复制官方全文到公开仓库。
