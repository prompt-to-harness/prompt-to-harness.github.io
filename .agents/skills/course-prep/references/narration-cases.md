# 从准备到讲法：三个真实案例

当 Discussion 已确定方向，却还不清楚怎样准备、怎样将知识与实例对应时，按问题选读。方法分别由 [准备与预跑](materials.md#执行路径)和[讲述设计](narration-html.md#执行路径)维护；本文只展示判断过程，不另设流程。

三个案例来自第三章 3.2.3 的备课迭代。讲师认可调整后的思路，并反馈沿该思路写逐字稿效果很好；这不等于学员学习效果已经试讲验证。完整运行与截图按真实来源定位，不把作者解释冒充模型原话。

## Reference：从预看到任务讲法

### Discussion 的方向与准备问题

讨论稿确定讲 Reference 怎样补充正文。仅知道“正文可以链接一份清单”，还不足以安排讲述。备课需要查清：清单具体补什么；当前任务为什么需要它；通用条目怎样变成实际动作；用什么证据确认查阅与执行。

本例选游戏通关后的恢复检查，是因为它能呈现从通用条目到具体检查的转换。修复提前通关是本轮验收的前提，不展开成另一段调试教学。

### 预看与预跑获得的上下文

先看 `game-playtest` 正文的 References，沿 Full checklist 定位试玩清单，再看暂停、失败、恢复相关条目。通用条目没有为翻牌游戏规定所有操作，因而需要结合游戏理解“恢复”具体意味着什么。

实际预跑从有提前通关缺陷的早期版本独立副本开始。请求明确要求复现、修复、复验，并沿引用查阅清单、选择恢复相关检查。备课者查看了本轮请求、正文与清单的读取、修后浏览器操作及输出：三对时能继续、六对才通关；重开后计数归零、通关横幅消失、牌面复位；随后再次翻牌。

这些记录支持“本轮明确要求查阅后，实际读取并执行了恢复检查”，不能推出所有调用都会自动打开清单。读取发生在运行开头，修复与复验在后；教学解释可以先读原文再看记录，但不能改述事件先后。 [请求与运行来源](../../../../courseware/ch03/materials/playtest-old5-20261111/README.md#run-b) · [读取](../../../../courseware/ch03/materials/playtest-old5-20261111/README.md#run-b-read) · [实际复验](../../../../courseware/ch03/materials/playtest-old5-20261111/README.md#run-b-verify)

### 观察怎样改变教学安排

| 观察到的事实 | 对讲法的影响 |
| --- | --- |
| 正文提供引用，清单提供通用恢复条目 | 先解释共同流程与配套细则的分工，再解释本次怎样选择条目 |
| 重开后既检查状态，又再次翻牌 | 将具体预期分成“状态恢复”和“可以继续操作”；这层归纳有实际证据支撑 |
| 读取记录与操作结果分别存在 | 分别核对取得了什么依据、执行了什么检查，不用“读过”代替“做过” |
| 关键关系分散在请求、原文与结果中 | 使用一页知识对应 PPT，将通用条目、当前动作与两层预期放在一起 |

这里的教学主线是“通用条目怎样落成当前对象的检查”。任务中其他修改细节只保留必要前提。PPT 的作用是呈现跨材料的关系，不是复刻日志。

### 最终讲述顺序与画面职责

| 顺序 | 画面 | 此时解释什么、为什么切换 |
| --- | --- | --- |
| 1 | 任务请求 | 交代修复及新增恢复检查，带出细则从哪里取得的问题 |
| 2 | 对应页第一步 | 建立正文共同流程、引用入口与配套细则的关系；随后查原文依据 |
| 3 | 正文引用 → 清单条目 | 沿实际入口连续阅读，确认恢复条目；不在这里提前复述运行结果 |
| 4 | 返回同页第二步 | 将条目对应到通关后重开，解释状态恢复与操作恢复各需要观察什么 |
| 5 | 读取记录 → 复验输出 | 确认实际查阅；再核对状态重置与再次翻牌。说明事实，不再完整重讲前一步推导 |
| 6 | 返回同页第三步 | 把结果放回两层预期，归纳使用 Reference 的读法，承接专项指导 |

本例共一页、三个展开状态，原文与实录是独立材料画面。返回时新增的是关系的具体化或证据核对，不要求每个操作后都回 PPT。 [讲述线](../../../../courseware/ch03/lessons/02-rules/speaker.html#plan323-3) · [对应 PPT](../../../../courseware/ch03/lessons/02-rules/index.html?mode=slides&step=0#p07t2) · [讲述线源](../../../../courseware/ch03/lessons/02-rules/screen-plan.json)

### 顺读发现的问题与修正

初版原文段重复解释了首步 PPT 的分工；实录段已经归纳两层预期，末步 PPT 又完整讲一次。修订后，原文只指认入口和条目，第二步 PPT 完成具体化，实录交代观察，末步完成归纳。每次返回写清页和状态。

后一次走查中，本地材料可达，但 GitHub 原文在该环境加载超时，不能声称原文窗口切换已实测通过。知识和事实的核对、网页可达性、讲师写稿反馈与试讲结果是不同验证，分别报告。

### 可迁移的判断与本例边界

换成其他检查清单，仍可先看条目的适用情形，再结合当前对象确定动作、预期及证据。已有记录能支持时不必新跑；原文旁注或材料对照能讲清时不必制作同款 PPT。恢复的两层预期、独立副本、一页三态都属于本例，不能要求所有课程照搬。

## 全局小结：从文件分类转向知识结构

**原先的停留点**：按文件用途分类、比较两份正文、复述几轮读取，事实虽齐，却难以形成 Skill 的整体认识。

**关键转折**：讲师要求全局总结后，重新梳理入口与正文、配套资料／脚本／素材的用途、边界外另一份 Skill 的引用。先用关系草图核对包含、分工与引用，再制作逐步展开的全局图；后续复用同一图解释识别、核心指导与按需取用。

**为什么有效**：已有实例成为关系的依据，小结开始回答知识怎样组织与使用。它需要的是抽象关系，并非新增一次试玩。迁移时先确定要建立的整体认识，再决定用结构图、对照或其他表达，不把“所有小结都画文件树”当作规则。

## 窄屏检查：让实际观察修正判断维度

**准备与发现**：任务关注信息区与牌阵。预看本轮截图及测量时发现，窄屏滚到牌阵底部后，重叠面积为零，但计数已不在视口。两个结果可以同时成立。

**关键转折**：将“界面是否正常”展开为两个问题：信息区是否遮挡牌阵，玩家操作底部牌时是否仍能看到计数。前端专项指导提供选取判断维度的依据，具体截图和测量支持本轮结论；共同试玩流程负责操作、取证和报告。

**对选材的影响**：保留窄屏完整视口与对应输出；桌面游戏区截图只用于位置关系，不当作单视口可见性证明。本轮来自未修复的独立副本，不混用上一轮修复结果。讲到两个判断的区别即可，不扩成界面改造课。

迁移时，检查同一“正常”结论是否包含不同条件下的多个判断，寻找各自证据；不能要求每个任务恰好拆成两个问题，也不能把一次观察提升为普遍效果。
