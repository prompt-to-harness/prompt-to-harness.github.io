# PPT 信息组织与展示推进

按编号读取完整正文：从仓库根目录运行 `python3 tools/read-editorial-rules.py ED-编号 ...`；合并去重，已读且未变的不重读，缺号或截断时补取并核对结束标记。跨项目使用见 [PPT 入口的读取约定](ppt.md#编辑规则读取)。 设计或调整解释关系读 ED-002、ED-004、ED-007、ED-008、ED-019；只改屏幕文案读 ED-001、ED-012、ED-014。改变深度补 ED-006、ED-021，运行结论补 ED-020，来源补 ED-018，材料分工与教学同步补 ED-003、ED-017。

新制或实质修改内容、布局与展开时读取。本文决定信息取舍、关系含义和展示时机；具体形象、构图和强调同时参考[视觉方法](ppt-visual.md)。沿用上游已定的页数、逐页职责和关键教学递进，必要调整按授权处理，不重新承担 Discussion 或讲述设计的全部工作。

## 接住现有内容

读取本节有效设计、当前讲述线和已有页面，确认学生要理解或完成什么，以及本轮改动范围。课程仓库按 `docs/agents/sources-of-truth.md` 判断新旧依据；其他项目按其自己的内容源。

沿现有讲述顺序找到：PPT 的知识画面、原文阅读、真实项目、请求或运行结果，以及它们之间的打开、定位和返回动作。已有口播直接复用，保留讲师修改及编辑、评论坐标。尚无完整稿时按当前讲述设计制作，不为做 PPT 提前另写一套逐字稿；成稿后仍保留并维护对应设计。

逐段明确当前讲述对象及具体位置。材料窗口中的讲述归到材料位置，不能全部挂在打开它的 PPT 页下。实际需要打开的材料入口及目标锚点也要纳入制作范围，不能等页面做完再补链接。

如果缺少会改变讲法的事实、材料或画面关系，回到讲述设计处理。如果问题涉及目标、深度或部分职责，指出受影响的内容设计条目，再按任务授权同步。证据不足的片段保持待处理，不靠美化图示完成放行；其余不受影响部分可继续。 [讲述设计](narration-html.md#执行路径)

## 核对前后衔接

<a id="一先确定观众要通过画面完成什么判断"></a>
沿讲述线的逐页安排复核本组页面要说明的知识和各页职责。知识页保留可用于同类问题的概念、方法和依据。立题、过渡和回顾页按已定作用制作。遇到关键页面、主题或内容还没定清，回到讲述设计补齐再制作。

按以下问题安排整组内容：

- 学生已经知道什么，还缺哪项前提？后页是否依赖前页尚未解释的知识？
- 哪些内容属于核心知识、必要例子和依据，哪些属于旁支或拓展？每页是否有明确作用？
- 哪些关系必须共同可见？比较的双方、条件与动作、输入与结果，不应让学生只凭上一页的记忆拼接。
- 哪些解释在 PPT 完成，哪些直接在原文或真实材料中连续讲？切出前看什么，返回后形成什么判断？

制作时若发现需要分合页面或调整揭示来改善展示，说明理由与影响，核对各页仍承担已定讲解，在授权范围内同步讲述设计、总页数、逐页对应和切点。需要改变哪一段讲什么、用哪个画面讲时，先在同一讲述线完善设计；涉及上游目标、范围或关键结论时按入口原则与讲师对齐。只有 PPT 修改授权时，列出未覆盖的上游影响，不静默改写 Discussion。

原文、代码和日志能直接支持观察时，优先确定取景与定位，不在 PPT 中仿画一套界面。已有调研和真实案例优先使用；事实、示意与未知结果分别标明，不能补造运行结论。

## 内容与画面联合设计

从逐页安排取出本页已定的对象、依据和关系，把具体文案、信息组织和构图放在一起推敲：用内容关系选择表现形式，也用实际画面检验信息取舍、分组和阅读顺序。保留教学判断与必要证据，允许在授权范围内反复调整表达；不把“确定内容、选择构图、组织内容”拆成固定先后步骤。若只收到“展示三个差异”“介绍工作流程”，先回讲述设计明确要比较的对象与关系、哪些内容必须同时可见。

标题按本页的任务、知识、回顾或提问职责组织，例如点明一个判断或提出当前要解释的问题；不要求所有页面采用断言标题。

按当前内容检查必要信息：比较要有双方及共同维度；流程要有关键输入、动作与结果；条件指导要有条件及相应动作；归纳要让实例与归纳项的对应可见。概念需要必要的解释和例子，不能只剩术语。上述是选择依据，不要求每页全部包含。

**信息取舍与简约**：围绕本页主题缩短重复解释、移出旁支，保留解释所需的条件、关系和依据。内容多时可先区分主次、按需展开，确有不同职责再分页；内容少却看不懂时补足解释依据。删减文字与调整视觉表达分别判断：安装说明缩短后，步骤编号仍可能帮助定位；包含关系已用文字说明，外框仍可能帮助一眼辨认整体。准备删掉某个标记时，可先看它是否承担识别、分组、对应或强调的作用；功能仍有用时，保留或换一种更清楚的表达。简约的目标是减少理解负担。

## 让每次推进增加理解

每次按下一步，都能说出观众新看到了什么、新建立了哪条联系。可沿讲述观察哪里需要停下来辨认或比较，再决定逐步出现、局部强调还是保持静态。例如，讲连续操作时可保留步骤编号，只改变当前步骤的强调；比较前后结果时可让两端同时可见。步骤服务于解释，不为一句文案多造一个状态。

| 讲解需要 | 适合的推进 | 需要防止的断点 |
| --- | --- | --- |
| 比较差异 | 同屏保留，逐处高亮 | 只靠观众记住上一张图再比较 |
| 看架构随问题变化 | 同一对象连续增改，已有节点让位 | 换整张图后看不出新增了什么 |
| 理解层级或内部结构 | 从整体放大局部，保留来源线索，再回整体 | 放大后失去位置感 |
| 看长流程与真实材料 | 逐段聚焦，保持稳定的名称和定位 | 图、日志、口播各用一套叫法 |
| 观察因果 | 改一个条件，观察结果；明确其他条件 | 同时改多项却把变化归因于其中一项 |
| 收住一段 | 回到可读的关系全貌或结论画面 | 拉远成缩略图后还要求学员读细节 |

动画的内容和速度要让人准确感知；动画并不天然优于静态图。（方法来源见 [背景参考](ppt-background.md#方法来源与适用边界)：S8） 表格、示意图、截图、运行记录同时使用时，要帮观众建立对应，不能期待他们自动完成转换。（方法来源见 [背景参考](ppt-background.md#方法来源与适用边界)：S9）

## 白板与静态页的选择

**已定课程约定**。一层层展开且需要保留前面内容的位置与联系时用白板。架构随问题变化时用同一张图逐步增加内容。制作时按讲述线已定的关系和进入顺序实现。若呈现形式的变化会改变学员观察的对象或顺序，先回讲述设计同步。普通静态图按静态页制作（2026-10-26/27、2026-11-01 讲师纠正）。

- **白板**：内容占固定空间，讲到哪块画出哪块，讲过的主线留在原处；箭头引向下一块，镜头跟随移动；未讲内容不提前露出，最后回看整体关系，突出当前层。主线上的旧内容不靠缩小、隐藏来给新内容让位；收尾拉远是另一个明确步骤。
- **架构生长**：新增问题带来新增节点、分支或回线，已有框滑开让位，读者始终识别为同一个 workflow。几个问题叠加时保留叠加的效果；并行支路展开画两个，更多支路以省略号表示。
- **分支材料**：为了讲全真实情况临时进入的旁支，只在自己那一步出现，结束后收起；不必把所有旁支带进收尾全貌。第 2 节“每条数据各写一句”等是已有例子。
- **全屏**：白板在 PPT 中占一个框，右上角有全屏按钮；用于放大真实画布及其镜头，不把静态幻灯片放大称作白板；全屏中仍可上一步、下一步，Esc 能退出。
- **关系检查**：把几张独立 PPT 横铺，再平移镜头，只改变了容器。必须检查它们在空间中有没有必要的联系，以及镜头是否帮助观众理解这些联系。

可借漫画叙事检查图文分工、画面之间的连续性和时间表达；这是制作上的借鉴，不宣称漫画方法已在本课验证。（方法来源见 [背景参考](ppt-background.md#方法来源与适用边界)：S10） 交互只在能观察条件、检验假设或理解变化时使用，不因 HTML 能做就增加控件；录播由讲师操作即可，课程不依赖学员自行探索。（方法来源见 [背景参考](ppt-background.md#方法来源与适用边界)：S11）

本环节形成可用于制作的具体内容、关系与展示状态，保留在既有源中。初步布局继续按[视觉方法](ppt-visual.md)完善，实际成品按[信息逻辑检查](ppt-review.md#信息逻辑检查)复看；不以写完文字或列出框名作为画面制作完成。
