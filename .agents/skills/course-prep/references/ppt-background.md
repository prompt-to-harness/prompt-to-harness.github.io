## 历史制作案例与排障记录

以下为来源工作区的历史问题与修复依据，其中“已修复”、成绩、文件路径、环境与命令不代表本仓库当前状态。只复用适合当前任务的判断，实际源与工具按本课核对；通用方法仍以上文为准。

### 讲述段落与画面不一一对应（2026-11-02）

第三节首次把六段讲述做成六页十六次推进，讲师指出太碎；随后压成三张静态全图，又把需求、职责、交接与异常一次堆出，讲师再次指出在两个极端之间摇摆。两次都没有先确定合适的抽象层次，不能把第二次处理登记成成功方法。

参照第 1 节 p01、p02 和第 2 节 pfind、pdata：先让当前判断需要的对象共同可见，再在同一对象上增加关系。比较的两端一起出现；新工作要和需要它的依据一起出现；同一架构讲职责、连接、交接时保留主线，切换当前所需的标注。**一页承载一个完整的设计判断，不按一句话、一段口播或全部知识来定粒度。** 初步架构先画职责与关键连接，一格可以包含多次调用；只有解释交接确实需要时才展开一个例子，不把实现细节塞进全图。口头解释原因、取舍与转场；原文、SPEC 与真实运行使用各自材料。

页数和步骤数是这些判断的结果，不以增减它们证明改好了。检查时把本节与已认可的具体页面逐步对照，复述每步新增的关系，确认同屏保留的内容仍与当前判断有关。当前重做仍须讲师审阅与试讲，机器通过不代表讲法已经被认可。

- **截图等待目标场景（2026-11-02）**：播放器用 section.hidden 控制场景，不添加 .scene.is-active。初始页可等 .scene[data-index="0"] 可见；深链等具体 #页id 可见，再等 document.fonts.ready 并按真实按键推进、等待约三秒后截图。

- **截图联系表缺 Pillow（2026-11-02）**：仓库 uv 环境不默认带 PIL。需要拼图检查全部状态时，用 `uv run --with pillow python <联系表脚本>` 临时提供依赖，不为截图改项目依赖。

### 原话对应与需求白板的本轮修正（2026-11-02）

- 参照已有页时比较信息关系，不只借颜色。第二节 pfind 直接把原话条件连到真实字段；第三节用整句横幅、重复的 SO 标签和另一排流程框，多造了一层阅读。改为原话与字段直接对应，口播解释取值与判断的分工。
- 需求改变已有架构时，先保留此前已经推出的工作，避免重置成更早的骨架再“发现”同一步。新需求可能复用工作、扩充职责或新增步骤；据实际需要选择，不强制一条需求对应一个新模块。
- **全屏后的节点移动**：canvas.js 会把画布从 `.scene` 移到全屏层；flow.js 若每次只在 `.scene` 内查节点，全屏推进就会失去移动目标。现在初始化时保留场景与节点引用；第三节专项检查覆盖进入全屏后新增检查、回答让位、后退及 Esc。阅读模式克隆每帧时同时回放 `data-tf` 并移除控制属性，避免静态帧被播放器的末步状态覆盖。
- **镜头边缘检查**：`data-cams` 等比容纳目标范围，受视口比例影响，边缘可能额外露出目标范围外的物体。不能只根据设定的坐标推断画面；本轮首轮截图发现半截节点及走图时残留的上方标注，改为完整容纳架构，并在临时交接镜头收起需求标注，回看时恢复。

以上为制作与排障记录；讲师尚未审阅本轮白板，不据此宣称教学效果已验证。

### 镜头必须检查运动过程（2026-11-02）

讲师指出第三节白板仍像跳页。复查发现 `.dw.x-ready [data-on]` 的 opacity 规则写在同优先级的镜头／节点规则之后，而移动组也带 data-on，因此覆盖了 transform 过渡。运动探针实际测到 transition 只有 opacity、变位时没有运行中的 transform 动画。修复为先写显隐、再写镜头和节点的复合过渡；专项检查按下一步后在 120 ms 采样，要求中间矩阵不同于起点和终点、存在活动的 transform 过渡。前一轮全屏终点与截图检查不能证明移动连续，应纠正此前过度概括的判断。

空间上让需要展开的细节有固定位置，以连线说明它从哪个对象展开，镜头跟着连线进入和返回；不要用擦除整块内容配合缩放模拟白板。具体讲法仍须讲师审阅。

### 旧页定位要检查同页跳转（2026-11-02）

第三节将旧 p03 定位到新 ppatterns 后，专项检查发现连续打开 pcheck、pbuild 会留在上一页：路径和查询参数相同时，浏览器只触发 hashchange，不重新执行页面初始化脚本。旧编号映射必须在首次加载和 hashchange 时都执行，并先于播放器处理；检查同时断言目标页可见、真实锚点和步骤，不能只看 URL 的 step。第三节 index.html 已补该处理，check-canvas.py 覆盖三个旧入口。最初把失败归因于 step=0 的省略，补查实际 URL 后确认是上述同文档导航问题。

### 交接的出现时机与单步焦点（2026-11-02）

讲师指出 P3-1 的箭头先于接收模块出现，P3-2 同时放流程、底部问句和侧栏结果，听者不知道先看哪里。接收模块出现时，再显示指向它的箭头及交接内容。屏幕上的解释小字不能代替信息设计：参照 7.2 pfind，用颜色把原话中的条件直接对到字段或查询条件；不要只高亮当前讨论的型号而漏掉摄像头和帧率。原因、疑问和取舍由口述展开，需要比较时才保留比较依据，不能因为之前讲过就把所有说明持续堆在画面上。本轮具体呈现仍待讲师审阅。

### 完整关系不能靠删内容换清爽（2026-11-03）

讲师指出上一轮 P3-2 移除后两步输出，又让“补型号写法”只剩框名：画面虽简化，但观众仍不知道这一步具体产生什么。参照 7.1 p02 的输入—动作—真实结果闭环、7.2 pdata 第七步 `on(6,6)` 的局部批注讲完收起、pfind 的原话—字段—结果对应，先确定每一步需要观众看见的对象和交接，再设计焦点。主链路及输出保留，讲当前方案才出现的弧线批注指向具体值；不变内容降低显著度，相关变化突出。不是每页加装饰箭头，也不是把“少放内容”理解成删除输出。教学假设的具体值可用于设计推演，但须就地标明，计算出的 SQL 结果不能称为模型实录。

- **中文临时编辑脚本使用项目 Python（2026-11-03）**：本机系统 Python 3.9.6 执行含长中文字符串的编辑脚本时报 Non-UTF-8；逐字节 UTF-8 解码及 compile(bytes) 均通过，同文件改用 `uv run python`（项目 Python 3.12.15）执行成功。没有确定系统解释器内部原因，不把它误记成文件已损坏；此类脚本先用项目解释器，避免仅凭报错改写内容编码。

### 产品案例用真实模型产物（2026-11-03 讲师纠正）

P3-2 虽标了“假设补出”，并对该假设词组实际执行 SQL，讲师仍明确拒绝：要真实产品测试，可以只测部分。涉及模型输出的课程案例，先做对应真实调用并留下输入、输出、执行结果；缺材料就按最小范围补测，不能以假设词组加真实 SQL 顶替。局部试验要说明复用哪些产品组件、提示是否新写、哪些条件固定，不能称为历史版本或完整产品的成绩。遇到 0 份、漏项或超时，照实记录与调整讲法，不为符合预设曲线重跑或改数字。真实案例可以用简化图，但图中的关键词与数量必须能定位回记录。

- **同材料多锚点检查（2026-11-03）**：Playwright 连续 goto 同一 HTML 的不同 hash 时返回 None，因为没有新 HTTP 请求。先判断是否同文档导航，确认前后路径相同并检查目标锚点可见；有响应的加载仍检查 HTTP 200。不能把 None 当材料加载失败，也不能直接跳过定位检查。
- **兼容入口的实际跳转（2026-11-06）**：产品回放等旧入口可能按源文件重定向，并在hash中补上事件和视图。实际点击检查应核对入口声明的目标、案例ID和最终可见内容，再断言原PPT未变；不能只要求新窗口最终URL逐字等于链接。7.4沿用的D14入口跳到固定的product-replay-20261103，仍须检查case=d14-after及D14内容。

### 提词起点不能暗含语义判断（2026-11-03）

讲“直接提取关键词”时，画面中的词必须已经出现在原问题里。P3-2 原问题写“SO 系列”，第一步却查 so_follower，等于先替模型做了本来要教的对齐。按讲师意见将原问题明确写出 so_follower，再由原词查询引出系列其他写法。修改问题后，依赖该问题的模型输出与 SQL 结果必须重新实测；旧记录保留但不能换上新问题标题。此次新实测为 5／5／9，最后仍有漏项，按实测调整讲法，不为预设结果改输出。

- **SVG 动态属性中的 JSON 引号（2026-11-03）**：给 data-tf 写坐标数组时，不在 Python 单引号长字符串中手工嵌套引号；用 json.dumps 生成数组、外层属性单引号并拼接。先运行构建检查 Python 语法，再启动浏览器。
- **回放与显隐专项检查（同日）**：SVG opacity 隐藏的节点仍可能出现在 inner_text 中，断言当前画面时过滤 .x-off 祖先，并实际截图；历史 A02 UI 没有新回放的 #course-case，按具体回放类型检查真实控件，不能用文件名都含 product-replay 便套同一 DOM。

### 连续步骤保留稳定组件（2026-11-03 讲师纠正）

同一组件在后一步仍承担同一工作，位置、尺寸和名称尽量不变；新输入、批注或结果围绕它增加，不为了展示另一块内容而搬动已有节点。确有空间或关系变化才移动，并让观众看见连续运动。PPT 02 的生成型号写法节点由第三至第五步固定，真实候选作为新增输入放在下方。箭头要有完整可读的路径，先留足组件间距，再画弧线；不能在窄缝里塞回弯和箭头尖。逐步截图同时检查路径本身和前后组件坐标，不只看最终页。

本机运行仓库 Python 工具使用 `python3`（2026-11-04 核验，`python` 命令不存在）；需 Playwright 的检查用 `uv run`。

官方快照浮动导航若按 hash 定位，创建按钮后应立即初始化当前段落，不等外部 CSS、图片全部 load；load 后可再校准滚动位置（2026-11-04，直接进入末段快速返回曾误跳回串联，已在 workflow_patterns.py 修复）。

本地操作入口不要调用只接受HTTPS的lessonkit.ref（2026-11-04已核验会断言失败）；沿用现有本地link返回的refs对象{text,url,group,kind}，保持根相对本地路径，不伪装外链。

### 2026-11-05：操作入口与浏览器检查

- 演示页下沿有固定进度条和页脚。折叠入口本身可见，不代表展开后的链接可点；必须展开后实际点击全部链接。本次P4将入口列表向上浮出，避免被进度条拦截；只检查文字边界不足以发现这个问题。
- Playwright注入失败模拟时，用 `() => { navigator.clipboard.writeText = async () => { throw new Error('denied'); }; }`；不要直接把函数赋值表达式作为evaluate返回值，Playwright会把返回函数执行，测试先于点击失败。模拟后恢复原方法，避免同文档hash跳转沿用故障。
- 本机系统与项目Python都未带Pillow；拼接审阅截图使用 `uv run --with pillow python`，不为临时截图修改项目依赖。

### 2026-11-06：允许用过渡页保证讲解逻辑完整（讲师确认）

PPT不只有纯知识讲解页。为了提出问题、说明为什么要继续、承接上一段与下一段、形成必要停顿，可以单独安排过渡页。是否保留取决于讲述职责，不以页数少或每节一张图为目标。

提问式过渡页可以只放一句问题加问号，不另加同义标题或解释列表；用大字、留白及居中或其他合适布局聚焦问题。讲师接着用口播回答，再进入图解或真实材料。不要在问题出现时提前显示后文全部答案，也不把录播问题写成依赖学员现场回应的互动。

P4以“初版已经能运行了”承接前文，再提出“怎么知道它做得好不好？”，用于引出判断表现的需要。它是承接作用的例子，不要求每节都有提问页；当前页序与对应口播查本节讲述线及其源文件，不把历史页号当作通用要求。调研来源见docs/research/reports/提问式过渡页与P4开场.md。

提问页在现有播放器中居中时，需覆写`.scene-content`原有的固定宽高；仅设`inset:0`和flex仍会沿用知识页正文区尺寸，实际偏上偏左。限定到提问页layout设置宽高100%，并截图核对文字中心，不改全课普通页面布局（2026-11-06）。

### 2026-11-06：教学案例的事实边界

基础知识的教学取舍见第一节；具体课次的例子与来源留在讲述线和研究报告。运行路径要由原始事件核对，不能把讲师启发性的假设直接写成事实，也不能把路径经过当作通过评分。方法论总结不替代案例核验。

本机执行Python使用`uv run python`；未提供`python`裸命令（2026-11-06实测）。当时未找到旧规则提到的绘图工具，实际用现有可编辑SVG重绘；该工具要求已于2026-11-11撤销；共享证据文档`docs/production/trace-evidence-proposal.md`也不存在，沿用已核验的历史recording-html入口，不另造回放。

来源工作区曾使用 `uv run tools/ppt_gate.py check <节目录>`；这是历史实现记录，当前项目未提供该工具时不得照抄运行或声称已接入。系统机制的能力边界见 [门禁实施方案](recording-gates-proposal.md)。

- **来源与操作入口同时出现时检查页底（2026-11-06）**：固定高度的正文区里，材料入口和来源链接依次排布会把来源挤到进度条上。7.4用页底同一行分别放来源与操作入口，展开列表向上浮出，并逐个实际点击。仅检查SVG正文边界不足以发现这个问题。浏览器通用文字检查还可能把关闭的details后代和供读屏使用的裁切标题算作可见文本；专项检查须排除这两类实际不可见节点，同时保留来源与进度条的碰撞检查，不能把整组失败都当成误报。

增页会改变共享SVG生成器的自动marker编号（x-ar1等），导致未编辑的页面HTML字符串不同；验证原画面保留时只归一化这类生成标识，不能忽略正文或图形属性的差异（2026-11-06实测）。

### 画面说明要落实到实际内容（2026-11-07，3.1 反馈）

讲师指出“画面有什么／讲什么”仍像逐字稿的翻译。审阅稿中不要止于“展示三个差异”“汇总案例”：写出实际要出现的短文案、原文或数据，说明比较的两端怎样共同可见，哪些位置需要标注。真实产品和记录能承担的观察，直接确定取景与定位，不为每条口播配一张 PPT。

精简的依据是保留支持判断的对象、关系和必要证据。以 B2 牌数案例为例，画面聚焦原要求、实际数量、修正后的同项结果；原因、范围及转场放在讲述说明。检查时暂时遮住逐字稿：如果左栏仍无法让制作人确定画面内容，就继续设计；如果只有漂亮短词而看不出对象之间的关系，则补回必要证据。页数减少或文字变短，本身不算完成这项工作。
