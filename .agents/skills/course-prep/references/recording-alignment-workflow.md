# 按录制顺序制作、验收和修正课件

按编号读取完整正文：从仓库根目录运行 `python3 tools/read-editorial-rules.py ED-编号 ...`；合并去重，已读且未变的不重读，缺号或截断时补取并核对结束标记。 按核对对象合并编号：讲述逻辑 ED-002、ED-004、ED-007、ED-008、ED-019；口播表达 ED-010、ED-012；屏幕文字 ED-001、ED-012、ED-014；操作与同步 ED-003、ED-011、ED-013、ED-017；状态与证据 ED-015、ED-016、ED-018、ED-020；目标、深度与练习 ED-005、ED-006、ED-009、ED-021。整节覆盖全部涉及的对象并分批读取，局部复验只选受影响对象。

> 在本课程仓库使用时，制作与编辑规则以当前 `docs/production/` 为准；包内 `assets/course-reference/docs/production/` 是跨项目参照快照，不覆盖仓库真源。历史工具与检查能力须按当前环境核实。

适用任务：整段录制验收，或同时调整 PPT、逐字稿和演示顺序。仅改某类产物时，按其专用 reference 检查，不要求执行整套流程。

依据：2026-11-06 讲师说明的实际录制方式，以及本次关于验收、修正和局部复验的约定。本文将这些要求整理成完整执行方法。

**能力边界：本文规定人工核对、实际操作、修正和复验的方法，不表示系统已经实现强制执行。自动门禁的设计与接入状态单独维护在 recording-gates-proposal.md。**

本方法属于 course-prep 的共用知识，harness-prep 等专属 Skill 引用本文，不另存副本。它落实本仓库编辑规则 ED-002、ED-003、ED-008、ED-011、ED-013 和 ED-017；本仓库编辑规则以[当前课件编辑规范](../../../../docs/production/editorial-checklist.md)为准，包内快照仅供跨项目参考。局部复验按本文开头的检查对象选择规则，不返回公共任务表。本方法可独立执行，无需依赖其他审查 Skill。本文可以作为独立方法交给其他 Coding Agent；项目路径、生成命令和现有工具应换成所在项目实际使用的入口。

## 1. 目标与完成标准

讲师应能执行以下过程：

1. 从讲述线的第一个实际画面开始，找到对应逐字稿。
2. 按操作提示展开、定位或切换到下一个画面，在指定位置继续讲。
3. 在 PPT、实操、回放或原文的对应位置指认依据，再推进到下一段。
4. 返回已打开的画面时，回到明确的页、展开状态或材料位置。

讲师不需要临场寻找当前句子对应的画面，不需要自行拆分长段落来决定何时翻页，也不需要替作者补上缺失的解释和转场。

**实际画面核验的片段是：一个确定讲述位置上的连续口播。** 它可以是一个讲解段中的局部，不等于目录场景或源文件数组项；讲解段按解释目的组织，片段用于逐处核对实际可见依据。 一次完整验收包含内容核对、实际操作、问题修正和修正后复验。全部适用片段通过，且没有未解决的对应问题，才能报告本轮对齐验收完成。

“对应”指观众从当前画面与口播共同理解了对象、关系和判断。画面与口播不要求逐字重复；链接可达、页码正确或段落齐全，都不足以单独证明内容对应。

## 2. 开始前确认输入与范围

先确定以下内容，沿用项目已有真源和文件格式：

- 本次要处理的小节及其学习任务。
- 当前有效讲述设计及其 Discussion 依据；完整逐字稿的源文件，以及必须保留的讲师原话。
- PPT 源文件、实际页序、状态和生成入口。
- 配套 HTML、数据、历史记录及其真实来源和版本。
- 哪些属于当前运行、历史回放、示意或尚未准备好的材料。
- 本轮允许修改的范围、已有决定与未完成项。

读取已有材料后再判断，不因某份文件更新较晚就默认它正确。联合优化任务允许综合调整讲稿和画面；局部任务按已授权范围处理。修改生成源，再生成页面，避免只修改下次会被覆盖的产物。

能够在授权范围内解决的不对应问题，直接修正并复验。事实材料缺失、两份证据矛盾或需要改变教学目标时，如实标记具体问题，继续处理不依赖它的部分；不能补造内容或标成通过。

## 3. 先讲通小节，再排实际画面

先用简短文字说明：本小节解决什么问题、需要哪些事实和解释、最后形成什么判断。随后按讲师实际操作排列画面。

例如，以下只是顺序示例，不是指定所有课程都采用这些页：

```text
PPT 第03页：题集覆盖
→ 题集 HTML：类别与问题
→ 历史记录 HTML：召回步骤
→ 同一 HTML：判断步骤
→ PPT 第04页：预期与判分
→ 同页收束
→ PPT 第05页：结果记录
```

相邻知识页分别承担的内容应尽量成段讲完。确需重访前页时，说明这次返回增加了什么比较或理解；不要为收尾几句话来回翻页。存在有意义的回顾时可以回翻，不把“页码只能递增”写成普遍规则。

同一材料内能连续讲解的几个位置，直接在材料中推进，不要求每次先返回 PPT。PPT 的材料入口页与材料窗口中的讲述位置分开记录。

## 4. 以画面位置划分片段

每个片段必须明确下表内容。画面与操作对应写回讲述线源，台词写回正式口播源。检查表引用原处。

| 项目 | 要记录什么 |
| --- | --- |
| 稳定片段 ID | 用于关联、定位和复验，不能把它当 PPT 页码 |
| 本段作用 | 观众此刻需要理解或判断什么 |
| 当前画面 | PPT、材料 HTML、AI 会话或工程窗口 |
| 具体位置 | PPT 页及状态；HTML 锚点、标题、步骤和必要展开状态 |
| 进入动作 | 从上一片段怎样实际到达这里 |
| 口播引用 | 唯一源中的具体段落，能解析出本段完整正文 |
| 可见依据 | 此刻要指认的对象、数据、文字或图中关系 |
| 前后衔接 | 本段接住什么，结束后下一段为何发生 |

划分规则：

- 一个位置可以对应多个自然段，不按每一句话增加 PPT 页或操作。
- 需要翻页、切窗、定位到另一处或展开下一项关键内容时，明确进入下一片段。
- PPT 动画状态也属于具体位置，不能把尚未出现的节点当成当前可见依据。
- 大段代码、长表或日志需要中途滚动才能讲下去时，把定位动作放在实际发生的位置。
- 一页上不影响讲述对象的鼠标指示不必机械拆段。
- 每段正文在录制顺序中有明确归属；缺段、错序和无意重复必须检查。刻意回顾可以保留，但需说明用途。

页码与标题从实际页序取得，并与播放器核对。页序变化后检查全部受影响的提示。材料讲述的当前画面应写材料位置，不能因为从某页 PPT 打开，就把这一段归成该页 PPT 的口播。

## 5. 分配画面与口播的信息

画面和口播共同传递内容。画面展示对象、原文、数据和关系；口播引导注意，解释原因、关联、差异和判断。

### 可以省略的复述

- 已清楚列出的完整题干、名单、字段名或数值，可以让观众直接看。
- 画面已展示完整操作或结果时，不必逐项播报界面上的所有文字。
- 引导关注后，可以直接解释重要差异，无需重新朗读整张表。

省略的前提是：信息在当前实际画面中可见、字号可读、相关对象容易找到，且观众有观察机会。被折叠、被遮挡、处于滚动区域之外或下一页才出现的信息，不算已经展示。

### 必须保留的解释

- 当前为什么需要看这项信息。
- 数据或对象之间有什么关系。
- 哪些事实支持当前判断，判断适用于什么范围。
- 从这一段进入下一段所需的理由和承接。

“这个结果”“这两个条件”等指代必须能准确定位。纯口头解释无需逐句强配图；但需要指认或用作证据的对象，必须已经展示或明确承接前文。

例如，画面已列出两道题及其参考结果，可以讲：“两题都要求排名正确，第二题还要求说明大小信息缺失。”无需再念全部题干和五个数据集名称。若名单顺序正是当前要核对的重点，则仍需引导观众观察具体顺序。

检查完整性时，结合画面和口播判断。不要为了让逐字稿脱离画面也像一篇完整文章，把所有屏幕文字复制回正文。独立阅读模式需要的解释，仍按项目要求补在阅读模式中。

## 6. 把切换动作写在正确位置

需要进入动作的片段先写动作，再写在该位置念完的正文。静态画面已经就位时只写定位；边做边讲注明执行时机；讲完才做的下一动作放在正文之后。中间无讲述的连续点击可合成操作组，但需要解释的新状态必须保留操作与口播的对应。操作提示不念出口，既有源标记沿用本课格式。

```text
【操作】打开 PPT 第03页，停留在指定状态。
这页对应的连续口播……

【操作】从本页点击“完整评测集”，定位“按类别看问题”。
这个 HTML 位置对应的连续口播……

【操作】在同一 HTML 中选择 D33，点击“预期 expected”。
这个位置对应的连续口播……

【操作】返回 PPT，翻到第04页。
这页对应的连续口播……
```

以上是格式示例，使用时替换为实际页名、按钮和位置。不得把几次操作集中放在长稿段首，让讲师自行判断中途切换时机；也不要在上段结尾和下段开头重复安排同一次动作。

**每次改变讲述位置，都紧跟该位置的口播（2026-11-06 讲师明确）。** “依次看召回、两批判断和查询”是多个讲述位置，不能只配一段概括性口播。按必要位置逐个交替；不服务当前判断的点击可以从主讲路线删去，原材料仍完整保留。一次定位按钮自动完成选题、展开和滚动时，可以是一条操作，关键是讲师停住时知道这一处该念哪段。不要为了减少稿中操作条数，把真实的多次切换藏回一句提示里。

操作提示使用纯文字说明动作与定位。实际材料链接维护在对应 PPT 或材料导航中。PPT 上重要的演示入口应能直接发现，按钮名称与提示一致；来源引用与课堂要打开的材料入口应能区分。

HTML 的定位按钮或锚点必须对应真实内容，跳转时展开所需信息，并避免固定导航遮住目标。只到文件首页、只找到隐藏 DOM 元素或只返回 HTTP 200，不算准确定位。PPT 打开材料时保留原窗口，材料中的连续阅读操作按实际需要推进。

## 7. 对着实际页面逐段验收

整节验收覆盖本轮小节的全部片段；局部任务覆盖修改部分及其实际影响，不因使用本方法自动扩大到整节。从讲述线的第一个实际画面开始，按讲师操作顺序逐段执行。每到一个位置都核对实际画面和口播，并以源码、映射和记录辅助定位。

每个片段按以下顺序检查：

1. **进入。** 执行上一位置可见的操作，确认打开正确窗口、页和状态。
2. **观察。** 查看实际渲染画面，确认正文需要指认的内容可见、可读、无遮挡。
3. **逐段对照。** 保持当前画面，对照本段全部口播逐句检查，直到本段结束，不提前操作下一页来补救缺失依据。
4. **判断。** 回答下方的内容问题；发现不符，进入第 8 节的修正流程。
5. **推进。** 本段通过后，执行下一条提示，确认下一段能接着讲。

每段必须回答：

- 观众知道此刻讲的是哪个对象、什么问题吗？
- 口播需要指认的证据，在当前画面能准确找到吗？
- 画面与口播中的关系、数字、版本、题号或事实是否一致？
- 画面提供的信息与口播解释合起来，足以支持这一段的判断吗？
- 当前讲述设计的解释目的与关键递进是否实际落实，制作中的有效变化是否已回写？
- 沿时序阅读时，此刻在哪里、下一步做什么、何时讲是否清楚；被折叠的信息是否藏住了正常路线必做动作或事实限制？
- 是否需要未写明的滚动、切窗、提前翻页或回头找材料才能讲下去？
- 被省略的屏幕内容是否清楚可读？保留的口播是否存在无用途的重复朗读？
- 前一段留下的问题是否被接住，下一段是否自然发生？

留下简短、具体的核对依据，例如“正文第2段比较两题保留的排名要求；当前画面两行均含排名，第二行另列大小缺失说明”。只写“语义一致”“已检查”没有可复查信息。

浏览器检查和逐段语义核对分开记录。截图用于支持画面核对，不能单独证明讲述逻辑成立。文字对照不等于出声试读；未做朗读、节奏检查或课堂试讲时，不声称这些项目已通过。

## 8. 发现问题后修正，并验证修改结果

验收应完成以下闭环：

```text
实际打开画面
→ 对照本段口播
→ 发现具体问题
→ 调整对应源文件
→ 重新生成并加载页面
→ 复验修改部分及受影响的衔接
→ 通过后关闭问题，继续验收
```

### 8.1 按问题调整

| 问题 | 调整方向 |
| --- | --- |
| 口播事实或解释错误 | 按证据修正口播，检查相关图示是否也需调整 |
| 画面遗漏、误画或表达关系不清 | 修改画面，使当前判断所需的对象和关系可见 |
| 正文跨越多个实际位置 | 在真实切换处拆分操作与口播，不强行把整段挂到一页 |
| 前后顺序混乱、频繁无意义回翻 | 调整讲述顺序及画面职责，保留必要的推导与承接 |
| 链接、锚点或按钮不准确 | 修复入口和目标状态，执行一次完整跳转验证 |
| 屏幕信息与口播重复过多 | 保留必要解释和重点指认，删去不增加理解的复述 |
| 材料不足或结论超出证据 | 补已有可信材料，或调整讲法和结论；缺失项如实保留 |

联合优化时同时核对设计、PPT 和逐字稿，不默认任一产物就是最终答案。变化按职责写回当前源；涉及 Discussion 的目标、范围、关键结论按入口原则处理。授权未覆盖的上游问题列明位置与影响，受影响片段保持待处理，不用口播绕过矛盾。不能仅修改页码、增加标签或补一张映射表，就关闭内容不对应的问题。

### 8.2 按影响范围复验

- 修改正文：核对修改段与当前画面，以及必要的前后承接。
- 修改图示、数据或材料：核对所有引用该内容的片段。
- 修改切换、顺序或定位：从前一个相关片段进入，走完修改片段，再进入后一个相关片段。
- 修改页序、共享导航、样式或生成器：检查所有可能受影响的位置，不能只检查最先发现问题的一处。
- 影响范围无法确定时，扩大复验；已通过且未受影响的部分不必无条件重验。

复验必须面对修改后重新生成、重新加载的真实页面。旧截图、旧浏览器状态和修改前的通过记录不能作为新版本已验证的证据。

复验失败则继续调整，再次复验。只有复验通过，问题才能从“已修改、待复验”转为“已解决”。发现问题、列出清单或完成编辑，都只是中间状态。

## 9. 核对记录与交付

例行核对在本轮交付中说明。需要交接的画面、操作和素材定位写回讲述页对应位置。正式审查沿用项目已有的审查约定。

| 片段 | 当前源版本与画面位置 | 技术检查 | 内容核对依据 | 发现的问题 | 修正与复验 | 当前状态 |
| --- | --- | --- | --- | --- | --- | --- |
| 示例片段 | 源指纹；页/状态或锚点；截图引用 | 实际操作结果 | 哪段话对应哪些可见信息、关系是否成立 | 具体原句及画面差异 | 改动位置、受影响片段、最新复验结果 | 未检查/有问题/待复验/通过 |

记录应关联实际文件内容的指纹，时间仅作辅助。当前状态由最新有效证据决定，不能靠修改一个 `passed: true` 字段获得通过。技术通过和内容通过分别保留，避免混为一个无法解释的结果。

交付前检查：

- 本次范围内的完整正文有确定的画面归属，操作顺序连续。
- 需要的知识、事实和材料已核对，页面与源文件一致。
- 所有发现的对应问题已修正并复验，或者明确列为未完成，未完成时不报告全部通过。
- 最近改动影响到的核对结果已重新取得，无失效记录混入通过项。
- 说明实际修改、验收范围、复验结果及仍未做的检查。

交付直接指向本次核对的讲述页、PPT 或材料位置。截图、原日志和长材料按项目的公开/私有边界保存，报告不能泄露私有数据。

## 10. 如何减少跳过流程：让完成条件由系统检查

自动记录、失效传播、内容复核与受保护放行属于单独的 [门禁实施方案](recording-gates-proposal.md)，仅在设计或实现系统约束时读取。普通录制验收执行本文第 1–9 节；没有系统接入时如实报告作者核对，不宣称已强制放行。

## 11. 给 Coding Agent 的任务指令模板

```text
按《按录制顺序制作、验收和修正课件》处理指定范围。

先读取真实逐字稿、PPT 源及配套材料，确认授权和保留要求。
按讲师的实际操作排列画面，并把连续口播绑定到具体页、状态或 HTML 位置。
画面已有的可读信息可以省略逐项朗读，正文保留必要解释、判断和承接。

在实际生成页面中逐段验收：进入当前位置，对照完整口播，讲完再执行下一条操作。
发现不对应，直接在授权范围内调整源文件，重新生成并加载页面。
复验修改部分及受影响片段；复验通过才关闭问题，再继续后续验收。
材料缺失、事实无法核实或超出授权的问题，保留具体未完成项，不编造或标成通过。

交付修改后的源与页面，并说明核对范围、具体修正、最新复验结果和剩余问题。
技术检查与内容核对分别报告；不以链接可达、段落数或映射存在证明内容已经对应。
若项目已启用门禁，使用真实执行入口取得当前版本的结果，不手写通过记录。
若尚未启用门禁，明确说明目前只有工作规范和作者核对，不能宣称流程已被系统强制执行。
```


## 跨章巡检

讲师要求全量巡检时，覆盖全部已有课件与共用入口。章定稿或录制前，优先核对本章与相邻章的教学衔接及共用入口；按发现的共性问题扩展范围。先列清覆盖的章、入口和检查主题，再按适用对象读取本文件开头对应的 ED 条目。

1. 先读覆盖本轮范围的审查记录，优先复核上次待处理项。重复发现引用原文件和问题编号；已修复的在原记录更新状态。
2. 按同类位置横向比较。核对课程首页、章首页卡片、节标题、段名及屏幕短文案的术语和措辞（ED-012、ED-014）；对照相邻章 Discussion 的学习目标、能力递进和材料衔接，再查看讲述线与实际课件是否兑现这些安排（ED-007、ED-017）。
3. 对照有效 Discussion、讲述线及实际可打开的成果核实完成状态（ED-015），检查学生可见入口和授课画面是否露出制作或审阅状态（ED-016）。录制前从本章讲述线及操作入口列出演示形态未定的位置（ED-013），交付录制前逐项定案。
4. 按位置、现象、影响范围和建议汇总。只在本轮授权范围内修订；跨多节的标题、术语或教学递进先汇总给讲师。教学决定回写 Discussion，画面安排、操作与口播在实际讲述源维护，PPT 展示问题改课件源。巡检发现的局部修订可走小改动快路径，结果回到同一份巡检记录。
5. 按[仓库审查约定](../../../../docs/reviews/README.md)留一份跨章记录，列清覆盖范围、已修复项、待处理项与未检查项，分别说明机器检查、人工对照和实际操作。需要迁移到其他章节的判据通过既有编辑规则或措辞规范维护。
