# PPT 材料验证与链接门禁

讲师于 2026-11-04 明确要求：所有材料必须亲自检查验证通过后才能写入 PPT；PPT 中打开材料、跨页跳转必须进入新窗口，保留 PPT 本身。二者必须由代码强制。

## 验证顺序

1. 先在 PPT 外准备材料和验证脚本。验证必须覆盖实际交付路径：界面入口、复制出的内容、实际执行、结果正确性、错误反馈；仅检查文件存在、HTTP 200 或文本相等不够。SQL 必须在对应只读数据库执行，并核对数量、完整名单与字段；终端演示还须检查粘贴及回车行为。
2. 在节目录创建 `material-checks.json`，列出 `inputs`（仓库相对路径 glob）和 `checks`（每项含 `purpose`、参数数组 `argv`）。包括源数据、共享依赖及所有验证脚本；命令必须有实际断言，失败返回非零，不得用 echo、固定成功或仅人工填写状态冒充检查。
3. 运行 `uv run tools/ppt_gate.py verify <节目录>`。程序先删除旧通过记录，执行检查，确认检查期间输入未改变，才生成 `material-checks.passed.json`。命令失败不会留下通过记录；输入、检查脚本、计划、共享播放器及节目录文件的哈希改变后，记录自动失效。
4. 通过后才能生成 PPT；第 2、3 课及 Harness 草稿共用的 lessonkit 在写 `lesson.js` 之前检查。其他生成器和静态页面同样受 `make check`、站点构建和 CI 阻断，不得绕过。
5. `make check` 必须通过。链接检查会对全部 PPT 正文链接实际触发点击，断言产生新页面且原 PPT URL 不变，另测动态 SVG。材料窗口内的阅读操作不属于 PPT 窗口跳转；PPT 页内翻页锚点仍保留页内行为。

配置格式示例（替换为本节真实输入与检查，不能原样用于签发通过记录）：

```json
{
  "inputs": ["path/to/source-data.json", "path/to/check-materials.py"],
  "checks": [
    {"purpose": "实际执行并核对材料结果与交互", "argv": ["uv", "run", "path/to/check-materials.py"]}
  ]
}
```

代码能强制执行指定检查并识别材料变化，不能自行证明任意检查脚本足以验证教学事实。备课者仍需设计有实际断言的检查、检查原始结果和页面，并在审查记录中明确覆盖及缺口；不能因为程序返回零就扩大验证结论。通过记录不代表试讲通过。

## 检查工具自身的验证

`uv run tools/test-ppt-gate.py` 覆盖缺记录、检查失败、材料修改与新增的拦截，以及真实命令成功后的放行。

`uv run tools/check-ppt-links.py` 验证正文链接和动态 SVG 新窗口行为。测试用临时本地服务，不依赖 8841。浏览器关闭结果窗口时，临时 HTTP 服务可能遇到 BrokenPipe；服务只忽略连接关闭异常，页面断言失败仍报错。

新窗口浏览器检查在产生跳转后用固定 HTML 隔离目标内容，并断言新页面 URL 与链接一致；材料正确性由各节检查负责。Playwright 在新窗口首个导航请求产生时可能尚无 frame，不能读取 request.frame；隔离器在 PPT 首次载入后按 is_navigation_request() 处理后续导航，避免此时访问 frame。
