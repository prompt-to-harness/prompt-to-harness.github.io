# 从分镜做出一节课件

> 由 [SKILL.md](SKILL.md) 路由过来：一节已有 `STORYBOARD.md`（至少有“本节内容”），要从分页讨论一路做到课件页面。4.1、4.2 在 2026-11-03 至 11-08 按这个顺序做完，下面是从中沉淀的做法。

规则本身在 `docs/production/editorial-checklist.md`、课程设计原则和制作手册里，本文只规定顺序。每一步需要讲师拍板的，先列问题、给推荐，确认后再动手。

## 1. 拿到分镜，先查上层

读本节 `STORYBOARD.md`，再读章文件（或章级故事线）和内部大纲里这一节的条目，逐条对照：

- 三处对本节范围、产出、验收的说法是否一致；不一致先停下问讲师，从上层改起。
- 是否有绝对化的说法（“严禁”“彻底”“不行”），或和章级核心判断冲突的口径。
- 开场抛出的问题，本节内容里有没有明确回答。

## 2. 按奥卡姆剃刀整理“本节内容”

整理只动内容层，改完请讲师确认，并在决策记录里写一条。检查项：

- **每段都服务本节开头的问题**，不服务的删掉，或移到后面某节、实验说明里。
- **没必要不新增实体**：文件、页面、概念、记录格式。能并进已有文件就并进（例：4.2 的来源记录并进 `BRIEF.md`，不单建 intake 文件；第 4 章不建 LOG）。
- **工具和机制只讲到当前判断需要的程度**（例：4.2 的 MCP 只用一页讲是什么，接入放到 4.6）。
- **说法不过满**，降到证据能支持的强度。
- **每条信息只写一处**：正文只在“本节内容”，章文件只留摘要和链接。

## 3. 起草逐页表

按 2.4、4.1 的格式写：页面 | 页型 | 学员问题 | 画面证据与揭示顺序 | 讲稿要点 | 方式（跟做 / 看懂） | 层 | 讲透问题。表前一段写本节的分页约定。

先在对话里给讲师看，并列出要拍板的点，每点附推荐：哪些页现场演示、演示拆成几页、外部依据怎样展示、锚点图在哪出现、学员要不要跟做。确认后写进分镜的“逐页安排”，并标出哪些页没有演示、哪些页有演示。

## 4. 没有演示的页：讨论后直接做

开篇、概念、对照、自检、小结这类页，按逐页表做页面源（`tools/build-lesson.py`）和口播（`script.json`），不等实跑。贯穿全章的图由章 `lessonkit.py` 统一生成，不在页面里手写副本。

## 5. 有演示的页：讲师先演练，再定页面

1. **给讲师一份演练清单**：
   - 准备：在哪个目录、工作区要干净、端口空闲、新开会话。
   - 每一段的请求原文（同时写进分镜“演示请求草案”），按发送顺序排列，注明是否在同一会话里发。
   - 每段跑完要做的抽查。
   - 跑完要交回什么：对话导出路径、截图、有没有弹出确认以及是哪类操作、中途有没有插手、抽查结果、大致用时。
2. **讲师手动演练并交回材料。** 不替讲师执行需要其账号、凭证或会改变其环境的操作；被权限拦下的命令不绕过，交给讲师决定。
3. **核对材料再用**：逐条抽查 Agent 给出的路径、行号、数字；把实际结果写进分镜“讲师探索核验记录”（日期、做了什么、结果），并标明不是录制排练。
4. **按实际结果定页面**：
   - 页标题、转场、小结只写换一次运行也成立的机制；这次运行的细节只作例子，口播写明“我排练那一次”（ED-020）。
   - 结果页写观察点和核对对象，不预写 Agent 的回答。
   - 现场可能失败的地方，给出备用：截图放进弹窗，处理步骤放进实验说明。
   - 学员要跟做的安装、取材、模板放进实验说明（`repro`），不占主画面。

## 6. 做页面并检查

- 改源文件再重新生成，不手改 `lesson.js`；每一步口播以 `【操作提示｜…】` 开头。
- 每页截演示模式末步的图看一遍：有没有压到章节条、标题是否折行压住导语、长代码是否溢出。一轮看完全部，一次改完。
- 跑 `make check`；报缺字就重建字体子集（见 `docs/production/fonts.md`）。
- 录前一次做完的准备写进 `Lesson(prep=[…])`，显示在逐字稿页顶。

## 7. 整节审查

按 [review.md](review.md) 审一遍，正式记录写到 `docs/reviews/<章>/`。审出的问题列给讲师拍板，改完把记录里的状态改为“已修复”。

## 8. 收尾

- 同步章 README 的状态、首页和章首页的入口、上下节导航。
- 汇报：改了哪些文件、哪些还没验证（录制排练、出声试读、教学效果）。

## 少走弯路

- **不读、不打印密钥。** 查看配置只列键名，含凭证的文件不上屏、不入库（2026-11-07 打印 `config.toml` 时暴露过 App Secret）。
- **演练环境和录制环境一致。** 在基线副本里跑，不在课程仓库里跑；演练生成的文件录前要清掉。
- **实测之前不写定观察点。** 4.1 的 B、4.2 的调查都出现了预料之外的行为（自行验证十多分钟、服务留在后台、出处行号写错），这些都是实跑后才知道的。
