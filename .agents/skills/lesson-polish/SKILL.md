课程分层维护，改动只从上往下流。先判断这次改动的起点，再按表做；一次请求涉及几行，就按最上面那行开始。

| 要改的 | 从哪改起 | 往下同步 | 先问谁 |
| --- | --- | --- | --- |
| 对外承诺、平台交付版 | `docs/course-outline.md` | 内部大纲 | 两位讲师 |
| 全课结构、跨章安排、全课原则 | 先写 `docs/outline/proposals/` 提案，确认后改内部大纲 | 受影响的章文件 | 两位讲师 |
| 章主线、各节分工、讲透问题、节表、时长、验收 | 章文件；在章 `LOG.md` 记一条决策（依据、重开条件） | 分镜 → 页面源；内部大纲里这一章的摘要 | 负责讲师 |
| 一节的连贯讲述内容（已采用分区结构） | `STORYBOARD.md` 的“本节内容”；决定记章 LOG | 同文件“逐页安排” → 页面源 | 负责讲师 |
| 增删页、调顺序、某页讲什么 | 分镜 `STORYBOARD.md` 的逐页区 | 页面源 → 重新生成 | 负责讲师 |
| 措辞、版式、口播 | 页面源：`tools/build-lesson.py`、`script.json` | 重新生成 | 不用问 |
| 重跑、重录、实测结果 | 章 `LOG.md` 的实测记录 | 分镜“素材状态” → 页面数字 | 不用问 |
| 找外部佐证 | 项目 skill `external-sources` | 它自己会写回章文件 | 讲师挑选 |
| 审查一节、跨章巡检 | 读本目录 [review.md](review.md)，按它做 | — | — |
| 试讲或讲述之后整体改一节 | 读本目录 [trial-run.md](trial-run.md)，按它做 | 各层按上面几行 | 负责讲师 |

**章文件在哪**：已迁移的章（有 `courseware/chNN/LOG.md` 的，目前是第 2 章）是 `courseware/chNN/README.md`，各文件写什么见它的“各节文件与改法”。其他章的章一级内容还在 `docs/outline/course-outline-internal.md`，节一级说明在各节 `README.md`；这些章不建 LOG，决策写进内部大纲。

**同文件分区，不新增重复入口**

新写或整体重写一节时（2.3 起，课程设计流程，2026-10-25 讲师确认），`STORYBOARD.md` 按“本节内容 → 逐页安排 → 素材状态与操作备注”分区。正文解释只在本节内容写一次，逐页区只安排画面、证据、揭示与转场；素材区记录采用来源、定位和待补，实测过程与决策仍在 LOG。章 README 只保留章级分工、范围、验收、摘要和链接，不复制单节全文。不新增 CONTENT.md。已有小节保留原结构，不为修改一个小节批量迁移；下次整体重写时再迁移。

**先有文字内容，再做下游**

新设计或实质调整一章／一节的主线、讲述内容时，先在该节既定内容入口写出可独立读通的文字内容：从什么项目状态和问题开始、做什么及为什么、如何用证据解释知识、与本章主线和前面小节的关系、最后留下什么能力和交付物。连贯讲清，不只列要点或节表；不带页码、版式和点击步骤，也不预写固定的运行结果。已有文字内容够用时直接修订，不另建一套讲义或重复口播稿。

先让负责讲师讨论这份内容；已在当前讨论中确认的不用再问。内容确认后再细化或调整分镜、演示 Prompt、重跑与页面，既有分镜和素材只作参考，不能反推必须出现的剧情。若需要实验才能判断内容是否成立，可先做范围明确的探索核验，标明它不等于内容定稿；用户明确要求先讨论时，不提前重跑。Prompt 的自然程度与不构造失败按编辑规范 ED-004–006 和章内约定处理，不把教学观察点都写成模型必走步骤。

只改措辞、版式、口播或按已确认方案更新实测，不要求补写整节文字内容；但若发现主线缺失或矛盾，先回到这一层。下游暂缓时在章文件“待定”登记。

**做法**

1. 说出起点那一行；“先问谁”不是“不用问”且讲师没在这次请求里确认过的，先列出要改的内容问讲师，确认后再动手。
2. 在下层发现上层的问题（页面对不上任何讲透问题、分镜和节表矛盾），停下指出，回上层改，不在下层将就。
3. 每条信息只写在一处：章级范围、时长和验收不在分镜复述；分区结构的逐页区不复述本节内容，变更说明写进提交说明和 `LOG.md`，不写进分镜或章文件开头。
4. 页面改源文件，再重新生成，不手改 `lesson.js`；口播在 `script.json`。
5. 下游这次来不及同步的（例如要重录才有的数字），在章文件“待定”写一行，不留空。
6. 跑检查：快路径跑 `python3 courseware/tools/check-editorial.py`，其他跑 `make check`，error 清零；报错的处理方式见 checklist 对应条目。

**快路径**：只动一页或几页的措辞、版式、口播，范围内没有事实和数字变化，就改源文件、重新生成、跑 `check-editorial.py`，结束。不写审查记录。

**收尾汇报**：改了哪几层、各改了什么文件；哪几层判断后不用改；哪些写进了“待定”；跑了哪些检查。没检查的照实说，不写教学效果已验证。

编辑规则只在 `docs/production/editorial-checklist.md`，本文件只管路由和顺序；新发现的可迁移问题登记到那里，不写进本文件。
