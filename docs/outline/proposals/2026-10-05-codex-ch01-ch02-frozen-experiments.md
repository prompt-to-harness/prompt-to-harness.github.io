## 范围与依据

本次梳理第一、二章教学中的演示、机制实验、故障案例和项目验证，不是课程站自动检查的运行报告，也不是课件逐页审校。依据共同内部大纲 1.1–1.6、2.1–2.5，各节分镜、现有验证记录，以及 `starters/personal-homepage/ch01-complete/CHECKPOINT.md` 和第二章材料说明。没有修改课件或学员验收要求。

## 建议的关系

讲师项目仍沿同一条提交链演进：Starter → 欢迎语修改 → 人工确认的 Prompt → 首页 v0 → 内容迭代候选 → 评审后的 v1 → 发布配置与线上验收。每个阶段先真实执行、验证，再冻结其起点、产物和记录，作为后续录制的输入。分节录制时从对应检查点继续，原始提交与证据保持可追溯。

机制实验从适用检查点复制到独立目录或分支，完成后回到主线；实验修改不自动合入项目。讲述时说明切出和返回的位置。学员主线继续使用自己的成果，通过同一组验收即可；需要观察固定现象时打开实验副本，参考快照也支持从第二章开始。

冻结分三种：固定文件与命令能复现的状态变化；固定输入但输出仍会变化的模型实验；已经发生并保存的真实运行记录。三者在材料中标明，不能把历史运行的请求次数、摘要内容或失败当成学员重跑必须得到的结果。

## 逐节梳理

| 小节 | 当前安排与不稳定因素 | 建议冻结什么 | 与项目主线的关系 |
| --- | --- | --- | --- |
| 1.1 首次闭环 | 欢迎语任务较小；大纲要求指出一次偏差，实际可能一次成功。分镜已允许使用注明来源的失败素材 | 固定 HTML、指定文案、允许范围、检查方法；保存完整真实闭环。修正案例用已有真实记录，缺少时另设标注的练习副本 | 欢迎语修改保留在主线；纠错练习不要求学员等 AI 犯错 |
| 1.2 执行机制 | 本来就复盘 1.1，不重新运行；各人的工具轨迹不同 | 从同一轮 1.1 记录提取要求、调用、返回、决定，固定片段与分类解析 | 不产生新代码，继续复用主线证据 |
| 1.3 工具与权限 | 配置可固定；AI 是否提出某动作、批准后是否执行成功仍有变化 | 独立副本上的只读/允许写入对照，版本与实际返回；四类权限题固定。技术阻断可用固定低风险命令核验并说明这是限制测试 | 复用欢迎语文件；实验结果单独记录，不在主线测试真实发布或访问私人目录 |
| 1.4 澄清与 Prompt | Agent 的提问及顺序不确定，可能直接采用默认值 | 固定 Brief 中的已知和未决项、讲师人工答案、批准后的 Prompt；录制使用真实澄清记录，验收看关键决定是否齐全 | 批准后的 Prompt 成为 1.5 输入；不能为凑固定追问偷偷改变已确认需求 |
| 1.5 首页 v0 | 样式、源码结构、依赖安装与运行环境可能不同 | 冻结 Starter SHA、工具链、必要依赖版本、锁文件形成过程、批准输入；真实运行验收后冻结 v0 和证据。阶段运行前准备好安装所需条件 | 保留从 Prompt 实现首页的真实过程；学员允许不同实现，通过验收后继续 |
| 1.6 最小权限 | 当前以固定链接核对任务作判断，不实际做危险动作 | 固定链接列表、服务状态、工具与允许范围，配明确解析 | 使用 v0 的任务情境，不增加正式功能 |
| 2.1 反馈基线与请求 | 已计划冻结讲师 v0；反馈不一定适用于所有首页。工具调用错误和决定识别也有随机性 | 先按实际 v0 核对或改写课程反馈卡；固定三种视口、点击与 Tab 路线。请求解剖用真实脱敏记录；环境/权限对照用独立实验配置 | 反馈清单接入主线；读标题实验标明换任务，不能混用其数字和反馈核对记录 |
| 2.2 会话与内容迭代 | 相邻请求、次数、缓存、压缩摘要有版本和模型差异；内容修改也可能扩大范围 | 固定会话/文件/服务对照的目录与状态；历史请求差异用真实记录；压缩实验固定文件证据和观察表，不要求摘要遗漏或答错；源码历史固定 SHA；内容迭代固定人提供的文字与验收 | 会话实验在副本；2.2 真实内容迭代留在主线，输出候选 diff 和验证证据 |
| 2.3 Review 与回退 | 真实 diff 不一定包含越界；回退操作在确定的提交上可复现 | Review 主例取 2.2 实际 diff；独立副本预置明确的未提交改动和代码/记录提交，核验 restore、revert 前后状态 | 评审形成主线 v1；回退实验结束回到正常分支，不为演示制造主线事故 |
| 2.4 发布 | 外部服务、账号、界面及联网条件不能完全冻结；不一定自然出现部署失败 | 固定本地 v1、发布配置、构建输入与公开检查清单，提前跑通真实发布并保存记录；如需教 404 定位，可在独立本地副本准备明确标注的错误路径案例 | 发布主线仍实际核对 URL、资源和刷新；本地实验不能替代线上验收 |
| 2.5 重构判断 | 已有两份固定教学 diff，基于排练 v1；不是现场 AI 输出 | 将 A/B 重新基于录制 v1 制作，固定内容、点击、Tab、三种视口的对照。可提供完整副本，减少学员应用 diff 的前置负担 | 从 v1 切出判断实验，不要求把任一教学 diff 合入学员主线 |

## 已发现的具体影响

1. **2.1 的反馈要以冻结产物为依据。** 当前排练 v0 的记录明确说 360 视口不挤，第 1 条反馈不复现。应先核对真实 v0，再决定反馈卡描述；可以展示“该条件下未复现”及后续处理。若必须演示窄屏缺陷，另设标注案例，不能无说明地改坏 v0。
2. **1.1 不宜强制每人出现修正轮。** 当前大纲练习要求一次修正记录，而自然任务可能一次成功。若采用固定修正实验，须共同确认是否允许“真实任务一次通过 + 独立案例修正”满足该项，再同步大纲与课件。
3. **1.4 的固定台词应改为核对决定。** 能冻结人工答案和待确认问题，无法保证 Agent 恰好问出课件里的四个问题。省略的关键决定由讲师主动核对，不能据此假装模型已经追问。
4. **2.2 新建与继续均可能合理。** 若冻结演示会话，应保留其真实内容并据此解释选择；不能为了证明新建更好而人为堆无关历史。压缩实验观察证据转换，遗漏只是可能结果。
5. **2.3/2.4 的故障安排需要区分教学副本。** 现大纲不准备坏 diff 或错误 base。如新增受控故障，明确限定在独立副本，并在采纳后同步大纲；正常主线继续使用真实运行与实际错误。

## 实验包的最低内容（建议）

- 起点：适用章节、来源 SHA 或快照、必要文件、版本与权限、服务状态。
- 操作：固定任务、人工决定、命令或检查路线，以及重置副本的方法。
- 观察：哪些结果由输入状态确定，哪些允许随模型变化；正常、失败和无法运行时如何继续。
- 证据：真实运行输出、截图、diff、退出状态和脱敏后的可公开记录；没有检查的项明确标为待核验。
- 去向：哪些产物进入主线，哪些只用于实验；学员独立完成的标准与参考快照的用途。

## 建议的先后顺序与待讨论取舍

先冻结 Starter 和讲师真实 v0，核对反馈卡，再完成 2.2 真实迭代、2.3 评审并冻结 v1；最后基于这条链制作会话/请求、权限、回退和重构实验。版本、锁文件或内容更新后，只复验受影响的材料。当前已有排练快照与部分单次实测，统一录制版本、脱敏请求记录及配套操作页仍需补齐。

待讨论的核心选择：第一、二章是否继续让学员用自己的首页走主线，仅在机制实验进入固定副本（建议），或第一遍连主线也统一使用讲师案例，个性化移到第二遍。前者保留自己的需求与成果，但需提供差异分支；后者更易对照，代价是第一遍的个人需求澄清变弱，并需要调整 1.4、2.1、2.2 的练习设计。
