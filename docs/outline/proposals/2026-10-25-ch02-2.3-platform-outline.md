## 现在的写法（`docs/course-outline.md`）

第 3 节标题“它看到了什么：审查改动的依据”，四条：走读候选代码、Review 影响范围；回看请求记录，判断 Codex 依据哪些内容做出改动、看全了没有、有哪些看不见；形成可回退的提交，接受错了能用 Git 退回；无法解释或验证的候选必须缩小、拒绝或回退。

## 和现在的 2.3 对不上的地方

1. **不再走读代码**：2.3 的 diff 有几百行，课上只看像不像、新加了什么、范围对不对，不逐行走读。
2. **项目动作变了**：2.3 是参考一个主页分两轮改风格，第二轮把当前效果和参考的截图交给 Codex，再说一句哪里不满意；四条里没有这件事。
3. **“缩小、拒绝”降为一句**：演示只走接受这一条路，不满意用 `git restore` 放弃只在页面上一句。
4. **留检查点挪到 2.2**：homepage-v1 在 2.2 结尾提交，2.3 结尾再提交一次风格改动。

第 2 条（回看请求记录、看全了没有、有哪些看不见）仍然成立，是 2.3 的 Context 主线。

保持工具中立，不写请求查看工具、模型名和请求次数（章文件“对外措辞”）。

#### 第2节：补充项目经历：Context 怎样变长、清空与压缩

- 在浏览器里看过页面、构建通过后提交，留下可回退的检查点

#### 第3节：参考一个主页改风格：它看到了什么

- 参考一个喜欢的主页，让 Codex 先给计划，人确认后分两轮改出自己的风格
- 回看请求记录，判断 Codex 依据哪些内容做出改动、看全了没有：取回的参考只是它挑着读的片段，渲染出来的页面不在 Context 里
- 把看到的页面截图和自己的看法交给 Codex，理解图片怎样进入 Context；像不像，由人在浏览器里判断
- 审查新加的行为和借用素材的出处，接受后提交，不满意用 Git 回退
