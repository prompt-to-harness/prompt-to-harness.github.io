> 状态：草稿（2026-10-19），讨论起点。一位讲师已确认：地图区域对应课程三个大分组，每章一到两个地图点，画风用奇幻地图。各章的点还要两位讲师一起定。只画了本地草图，没有改动课件或大纲。
> 本文不是课程承诺。地图上的概念和章节以[内部大纲](../course-outline-internal.md) §6.1 的概念表为底稿，大纲调整时以大纲为准。

## 一、要解决的问题

- 学员学到某个概念时，不知道它在全课里处在什么位置，也不知道还有哪些大块没讲到。
- 一位讲师希望有一张统一的地图，各章讲到哪里就点亮哪里。

第 2 章已按“每章一到两个重点”的思路改以 Context 为主线，见[第 2 章提案](2026-10-19-ch02-context-storyline.md)。

## 二、每章一到两个地图点（2026-10-19 讲师确认）

地图上的区域和课程首页的三个大分组对应，四层能力落在其中：

| 课程分组 | 项目 | 地图区域 |
| --- | --- | --- |
| 第 1–3 章 | 个人主页与小游戏 | 第一块疆域，分 Prompt、Vibe Coding 两个行省 |
| 第 4–6 章 | JSON Diff | SDD 疆域 |
| 第 7–9 章 | dependency-cruiser 快照判定 | Harness 疆域 |

每章在地图上对应一到两个点，不强求只有一个。分两条线理解：

- **知识地图线**：每章点亮一到两座城市，各节从不同角度展开它们。
- **工程实践线**：验证、审查、回退、隐私和责任边界，每章都有，不算地图点。这条线是课程底线，不能因为“每章只点亮一两座城市”而变弱；现在每章最后一节的“工程经验”承担它。

## 三、形式：参考与建议

**参考**：Jonathan Boccara 在 Fluent C++ 博客上画的 [The World Map of C++ STL Algorithms](https://www.fluentcpp.com/getthemap/)（相关演讲：[105 STL Algorithms in Less Than an Hour](https://www.fluentcpp.com/2018/07/10/105-stl-algorithms-in-less-than-an-hour/)）。它把一百多个算法画成一张奇幻风格的地图：算法家族是“领土”，子家族是“行省”，每个算法是一座“城市”。只借鉴思路，不使用它的图。

地图的叙事元素：

| 地图元素 | 对应课程 |
| --- | --- |
| 三块疆域 | 三个课程分组；第一块分 Prompt、Vibe Coding 两个行省 |
| 城市 | 第二节表里的地图点；城市大小或图标区分“必做”与“看懂”，对应 §6.1 的“学习深度” |
| 一条贯穿全图的河 | Context。它在 1.2、第 2 章、3.6 Memory、7.2 版本化上下文反复出现，后面的概念大多是“什么进入 context、怎样进入” |
| 路线 | 三个项目的行程：个人主页 → JSON Diff → dependency-cruiser |
| 迷雾 | 没讲到的区域盖着迷雾，讲到的城市点亮，本章所在的城市高亮。“点亮”就是驱散迷雾 |
| 海外群岛 | §6.1 附表的“行业概念路标”（RAG、代码补全等）：看得到，但本课不登岛 |

**画风**：讲师认为地铁图太单调，不采用。2026-10-19 画了两张粗略草图对比，只在本地 `lab-runs/concept-map-sketches/`，不提交：

- **奇幻地图**：羊皮纸疆域、Context 河、迷雾和海外群岛，最有探索感；手机上要靠局部放大，整张底图难以局部修改。
- **等距群岛**：岛对应疆域，小建筑对应城市，桥按课程顺序相连；更像游戏，每个元素独立、好改；Context 河不好放。

**选定奇幻地图**（2026-10-19 讲师确认），理由：

1. **放得下 Context 河**。第 2 章以 Context 为主线，这个概念在 1.2、第 2 章、3.6、7.2 反复出现；一条河穿过三块疆域，能直接表现它贯穿全课。群岛之间隔着海，表达不出来。
2. **行省对应分组更自然**。第 1–3 章一块疆域分 Prompt、Vibe Coding 两个行省，第 3 章的城市也落在 Vibe Coding 行省里；群岛要把一个岛切成两半，或者多画一个岛。
3. **迷雾更有探索感**。这是参考 Boccara 地图的初衷；群岛的灰色建筑更像锁定的关卡。

群岛“每个元素独立、好改”的优势，已由下面的分两层制作抵消。奇幻地图在手机上看不清全图的问题，靠章节页只显示本章疆域的局部来绕开。

**分两层制作**：

1. **底图**：疆域、地形和装饰，之后交给 Codex 生图细化。底图里不画文字。
2. **状态层**：城市标记、中文文字、迷雾和高亮用我们自己的 SVG 叠在底图上，各章只切换这一层的状态（迷雾 / 已点亮 / 本章），能接上现有播放器的分步揭示。

这样大纲调整时只改 SVG 层，不用重新生图；中文文字用课程字体，不会被生图画歪。

**用在哪里**：每章开篇页和章末小结各一次，章节页只显示本章所在区域的局部，课程首页放全图。不进各节正文，避免抢画面。

## 四、制作约束

- 底图和状态层的源文件都放在 `courseware/shared/`，底图保留生图时用的提示词和版本；状态层是可编辑的 SVG，各章按状态数据渲染。离线可用，文字用现有字体子集，新增字要重建子集。
- 生图结果要确认可以在公开仓库发布；不要求生图模仿参考地图的具体画面。
- 地图不是流程图，但城市之间的连线表示概念关系，必须先对照大纲 §6.1 核对，渲染成功不代表关系正确。手绘风格可以用 `archscribe`，美化不得改变含义（见 `docs/agents/courseware-workflow.md`）。
- 不画大纲里没有的概念，不把附表的行业概念画成要学的城市。
