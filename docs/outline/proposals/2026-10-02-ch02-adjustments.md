## 一、不变与改变

**不变**：本章目标与 Vibe Coding 定位；五个小节的标题与顺序；章末工程经验节；交付物仍为迭代记录、可回退提交、公开 URL 与 `ch02-homepage-live` tag。

**改变**：

- 课程按录播设计，没有课上互动（见 `AGENTS.md`）。讲师演示推动故事线；学员可以暂停视频跟做，跟做只覆盖项目主线：反馈基线、一轮内容迭代、发布。请求查看与压缩等机制演示以看懂为准。
- 2.1 的触发点从“首页 v0 的一个窄屏问题”改为固定的课程示例反馈卡；窄屏问题依赖 AI 生成结果，不稳定。
- 2.2 的改动从“首页响应式改进”改为“补充自己的项目经历”的内容迭代，响应式与键盘检查保留为验证步骤。
- 会话选择与压缩从 2.1 移到 2.2。

## 二、故事线

**一句话**：第 1 章做出的首页 v0 只在自己电脑上运行；第 2 章把它变成**可以拿给认识的人看的 v1**，并发布出去。

**这一章在做什么**：你在自己电脑上把首页给一两个认识的人看，收到几条建议。先分清哪些是能复现的问题、哪些是偏好、哪些其实是之前做过的决定；然后只改一处，并证明改好了；AI 交回的改动读懂了再决定收不收；第一次公开前意识到，公开的不只是页面，还有整段提交历史；最后回头判断，AI 说“我只是重构了一下”能不能信。

**学员获得**：一个公开 URL；“证据 → 小改 → 审查 → 发布”的习惯；第一次看到自己一句话背后，Harness 实际发给模型的内容。

| 节 | 结构 | 情境 | 留下的东西 |
| --- | --- | --- | --- |
| 2.1 | 起 | 熟人给了三条建议，哪些是真问题？ | 带证据的反馈清单，选定一个问题 |
| 2.2 | 承 | 开始改：继续会话还是新建？只改一处并验证 | 候选改动与验证证据 |
| 2.3 | 转① | AI 交回了 diff，收不收？ | 评审过、可回退的提交 |
| 2.4 | 转② / 合 | 第一次公开：公开的不只是页面，还有历史 | 公开 URL 与 tag |
| 2.5 | 尾声 | AI 说“只是重构”，行为真的没变吗？ | 重构与行为变化判断；“没有测试，验证很贵”的伏笔 |

主转折是 2.4 的“公开的不只是页面，还有历史”：无论历史里有没有问题，这个认识本身都成立，不依赖 AI 输出。2.3 的范围扩大、2.4 的部署失败出现时就地使用，不出现不伪造。

### 示例反馈卡

课程提供一张固定的示例反馈卡，并明确标为“课程示例反馈”，学员可以换成自己收集的建议。三条各对应一种判断：

| 条目 | 类型 | 说明 |
| --- | --- | --- |
| 1. “手机上看着有点挤” | 视觉现象 | 需要在 360 视口复现，可能复现也可能不复现 |
| 2. “项目卡看着能点，点了没反应” | 既有决定 | 1.4 确认过项目卡不跳转（见 course-starter `PLACEHOLDER_CONTENT.md`）；同时用 Tab 检查键盘焦点 |
| 3. “看不出你做过什么” | 内容缺失 | 占位内容只有一句，因此必然成立；2.2 固定修改这一条 |

跟做学员的首页各不相同，配套页给出分支表：能复现 / 不能复现 / 与我在 1.4 的决定不同时，分别怎样记录和继续。讲师首页 v0 在录制前冻结，并核对第 1、2 条在其上确实成立，否则调整卡片措辞，避免变成伪装的构造失败。

## 四、逐节分镜

每节按“学员此刻面对的问题 → 证据 → 判断 → 归纳的概念”组织。下一层分段分镜（带秒数与跟做/看懂标记）见[附件](2026-10-02-ch02-storyboards.md)。

### 2.1 起：先听听别人怎么说

- **情境**：隔天回到项目，先重新启动开发服务器才能看到页面；只操作，不解释，留到 2.2 再命名。你已在自己电脑上给熟人看过首页，收到示例反馈卡上的三条建议。
- **证据**：讲师逐条核对，每条只看相关视口：第 1 条看 360；第 2 条看桌面并按 Tab；第 3 条任一视口。再让 Codex 只读核对三条建议分别对应哪些代码，不修改文件；全过程用 claude-tap 记录。
- **揭示**：Codex 怎么知道第 2 条是 1.4 定下的决定？它记得 1.4 吗？打开记录：要么看到是工具调用读取了 `PROMPT_V1.md` 等文件，而不是“记得”；要么 Codex 把第 2 条当成缺陷，说明这条决定不在它的上下文里。两种结果都能讲。顺带指出：我们写的那句话、Harness 加入的系统指令、工具定义、环境信息、工具调用与返回；一句话回扣 1.6：权限说明以文本交给模型，实际限制由本地沙箱执行。
- **判断**：第 1 条是可复现的现象还是偏好？第 2 条是既有决定，要不要改由人决定；第 3 条是内容缺失。选定第 3 条进入下一轮。
- **归纳**：反馈要有复现条件、期望、实际和证据；区分视觉现象、行为事实、个人偏好与既有决定。
- **跟做**：输入为自己的首页 v0、示例反馈卡（或自己收集的建议）与三种视口；产出为写入 `CH02_VIBE_ITERATIONS.md` 的反馈清单和选定问题。自己运行 claude-tap 为选做。
- **跟做验收**：每个问题有复现条件、期望、实际和证据，并标明类型。
- **自检（看懂即可）**：能从讲师记录中指出至少四类非用户内容。
- **1.2 衔接**：1.2 分镜不推断隐藏内容、不给固定 token 数；2.1 是第一次看到真实请求，数字只说明结构，随版本和环境变化。

### 2.2 承：只改一处，并证明改好了

- **情境**：要开始改了，继续 2.1 的会话、恢复，还是新建？
- **证据**：用 2.1 的请求记录说明三种状态：模型不保存状态；Harness 在会话内保存并重发历史（相邻请求对比）；文件和进程独立存在，回到 2.1 开场重启服务器的经历。讲师用 2.1 的会话做一次对比：“继续 + 压缩”与“新建 + 交接文件”，展示压缩后的摘要丢掉了哪些具体证据。
- **判断**：2.1 是只读探索，历史里有大量无关内容；新建会话，用反馈清单交接。
- **操作**：项目经历由人提供（讲师使用提前写好的虚构人设内容，不在镜头前现写）；Codex 只把这些内容放进项目卡，不得编造。提醒：只写愿意公开的内容。改完后在三种视口和键盘下检查，第 1 条若因内容变多而复现，记为剩余问题。
- **归纳**：一轮只解决一个连贯结果；Prompt 引用当前证据；恢复对话不等于恢复文件或服务。
- **轮数**：课上 1 轮完整闭环；课后 0–2 轮选做，不计分。
- **记录**：第 2 章轻量模板（问题证据、本轮目标、改动文件、验证结果、回退点）。
- **跟做验收**：第 3 条反馈对应的内容已呈现；三种视口与键盘没有回归；本轮记录完整；会话选择理由引用具体状态。
- **自检**：能解释“恢复对话不等于恢复文件或服务”；能说出压缩后模型不再看到哪些原始信息。
- **试讲调整**：2.2 过满时，压缩对比第一个移到配套页。

### 2.3 转①：AI 交回的改动，收不收

- **情境**：Codex 说完成了，手上是一份 diff。
- **证据**：走读 diff：内容数据放在哪里、组件怎样渲染、样式影响到哪些视口；逐项对照本轮目标，检查范围。
- **判断**：接受、缩小还是拒绝。候选若自然出现范围扩大（顺手改了无关文件或引入依赖），就地处理；内容改动多半是干净的，此时讲师用一两分钟演示如何回到上一个检查点，作为操作知识讲解，不包装成事故。
- **归纳**：commit 是让“拒绝”变便宜的检查点。2.3 判断范围（该不该收），2.5 判断性质（是否保持行为）。
- **跟做验收**：维持原验收；能说出本次回退点（commit 或 tag）以及回到它的命令。

### 2.4 转② / 合：公开的不只是页面

- **情境**：第一次推送到公开仓库。
- **证据**：用固定命令查看即将公开的提交与文件：第 1 章的环境记录、`docs/evidence/`，以及 2.2 刚写入的个人内容都在里面。例如第 1 章环境记录中的本机路径包含系统用户名，讲师示范判断“可以公开”。
- **判断**：这些内容可以让所有人看到吗？发现确实不该公开的内容（secret、他人信息、截图隐私）时先停下，不推送；改写历史的方法放在配套页，需人工复核。
- **操作**：Codex 生成部署工作流，人工审查 `base`、资源路径与工作流权限后再推送并启用 Pages；推送和启用 Pages 属于外部副作用，保留人工确认，回扣 1.6。部署后固定做三项检查：未登录窗口打开公开 URL；Network 面板没有 404 资源；刷新后仍可用。首次部署若自然出错，就地从 Actions 日志、Network 和 build 输出定位出错环节；录制时出现的真实失败保留在课件中。
- **归纳**：推送是第一个对外副作用；Actions 成功不等于页面可用。
- **仓库可见性**：学员仓库在发布前设为公开；课前准备页提前说明，避免在 1.1 创建为私有到 2.4 才发现。
- **跟做验收**：维持原验收；增加推送前检查记录与三项发布检查结果。

### 2.5 尾声：AI 说“只是重构”

- **情境**：两份标注为教学材料的 diff，都把项目卡提取为独立组件。一份保留行为；另一份顺带让卡片变得可点击、可聚焦。
- **判断**：哪一份保持了可观察行为？第二份看起来正好“解决”了 2.1 的第 2 条反馈，容易让人想接受；但 1.4 已决定卡片不跳转，AI 又声称只是重构，它仍是一次未经确认的行为变化。回指 2.2：补内容是需求变化，不是重构。
- **伏笔**：本项目没有测试，确认“行为不变”只能手工重查三种视口和键盘，成本很高，为后续规格与 Harness 章节铺路。
- **跟做验收**：判断引用具体行为证据；不因代码更短或截图更好看认定重构正确；受欢迎的行为变化也需另行确认。

## 六、请求查看工具

**当前选择：claude-tap**（[liaohch3/claude-tap](https://github.com/liaohch3/claude-tap)，MIT）。讲师演示使用；学员按配套 setup 页自愿尝试。

选择理由：单条命令接入 Codex 自定义 provider，不修改 Codex 配置文件；本地查看器支持相邻请求结构化 diff；导出 HTML 时对鉴权头脱敏；trace 默认保存在用户目录，不进入项目仓库。

已验证的接入方式（2026-10-02，Codex 0.160.0 + MiniMax 自定义 provider）：`uvx claude-tap --tap-client codex --tap-target https://api.minimax.cn/v1`，trace 写入 `~/.local/share/claude-tap/traces.sqlite3`。不经 claude-tap 时，也可用 `codex -c 'model_providers.minimax.base_url="http://127.0.0.1:端口/v1"'` 指向自写透传代理。

## 七、实测记录（2026-10-02，讲师机器，单次运行）

环境：Codex CLI 0.160.0，模型 MiniMax-M3.1-Flash-Preview，自定义 provider，Responses API。任务：只读询问一个 15 字节 `index.html` 的标题。

- 用户输入 70 字符；第一次请求输入约 1.15 万 token，其中包含约 1.7 万字符系统指令、9 个工具定义（约 1.8 万字符）、本机已安装 skills 的说明、权限说明和环境信息。
- 一次提问产生 4 次请求，`input` 从 3 项增至 10 项；缓存命中从约 1 千 token 增至约 1.18 万 token。
- 模型调用了不存在的 `read_file` 工具，收到错误后改用 `cat`；同一提问经 claude-tap 再跑一次只用 2 次请求，可作非确定性例子。
- 本地会话记录包含基础指令、developer 消息、环境信息与用量，不含工具定义。
- claude-tap 导出的 HTML 与本地 trace 库只保留鉴权头前缀，不含完整密钥。

数字随 Codex 版本、模型、已安装 skills 和任务变化，课件只用于说明结构，不承诺固定数值。

### Codex 开源仓库中的系统指令（2026-10-02 核对）

来源：[openai/codex](https://github.com/openai/codex)（Apache-2.0），核对时仓库最新提交 `ca466061d6`。大小为文件字节数，内容为英文，近似字符数。

- 系统指令按模型分文件：通用基础指令 `codex-rs/protocol/src/prompts/base_instructions/default.md`（约 20.9 KB）；`gpt_5_1_prompt.md`（约 24.2 KB）、`gpt_5_2_prompt.md`（约 21.7 KB）；为 Codex 专门训练的模型 `gpt_5_codex_prompt.md`（约 6.6 KB）、`gpt-5.1-codex-max_prompt.md` 与 `gpt-5.2-codex_prompt.md`（各约 7.6 KB）。按模型分文件始于 2025-09-14 的提交 `916fdc2a37`（“Add per-model-family prompts”）。
- 通用指令的历史不是单调变短：2025-04 首版约 5.7 KB；2025-08-05 约 9.8 KB；2025-08-07 的提交 `81b148bda2`（“update system prompt”）重写为约 23.6 KB，新增工作方式、性格、计划示例、汇报格式等章节；此后在 21.8–24.4 KB 间波动，2026-01 降到约 20.9 KB。`gpt_5_1_prompt.md` 曾增至约 28.7 KB，2026-01 降回约 24.2 KB。`gpt_5_codex_prompt.md` 从约 10–11 KB 降到 2026-01 的约 6.6 KB。
- 2026-01-12 的提交 `87f7226cca`（“Assemble sandbox/approval/network prompts dynamically”）把沙箱与审批说明从基础指令中移出，改为按配置从 `codex-rs/prompts/templates/permissions/` 下的模板拼装（如 `sandbox_mode/workspace_write.md`、`approval_policy/on_request.md`）。压缩也有独立模板 `codex-rs/prompts/templates/compact/prompt.md`。
- 与本机实测对照：本节第一次实测（Codex 0.160.0，MiniMax 自定义 provider，`codex exec`）发出的 `instructions` 约 1.7 万字符，内容与 `default.md` 一致，只是少了“Planning”及其示例和 `update_plan` 两节。为什么少这两节（是否与 `exec` 模式或工具集有关）尚未在源码中核实。

可讲的观察（设计假设，讲述时用“仓库历史显示”的口吻，不推断 OpenAI 的内部动机）：通用模型配的指令长，专门为 Codex 训练的模型配的指令短得多；新一代通用模型上线时指令反而变长；权限说明从固定段落变成按配置拼装，所以同一句话在不同配置下发出的请求不同。

### 第二轮实测（2026-10-02，Codex 0.160.0 源码 `rust-v0.160.0` 与本机运行）

本机运行均为 `codex exec`、MiniMax 自定义 provider、只读任务“读 `index.html` 的标题”，每种条件一次运行。

- **隔离 HOME**：临时 HOME 下只放 `.codex/config.toml`（model 与 provider 两段），可以正常运行。个人 Skills 列表从约 1.24 万字符降到约 2 千字符；剩下的是 Codex 自带的 4 个 Skills（imagegen、openai-docs、skill-creator、skill-installer）。第一次请求输入从约 1.15 万 token 降到约 9 千 token。隔离环境里 Codex 会自建 `$CODEX_HOME/skills` 等目录。
- **权限说明随配置变化**：权限说明是独立的 developer 消息；只读约 340 字符，`workspace-write` 约 670 字符；后者的环境信息也从约 630 字符增至约 1590 字符（多出可写范围等）。
- **Planning 两节为何缺失**：0.160.0 默认关闭 `update_plan` 工具（需配置 `[tools.update_plan] enabled = true`）；工具关闭时，Harness 在发送前删掉指令中讲计划工具的章节（`core/src/session/mod.rs`，`prompts/src/update_plan_instructions.rs`）。本地会话记录中的 `base_instructions` 保存的是删减前的全文，与实际发出的不同。
- **重发历史**：MiniMax 配置下请求体 `store` 为 false、没有 `previous_response_id`，每次请求都带上完整输入，结论限于这一配置。
- **压缩**：自定义 provider 不支持远程压缩，`/compact` 走本地压缩：用 `prompts/templates/compact/prompt.md` 让模型写一份“交接摘要”，压缩后的历史保留最近的用户消息（上限约 2 万 token）、摘要和重新插入的初始上下文；OpenAI 与 Azure provider 走远程压缩（`model-provider/src/provider.rs`）。
- **恢复会话**：在另一个目录用 `codex exec resume <会话 id>` 恢复，模型仍能答出上一轮读的是 `index.html`；Harness 追加了新的权限说明和新的环境信息，`cwd` 已是新目录，而新目录里并没有这个文件。`--last` 默认只在当前目录的会话中挑选，`--all` 取消这个过滤。
- **角色**：环境信息与 `AGENTS.md`（以 `# AGENTS.md instructions` 开头）都以 user 角色注入（`core/src/context/user_instructions.rs`）；Skills 列表与权限说明是 developer 角色。
- **Git 命令**（Git 2.50.1，本地裸仓库模拟 Template 远端）：`git log --stat origin/main..HEAD` 只列出本地新增提交；`git restore` 丢弃未提交改动；`git revert --no-edit HEAD` 新增撤回提交；只推送单个 tag 时远端只出现该 tag。course-starter 默认分支为 `main`。
- **Skill 开关**：0.160.0 有按 Skill 配置的规则（`ext/skills/src/host_service.rs` 的 `SkillConfigRules`），具体写法留到讲 Skill 的章节实测。

## 八、风险与待核实

1. **录制环境**：用户级 skills 目录位于 Codex 配置目录之外，清理 Codex 配置不会移除它们，会出现在每次请求中。2026-10-02 核对 Codex 0.160.0 源码（`codex-rs/ext/skills/src/host_roots.rs`）：个人 Skills 读自 `$HOME/.agents/skills`，`$CODEX_HOME/skills` 为兼容保留的旧位置，项目 Skills 读自仓库 `.agents/skills`。录制时同时隔离 HOME，使请求内容接近学员基线。**已实测**：临时 HOME 只放 model 与 provider 配置即可运行，Codex 自带的 4 个 Skills 仍会出现（见第二轮实测）。ChatGPT 登录方式下需要复制哪些登录文件未实测。
2. **课件中的请求记录**：截图与样例需再次检查本机路径、用户名和个人 skills 列表；统一记录标明“一次运行”，请求次数会变化（实测同一提问出现过 4 次与 2 次请求）。课程演示密钥计划在录制后轮换。claude-tap 记录不放入学员仓库的 `docs/evidence/`。
3. **ChatGPT 账号登录与 Windows**：按决定 28 不作为本章核实项。
4. **“每次重发完整历史”的适用范围**：只在 MiniMax 自定义 provider + Responses API 下实测；ChatGPT 登录、服务端保存状态或其他传输方式下可能不同。讲述时限定为“在我们看到的这次运行里”，核实前不讲成普遍规律。**MiniMax 配置已核实**：`store` 为 false、无 `previous_response_id`；OpenAI 官方 provider 未核实。
5. **压缩与恢复**：`/compact` 在录制配置下是本地摘要还是远程压缩、压缩后是否保留最近的用户消息；`codex resume` 恢复后环境信息是否按当前目录重新注入。**已核实**（0.160.0）：自定义 provider 走本地压缩，保留最近用户消息与交接摘要；恢复后按当前目录和配置追加新的环境信息与权限说明。录制若升级版本需复核。
6. **“我写的 / Harness 加的”的划分**：**已核实**：环境信息与 `AGENTS.md` 都以 user 角色注入，标注时不能只按消息角色划分。
7. **claude-tap 的边界**：只能看到经过代理的内容；服务端组装的部分看不到，在配套 setup 页说明。
8. **第 1 章的厚度**：评审认为第 1 章偏重、第 2 章偏薄。第 2 章有了真实请求证据后，1.2 中 Context Window 的讲解可能可以减轻；第 2 章定稿后再评估，暂不改第 1 章课件。

## 九、已决定（2026-10-02）

以下为本提案讨论中的决定，仍需两位讲师共同确认后才并入共同内部大纲。

1. 2.4 要求学员仓库在发布前设为公开。
2. 部署工作流由 Codex 生成、人工审查；不提供兜底参考工作流。录播学员出错时可以让 Codex 多试几次，不另备参考工作流。
3. 2.2 改为“课上 1 轮完整闭环、课后 0–2 轮选做不计分”，替代“三轮以内”。
4. 统一脱敏请求记录用 2.1 的同一只读核对任务生成，用于讲师演示与配套页；跟做不要求标注。
5. 请求查看工具当前选用 claude-tap；讲师演示，学员按 setup 页自愿尝试。
6. 时长暂不作为约束，试讲后核算。
7. 不为项目故事人为构造失败：2.3 不准备坏 diff，2.4 不准备错误 `base` 分支。真实运行中自然出现的失败就地使用并保留；没有出现时不伪造，只讲对应的检查方法。2.5 的两份对照 diff 是标明为教学材料的判断题，不属于此类，保留。与内部大纲 8.1“不得把准备好的缺陷伪装成随机现场事故”一致。
8. 不新增小节；会话选择与压缩整体移到 2.2，前缀缓存、服务端组装 Prompt 等细节放配套页。2026-10-02 评审后修订：请求解剖分两处讲，2.1 讲“一次请求里有什么”，2.2 讲“多次请求之间发生了什么”（历史重发、代价与缓存、非确定性、压缩）；仍不新增小节，平台版节数不变。
9. 第 2 章记录使用轻量模板（问题证据、本轮目标、改动文件、验证结果、回退点）；8.2 的完整证据链改为逐步要求，完整要求从第 4 章开始。
10. 三种视口与键盘检查由人完成；让 AI 打开浏览器自验证留到 Harness 章节，形成对照。
11. 课件与讲稿中的模型名以录制时实际使用的具体型号为准，录制前冻结。
12. 课程按录播设计，讲师演示推动故事线；学员跟做只覆盖反馈基线、一轮内容迭代与发布，机制演示看懂即可（已写入 `AGENTS.md`）。
13. 章节主线：把本机首页 v0 变成可以拿给认识的人看的 v1。熟人在讲师电脑上或通过截图看页面，不先发布；五节顺序不变。
14. 2.1 用固定的“课程示例反馈卡”替代窄屏问题，三条分别对应视觉现象、既有决定和内容缺失；配分支表；讲师 v0 录制前冻结并核对。
15. 2.2 固定修改第 3 条：由人提供项目经历，Codex 只负责呈现，不得编造；写入时提醒只写愿意公开的内容。
16. 2.1 以“Codex 怎么知道 1.4 的决定”引出查看请求。
17. 压缩放在 2.2 选会话时，作“继续 + 压缩”与“新建 + 交接文件”的对比；过满时先移到配套页。
18. 第 1 章记录本机完整路径不改；2.4 推送前检查时，用其中的系统用户名示范“由人判断可以公开”。
19. 第 2 条反馈贯穿全章：2.1 用 Tab 检查键盘焦点，兑现键盘检查；2.5 的行为变化 diff 让卡片变得可点击，说明受欢迎的行为变化也需确认。
20. 全章主转折是 2.4“公开的不只是页面，还有历史”。
21. 各节厚度不要求均匀：2.2 的内容迭代若只产生很小的 diff，2.3 就以演示回到检查点为主，不为加厚 2.3 而扩大 2.2 的需求。
22. 平台交付版只写工具中立的能力描述（如“查看一次真实请求的组成，理解会话与上下文”），不写请求查看工具、模型或请求次数等会变的细节。
23. 用统一脱敏请求记录制作静态“请求解剖”页，放课件站：逐块点开看原文片段和“如果没有它会怎样”；没有运行 claude-tap 的学员也能自己探索；3.6、第 7 章复用。
24. 第 1 章暂不挪内容到第 2 章；第 2 章定稿后再评估 1.2 的 Context Window 部分能否减轻（见风险与待核实）。
25. “请求会变”分两处：配置线放 2.1 请求解剖之后（隔离环境对比、只读与可写的权限说明对比）；版本线放 2.2 非确定性之后（Codex 开源仓库中系统指令的长度历史、通用模型与专用模型的指令对比）。
26. 配置对比与版本对比由讲师做示例，学员按配套页自主尝试，不要求跟做、不计入验收。
27. 隔离 Codex 环境在 2.1 首次简单讲清：个人、项目、本次三层来源，`CODEX_HOME` 与 HOME 各管什么；7.2 复用这一概念，只新增全局与项目 `AGENTS.md` 的作用域验证。Skill 的编写与禁用对比仍留到讲 Skill 的章节。
28. 课程演示与实测范围限定为 macOS 上的 Codex CLI + MiniMax 自定义 provider：国内学员不易使用 ChatGPT 账号。ChatGPT 登录、Windows、OpenAI 官方 provider 下的行为不作为本章核实项；GitHub Pages 设置较稳定，不单独跟踪；单个 Skill 开关的写法留到讲 Skill 的章节实测。
