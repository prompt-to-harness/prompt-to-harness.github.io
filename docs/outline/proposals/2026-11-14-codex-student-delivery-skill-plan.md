# 学生交付 Skill 需求 Plan

> 状态：2026-11-14，讲师提出需求，Codex 整理。本文保存需求、项目现状与待明确边界，不是 Skill 实施计划、已生效制作规范或对外承诺。适用全课，不改变现有章节内容。

## 需求与目的

备课工作的主要交付对象是负责讲师。AI 提供可审阅、可修改的内容、检查依据与缺口，由讲师作最终判断并负责。Discussion、讲述线、口播稿、教师授课 PPT、演示和必要材料，首先服务于讲师完成授课准备，不默认全部对外交付。

讲师确认授课准备完成后，再根据学生使用需要，以及其他讲师或课程负责人的具体要求，制作学生版 PPT、配套材料和其他明确需要的交付物。这部分拟由新的 Skill 承担，暂称“学生交付 Skill”；名称与最终范围待明确。

新 Skill 的需求是承接已确认的备课成果，完成面向接收方的内容组织、格式适配和必要检查，减少每次重新解释交付边界的成本。它不替代讲师确认，不重新设计课程主线，也不默认把所有备课文件导出。接收方要求若影响教学目标、范围、关键结论或讲法，应把影响交给负责讲师判断。

## 两种交付的边界

| | 备课过程交付 | 确认后的学生交付制作 |
| --- | --- | --- |
| 主要对象 | 负责讲师本人 | 学生，以及按明确要求接收成果的协作讲师或课程负责人 |
| 目的 | 支持讲师审阅、调整、确认并完成授课准备 | 支持学生阅读、回顾、跟做或查询，满足明确的交付形式 |
| 主要成果 | Discussion、讲述线、口播、教师授课 PPT、演示与材料 | 学生版 PPT、学生配套材料及讲师指定的其他成果，清单不预设为固定必交项 |
| 工作关系 | 持续维护有效内容源，保留取舍、依据和真实缺口 | 基于讲师确认的内容进行适配，不自动复制内部设计、操作提示和评论 |

学生版成品可以后置，但学生学习需要必须在备课中考虑。学习目标、项目起点、判断依据、自检解析和失败后如何继续，可能直接影响讲师的教学安排；不能等制作学生文件时才发现这些内容缺失。

教师授课 PPT 虽由讲师使用和确认，其画面仍可能出现在录制视频中。因此，授课画面的可理解性、来源与事实边界，以及不混入制作状态等要求，在备课阶段仍然适用。这不等于要求备课时同步完成另一套学生版 PPT。

## 当前仓库已有的基础

### 备课与交接方法

[course-prep](../../../.agents/skills/course-prep/SKILL.md) 已覆盖内容设计、讲述设计、制作和检查；[录制核对方法](../../../.agents/skills/course-prep/references/recording-alignment-workflow.md) 处理画面、口播、操作、材料之间的对应及复验；[共用备课方法](../../../.agents/skills/course-prep/references/preparation.md) 规定跨窗口、跨机器接续所需的源文件、入口与缺口。

这些主要支持备课成果的持续维护和录制准备，不能直接等同于面向学生或课程负责人的交付规格。分享整个 course-prep 目录属于分享备课工具，也不同于交付课程成品。

### 内容分层与现有实现

[制作手册](../../production/lesson-authoring-playbook.md#4-三层内容逐字稿阅读模式展示画面) 已区分逐字稿、阅读模式和展示画面；[课程设计原则](../../design/course-design-principles.md) 区分上课看、自己做、以后查，并明确 PPT 导出不自动等于完整讲义。

当前工程并非两套独立 PPT：[播放器](../../../courseware/shared/app.js) 使用同一组课件数据切换演示与阅读模式，阅读模式增加 `lead`、`closing` 等内容；[第 2 章示例源](../../../courseware/ch02/lessons/02-iteration/tools/build-lesson.py) 已有阅读说明。因此，“后续再制作学生版”是工作边界，不意味着现有阅读内容可以删除，也不预先决定必须拆成两套独立文件。

此前调研时，Skill 将定稿后制作“录制逐字稿页、学员阅读页和章首页”放在同一阶段，但三者用途不同：录制逐字稿页服务讲师授课准备；学员阅读页服务学生；章首页取决于其实际读者。这一混合不能仅按文件名划分；当前交接边界已明确，授课所需的录制讲稿入口不得推迟到学生材料制作阶段。

### 公开站点与平台资料

[站点构建脚本](../../../tools/build-site.py) 已按目录和文件名筛选发布内容，默认排除逐字稿页、口播源、评论、部分讲述计划和制作材料，并处理未发布章节及相关链接。调研时第三章仍在待发布集合中。这是当前实现状态，不作为新 Skill 的固定规则。

构建脚本负责文件筛选和本地链接检查，不负责判断教学内容是否适合学生，也不证明页面没有制作状态。未发布到 Pages 的文件若已提交到公开仓库，仍然是公开内容，继续遵守 [AGENTS.md](../../../AGENTS.md) 的边界。

[平台交付版大纲](../../course-outline.md) 已承载课程详情、讲师资料及宣传填写项，但未在本次调研范围内找到覆盖学生课件、视频、下载材料和协作接收要求的集中交付规格。不能从公开站点的规则推导出所有接收方的要求。

## ED 规则与这项需求的关系

| 规则 | 现有作用 | 后续需要判断的归属 |
| --- | --- | --- |
| ED-003 | 不同材料层承担不同职责，同步不等于全文复制 | 两类工作共用的基础，不应只在最终交付时读取 |
| ED-011 | 源文件与生成物一致，删除时清理引用 | 备课及学生版本转换都适用 |
| ED-013 | 操作提示与口播分开 | 主要服务讲师录制；学生材料不自动继承全部操作提示 |
| ED-015 | 完成状态在不同入口一致 | 当前已改为依据有效内容源与实际核验结果报告状态，取消旧 README 逐层同步；主要仍属于备课状态管理 |
| ED-016 | 学员页面不显示制作进度、审阅状态和排练预算 | 当前已区分备课上屏检查与学生产物检查，并移除旧 README、LOG 保存要求；必要事实限制仍保留 |
| ED-017 | 章级设计、讲述线与课件一致 | 保证转换仍承接讲师确认的方案 |
| ED-018 | 来源标注简洁，制作信息不挤入演示 | 按实际展示及接收用途处理，必要出处不能因适配被删掉 |

规则正文见[编辑规范](../../production/editorial-checklist.md)。此表是职责分析，不是迁移决定。特别是 ED-016 不能简单推广成“对外交付删掉所有状态”：学生可能不需要制作状态，接手成果的课程负责人却可能需要明确版本和缺口。

### 调研后已补充的交接约定

保存本 Plan 时，仓库已新增[学生独立使用材料交接边界](../../production/student-materials-handoff.md)，明确教师备课完成范围、后续输入输出及规则归属，并更新 ED-015、016。这些属于当前依据；本 Plan 保留前述历史问题以说明需求来源，不重复维护一套有效规则。具体学生格式、文件清单与交付流程仍待设计。

## 新 Skill 应解决的问题

- 接收讲师确认的备课成果，明确本次面向谁、要交什么、哪些内容不用交。
- 根据使用场景选择适配方式：授课画面供回顾、独立阅读、项目跟做、资料查询等用途可能需要不同内容，不默认一种格式覆盖全部需求。
- 保留已确认知识、依据和必要边界；允许补充独立使用所需的解释，但涉及教学决定的变化交由讲师确认。
- 明确交付版本、可访问入口、必要材料与实际检查结果，避免把源文件存在或构建通过当作适配完成。
- 复用现有制作和检查方法，不再复制一套 PPT、口播或教学设计规则。

## 尚待明确

1. 教师备课完成包含哪些必须可用的成果，特别是录制视图与演示准备；由讲师明确确认的范围怎样传给后续任务。
2. 学生版 PPT 的主要用途是什么，是否需要独立于视频读懂；不同课次是否允许不同交付组合。
3. 学生材料中哪些是已有成果的整理，哪些需要新增说明或制作；涉及变化时如何回到讲师判断。
4. 学生版本与教师版本采用共享数据、派生视图还是独立文件，怎样避免两边更新后失去对应。暂不作工程选择。
5. 协作讲师、课程负责人和平台分别要求哪些格式、材料和状态信息；这些要求不能代替负责讲师的教学判断。
6. 独立 Skill 的边界是否仅覆盖学生材料，还是也承接其他接收方的适配；在明确需求前，不把发布、上传、视频制作等自动纳入范围。

## 本次范围

本 Plan 只提出需求并保留调研上下文。不新建 Skill，不迁移 ED 规则，不修改课件、播放器或发布流程，不规定实施步骤与字数目标。后续讨论以职责和交付用途为依据，再决定具体组织方式。

调研采用仓库文档与代码静态阅读，未执行发布构建、线上验收或教学效果测试。外部参考仅支持学习目标、教学活动与评价需要提前对齐，不证明必须采用某种文件结构或 Skill 拆分方式：[CMU 教学设计说明](https://www.cmu.edu/teaching/assessment/basics/alignment.html)。
