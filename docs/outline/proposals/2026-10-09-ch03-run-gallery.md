# 提案：预跑多组讲共性，加一次正式主线录屏，官网展示运行对比

> 状态：草稿（2026-10-09），讨论起点，待两位讲师审阅；尚未改动任何课件页面、大纲或制作手册。原型页已做（见第五节），只用 2026-10-07 一组真实运行，未试讲。
> 针对：第 3 章（3.1–3.3 为主），方法适用于所有用真实 Codex 运行做证据的章节。
> 关联：[第 3 章故事线提案](2026-10-05-ch03-storyline.md)第六节“重跑与录制定稿”；[制作手册“重跑与录制定稿”](../../production/lesson-authoring-playbook.md#重跑与录制定稿)；[预检 A 新机器重跑](../../../courseware/ch03/materials/mainline/README.md#新机器重跑2026-10-07)。

## 一、要解决的问题

现行做法把内容分三层：代码决定的行为、行为模式、具体实例。第三层规定“录制当天替换”。2026-10-07 在另一台机器上重跑 3.1，结论都还成立，但具体实例全变了：牌数、计步规则、重开入口、缺陷类型都不一样。照现在的写法，3.1 p03、p05，3.2 p11 和 3.3 全节都要等录制当天才能定稿；录制那次没出现预期的缺陷，就得改走备用分支或临时改页。

PPT 的稳定性不应该押在单次运行上。

## 二、提议

| | 现行 | 提议 |
| --- | --- | --- |
| 课件画面的结论 | 来自一次排练，录制当天替换 | 只写跨多次运行都成立的共性，标“讲师 N 次运行中 M 次” |
| 具体截图、行号、diff | 录制当天替换 | 来自一份固定的课程样本（提交进仓库），不再替换 |
| 正式录屏 | 录制运行即定稿，没出现就走备用分支 | 保留一次主线录屏，展示操作方式；它是“又一次运行”，按检查表归类，不改 PPT |
| 多次运行的差异 | 当作噪音 | 当作证据：3.2 的“这条规则是谁定的”直接用对比表讲 |
| 重跑的作用 | 核对前两层 | 核对前两层，同时给对比页增加样本 |
| 学员看到的 | 一次排练输出 | 官网对比页：并排试玩、对比矩阵、共性归纳、逐轮证据 |

讲法顺序（依据见第三节）：先用一次完整的主线录屏把操作走通 → 学员自己跑或试玩两三份 → 并排对比 → 讲师点明共性 → 回到学员自己的结果，按检查表归类。

## 三、社区有没有人这样做（2026-10-09 调研）

调研笔记与完整报告在讲师本机 `lab-runs/research_notes/`、`lab-runs/reports/`（不提交）。要点：

- **没找到把“先跑 N 次、讲共性”当成教学方法的公开课程**，也没找到“同一模型多次运行、并排可试玩”的课程网站。中文社区（B 站、知乎、掘金）未做站内检索，是空白。
- **跨模型对比画廊**最接近展示形式：oneshotlm（<https://oneshotlm.com/>）每个 prompt 一页截图网格，单个 run 页同时给出完整过程和可运行产物；Goldie Bench（<https://goldiebench.com/>）收录可试玩 demo。它们比的是不同模型，一个模型通常只有一份。
- **同一模型多次采样**：Dylan Castillo 的 pelicanmaxxing（<https://dylancastillo.co/posts/pelicanmaxxing.html>，2026-07）每个 prompt 采样 3 次，可按次筛选；Simon Willison 的 pelican 系列是长期跑同一个 prompt。
- **研究**：Ouyang 等 “LLM is Like a Box of Chocolates”（<https://arxiv.org/abs/2308.02828>，2023）记录了同一编程 prompt 多次请求结果不一致；“Identical Runs, Different Results”（<https://arxiv.org/abs/2609.33812>，2026-09）同一任务跑了 584 次，同一组合内部的差异大于组合之间，得分最高的几次运行违反了任务规则，并公开了全部产物。后者与本章“能玩不等于验收”直接呼应。
- **录制实践**：开源课程仓库 coding-agent-cursus 的 issue #42（<https://github.com/GuilhemBusset/coding-agent-cursus/issues/42>）：真实运行只录一次，附 CLI 版本、模型、日期，录前去掉路径与密钥，失败也照录。
- **教学依据**（多为数学与 CS1 研究，迁移到 AI 运行属于推论，部分只核对到摘要）：CS1 对照实验中 live coding 没有测出学习收益（Shah、Raj 等，ICER 2023）；并排比较多种解法优于逐个看，前提是有支架、不要太早比较（Rittle-Johnson & Star）；variation theory 主张在不变的背景上呈现变化（Marton）。
- **工具**：Inspect AI 的 `inspect view bundle` 可导出静态站点；Docent 能把失败模式聚类，但需要服务端；promptfoo 的分享链接不公开。会话转 HTML 的社区工具多数只有二手描述，未核实，不写进课件。

## 四、官网对比页的设计

- **入口按问题组织，不按运行编号。** 页面顺序：不变的条件 → 先自己玩 → 对比矩阵（行是规则，列是运行）→ 共性卡片 → 逐轮证据。
- **每个结论能追到证据**：发现附代码片段与行号；Codex 计划原文、执行步骤（命令只取首行）、交回说明、完整 diff 都可展开。作废的运行也列出，并写明原因。
- **试玩按不可信内容处理**：点开才加载；单文件构建放进 `sandbox="allow-scripts"` 的 iframe（不加 `allow-same-origin`），用 `srcdoc` 载入。实测内置浏览器里 sandbox 加 `src=` 的页面脚本不执行，`srcdoc` 才正常。
- **数据管线**：原始记录留在被忽略的 `lab-runs/`；人工标注写在 `courseware/ch03/materials/runs/annotations.json`；`build-gallery.py` 生成脱敏的 `data.js` 与单文件构建，写出前检查不得残留本机路径或疑似密钥。不提交 `exec --json` 原文、claude-tap 记录与 Codex home。
- **措辞边界**：统计一律写成“讲师某机器某日 N 次运行中 M 次”，不写成 Codex 的普遍行为；机器与 Node 版本作为条件列出。

## 六、待讨论

1. 方向是否采纳：课件只写共性加固定样本，录屏不再替换 PPT。
2. 固定样本选哪份：现有 run8（10-06），或 10-07 第 3 轮（说明与牌组矛盾，修法要由人定）、第 5 轮（3 对就通关）。无论选哪份，源码都要以 diff 形式提交，换机器才能复现。
3. 对比页放在哪里：第 3 章首页链接，还是只在 3.2 课件里给入口；学员是否要提交自己的运行参与对比。
4. 样本规模：每章跑几组、几台机器才算“共性”；10-06 与 10-07 两组是否合并展示，是否让机器与环境差异单独成为一个维度。
5. 字体：对比页收录了 Codex 原文，每加一批运行都会带来新汉字，手写字体子集也得跟着重建。可以考虑让 `data.js` 的文字只用正文字体，并从标题字体的覆盖检查里排除。
6. 制作手册“重跑与录制定稿”一节要不要按本提案改写，以及其他章节是否沿用。
