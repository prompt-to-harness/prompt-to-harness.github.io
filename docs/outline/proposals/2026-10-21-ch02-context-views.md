## 三、建议的各节视角

项目动作不变（看请求 → 补经历 → 审改动 → 发布），每节换一个 context 视角：

| 节 | 项目动作 | context 视角 | 主要变化 |
| --- | --- | --- | --- |
| 2.1 | 重启服务器，问两句 | **组成**：一次请求里有什么 | 不变；可加“点名文件 vs 让它找”的对比（待实测） |
| 2.2 | 写 `AGENTS.md`，补项目经历 | **增长与管理**：重发、代价、`/status` 看剩余、`/clear`、压缩与自动压缩 | 去掉屏幕尺寸教学页和记录建议页；加 `/status` 和自动压缩阈值 |
| 2.3 | 审 diff，提交一次 | **可见范围**：它依据什么改，看得全不全，看不见什么（浏览器、没读的文件、被截断的输出） | Git 收成一页；屏幕尺寸改成“它看不见页面”的例子；去掉三层检查 |
| 2.4 | 推送、部署 | **context 和外部**：网页搜索进 context、`gh` 调用出 context、context 发给了谁 | 部署原理压缩成跟做清单；推送前隐私检查和“context 发给谁”合讲 |
| 2.5 | — | 经验分享 | 已重做 |

## 四、要讲师决定的

1. 第三节的视角划分是否采用；2.3 改叫“可见范围”是否合适。
2. 三种屏幕尺寸：完全不教设备模拟（只说“打开页面看一眼”），还是保留一句操作提示。
3. 是否要做“点名文件 vs 让它找”的对比实验（成本：一次 `codex exec`）。
4. “context 发给谁”从“最多口播一句”提升为一页，是否同意。

确认后，按决定改章文件和课件，`/status`、自动压缩、输出截断三处先在课程基线上实测，再写进课件。
