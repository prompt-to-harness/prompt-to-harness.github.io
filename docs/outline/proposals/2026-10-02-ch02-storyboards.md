## 2.3 AI 交回的改动，收不收

| 段落 | 学员问题 | 证据与揭示顺序 | 学员判断 | 归纳 | 方式 |
| --- | --- | --- | --- | --- | --- |
| 拿到 diff | Codex 说完成了，就能收吗？ | `git status --short` → `git diff --stat` → 改了几个文件 | 文件范围对不对 | 完成不等于可接受 | 跟做 |
| 走读 diff | 这些改动分别做了什么？ | 内容数据在哪 → 组件怎样渲染 → 样式影响哪些视口 → 逐项对照本轮目标 | 有没有无关修改或新依赖 | 读懂再决定 | 跟做 |
| 接受、缩小或拒绝 | 我该怎样处置？ | 三种处置的条件 → 本次结论 → 提交 | 本次属于哪一种 | 范围扩大就地处理，不伪造 | 跟做 |
| 回到检查点 | 万一收错了，怎样回去？ | 未提交：丢弃工作区改动；已提交：用新提交撤回；指出回退点 | 说出本次回退点和命令 | commit 让“拒绝”变便宜 | 看懂（命令跟做验收要求能说出） |
| 小结 | — | 2.3 判断范围，2.5 判断性质；三层检查本章只有人工 | — | — | 看懂 |

**回退命令的默认选择**：未提交用 `git restore`；已提交用 `git revert`；不教 `git reset --hard`，因为 2.4 要公开历史，改写历史放配套页。录制前按实际 Git 版本实测。
