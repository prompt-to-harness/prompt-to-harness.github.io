# 从 Prompt 到 Harness：用 Codex 完成三个递进式真实项目（简化版）

## 第 0 章导入与九章课程大纲

> 第 0 章为独立开场访谈，新增暂估 25–30 分钟；含导入全课暂估 878–883 分钟（14 小时 38–43 分钟）。以下九章按 3+3+3 分配，共 46 小节、暂估 853 分钟（14 小时 13 分钟）；第 1-6 章共 628 分钟，Harness 三章各 75 分钟、共 225 分钟。每章至少 4 节、建议不超过 8 节；工程经验第 1 章暂排 10 分钟，其余暂排 15 分钟，可在 10–15 分钟内试讲调整。第 2 章先选会话再迭代；第 3 章拆开 Plugin 审查与实践，第 4 章拆开需求来源与仓库调查。知识按首次需要讲清，实践连续推进，章末复用证据做判断；所有时长待试讲。

### 全局约束与讲解边界

- 课程按 `Prompt -> Vibe Coding -> SDD -> Harness` 逐层叠加，三个教学仓库互不依赖：第 1-3 章使用个人主页 Starter Repo，第 4-6 章使用 JSON Crack 固定 Release，第 7-9 章使用 dependency-cruiser 固定 Release。后一仓库不继承前一仓库的代码、Git 历史、会话或 Harness。
- Codex CLI 是主要教学界面和完整验收路径。第 1.1 节允许把经核验的 ChatGPT 桌面端作为同一最小任务的临时入口，最迟在第 1.3 节结束前切回 CLI；桌面端、其他智能体或录制快照不能冒充 Codex CLI 操作通过。
- 必须长期生效的团队规则写入仓库 `AGENTS.md` 或版本化文档。全局 `AGENTS.md` 只保存个人跨项目偏好；Memory 只承担辅助回忆，不能成为团队规则或项目事实的唯一来源。
- Plugin、MCP、GSD 和其他第三方能力都必须先审查来源、许可证、版本、脚本、网络和权限。核心项目不得依赖某个外部插件或服务；不可用时走标明降级的课程快照或工具无关路径，且降级观察不得记作实际操作通过。
- Skill 只能沉淀已经验证的重复流程，必须包含输入、步骤、输出、停止条件和验收标准。第 7 章不创建项目 Skill；第 9.2 节在成功流程通过门禁后才允许封装。
- Sub-agent 只承担边界清楚的调查或分区写入，生产代码修改保持串行。主 Agent 负责证据核验和冲突裁决；顺序调查、回放或 generic fallback 不能计为命名角色委派通过。
- 运行结果、测试、浏览器检查、diff、Review 和 Git 检查点共同构成合入证据。看不懂、无法验证或超出范围的方案必须暂停、拆小、拒绝或回退。
- 正式录制前需再次核对 Codex CLI 版本、账号权限、workspace 配置，以及 JSON Crack、dependency-cruiser、GSD Core 的固定 Release 与完整 commit。可选功能不得成为完成核心项目的前置条件。

### 第 0 章：开场访谈——我们为什么这样学 Vibe Coding

- **形式与时长**：双讲师访谈，暂估 25–30 分钟，待试讲；开场自我介绍加 8 个正式问题，11 页课件。不套用正课每章至少 4 节的结构，原第 1–9 章编号和 46 小节不变。
- **学习目标**：说清三个独立项目、希望获得的协作能力，以及第 1.1 节的首次任务。
- **开场**：两位讲师各用 60–90 秒介绍姓名、工作方向、接触 Vibe Coding 的时间与起因。
- **访谈顺序**：①哪次经历让你觉得值得认真用；②工作发生的变化；③踩过的坑与调整；④人与 AI 怎样分工；⑤三个课程项目及安排理由；⑥成果与可独立完成的任务；⑦适合的基础与卡住时怎么办；⑧怎样跟课才能真正学会。每题两人分别回答，交替首答，避免重复。
- **课程路线**：第 1–3 章个人主页与小游戏，第 4–6 章 JSON Crack JSON Diff，第 7–9 章 dependency-cruiser 快照身份与新鲜度判定核心。用通俗语言介绍 Prompt、Vibe Coding、SDD、Harness，不提前展开工具操作。
- **输入与产出**：两位讲师经核对的真实履历、案例与现行大纲；产出为学员的一句学习目标与课程路线自检，不新增代码交付或计分作业。
- **验收与衔接**：能说出三个项目、一个希望独立完成的任务、首次实操的目标；进入 1.1，完成环境检查、修改指定欢迎语并检查结果与 diff。
- **讲解边界**：个人经历必须由讲师提供，未提供处明确待填；不编造效率数据，不承诺零基础就业、全自动开发或工具永远可用。三个项目各自从固定基线开始，Harness 正课只完成限定垂直切片。
- **课件入口**：[开场访谈](../../../courseware/ch00/index.html)、[双讲师提纲](../../../courseware/ch00/speaker.html)。

### 第 1 章：Prompt - 从环境启动到首页原型

> **学习顺序**：1.1 实践 → 1.2 知识 → 1.3 知识＋操作 → 1.4 知识＋练习 → 1.5 实践 → 1.6 工程经验。各节输入与产出见下文；外部练习材料单独提供，章末复用本章证据。

#### 1.1 环境搭建与第一次 AI 协作闭环

- **时长与定位**：28 分钟；实践（原 25 分钟，另加 3 分钟官方安装入口与课程模型介绍，不压缩其他内容）。
- **新增导入**：在环境检查前，用 3 分钟从 OpenAI 官方资料演示 Codex CLI 安装入口、按系统选择安装方式与登录路径，并说明课程主要使用 MiniMax M3，简要介绍 GPT-6 Astra、Claude Opus 5、Claude Fable 5 等观察对象。MiniMax M3 接入教学 Codex 的方式尚待实测，Claude 两个名称与定位尚待官方资料核验；不作未经验证的性能排名。区分工具安装与模型选择；模型可用性以教学账号为准，不扩展为模型原理课。
- **教学目标**：按已核验路径完成环境检查和首次小任务，留下浏览器、diff 与反馈修正证据；操作前说明目录、文件范围和确认点。
- **输入与衔接**：课前环境与指定欢迎语；产出：首次闭环证据→1.2。
- **验收标准**：版本、路径、分支和初始工作树状态有记录；Agent 在执行前复述目标并给出小计划；实际结果与 diff 均已人工检查；改动仅位于允许范围；发现的问题已经修正或明确记录。若使用桌面端起步，状态标记为“临时通过”，必须在第 1.3 节结束前补齐 CLI 基线；其他智能体或录制快照不能计作 Codex 操作通过。
- **讲解边界**：本节只改指定欢迎语和必要仓库状态，不进入正式 React 应用；CLI 是教师主演示和完整验收路径，经核验的桌面端只作为同一任务的临时入口；不在视频中等待长时间下载，环境失败按降级路径处理，不改源码伪装成功；其他智能体或录制快照不计为 Codex 操作通过。

#### 1.2 Agent 执行机制与 AI 协作基础

- **时长与定位**：15 分钟（含末尾 1-2 分钟行业概念口播，不另加课时）；知识。
- **教学目标**：从首次任务讲清 Agent、Context、Tool 与执行循环，区分输入、请求和结果；后续工具在首次使用时再展开。
- **输入与衔接**：1.1 的原始记录；产出：循环图与信息分类→1.3/1.4。
- **验收标准**：能各用一句话解释 Agent、Tool、Context 和 Context Window；能够从自己的首次任务中指出对应证据；分类理由可解释；没有把 AI 输出直接标成事实；能说出至少 3 种失败方式。术语表述不要求逐字一致。听过或未记住代码补全、RAG、工具调用、多模态理解或发展脉络，均不作为本节不合格理由。
- **讲解边界**：概念必须对应首次闭环中的证据，不讲模型训练、推理架构或完整配置字段；行业概念口播只对照代码补全、RAG、工具调用、多模态理解和 AI Coding 发展脉络各说一句，不练习、不考核、不另加课时，也不引入 Auto Research。

#### 1.3 工具使用与权限

- **讲授顺序**：工具入口介绍 → 动作辨认 → 权限三层 → 授权流程 → 执行结果 → 场景判断。先比较 ChatGPT App 的图形入口与 Codex CLI 的终端入口，再说明课程以 CLI 统一实操与记录；桌面端的项目接入、工具执行与权限行为须按授课版本核验。复用 1.1 的环境检查结果，不再单设环境验收页；仅从桌面端临时起步者补 CLI 只读检查，环境变化者复核变化项，所有学员核对本次实际权限与停止条件。结合欢迎语任务辨认读取、修改、命令执行与对外操作的影响，并阅读请求、批准、工具返回和结果证据，区分执行成功与任务完成。本节仍为 15 分钟。

- **时长与定位**：15 分钟；知识＋操作。
- **教学目标**：完成 CLI 基线，判断当前操作的权限与停止条件；界面选择不能代替权限核验。
- **输入与衔接**：循环图与环境记录；产出：CLI 基线、权限选择→1.4/1.5。
- **验收标准**：能说明两种界面的选择理由和替代边界；CLI 的路径、状态和权限已经核对；没有使用危险的全权限配置；外部副作用保留人工确认；失败环境没有靠改源码或改用其他工具伪装成功。从桌面端起步但未完成 CLI 基线者不得进入后续 CLI 专属验收。
- **讲解边界**：不演示危险的全权限或 bypass 配置；不把未经核验的桌面端、其他智能体或其他模型说成 CLI 的等价替代；界面更好用不等于权限可以放宽；从桌面端起步但未完成 CLI 基线者，不得进入后续 CLI 专属验收。

#### 1.4 写清首页任务：从模糊需求到可执行 Prompt

- **时长与定位**：20 分钟；知识＋练习。
- **教学目标**：将模糊首页需求改成 Goal、Context、Constraints、Done when，并由人确认未知项。
- **输入与衔接**：目标、占位内容与权限范围；产出：已确认 Prompt→1.5。
- **验收标准**：四要素齐全；完成标准能观察或执行；写明非目标、文件范围和停止条件；执行前存在人工确认点；未知项没有被偷偷决定。
- **讲解边界**：只针对主页首屏与项目展示区收集上下文，不提前写代码；完成标准必须可观察或可执行，并写明非目标、文件范围和停止条件；未知项不得被偷偷写成已决定事实。

#### 1.5 完成首页任务：从已确认 Prompt 到可验收的首页 v0

- **时长与定位**：20 分钟；实践。
- **教学目标**：依据确认的 Prompt 生成首页 v0，运行、构建、Review 并建立检查点。
- **输入与衔接**：Prompt 与 CLI 基线；产出：首页 v0、build、diff→第 2 章。
- **验收标准**：页面能启动；`npm run build` 成功；无明显控制台错误；diff 只包含目标范围；环境检查页未进入正式应用；仓库无 secret 和私人资料。
- **讲解边界**：环境检查页不得进入正式应用或发布产物；不在现场追加无限美化；页面“看起来像成品”不能替代构建、diff 和代码理解；v0 仍是 Prompt 原型，不把当前视觉和行为冻结为正式产品规格。

#### 1.6 工程经验：为什么不能给 Agent 所有权限

- **时长与定位**：10 分钟（工程经验允许在 10–15 分钟内试讲调整）；工程经验。
- **教学目标**：解释最小权限，用新任务条件作判断，复用本章记录而不重复权限操作。
- **输入与衔接**：本章权限记录与新任务卡；产出：最小权限判断→后续外部工具审查。
- **验收标准**：能把权限选择对应到具体任务；不把 Prompt 中的禁止语句当作已生效的技术限制；不执行危险操作来证明风险。
- **参考与讲解边界**：Saltzer & Schroeder 的系统保护原则；知识线中即时解释操作前提，本节集中解释取舍，不重复安装与权限操作。

### 第 2 章：Vibe Coding - 迭代首页并发布 GitHub Pages

> **学习顺序**：2.1 知识＋观察 → 2.2 实践 → 2.3 实践 → 2.4 知识＋实践 → 2.5 工程经验。各节输入与产出见下文；外部练习材料单独提供，章末复用本章证据。

#### 2.1 用真实页面建立反馈基线

- **时长与定位**：25 分钟；知识＋观察。
- **教学目标**：用页面证据形成问题清单；先讲清会话、文件与进程的区别，再选继续、恢复、压缩或新建会话。
- **输入与衔接**：首页 v0 与会话摘要；产出：反馈清单与会话策略→2.2。
- **验收标准**：每个问题有复现条件、期望、实际和证据；能说明继续、恢复、压缩或新建会话的理由，不要求背诵命令；能区分对话、文件和进程问题。
- **讲解边界**：截图只作为上下文，不能单独当作结论；至少覆盖布局、键盘和内容三类检查，不把个人审美偏好写成缺陷。

#### 2.2 小反馈、小改动、小验证

- **时长与定位**：20 分钟；实践。
- **教学目标**：按已选会话策略完成小改动与前后验证，不重讲会话概念；留下候选 diff。
- **输入与衔接**：选定问题与会话策略；产出：候选修改与验证证据→2.3。
- **验收标准**：原问题不再复现；桌面视图没有回归；每轮变更目标、文件、验证结果和剩余问题均有记录。
- **讲解边界**：Prompt 必须引用当前证据；发现新问题时不顺带扩大范围，也不为修一个 CSS 问题重写全部组件或引入大型 UI 依赖。

#### 2.3 读懂 AI 代码、Review 与回退

- **时长与定位**：15 分钟；实践。
- **教学目标**：走读候选代码、Review 影响范围，完成修正或回退并形成可发布提交。
- **输入与衔接**：候选 diff 与完成标准；产出：评审通过的提交→2.4。
- **验收标准**：修改目的与影响面可解释，阻塞问题已处理；无无关依赖、整页重写或未说明的行为变化；可定位回退点。
- **讲解边界**：会话选择在 2.1、操作在 2.2；本节只评审实际变更，无法解释或验证的候选必须缩小、拒绝或回退。

#### 2.4 GitHub Pages 首次发布

- **时长与定位**：20 分钟；知识＋实践。
- **教学目标**：建立最小部署流程，人工确认后发布，并在公开 URL 验证。
- **输入与衔接**：通过 Review 的首页；产出：公开 URL 与部署证据→第 3 章。
- **验收标准**：Actions 成功；URL 可在未登录窗口访问；CSS/图片路径正确；刷新后仍可用；公开内容与提交历史通过隐私检查。
- **讲解边界**：外部发布必须由人确认；本章不加完整质量门禁；GitHub Actions 成功不等于页面已经可用；不得硬编码讲师仓库名，也不得把 secret、私人资料或未授权素材放入公开站点。

#### 2.5 工程经验：AI 说只做重构，意味着什么

- **时长与定位**：15 分钟（工程经验允许在 10–15 分钟内试讲调整）；工程经验。
- **教学目标**：区分保持行为的重构与需求变化，指出需要复查的证据。
- **输入与衔接**：首页 diff 与对照材料；产出：重构/行为变化判断→后续 Review。
- **验收标准**：判断引用具体行为证据；不因函数更短或截图更好看认定重构正确；需求变化应另行确认。
- **参考与讲解边界**：Fowler《重构》；代码气味只作一句补充，不新增一轮无必要重构。

### 第 3 章：Vibe Coding + Plugin - 用小游戏体验快速迭代与 Plugin

> **学习顺序**：3.1 实践 → 3.2 知识＋观察 → 3.3 实践 → 3.4 知识＋审查 → 3.5 实践 → 3.6 知识＋对照 → 3.7 工程经验。各节输入与产出见下文；外部练习材料单独提供，章末复用本章证据。

#### 3.1 用 Vibe Coding 加入记忆翻牌

- **时长与定位**：20 分钟；实践。
- **教学目标**：用普通 Vibe Coding 完成记忆翻牌的可玩切片，保留首页原功能。
- **输入与衔接**：公开首页 v1；产出：记忆翻牌 v0→3.2。
- **验收标准**：能翻牌、配对、完成和重开；首页原功能可用；production build 通过；未加入非目标功能。
- **讲解边界**：允许 Codex 提少量问题并给出计划，但暂不建立正式规格；保持一个仓库和现有视觉语言；不加入排行榜、账号、后端或其他非目标功能。

#### 3.2 探索状态空间而不是只走 Happy Path

- **时长与定位**：15 分钟；知识＋观察。
- **教学目标**：先画游戏状态，再探索快速操作、等待和重开；记录问题，本节不试修。
- **输入与衔接**：游戏 v0；产出：状态图与复现步骤→3.3。
- **验收标准**：每个问题有最小步骤、期望、实际和截图或日志；至少覆盖快速操作、重开和移动端。
- **讲解边界**：不得只测一条成功路径就把“我玩了一遍”当作验证；至少覆盖快速操作、重开和移动端。

#### 3.3 基于证据调试一次真实缺陷

- **时长与定位**：20 分钟；实践。

> **学习顺序**：7.1 知识＋实践 → 7.2 知识＋实践 → 7.3 实践 → 7.4 工程经验。各节输入与产出见下文；外部练习材料单独提供，章末复用本章证据。

> Harness 三章暂排各 75 分钟，先冻结任务与评分，再做 A/B 对照；独立故障练习不污染原始运行。产品只实现快照身份与 fresh/equivalent/stale/unknown 判定核心，不增加 CLI、真实 Git 探测或新 reporter。

#### 7.1 无 Harness 冷启动与摩擦基线

- **时长与定位**：20 分钟；知识＋实践。
- **教学目标**：先区分 Worktree 文件隔离与 Session 对话；在 A 运行前冻结任务、评分与对照条件，记录无课程 Harness 的真实结果。
- **输入与衔接**：运行前冻结的任务、评分与基线；产出：A 原始记录→7.2；保留到9.1。
- **验收标准**：运行条件在开始前锁定；失败和成功均如实保留；没有事后修改评分标准；A 工作树与后续 B 工作树隔离；一次运行只作为本课对照证据，不宣称普遍结论。
- **讲解边界**：运行条件在开始前锁定；失败和成功均如实保留；没有事后修改评分标准；A 工作树与后续 B 工作树隔离；一次运行只作为本课对照证据，不宣称普遍结论。

#### 7.2 自举代码地图与版本化上下文

- **时长与定位**：20 分钟；知识＋实践。
- **教学目标**：讲清个人偏好、常驻项目规则和按需地图，核验入口后建立版本化上下文。
- **输入与衔接**：A 记录与源码；产出：版本化地图和规则→7.3。
- **验收标准**：能说明“个人跨项目偏好”和“团队项目规则”的区别；新会话能指出规则来源、项目入口和验证命令；仓库文件没有复制整份教程；不存在尚未运行成功却写成事实的命令。
- **讲解边界**：能说明“个人跨项目偏好”和“团队项目规则”的区别；新会话能指出规则来源、项目入口和验证命令；仓库文件没有复制整份教程；不存在尚未运行成功却写成事实的命令。

#### 7.3 建立任务模板与统一检查入口

- **时长与定位**：20 分钟；实践。
- **教学目标**：复用冻结任务与已验证命令，建立统一检查入口和 Harness v1，不提前封装 Skill。

- **讲解边界**：检查实际运行成功；命令不暗中修改文件；模板不引入隐藏产品要求；Harness patch 与任务包、产品实现分离。四状态优先级为：必要 provenance 缺失或 dirty 为 unknown；否则图、配置、规则、范围或工具版本指纹不同为 stale；指纹相同且 commit 相同为 fresh，否则为 equivalent。

#### 7.4 工程经验：上下文与文档为什么会过期

- **时长与定位**：15 分钟（工程经验允许在 10–15 分钟内试讲调整）；工程经验。
- **教学目标**：用独立过期地图判断失效与维护责任，解释文档为何不自动等于理解。
- **输入与衔接**：独立的过期地图练习；产出：维护判断；不污染冻结评测输入。
- **验收标准**：能区分仓库事实、AI 推断和个人偏好；不把未经核验的命令写成事实；地图练习不更改冻结任务与评分。
- **参考与讲解边界**：Naur《Programming as Theory Building》及试讲卡；应用到 Agent 是教学映射，不把多写文档当作唯一解法。

### 第 8 章：Harness - 执行任务与处理失败

#### 8.1 在 Harness 条件下执行固定任务

- **时长与定位**：20 分钟；实践。

- **讲解边界**：能指出两个 Worktree 的共同代码基线和唯一 Harness 差异；两次输入、设置、权限和停止条件一致；`fresh/equivalent/stale/unknown` 及输入顺序无关案例可重复；结果互不污染；结论区分产品结果、过程差异和非确定性，不能用单次实验声称普遍提升。

#### 8.2 检查失败后的有限修复与人工交接

- **验收标准**：成功路径能因正确原因失败并在修复后通过；停止路径说明已尝试内容、剩余问题与所需人工决定。教学故障不混入 A/B 评测，不修改验收期望来消除失败。
- **讲解边界**：成功路径能因正确原因失败并在修复后通过；停止路径说明已尝试内容、剩余问题与所需人工决定。教学故障不混入 A/B 评测，不修改验收期望来消除失败。

#### 8.4 工程经验：自动化的责任边界与快速失败
