## 本章主线

**一句话**：把个人主页补成真正能用的样子（个人信息、经历、项目，再参考一个喜欢的主页调一处风格）并发布上线；一路打开 Codex 实际发出的请求，看清 context 长什么样、怎么变。

**主知识点**：Context，本章要讲透。每节一个项目动作，配 context 的一种状态：组成 → 变化 → 后果（依据与看不见的、发到了哪里）。

**锚点图**：“这一次请求里有什么”，画成一列方块（系统指令、工具、环境、规则、对话历史、工具返回、这一句）。全章都回到这张图：2.1 认识它，2.2 看它变长、被清空、被压缩，2.3 指着它问依据在哪一块、哪些东西不在里面，2.4 指着它问它发到了哪里。数字只做旁注。

**起点**：项目连续，证据不连续。讲师演示从第 2 章起点快照开始；课件只引用当前的产品代码和本章任务卡，不引用第 1 章的过程记录（C2-54）。

## 各节要点

主线跟做，计入验收；深入只要求看懂，每一条回答主线引出的一个追问，只收机制类内容（每次运行都一样的）。时长合计约 95 分钟。

| 节 | 项目动作 | 主线（跟做） | 深入（看懂）：回答的追问 | 验收 |
| --- | --- | --- | --- | --- |
| 2.1 只说了一句话，模型收到了什么（25 分钟） | 重启开发服务器，问两句 | 一次请求里有什么；工具调用和返回进入 context；点名文件和让它自己找，代价差几倍。第二问问“项目区现在显示什么、数据在哪个文件”，答案在当前代码里，正好是 2.2 要改的地方 | **这一列是谁定的？** Codex（这层 Harness）按个人、项目、本次三层来源组装；同一句话在不同权限、能力目录开或关时的请求并排一页；子代理有自己的 context，只露出一句 | 跟做：开发服务器重启，个人主页可用。看懂：从讲师请求记录中指出至少四类非用户内容，说出缺了其中一类会怎样；指出一次工具调用和它的返回 |
| 2.2 补上个人经历，看对话怎么变长（25 分钟） | 写两三行 `AGENTS.md`；学员先自己写一份个人信息文件（学校、工作经历、项目，只写愿意公开的），`/clear` 后分几轮让 Codex 放进页面 | 每次请求都重发前面的内容，代价是 token 和注意力；失败的返回也一直留着；`/clear` 清对话不清文件；压缩后只剩摘要；会话和文件是两回事 | **能不能少发一点、留下想要的？** `AGENTS.md` 在清空和压缩后重新进入；缓存为什么便宜却不省注意力；`/status` 看还剩多少，到窗口 90% 自动压缩 | 跟做：个人信息、经历和项目已呈现，内容都来自人写的个人信息文件、没有 AI 编造；在浏览器里看过页面，`npm run build` 通过；能说出本轮会话选择的理由，依据是 Codex 界面里看得到的“这个会话读过哪些文件、做过哪些事”（不装 claude-tap 也能做到） |
| 2.3 它看到了什么，才这样改（20 分钟） | 找一个喜欢的主页作参考，只改一处风格（配色、排版或某一个区块）；审查 diff，接受、缩小或拒绝，提交 homepage-v1 作为检查点 | 给参考时用的是 URL、截图还是文字描述，模型实际拿到的东西不同；参考的是风格，不照搬别人的代码和内容。在请求记录里找改动的依据：改的文件改前读过没有，每处改动来自 Prompt、规则文件还是读到的文件；Prompt 之外的调用 diff 里看不到；提交一次留下检查点 | **它看全了吗、看得见吗？** 长输出会被截断；没读的文件、浏览器里的页面不在 context 里，它会自己想办法补；确认计划时，验证步骤也要看 | 跟做：修改目的与影响面说得清，没有无关依赖、整页重写或未说明的行为变化；提交 homepage-v1，提交说明写本轮目标与改动文件，能说出回到它的命令。看懂：能指出 Codex 改动的依据，说出它看不见的一样东西 |
| 2.4 发布上线（15 分钟） | 推送前看清整段历史，部署 GitHub Pages | 推送前看历史，发布，做三项检查；对外动作由人确认 | **这一列发到了哪里，外面的东西怎么进来？** context 每次都发给模型服务，和推送公开是两回事；网页搜索的结果进 context；`gh` 把动作送出去，要经批准 | 跟做：URL 未登录可访问、Network 中没有 404 资源、刷新后仍可用；推送前看过完整历史，公开内容与历史里没有 secret、他人信息或不愿公开的个人信息（自检）；推送、改设置这类对外动作都经人确认。看懂：context 发给了谁 |
| 2.5 用好 context 的三个做法（10 分钟） | 无，另一位讲师分享 | — | 重发换算成费用；换会话时自己写交接；换一个工具看同一句话的请求 | 看懂即可，不设练习和自检题 |

**不放进本章**：系统指令的版本历史（配套页，第 7 章讲“规则会过期”时再用）；`gh` 调用在记录里的位置细节（讲师提示）；`git revert` 的完整演示（复现按钮）；只在某一次运行里出现的现象（只放讲师提示，见[可讲点清单](../outline/proposals/2026-10-21-ch02-teachable-points.md)的稳定性列）。
