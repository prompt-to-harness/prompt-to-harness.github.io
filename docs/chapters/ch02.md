## 本章主线

**一句话**：把第 1 章的首页 v0 补完整并发布上线；一路打开 Codex 实际发出的请求，看清 context 长什么样、怎么变。

**本章目标**：学员把首页 v0 补完整，发布第一个公开版本；过程中打开 Codex 实际发出的请求，能指出 context 由什么组成、怎样随对话变长、清空和压缩之后还剩什么，并据此选择会话、审查改动。

**主知识点**：Context。第 1 章讲 context 里该放什么，本章打开请求看它实际长什么样、怎么变。每节一个项目动作，配一个 context 视角。第二个主点是否为项目 `AGENTS.md`，见“待定”。

**这一章在做什么**：先用 claude-tap 启动 Codex，只发一句话，就能看到请求里远不止这句话。接着把自己的项目经历加进首页：对话多了，context 跟着变长；`/clear` 和压缩之后还剩什么，也在记录里看得到。Codex 交回改动时，回到记录里看它是根据哪些内容改的，再决定要不要接受；回退靠 git，不靠对话。发布时，在记录里看 Codex 怎样调用 `gh`。最后，Codex 说“只是重构”，而 context 里没有能证明行为没变的运行结果。

**学员获得**：

- 一个公开 URL，以及一份评审过、可回退的提交。
- 能从一份请求记录里指出不是自己写的内容，并说出缺了会怎样。
- 能根据会话的状态选择继续、`/clear`、压缩或新建会话，并说出理由。
- 习惯在接受改动前问“它当时看到了什么”。

**贯穿线索**：同一套配置下的 claude-tap 请求记录。不要求是同一次运行，可以分开录；2.4 因为 `gh` 要读本机登录，另起一次。2.1 第一次打开，后面每节都回到它。画面每段标“一次运行”。

**不设转折**：章内按顺序展开，不为起伏安排情节；自然出现的失败就地使用，不伪造。2.4 的推送前检查是一项正常检查，不是全章转折。

## 2.1 看懂一次请求：Context 由什么组成

- **时长**：25 分钟
- **知识点与 Codex 操作**：一次请求的组成：系统指令、工具定义、Skills 列表、环境信息、权限说明与用户输入，逐块说明“如果没有它会怎样”。这些加在一起就是 context，引用 Anthropic《Effective context engineering for AI agents》（2025-09-29）的说法，不自造定义，录制前核对。工具调用与返回怎样进入 context，回扣 1.2 的循环。同一句话在不同权限配置或不同模型配置（模型能力目录开或关）下发出的请求不同；请求由个人、项目、本次三层来源组装。Skills 只指出“列在这里”，不展开，留到第 3 章。会话、清空与压缩在 2.2。
- **教师演示**：开场直接说明本章要做什么（补完整、发布上线、看清 context）。回到项目先重启开发服务器（只操作，2.2 再解释）。PPT 给出 claude-tap 的启动方式和三条说明，然后用它启动 Codex。分两步发 Prompt，两个都事先设计、保证稳定触发要展示的内容：先发一句与项目无关的话，看 context 的基本组成；再发一个与项目相关的只读问题（“Codex 怎么知道 1.4 的决定”），看工具调用和返回怎样进入 context。对比同一句话在不同权限下发出的请求；示例对比同一句话在模型能力目录开、关时的请求（系统指令、工具数量和形态都不同）。隔离 HOME 与个人 Skills 的对比放配套页。
- **学员练习**：跟做部分为重启开发服务器，确认首页 v0 可用。请求组成看懂即可；自己运行 claude-tap 为选做，不计入验收。
- **阶段产出**：讲师的第一份请求记录（全章复用）。
- **验收方式**：能从讲师请求记录中指出至少四类非用户内容，并说出缺了其中一类会怎样；能指出一次工具调用和它的返回在记录里的位置。

## 2.2 补充项目经历：Context 怎样变长、清空与压缩

- **时长**：25 分钟
- **知识点与 Codex 操作**：三种状态：模型不保存状态，会话由 Harness 保存并在每次请求中重发，文件与进程独立存在。相邻两次请求：前一轮的内容被重发，代价是 token 与注意力，重复前缀可被缓存。失败或白跑的工具调用和报错返回也留在 context 里，之后每次请求都会重发；用本轮实录里自然出现的弯路说明，不构造失败，弯路次数只算一次运行的观察（回指 0.1：结果会变，过程也会变，不再重讲随机性本身）。`/clear` 清屏并开始新对话，context 回到初始状态（另有 `/new` 只开始新对话、不清屏；录制版本再确认一次）。压缩后模型看到的是摘要。继续、清空、压缩后继续或新建会话加交接的选择条件；恢复对话不等于恢复文件或服务。一轮只解决一个连贯结果；Prompt 引用当前页面与文件；发现新问题时不顺带扩大范围。Codex 指令随版本和模型变化（以其开源仓库历史为例）放配套页。OpenAI 文档 Conversation state 作为阅读链接。
- **教师演示**：边做边看：先用 `/clear` 开始本轮并看清空后的请求，选会话、写 Prompt、让 Codex 执行，再用本轮的请求记录对比相邻两次请求，看重发的代价和留下的弯路。由人提供项目经历（讲师演示借用两位讲师已公开简介中的经历，合在第 1 章的示例页面上），Codex 只负责在项目区呈现、不得编造。在这次真实任务上压缩，对比压缩前后哪些具体内容被换成了摘要；会话太短、看不出差别时改用 `courseware/ch02/materials/compact/` 的独立实验，并如实说明。用三种屏幕尺寸、键盘与 `npm run build` 验证。
- **学员练习**：输入为自己的首页 v0 与愿意公开的项目经历；写本轮 Prompt，完成 1 轮完整闭环；课后 0–2 轮选做，不计分。PPT 上给一页建议记录项（本轮目标、会话选择与理由、验证结果、剩余问题），不计入验收。
- **阶段产出**：项目区内容迭代（候选改动，未提交）。
- **验收方式**：项目经历已呈现，内容由人提供，没有 AI 编造的经历；三种屏幕尺寸与键盘没有回归，`npm run build` 通过；能说出本轮会话选择的理由，依据是 Codex 界面里看得到的“这个会话已经读过哪些文件、做过哪些事”，学员不装 claude-tap 也能做到。

## 2.3 读懂 AI 代码、Review 与回退

- **时长**：15 分钟
- **知识点与 Codex 操作**：先看范围再看内容：走读候选 diff 中的内容数据、组件渲染与样式影响面，对照本轮目标决定接受、缩小或拒绝；判断看这一轮的证据。检查“有没有做 Prompt 没让它做的事”。打开本轮的请求记录，看 Codex 读了哪些文件、依据什么改；范围扩大时，常能在 context 里找到原因：多读了无关内容，或缺了本轮目标。commit 是让“拒绝”变便宜的检查点；未提交用 `git restore`，已提交用 `git revert`，不教改写历史。清空或压缩对话不会撤销文件改动，回退靠 git，呼应 2.2 的三种状态。三层检查（自动检查、自动 Review、人工 Review）中，本章自动检查只有构建，Review 全靠人工。2.3 判断范围，2.5 判断性质。
- **教师演示**：走读 2.2 的真实 diff，对照请求记录指出 Codex 的依据；范围扩大自然出现时就地处理，没有出现时在临时分支演示回到检查点。不准备坏 diff，不把演示包装成事故。跟做的 Git 命令收在六条左右（`git status`、`git diff`、`git add <路径>`、`git diff --cached`、`git commit`、`git restore`），配一张工作区 → 暂存区 → 本地提交 → 远端的状态图；`git revert` 只演示。
- **学员练习**：输入为 2.2 的 diff、验证结果和本轮目标；形成评审结论，完成必要修正或回退，输出 homepage-v1 提交，提交说明写明本轮目标与改动文件。
- **阶段产出**：可发布的 homepage-v1 提交。
- **验收方式**：修改目的与影响面可解释，阻塞问题已处理；无无关依赖、整页重写或未说明的行为变化；能说出本次检查点及回到它的命令。

## 2.4 GitHub Pages 首次发布

- **时长**：20 分钟
- **知识点与 Codex 操作**：推送是本课第一个对外副作用。推送前看清即将公开的源码和整段提交历史（含历史中出现过又删除的文件），由人判断能否公开；发现 secret、他人信息或截图隐私时先停下。公开仓库、Vite production build、GitHub Actions 和 Pages 的关系；审查 `base`、资源路径、工作流权限与触发分支；Actions 成功不等于页面可用。在请求记录里看 Codex 用 GitHub CLI（`gh`）设置 Pages 来源：命令、批准和返回各在哪里，作为一次清楚的 CLI 调用示范；批准申请写在调用里，点同意这一步不在记录里。本章只建立包含 build 的最小部署流程，第 7 章在独立 dependency-cruiser 仓库建立统一检查入口。推送由人执行；Pages 来源交给 Codex 用 `gh` 设置，每条命令由人在批准框中确认、在网页上刷新核对；没装 GitHub CLI 时在网页上手动设置。
- **教师演示**：先建立个人空远端并核对 origin，首次推送前检查当前分支的完整历史，以提交作者的姓名和邮箱示范“由人判断可以公开”。Codex 生成部署工作流与 Vite 配置，人工审查后提交；不提供兜底参考工作流，出错时让 Codex 再试。给 Codex 的 Prompt 写明“没有 Pages 站点就用 POST 创建，已有就用 PUT 修改”。Codex 设置 Pages 来源（人批准每条命令），随后在请求记录里指出这次 `gh` 调用；人来推送；做三项发布检查。首次部署若自然出错，就地从 Actions 日志、build 输出和 Network 定位。“请求里的文件内容也发给了模型”最多口播一句，不单独成页。
- **学员练习**：输入为本地通过检查的首页；发布前把仓库设为公开，完成推送前检查后发布；输出 URL、三项检查结果和 `ch02-homepage-live` tag（只推送这一个 tag）。
- **阶段产出**：公开首页 v1。
- **验收方式**：URL 可在未登录窗口访问；Network 中没有 404 资源；刷新后仍可用；推送前看过完整历史，公开内容与提交历史中没有 secret、他人信息或不愿公开的个人信息（自检）。

## 2.5 工程经验：AI 说只做重构，意味着什么

- **时长**：10 分钟（工程经验允许在 10–15 分钟内试讲调整）
- **情境**：个人主页已经上线。假设你让 Codex 整理一下代码，它交回五个改动，说明都写着“只是重构，行为不变”。这次推上去，所有看你主页的人都会看到结果：发布之后，改错了就是公开的回归。五张卡是标明的课程教学材料，不说成一次真实运行。
- **知识点与 Codex 操作**：解释 Refactoring / 重构、Observable Behavior / 可观察行为与 Regression / 回归；区分保留行为的结构调整和需求变化。“只是重构，行为不变”是 Codex 下的结论，依据要到 context 里找：context 里有说明、diff 和 build 结果，没有一次能证明行为没变的运行结果，build 只说明能打包。行为的证据要靠运行检查得到（打开页面、并排比样式、按 Tab、三种屏幕尺寸）。
- **教师演示**：五张标注为教学材料的小卡，各自基于 homepage-v1：提取组件、移动数据（行为没变）；按名称排序、缩短类名、让卡片可聚焦（行为变了；最后一张用到时就地复述第 1 章“项目卡不跳转”的决定）。学员先问“这个结论的依据在哪”：只看说明和 diff 能判断到哪一步；再按“打开页面 → 并排比 → 按键盘”逐张拿到运行证据揭晓，最后借 Fowler《重构》归纳。可回指本章两个真实对照：2.2 压缩后 Codex 自己区分了“亲眼看到的原文”和“只来自摘要的推断”；2.4 p48 它说“核对过版本”，请求记录里有网页搜索作为依据。证据图默认用静态截图，只有 ⑤ 的 Tab 焦点现场按一次。收尾：这一章回到 context 的运行结果只有 build；后面讲规格和测试的章节（第 4–6 章）把“行为”写成能运行、结果能回到 context 的检查。
- **学员练习**：输入为五张卡和原完成标准；对每张写出“依据在哪”：说明和 diff 能说明什么，还需要哪项运行检查（顺序、并排比样式、键盘与屏幕尺寸）才能下结论。
- **阶段产出**：重构与行为变化判断，答在暂停自检题里。
- **验收方式**：判断引用具体的运行证据；不因提交说明、代码更短、diff 更小、build 通过或截图更好看认定重构正确；受欢迎的行为变化也需另行确认。
- **参考与讲解边界**：Fowler《重构》；代码气味只作一句补充，不新增一轮无必要重构。

## 常见错误与风险

- 让 AI 为解决一个 CSS 问题重写全部组件或引入大型 UI 依赖；
- 让 AI 替自己编写项目经历，或把不愿公开的内容写进公开仓库；
- 只看最终截图，不检查键盘操作、链接、控制台和已有的屏幕尺寸；
- 把请求记录里的 token 数、请求次数或指令长度当成固定值；
- 以为清空或压缩对话会撤销文件改动；
- 硬编码讲师仓库名，导致学员的 Vite `base` 或 Pages 路径错误；
- 把 GitHub Actions 成功等同于页面已经可用；
- 在公开站点或提交历史中暴露个人敏感信息、未授权图片或 secret。

## 交付物与退出门禁

- 完成 2.5 的工程判断，引用具体行为证据与理由；允许合理接受 AI 建议，不按术语背诵评分。
- 1 轮必做的内容迭代，形成评审过、可回退的 homepage-v1 提交，提交说明写明本轮目标与改动文件；
- 推送前看过完整历史，以及一个可公开访问的 GitHub Pages 首页；该 URL 是必做自检项，但课程不统一收取；
- 学员能用公开 URL、Network 面板和 Actions 日志验证发布结果，不把 Actions 成功当作页面可用；出现失败时能指出出在哪一环；
- 能从讲师请求记录中指出 context 的组成；能用这个会话里已经读过的文件、做过的事解释一次会话选择。
