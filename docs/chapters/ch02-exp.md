# 第 2 章配套：约定、各节细节、决策与实测记录

> 第 2 章的重点（主线、各节要点与验收、退出门禁、待定）在 [ch02.md](ch02.md)，验收只写在那里；这里放支撑它的细节：全章约定、各节完整的演示与操作说明、实验安排、常见错误、决策记录和实测记录。两份合起来是第 2 章的唯一来源，改细节只改这里。

## 全章约定


- **全章基线**：`tools/clean-codex.sh` 默认的 MiniMax-M3.1-Flash、MiniMax 官方模型能力目录开、推理档位 max。能力目录开时系统指令只有一句加多代理团队说明，主要用法写在 code mode 的 `exec` 工具描述里。课件数字按这套配置录。
- **claude-tap**：讲师演示的必要内容，固定 0.1.146。PPT 上写清启动方式并录屏演示，说明它是本地代理、会经手 API 密钥、只看得到经过代理的内容。学员自己运行算选做，不计入验收；不另做分系统的排障文档。ChatGPT 登录下能否使用，不作为主演示内容。
- **演示与实测范围**：macOS 上的 Codex CLI + MiniMax 自定义 provider。ChatGPT 登录、Windows、OpenAI 官方 provider 下的行为不作为本章核实项。
- **章节独立**：本章只依赖第 1 章留下的个人主页；没做完第 1 章的学员可从第 1 章参考快照开始（见 course-starter `CHECKPOINTS.md`）。引用前面章节时就地复述决定或做法本身，检查点写“本轮开始前的最后一次提交”，不依赖之前各章的证据文件或 tag 名。
- **少用跨章引用**：不用“1.4 的决定”“回扣 1.2”这类节号当钩子，学员和讲师都记不住那段上下文。需要前面的内容时，直接说出内容本身，例如“项目卡点了不跳转，是做个人主页时定下的”。
- **Harness 的两个意思**：本章只用第一个意思，即 Codex 这层 Harness：包在模型外面、组装请求、调用工具、管权限的那一层。2.1 拆开请求时先用一句话说明，并点明课程第四层要为项目搭的 Harness 是另一层意思，第 7 章再讲。之后正文写“Codex（这层 Harness）”，不单写“Harness”。
- **记录方式**：本章不设固定记录文件，学员按自己的习惯记笔记或截图。本轮目标和改动文件写进提交说明；检查点就是提交本身；推送前检查结果学员自己看过即可；公开 URL 和三项发布检查放进自检清单；会话选择理由答在暂停自检题里。
- **页面检查**：本章由人在浏览器里看一眼页面、跑一次 build，不再列屏幕尺寸和键盘检查；想看手机上的样子，只在 2.2 p31 的操作提示里一句（设备工具栏切到 360×800）（C2-45、C2-48）。第 3 章讲 Skill 时，把页面检查做成 Codex 能自己跑、结果能回到 context 的检查（跨章安排，待第 3 章确认）。
- **对外动作由人确认**：推送、改 Pages 设置、触发部署都是对外动作。可以人自己执行，也可以交给 Codex、人在批准框里看清命令再确认；不能不经人确认就送出去（C2-47）。
- **跟做与看懂**：跟做＝学员暂停视频完成，计入验收；看懂＝机制演示，以自检为准；示例（选做）＝讲师演示，学员可按配套页自主尝试，不计入验收。学员跟做只覆盖一轮内容迭代、Review 与发布。
- **不构造失败**：2.3 不准备坏 diff，2.4 不准备错误的 `base`。用到准备好的教学材料时标明是教学材料，不说成一次真实运行。
- **演示只走正常路径**：录屏演示一条走通的路；分支情况（没装 `gh`、空仓库暂时不能启用 Pages 来源等）写在操作提示和配套页，口播不展开。自然出现的失败照常就地处理。
- **各节厚度不要求均匀**：2.2 的改动若很小，2.3 就以演示回到检查点为主，不为加厚 2.3 而扩大 2.2 的需求。
- **模型名**：课件与讲稿以录制时实际使用的具体型号为准，录制前冻结。
- **对外措辞**：平台交付版只写工具中立的能力描述，不写请求查看工具、模型或请求次数这类会变的细节。

## 细节：2.1 看懂一次请求：Context 由什么组成

- **时长**：25 分钟
- **知识点与 Codex 操作**：一次请求的组成：系统指令、工具定义、Skills 列表、环境信息、权限说明与用户输入，逐块说明“如果没有它会怎样”。这些加在一起就是 context，引用 Anthropic《Effective context engineering for AI agents》（2025-09-29）的说法，不自造定义，录制前核对。工具调用与返回怎样进入 context：模型提出动作，工具执行，结果返回，再决定下一步。先用一句话说明“组装请求的这一层叫 Harness”，见全章约定。同一句话在不同权限配置或不同模型配置（模型能力目录开或关）下发出的请求不同；请求由个人、项目、本次三层来源组装。Skills 只指出“列在这里”，不展开，留到第 3 章。会话、清空与压缩在 2.2。
- **教师演示**：开场直接说明本章要做什么（补完整、发布上线、看清 context）。回到项目先重启开发服务器（只操作，2.2 再解释）。PPT 给出 claude-tap 的启动方式和三条说明，然后用它启动 Codex。分两步发 Prompt，两个都事先设计、保证稳定触发要展示的内容：先发一句与项目无关的话，看 context 的基本组成；再发一个与项目相关的只读问题（“这个个人主页当初定了哪些要求和完成标准？依据来自哪个文件的哪一段”），看工具调用和返回怎样进入 context。对比同一句话在不同权限下发出的请求；示例对比同一句话在模型能力目录开、关时的请求（系统指令、工具数量和形态都不同）。隔离 HOME 与个人 Skills 的对比放配套页。p14a 对比同一个问题点名两个文件和不点名：8 → 3 次请求、15 → 2 次调用、输入约 12.6 万 → 2.6 万 token，依据相同（2026-10-21 实测）。
- **学员练习**：跟做部分为重启开发服务器，确认个人主页可用。请求组成看懂即可；自己运行 claude-tap 为选做，不计入验收。
- **阶段产出**：讲师的第一份请求记录；后面各节回到同一套配置下的请求记录（C2-30）。
- **验收**：见 [ch02.md](ch02.md) 各节要点。

## 细节：2.2 补充项目经历：Context 怎样变长、清空与压缩

- **时长**：25 分钟
- **知识点与 Codex 操作**：三种状态：模型不保存状态，会话由 Codex（这层 Harness）保存并在每次请求中重发，文件与进程独立存在。项目 `AGENTS.md` 是第三种状态的例子：它是一个文件，每次新对话开始时 Codex 读它、放进请求，所以对话清空了，写在里面的规则还在。只讲它在请求里的位置和“文件还在”这一点，怎样写好规则留到第 7 章。相邻两次请求：前一轮的内容被重发，代价是 token 与注意力，重复前缀可被缓存。失败或白跑的工具调用和报错返回也留在 context 里，之后每次请求都会重发；用本轮实录里自然出现的弯路说明，不构造失败，弯路次数只算一次运行的观察（回指 0.1：结果会变，过程也会变，不再重讲随机性本身）。`/clear` 清屏并开始新对话，context 回到初始状态（另有 `/new` 只开始新对话、不清屏；录制版本再确认一次）。压缩后模型看到的是摘要。`/status` 的 Context window 一行看现在用了多少（Token usage 是会话累计）；用到窗口 90% 时自动压缩（p27b，2026-10-21 实测，演示时把触发线调到 1 万）。继续、清空、压缩后继续或新建会话加交接的选择条件；恢复对话不等于恢复文件或服务。一轮只解决一个连贯结果；Prompt 引用当前页面与文件；发现新问题时不顺带扩大范围。Codex 指令随版本和模型变化（以其开源仓库历史为例）放配套页。OpenAI 文档 Conversation state 作为阅读链接。
- **教师演示**：边做边看：先在项目根目录写一份两三行的 `AGENTS.md`（例如“改完运行 `npm run build`，在回复里给出结果”“不新增依赖”），再用 `/clear` 开始本轮，在清空后的请求里指出它单独成块；然后选会话、写 Prompt、让 Codex 执行，用本轮的请求记录对比相邻两次请求，看重发的代价和留下的弯路，并看 Codex 是否照规则跑了 build。项目经历事先准备好，放在 `courseware/ch02/materials/README.md`（取自两位讲师已公开的简介，三条已确认），录制时由讲师粘进 Prompt，Codex 只负责放进项目区、不得编造；首屏仍是第 1 章的示例内容，口播说明“项目区借用了两位讲师的经历”。在这次真实任务上压缩，对比压缩前后哪些具体内容被换成了摘要；会话太短、看不出差别时改用 `courseware/ch02/materials/compact/` 的独立实验，并如实说明。验证只看一眼页面、跑一次 `npm run build`（p31）。p29 的 Done when 已简化为“我在浏览器里看过页面正常；你跑 build 成功；diff 只含项目区”，2026-10-21 20:30 按它重录。
- **学员练习**：输入为自己的个人主页与愿意公开的项目经历；按需写一份同样两三行的 `AGENTS.md`（选做，不计入验收）；写本轮 Prompt，完成 1 轮完整闭环；课后 0–2 轮选做，不计分。不设记录建议页（原 p32 已删除）。
- **阶段产出**：项目区内容迭代（候选改动，未提交）。
- **验收**：见 [ch02.md](ch02.md) 各节要点。

## 细节：2.3 它看到了什么，才这样改（可见范围）

- **时长**：15 分钟
- **知识点与 Codex 操作**：先看范围再看内容：走读候选 diff 中的内容数据、组件渲染与样式影响面，对照本轮目标决定接受、缩小或拒绝；判断看这一轮的证据。检查“有没有做 Prompt 没让它做的事”。打开本轮的请求记录，看 Codex 读了哪些文件、依据什么改；范围扩大时，常能在 context 里找到原因：多读了无关内容，或缺了本轮目标。commit 是让“拒绝”变便宜的检查点；未提交用 `git restore`，已提交用 `git revert`，不教改写历史。清空或压缩对话不会撤销文件改动，回退靠 git，呼应 2.2 的三种状态。看全了吗（p38b）：工具输出约 1 万 token 以上会被截断，中间插“…N tokens truncated…”，2026-10-21 用 `cat package-lock.json` 实测（原约 17178 token）。看不见什么（p38c）：没读的文件、浏览器里的页面不在 context 里，Codex 开无头 Chrome 是想把页面搬进来。它说“没动别的”“页面没问题”时，先问它实际拿到了什么。
- **教师演示**：走读 2.2 的真实 diff，对照请求记录指出 Codex 的依据；范围扩大自然出现时就地处理，没有出现时在临时分支演示回到检查点。不准备坏 diff，不把演示包装成事故。Git 收成 p40 一页：`git add`、`git diff --cached`、`git commit` 提交一次，加一句 `git restore` / `git revert`；revert 的完整步骤在 p40 的复现按钮里，讲师在临时分支演示（C2-45，原 p41、p41a 状态图已删除）。
- **学员练习**：输入为 2.2 的 diff、验证结果和本轮目标；形成评审结论，完成必要修正或回退，输出 homepage-v1 提交，提交说明写明本轮目标与改动文件。
- **阶段产出**：可发布的 homepage-v1 提交。
- **验收**：见 [ch02.md](ch02.md) 各节要点。
- **素材**：2.2 的 p23、p24、p27、p30、p31 和 2.3 全节都用 2026-10-21 20:30 那次 2.2 运行（`2.2-simple-20261021-203050`，Done when 已简化），学员在 2.2 看到的计划、弯路和压缩，就是 2.3 审的那份 diff 和请求记录（C2-50）；p22、p27a 只讲结构，仍用 16:22 那次。`git status` 里多一行 `?? AGENTS.md`（2.2 人写的规则），审过后和 `src/App.tsx` 一起提交；起预览服务器和 `curl` 核对写在计划的验证步骤里，各申请一次沙箱外运行，没有无头 Chrome。录制时按当次记录讲，不预设出现哪一种。

## 细节：2.4 GitHub Pages 首次发布

- **时长**：20 分钟
- **知识点与 Codex 操作**：推送是本课第一个对外副作用。推送前看清即将公开的源码和整段提交历史（含历史中出现过又删除的文件），由人判断能否公开；发现 secret、他人信息或截图隐私时先停下。公开仓库、Vite production build、GitHub Actions 和 Pages 的关系；审查 `base`、资源路径、工作流权限与触发分支；Actions 成功不等于页面可用。在请求记录里看 Codex 用 GitHub CLI（`gh`）设置 Pages 来源：命令、批准和返回各在哪里，作为一次清楚的 CLI 调用示范；批准申请写在调用里，点同意这一步不在记录里。本章只建立包含 build 的最小部署流程，第 7 章在独立 dependency-cruiser 仓库建立统一检查入口。推送和设置都由人确认（见全章约定）：讲师演示里推送由人自己执行；Pages 来源交给 Codex 用 `gh` 设置，每条命令由人在批准框中确认、在网页上刷新核对。2026-10-21 实测里 Codex 还自己用 `gh workflow run` 补跑了失败的部署，这条也走了批准框；录制时出现类似调用，就指出它也是对外动作，看清再批准。讲师用 `CLEAN_CODEX_GH=1 tools/clean-codex.sh` 启动，学员同样；没装 GitHub CLI 时在网页上手动设置，这条只写在操作提示里。
- **教师演示**：先建立个人空远端并核对 origin，首次推送前检查当前分支的完整历史，以提交作者的姓名和邮箱示范“由人判断可以公开”。Codex 生成部署工作流与 Vite 配置，人工审查后提交；不提供兜底参考工作流，出错时让 Codex 再试。给 Codex 的 Prompt 写明“没有 Pages 站点就用 POST 创建，已有就用 PUT 修改”。Codex 设置 Pages 来源（人批准每条命令），随后在请求记录里指出这次 `gh` 调用；人来推送；做三项发布检查。首次部署若自然出错，就地从 Actions 日志、build 输出和 Network 定位。“context 发给了谁”升为一页 p46a：推送是公开给所有人，context 是每次请求发给模型服务（课程基线是 api.minimax.cn），secret 和他人信息不推送也别让它读进 context（C2-45）。p48 补一句：写工作流时 14 次网页搜索的结果也进了 context。
- **学员练习**：输入为本地通过检查的个人主页；发布前把仓库设为公开，完成推送前检查后发布；输出 URL、三项检查结果和 `ch02-homepage-live` tag（只推送这一个 tag）。
- **阶段产出**：已发布的个人主页。
- **验收**：见 [ch02.md](ch02.md) 各节要点。

## 细节：2.5 用好 context 的三个做法（经验分享）

- **定位**：由另一位讲师讲，分享一组和本章 context 有关、学员马上用得上的做法；不再是一个独立的软件工程判断题。原来的软件工程内容分散到前面各节，在动作发生时讲（例如 2.3 的“它说没动别的，依据在哪”）。
- **时长**：10–15 分钟，试讲后定。
- **内容**：一组三条左右，彼此递进或并列，每条都能回到本章的请求记录（取自[经验分享候选池](../outline/proposals/2026-10-20-experience-sharing-pool.md)第 2 章一组，2026-10-21 各实测一次，见 2.5 分镜）：
  1. 看懂 token 和缓存花在哪：把 2.2 看到的“重发”换算成时间和费用；
  2. 什么时候开新会话、怎样写交接：比 2.2 的四种选择再往前一步；
  3. 换一个 coding agent 看请求：同一句话在另一个工具里发出的请求长什么样。
- **分镜与课件**：[2.5 分镜](../../courseware/ch02/lessons/05-experience/STORYBOARD.md)（目录 2026-10-21 由 `05-refactor` 改名），课件 p59–p63 已按它重做（2026-10-21），节标题“用好 context 的三个做法”；三条各实测一次，待核实事项列在分镜里。
- 原 2.5“AI 说只是重构”的五张分拣卡和重构、可观察行为、回归这几个术语，转入软件工程候选，放到有测试的章节（第 5–6 章）更合适，那时“行为没变”可以用测试结果回答。

## 常见错误与风险


- 让 AI 为解决一个 CSS 问题重写全部组件或引入大型 UI 依赖；
- 让 AI 替自己编写项目经历，或把不愿公开的内容写进公开仓库；
- 只看 Codex 的完成报告或截图，自己不在浏览器里看一眼页面、不跑 build；
- 把请求记录里的 token 数、请求次数或指令长度当成固定值；
- 以为清空或压缩对话会撤销文件改动；
- 会话中途写好 `AGENTS.md` 就以为 Codex 已经看到，没有 `/clear` 或开新会话；
- 2.4 启动时没加 `CLEAN_CODEX_GH=1`，Codex 发现 `gh` 未登录就自己发起登录，人没有拒绝；
- 硬编码讲师仓库名，导致学员的 Vite `base` 或 Pages 路径错误；
- 把 GitHub Actions 成功等同于页面已经可用；
- 在公开站点或提交历史中暴露个人敏感信息、未授权图片或 secret。

| 写入之后、同一对话 | 没有：会话中途新写的文件不会进请求 |
| `/clear` 之后 | 有：`# AGENTS.md instructions for <项目目录>` 加 `<INSTRUCTIONS>…</INSTRUCTIONS>`，和环境信息在同一条 user 消息里；`/clear` 后是新的会话 id |

所以 2.2 的顺序必须是先写 `AGENTS.md`、再 `/clear`。另外，每轮回答之后 Codex 还会单独发一次请求，让模型生成会话标题（“Generate a concise, single-line task title”）；数请求次数时要把它分开。

**`CLEAN_CODEX_GH`**（`gh-login-0-20261021-132530`、`gh-login-1-20261021-133702`）：同一句只读请求，让 Codex 运行 `gh api repos/prompt-to-harness/prompt-to-harness.github.io/pages`。

| 开关 | 结果 |
| --- | --- |
| 关 | 沙箱里 `gh api` 报未登录（退出码 4），Codex 随即自己发起 `gh auth login --web` 网页登录；讲师中止，没有完成登录，真实 `~/.config/gh` 未改动 |
| 开 | 沙箱里先报连不上网络，Codex 申请到沙箱外运行，批准一次后成功返回 `build_type: workflow` 和网址 |

教学上的含义：2.4 一定要带开关启动；没带时 Codex 会自己去登录，这一步要人拒绝。
