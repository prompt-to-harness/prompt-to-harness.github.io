## 本轮只研究 3.2.2：读懂简单 Skill

讲师已明确：3.2 的五部分拆分没有问题，本轮只解决第二部分的内容与讲法，不重新讨论整节结构。
这里的任务是让学生拿到一份简单 Skill，能够读懂其中的要求，并结合一次真实调用理解这些文字怎样指导 AI 工作。
不要求学生在本部分修改、从零编写或优化一份 Skill。

因此，阅读教学文章和企业分享时，只提取与“读懂正文”有关的内容：正文包含哪些指导、规则和例子各是什么意思、它们如何对应到行动与产物、为什么这样一份正文已经足够。
资料组织、脚本、Plugin 分发和紫色风格制作不是本报告建议展开的教学任务。

先前报告把“读懂”扩成了写法、资源选择和整节安排，范围偏大。
以下收窄为简单正文的精读，不改变已确定的五部分结构。

## 3.2.2 具体讲四件事

以下是根据调研提出的精读范围，不是 Skill 的固定目录，也不是让学生学会编写的步骤。
使用同一份简单正文和一次调用结果解释，不靠不断增加文件和案例拓展难度。

| 要讲清的问题 | 具体内容 | 用简单品牌 Skill 怎样讲 |
| --- | --- | --- |
| 1. 正文里究竟写了什么？ | 从文件实际内容辨认具体规范、默认做法、条件分支和例子。<br>说明它们分别让 AI 遵守什么，不要求每份 Skill 都有同一套栏目。 | 指出颜色值及用途、标题与正文字体、字体不可用时的替代。<br>学生应能解释这些要求的意思，不只是认出 Colors、Typography 等标题。 |
| 2. 这些文字怎样影响本次工作？ | 对照本次请求与产物，找出正文中具体要求的采用情况。<br>区分用户此次提供的内容、Skill 提供的规范，以及模型自行决定的细节。 | 本次请求给页面或产物的主题与内容，Skill 给品牌颜色和字体，未规定的布局可能由模型决定。<br>把实际产物中的一处颜色或字体定位回原句；当前没有本课实录，不能预填采用成功。 |
| 3. 哪些要求明确，哪些仍需判断？ | 读懂必须满足的要求、默认值和例外，区分规则与示例。<br>明白正文提供指导，实际是否符合仍要看动作和结果。 | 某种颜色用于什么位置、某字体缺失时用什么替代，都有具体依据。<br>整体排版若未规定，就不能归因于 Skill；示例也不能自动变成本次任务内容。 |
| 4. 这份正文为什么不需要写得很长？ | 解释有用的篇幅在于补充任务需要的具体知识，通用常识与重复介绍不必反复写。<br>本部分达到能读出取舍理由即可，不要求学生删改文件，也不展开 Reference 拆分方法。 | 品牌颜色值与用途需要明确提供，颜色或字体的一般定义通常无须重讲。<br>不讲固定行数硬上限，也不要求短文件必须补齐目的、输入、流程等所有栏目。 |

“输出格式”和“检查要求”随所选文件实际存在的内容讲，不为了覆盖术语而另补一份案例。
例如选 Sentry commit 时，可以读懂消息结构、例子与 footer 的含义；选品牌文件时，则集中解释视觉规范。
阅读的是原文件，而非预设框架中的栏目。

## 一份文件怎样从头讲下来

这是一条待预跑的精读路线，尚不是已准备完成的讲述线或逐字稿。

| 顺序与画面 | 具体讲法 | 承接 |
| --- | --- | --- |
| 1）真实 Skill 与本次请求 | 承接已讲过的 name、description，说明这份简单 Skill 用来做什么，以及本次让 AI 完成哪项小任务 | 先看 AI 在这项任务中交出了什么 |
| 2）实际读取与产物 | 简要确认读到的是哪份正文，展示本次返回或产物，选一两处能直接观察的细节 | 回正文找这些细节的具体依据 |
| 3）正文与产物对照 | 沿文件实际顺序讲颜色、字体、默认与替代等要求，就近对照产物，说明哪些有原句支持、哪些是本次需求或模型补充 | 已经看懂内容，再解释为什么不用把所有常识写进去 |
| 4）回看整份短正文 | 用刚读过的内容解释篇幅取舍，再给一个结果细节让学生定位依据或说明正文未作规定 | 完成本部分的正文阅读，后续内容按既定结构继续 |

学习检查只需围绕这份文件提出具体问题：这项选择在正文哪里写着？条件变了适用哪条？产物中哪一处是文件没规定的？
不在这里布置创建、修改或补充资源的任务。

## 来源的取舍与未完成项

编写指南中有大量超出本部分的内容，不能因为文章讲了就全部搬进 3.2.2。
企业分享用于帮助选出真实、具体的指导片段，不把企业级体系设计变成本部分教学目标。

下一步应先预跑一份简单 Skill 的小任务，确认完整正文、环境依赖、实际读取与产物之间有足够清楚的对应。
案例选择以能否讲清上述四个问题为准，不以是否覆盖后续紫色风格制作或所有 Skill 能力为准。
若要声称使用 Skill 改善了结果，还需单独准备效果证据；精读一次调用不承担证明稳定性或提效的任务。
本轮没有新增模型调用、课堂截图或样稿，没有修改讨论稿及其他课件源文件。

## 具体案例与画面方案（2026-11-10，供讲师审阅）

本轮按讲师给出的展示方式收敛到一份案例：**Sentry 的 brand-guidelines**。
它比前面优先考虑的 Anthropic 品牌视觉 Skill 更适合这次精读：任务只涉及短文案，规则和结果易于对照，不需要解释字体环境或 python-pptx。
原文件的主要规则在正文，末尾有两条参考外链；本部分不展开它们，也不把文件称为完全没有外部引用。

**完整原文入口**：[固定版本 GitHub 文件](https://github.com/getsentry/skills/blob/e94f22214528d69899d09c627b3315ddc3544816/skills/brand-guidelines/SKILL.md?plain=1)。
**原始文本入口**：[同版本 raw 文件](https://raw.githubusercontent.com/getsentry/skills/e94f22214528d69899d09c627b3315ddc3544816/skills/brand-guidelines/SKILL.md)。
保留原文件，不另复制全文进公开课程仓库；课堂从原文件顺序阅读，按需要定位重点。

### 原文拆解：沿文件实际顺序走

| 原文位置 | 对应的内容性质 | 拆解重点 |
| --- | --- | --- |
| 文件头及开头说明 | 识别、适用范围与任务说明 | 简短回顾名称与描述，再进入正文。 |
| Tone Selection | 默认做法与条件选择 | 先判断文案出现在哪里，再选语气。 |
| Plain Speech、Sentry Voice | 指导原则、例子与禁用场景 | 原则需要结合场景判断，例子帮助理解，不代表当前任务的固定答案。 |
| General Rules、Dash Usage | 具体约束及使用条件 | 识别可直接核对的语言、标点要求，以及例外。 |
| UI Element Guidelines | 按对象细化的方法和要求 | 同为界面文案，按钮、错误与空状态需要不同处理。 |
| Anti-Patterns、References | 反例与延伸入口 | 反例说明要避免的表达，末尾外链留作后续资料入口，不在本部分扩展阅读。 |

讲解时可用“指导原则、明确要求、默认与例外、示例”作临时标注，不强行把每段分成互斥类别。
“明确要求”是任务应遵守的约束，不是软件已经强制执行的保证；一句话也可能同时包含要求与例外。

### 整体画面顺序

| 顺序与画面 | 具体讲法 | 承接 |
| --- | --- | --- |
| 1）PPT：SKILL.md 的整体结构 | 用一份文件轮廓画出 YAML 文件头中的 name、description，以及分隔线下方的 Markdown 正文。<br>回顾前面已讲名称和描述，本部分展开正文；正文的 1、2、3 只表示若干内容块。 | 正文通常会放哪些指导？ |
| 2）PPT：正文内容概览 | 用规范、默认做法、条件与例子说明常见内容，简短解释各自用途。<br>这是阅读线索，不是每份 Skill 必须填写的四个栏目。 | 打开一份真实 Skill，看这些文字实际怎样组织 |
| 3）真实 SKILL.md：Sentry 文案规范 | 按上表沿文件顺序拆解，重点让学生判断语气选择、原则、具体要求和示例的不同作用。<br>不逐句翻译所有用词与标点细节，始终围绕怎样指导一次具体任务。 | 文件读懂了，实际工作会怎样采用这些内容？ |
| 4）Codex：一次小调用 | 对两个短文案提出同一请求，确认读取的文件版本，再看本次返回。<br>调用入口沿用第一部分已预检的方法，不重新讲选用机制。 | 回原文找返回中一两项选择的依据 |
| 5）结果与原文对照 | 对照可见文案与实际规则，区分 Skill 给的规范、请求给的事实和模型补充的措辞。<br>没有采用的要求如实说明，不把自述或输出中解释的依据当作唯一证据。 | 带着具体对应回 PPT 总结 |
| 6）PPT：正文怎样组织、怎样控制长度 | 回顾本例先说明任务和语气，再给规则与对象细则，随后列反例及资料。<br>归纳一种常见组织方式，但说明正文没有统一的强制栏目和顺序；篇幅先看必要性，长资料的组织留待下一部分。 | 从一份简单正文过渡到更复杂的 Skill |

建议保留步骤 4、5，并放在最终 PPT 总结之前。
没有调用，四件事中的“怎样影响本次工作”只能停留在文件解释；加入小调用，学生就能把原句、动作和结果连起来。
它不是第二次演示“怎样调用”，也不承担证明提效或稳定性的任务。

### 调用任务：只处理两处短文案

以下是课程拟用请求，尚未执行；不预填模型返回。
Sentry 规范针对英文，演示保留英文文案，讲师用中文解释。

```text
请使用 brand-guidelines，改写下面两处英文界面文案：

1. 保存失败提示：
   场景：网络断开，用户保存项目设置失败。
   原文：Oops!!! Your settings could not be saved!!!

2. 项目列表为空提示：
   场景：用户还没有创建任何项目，页面有创建项目的按钮。
   原文：Nothing here.

只输出每处的提示正文，以及第二处的按钮文案。
保持给定事实，不添加新的功能或失败原因。
不修改代码、不调用外部服务。
```

同一次请求含两个场景，是为了观察条件选择，不是增加第二个项目。
看返回时先核对文件对应的语气与具体要求，再指出网络断开、尚无项目等事实来自请求，而最终措辞由模型组织。
不要求模型逐条复述规则，以免解释淹没文案，也不要求输出逐字复现文件里的示例。
若当前环境未选中或未读到相应文件，应先处理调用链路，不能拿未读取的返回证明这份 Skill 的作用。

### 总结页要修正的两点
