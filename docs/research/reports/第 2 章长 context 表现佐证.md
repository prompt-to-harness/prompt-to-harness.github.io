> 2026-10-25 调研；同日讲师选定 C（C2-116），A、B 作链接，D 进口播。问题：2.2 p23a 讲“重发的代价不只是 token，还有注意力”，用什么外部材料比 Chroma 重复词任务更贴切。来源与核实见[笔记](../notes/第%202%20章长%20context%20表现佐证/sources.md)。本文是选材建议，讲师选定前不改分镜和页面。

## 对应的讲透问题

章文件讲透问题 4：“第二句话发出去时，带上了什么？代价是什么？”p23 已讲 token 和缓存；p23a 要说明另一半代价：内容越多，模型越难用好它们。这一页同时为 p28（怎样继续会话）铺垫。

## 推荐

p23a 改成 **C 上屏 + A、B 作链接**，口播引 D 的一句官方说法：

1. 画面：重画的示意图，“smart zone → dumb zone，分界因模型和任务而异，窗口上限还在更后面”；不写 125K–150K、40% 这些数字，因为它们是作者在别的模型和工具上的经验值，套到 MiniMax-M3.1-Flash 的 498K 窗口上没有依据。
2. 口播：说清这个说法来自 Matt Pocock 和 Dex Horthy，并说明两人给的分界不同、都说因模型和任务而异；再说一句 Claude Code 官方文档也写了 context 填满时性能下降。
3. 接回本节：我们这一轮 Plan 阶段最长一次请求不到两万 token（讲师选定后改用 p23 的数字，压缩前 26.3K 要到 p27b 才出现），离两人说的分界都远；可一个会话接着做很多事，就会越走越靠后。这为 p28 的“一个任务一个会话、在自然边界交接或压缩”做好铺垫。
4. 外部佐证数量不变（C2-97：一节 3～4 处），Chroma 从画面撤下，只留讲师提示。

## 与课件现有说法的出入

- 现 p23a 口播说“输入越长，表现越不稳定”，Chroma 的结果支持这句话，A、B、D 也是同一方向，没有冲突。
- 现 p23a 结尾“这一次主页改得对不对，仍要回到文件和页面检查”，换材料后仍然成立。
- 网上常见“分析了 10 万多个会话”“40% 规则”被说成固定阈值，都只见于二手转述；演讲原话是“取决于任务”的经验值，不能写成规则。
