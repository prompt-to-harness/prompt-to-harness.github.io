## 这里要讲清什么

对应章文件讲透问题 1“我只说了一句话，模型收到了哪些别的东西？”：p06-tap 先说明我们怎样取得下一页要看的请求记录。要证明的是**把客户端的 API 请求先送到本地代理，代理记录并转发，因此可以查看经过它的请求和返回**。这次只补该位置，不另加章首材料。

已查章文件的外部佐证表、materials/external 登记表和既有 Context 引入调研，没有这类方案对照或原理图。现有课程已实测 claude-tap；本次不建议换工具。

## 几种方案

| 方案 | 在哪里看到内容 | 接入与取舍 | 对 p06-tap 的建议 |
| --- | --- | --- | --- |
| [claude-tap](https://github.com/liaohch3/claude-tap/tree/v0.1.146#how-it-works) 专用本地代理 | 请求先到代理，再转发到模型服务；本地 trace 与查看器展示请求和返回 | 本章路径由启动器临时配置客户端的 API 地址；流式返回经过代理。它会经手鉴权信息；可见范围取决于哪些流量经过它 | 首选。保留已用的 0.1.146，画清路径 |
| [mitmproxy / mitmweb](https://docs.mitmproxy.org/stable/concepts/modes/#reverse-proxy) 通用 HTTP 调试代理 | 代理处查看 HTTP 请求与响应 | 反向代理模式也可让客户端访问本地地址，再转到指定上游；常规 HTTPS 拦截模式则涉及客户端信任代理证书，两种接法要分清 | 原理相近的替代方案；不在主课展开证书配置 |
| [LiteLLM Proxy](https://docs.litellm.ai/docs/proxy/ui_logs) 模型网关日志 | 请求经过网关时记录，可在 Logs 查看 | 正文记录默认关闭，需显式打开；适合已经使用统一模型网关的项目。网关可能进行协议适配，不能直接等同于网络原始报文 | 讲师备忘；本页没必要再搭一个网关 |
| [Langfuse tracing](https://langfuse.com/docs/observability/overview) 应用埋点 | 应用或框架通过集成上报输入、输出和工具执行等 trace | 适合能改代码或已有集成的 agent；能看到什么取决于埋点与上报范围，不应默认它能直接取得任意 CLI 的完整网络请求 | 后续自己做 agent 时可用；本页不引入 SDK |

以上是对四份项目官方资料的概括。推荐理由是本课程情境下的判断，不是工具性能评测。来源逐条核验见[笔记](../notes/第%202%20章请求查看方案/sources.md)。
