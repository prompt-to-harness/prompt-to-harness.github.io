## 4.1 顺序建议

1. 用口播说明本次从已有工程起步，迁移前几章的方法；所有演示使用独立 JSON Crack 仓库和当前基线。
2. 根据课件给出的上游、Release 与完整 SHA 取得代码，核对本地版本并建立课程分支。
3. 用 A 给出简短导航，用 B 启动并体验一个最小 JSON 可视化例子；D 用于核对关键结论。
4. 呈现“为 JSON Crack 增加 JSON 对比功能，把不同的地方高亮出来”这一句需求。
5. 围绕需求逐步说明 Brief、Spec、Acceptance、Plan、Tasks 的用途、对应与返回关系，再进入 4.2 的需求摄入与调查。

顺序的依据是让学员先知道正在操作什么产品，再理解要为它增加什么行为，以及五层分别回答哪些问题。这是教学建议，尚未试讲。五层关系是本节知识主线，Agent 导览为产品体验服务，避免逐目录讲解占据主体。

开场可用“很多开发任务是在已有工程上继续做”表达换项目的理由；本轮没有调查“多数开发任务都从已有工程开始”的统计依据。
