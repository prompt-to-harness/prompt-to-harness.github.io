# 3.4 资源平台与持续追踪材料

日期：2026-11-13。用途：服务当前 Discussion 的三个部分。推荐为备课选材建议，不是 Skill 效果实测。全程采用 PPT 与现成页面，不安装或执行外部 Skill。

## 选材结论

3.4.1 用 UI 样例开头，主要展开 skills.sh 的真实寻找路径，SkillsMP 补筛选能力，官方 GitHub 集合作来源入口。3.4.2 用作者实际删除或修改 Skill 的记录引入，给官方与实践者推荐。3.4.3 用当前页面中直接可见的现象讲小技巧。无需新增大批平台，也不把全文阅读变成教学主线。

平台选择：主讲 skills.sh，SkillsMP 补充不同筛选方式，官方集合提供直接入口。Tessl、Skills for Design 保留在已有调研池，不增加必讲平台；它们更适合读评价，当前节奏无需为覆盖类型强行展开。

## 3.4.2：生命周期与持续关注

### 生命周期的两个直接案例

1. **删除**：[Matt Pocock 的 v1.3 更新](https://www.aihero.dev/skills-changelog-v13-implement-spec-pr-retro-and-glossary-md)，2026-10-05，定位 `Removed: /resolving-merge-conflicts`。作者移除合并冲突 Skill，理由是 agent 已能处理；同时说明较弱模型可能仍有需要。适合 PPT 简短说明：曾经有用的指导，在特定工具与模型条件下可能不再需要。不能说所有合并冲突 Skill 都无用。
2. **更新**：[Superpowers v6.4.2](https://github.com/obra/superpowers/blob/main/RELEASE-NOTES.md#v642-2026-09-25)，2026-09-25。作者记录部分前沿模型可能在规划时提前实现项目，因此 writing-plans 改为记录接口、断言等决策，减少完整代码式计划。支持“模型行为变化也会要求调整指导”。不引用作者自述的耗时、token 降幅作为普遍效果。

[Impeccable 更新记录](https://impeccable.style/changelog/)可作备选：从多份 Skill 合并为一个入口与多条命令，是组织与维护方式变化，不能单独证明模型能力导致淘汰。[openai/skills](https://github.com/openai/skills)迁移也仅支持入口维护，不承担生命周期核心证据。

## 3.4.3：有实际材料的 tips

| Tip | 当前材料 | 讲述取舍 |
| --- | --- | --- |
| 看到好 Skill，反向找作者和其他内容 | [Matt 仓库](https://github.com/mattpocock/skills)有 AI Hero 入口及 newsletter 链接 | Skill → 作者的其他 Skill → 经验文章/视频。只浏览，不订阅或安装 |
| 搜索不只记名称，也看作者和仓库 | skills.sh 搜索 frontend-design 的实际结果 | 同名条目很多，用 owner/repo 辨认来源。一个短提醒即可 |
| 想知道还能怎么用，顺着相关条目找 | [frontend-design 详情](https://www.skills.sh/anthropics/skills/frontend-design)的 Related Skills | 从风格生成发现界面规范、组件组织等相邻用途；推荐关联不是质量认证 |
| 收藏时留原始仓库，不只留目录页 | Impeccable 当前 changelog 与 skills.sh design 主题仍列旧独立条目的差异 | 回源看当前入口和变化。备选，避免与生命周期段重复 |

另有更直接的维护状态例子：[Matt 的归档页面](https://www.aihero.dev/skills-resolving-merge-conflicts)仍保留安装框，正文却标记 Archived；可用来提醒先看当前维护状态。删除记录可交叉查 [v1.3.1 release](https://github.com/mattpocock/skills/releases/tag/v1.3.1)。

建议在这些小点中选择少量内容；不凑数量，不建立固定流程。
