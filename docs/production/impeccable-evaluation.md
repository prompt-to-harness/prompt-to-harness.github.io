# 外部设计 skill 评估：impeccable

> 状态：2026-10-05，Claude 评估，供讲师决定。结论是评估者的判断，不是讲师确认，也没有经过试讲验证。被评估的是 [pbakaus/impeccable](https://github.com/pbakaus/impeccable)：源码对应提交 `ece38d9`，CLI 版本 `impeccable@4.1.0`，Apache-2.0 许可。

## 结论

不整套安装进本仓库。采纳其中三条方法，改写后放进本仓库已有的规则来源；detector 可以作为录制前一次性的辅助扫描，只把它当作线索，不当作规则。

不安装的原因：

- **对象不同。** 它面向可交互的 Web 产品界面，检查响应式、hover/禁用/出错状态、性能等。我们的主体是 1280×720 固定画布的录播演示页，这些检查大多用不上。
- **规则和我们的规范冲突。** 它禁止标题上方的小标题（kicker），不鼓励 1px 以上的彩色左边线，把零模糊的硬阴影视为装饰。这三样分别对应我们规范要求的“小标题 + 断言标题”、语义色左边线和手绘卡片，都是有意的选择。
- **会多出一个规则来源。** 要消除这些冲突，就得另写 `DESIGN.md` 和 ignore 配置，与 [视觉规范](visual-design-system.md)、[编辑规范](editorial-checklist.md) 分叉。另外，安装后的 hook 会在每次编辑后自动扫描，在多人、多 agent 共用的公开仓库里噪音太大。

## detector 试扫结果

扫描范围是 `courseware/ch02`、`courseware/shared` 和课程首页。命令在临时目录下运行，没有往仓库写入配置。

**静态扫描**（直接读 HTML/CSS，不执行 JS）：共 66 条，没有需要修改的问题。

| 规则 | 条数 | 判断 |
| --- | --- | --- |
| `side-tab`（彩色左边线） | 26 | 有意设计：语义色左边线、代码当前行色带 |
| `cream-palette`（米色底） | 12 | 有意设计：课程纸色 `#F4F2EB` |
| `clipped-overflow-container` | 10 | 有意设计：固定画布要求裁切 |
| `organic-clip-path` / `repeating-stripes-gradient` | 12 | 有意设计：涂鸦星形、容量条 |
| `border-accent-on-rounded` | 4 | 有意设计：手绘零件 |
| `low-contrast` | 2 | 误报：结论条的深色底画在 `::before` 上，静态扫描读不到 |

**渲染扫描**（`--viewport 1280x720`，扫 2.1、2.3、2.5 三节的讲义页）：共 51 条。大部分与静态扫描相同，或者属于下面三类误报：

- 中文行宽被按拉丁字符估成约 103 字符/行；
- 中文破折号被算作 em-dash 过多；
- 结论条的黄字被当成画在纸色底上。

剩下几条值得人工复核，**尚未修改，也没有在录制画面里确认影响**：

| 候选问题 | 位置 | 观察 | 对照规范 |
| --- | --- | --- | --- |
| 代码行号偏小、偏浅 | `.p-ln i`（parts.css） | 15px，`#A0A8B4` 在浅底上对比度 2.0–2.4:1 | 低于图中标签 17px 的下限；行号是辅助信息，需讲师判断是否适用 |
| 开篇地图的非当前节名偏浅 | `.p-map>li b` | 21px，`#8A8F99` 在纸色上 2.9:1 | 在手机上看 720p 录屏时可能读不清 |
| 风险红直接当文字色 | `.p-pencil` 等 | `#D9481C` 在纸色上 3.8:1 | 视觉规范只给了风险红的主色，没有像 Tool 那样另设文字色；有的零件已经改用 `#AC3615`，用法不统一 |
| 标题层级跳级 | 2.1、2.3 小结页 | `h2` 后直接是 `h4` | 只影响阅读模式的可访问性 |

2.3 试修（2026-10-05）：四条都已修复，另外修了 2.4 代码注释颜色，见 [2.3 展示审查](../reviews/ch02/2026-10-05-2.3-contrast-claude.md)。2.3 的渲染扫描从 21 条降到 7 条，13 条对比度问题和标题跳级全部清零。这说明 detector 的结构性检查（对比度、字号、标题层级）有实际效果，风格类规则仍然不适用于本课程。

## 待讲师决定

- **是否用作课程案例。** impeccable 本身就是一个完整的 Harness 样例：skill 文本、`PRODUCT.md`/`DESIGN.md` 上下文文件、确定性 detector、编辑后自动运行的 hook，以及 LLM 评审和 detector 证据分两路再合并的评审流程。它可以作为 Harness 章节的外部参照，目前没有写进大纲。
- **是否把 detector 加进录制前检查。** 可选方式是录制前手动跑一次 `npx impeccable detect --viewport 1280x720 <讲义页 URL>`，只看 `low-contrast` 等少数规则。它需要联网下载第三方工具，不进 CI。
