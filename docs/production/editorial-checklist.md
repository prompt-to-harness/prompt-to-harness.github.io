# 课件编辑规范与改稿清单

> 状态：2026-10-05。本文件是课件文案、口播稿和讲解全文**唯一的**编辑规则来源，合并了原《课程编辑与审校记录》（ED-001–003）和课程共识中的“讲述与改稿原则”。它是讲师确认过的工作规范，不是已验证的教学效果。规则服务于画面、讲述和学习判断，不是禁词表；真实信息需要标点、重复或完整解释时，以信息是否丢失为准。

## 怎么使用

- 写或改任何一节之前先读本文；改完后按“改稿检查”走一遍。
- 新出现、可迁移到多节课的问题，在这里登记一条：问题、适用材料、已确认的处理、检查方法。用户或非作者指出例外时，在对应条目补例子，不另起相似规则。
- 能机器检查的，由 `courseware/tools/check-editorial.py` 执行（随 `check-courseware.py` 一起跑）；需要判断的，由项目 skill `lesson-polish` 逐页对照本文输出问题清单，结果留存到 `docs/reviews/`。两者只引用本文的条目编号，不复制规则正文。

## 规则

### ED-001 · 屏幕文案不加多余的中文句末标点

**问题**：画面里的标题、标签和短要点，句末的“。”只形成视觉噪声。

**处理**：

- 标题、章节标签、短要点、卡片标签、导航文字、单句的屏幕说明（如首页卡片描述、提示语）默认不加句号；已有箭头、冒号或分隔符能表达关系时，也不补句号。2026-10-03 确认单句说明同样适用。
- 同一元素里有多句时，句间句号保留；题干、请求、Prompt、解析、引用原文和讲解全文保留必要标点。
- 不为去句号把完整说明改成残缺短语。先判断它是标签、短提示，还是需要完整理解的说明。
- 口播稿的标点服务于朗读，不套用这条规则。

**检查**：只看屏幕文字，圈出句末标点，问“删掉后是否失去关系、条件或引用边界”。没有新增信息的删掉。

### ED-002 · “能读出来”包括逻辑连贯和听者接受

**问题**：朗读检查不只看发音、节奏和换气，还要让听者顺着当前对象、依据、动作和结果往下走。

**处理**：每个讲述点同时检查：

1. 听者能否说出这一段正在处理的对象或问题
2. 每个结论前的事实、例子或前提是否已经出现
3. 这一句和下一句之间的因果、转折或范围变化是否要听者自行补全
4. 术语、代词和“这里、刚才、这个结果”是否有明确指向
5. 听完后能否知道下一步要做什么，或能否独立作出题目要求的判断

必须停下来反推“为什么突然讲这个”“它指谁”“结论从哪来”，即使读得顺也要改。优先补对象、前提或过渡；补不出依据时，降低结论强度或把内容移到配套材料。不用“其实”“大家看”“对吧”之类口头填充词遮住缺口。

**补充（2026-10-05，2.2 P07 / P12）**：结论要对应眼前的证据和具体检查对象。不要用“页面对”“模型更好”等笼统判断代替说明；比较指令目录，就讲哪些章节不同；展示构建成功，就讲构建流程完成。提醒证据边界时，先检查前文是否提出了相应推论、是否影响当前判断；没有铺垫的能力评判或设计动机问题，留在讲师备注，待有相应证据和教学需要时再展开。必要的风险提醒、事实限定和失败停止条件仍按 ED-003、ED-006 保留。

**检查**：让没参与写作的人只看画面和听稿，复述“这一段讲什么、依据是什么、下一步是什么”。复述失败时，记录卡住的原句和缺少的连接。

### ED-003 · 课程材料分层，内容同步不等于全文复制

**问题**：页面、口播稿、讲解全文、录制说明和环境卡要一致，但各层读者和职责不同。

**处理**：

- 屏幕文字放对象、关键词、请求、差异和证据
- 口播解释当前画面变化、判断依据和下一步
- 讲解全文补足学员需要回看的解释
- 录制说明记录镜头、真实输出、剪辑、版本和未验证状态
- 环境卡记录命令、版本、路径和排障

作者才需要知道的制作状态（时长、切点、take、未验证状态）不进入学员口播；学员完成当前判断所必需的边界，不能因为“放到配套页”而消失。

**检查**：每段标记“对谁说、要完成什么”。既不帮助学员理解、也不是录制时要执行的动作，就删掉或移到正确的层。

### ED-004 · 先有具体对象，再归纳方法

工作示范从文件、需求或可见结果开始，让学员知道眼前要解决什么。操作之后再简短点明方法；不在开场连续宣读框架、步骤名和能力承诺。必要的前置解释仍放在操作之前。

### ED-005 · 流程的分量跟任务相称

小任务的计划可以只有一句话，读取范围只覆盖当前需要的信息。为了教学拆分阅读、计划和执行时，讲明拆分的用途，并说明熟悉后哪些步骤可以合并。不要让学员误以为每次小改动都要完整套流程。

### ED-006 · 主课只讲当前需要的判断

保留会影响下一步操作的提醒、失败时的停止条件和帮助入口；当前任务暂时用不到的原理、异常分支、详细恢复步骤、未来任务的环境准备放在配套页。移出主课的内容必须可定位、可跟做，不能只说“自行排查”。

### ED-007 · 重复要带来新信息

提要求时明确范围，执行时观察动作，检查时对照结果，自检时换一种情况让学员判断。相同原则不在每一步重新解释；删去没有增加理由、观察或行动的总结句。

### ED-008 · 围绕画面讲具体变化

说清哪个文件、哪段文字、哪项输出支持了判断。“目标、范围、完成标准”可以是简短标注，不必逐项念成定义。展示示例时标明示例；实际结果按录制输出解释，不预写固定的成功台词。

### ED-009 · 学习收获与练习相称

用“能发出修改请求并看懂实际差异”这样的可观察动作描述收获。练习训练同一能力，记录要求服务于检查和下一节；版本、目录等元数据用模板承接，不逐项口播。

### ED-010 · 通过信息取舍改善口语

一句话尽量说清一个动作或判断，长句按讲解顺序拆开。检查“这样做是为了”“这里练习的就是”“既看……也看……”这类句子是否增加了信息，不把它们机械列为禁词。

**补充（2026-10-05）**：检查“能……不能……”“……不等于……”这类正反对照是否回应了前文出现的误解，或解释了当前任务确需区分的对象。不要先制造一个读者尚未提出的推论，再用否定句纠正；也不要用限制判断的套话代替具体解释。默认直接说对象、变化、证据和下一步。确有误解或需要限定证据范围时，保留必要对照并讲清依据。

**通用检查**：

- 无铺垫的否定：前文是否已有相应判断，或当前操作是否确需区分？删去这句话后，是否损失必要的操作边界？
- 笼统的证据结论：说明的是哪个检查对象、结果和完成标准？能否直接说清这些信息？

例如，“恢复对话不等于恢复文件或服务”有实验支撑，并影响是否重启服务；“最小权限不等于越少越好”有只读权限无法写入的例子。这些必要区分可以保留。

**改写参照**：2.2 P07“能看到内容差异 · 不能据此判断模型能力或设计原因”改为“换一个模型，Codex 配给它的指令内容也会变化”，口播点出具体章节；P12“能构建，不等于页面对”改为“构建流程成功完成”，口播说明视口、Tab 和 build 各自的检查对象。

**检查**：遇到上述句式，复述它正在纠正哪个判断、区分哪两个对象，以及这一区分如何影响当前操作；说不清时，检查能否改成直接描述。属于语义判断，由人工 / skill 检查，不按句式一律报错。

### ED-011 · 生成物与源文件保持一致，删除要清残留引用

**问题**：有些页面由脚本生成（如 2.1 的 `lesson.js` 和 `script.md` 来自 `ch02/lessons/01-feedback/tools/build-lesson.py`；第 0 章 `script.md` 来自 `lesson.js`）。只改生成物，下次生成就被覆盖；删掉一个页面或入口而不清链接、检查脚本和说明，会留下死链。

**处理**：先找到内容源再改；改完重新生成。删除页面时同步清入口、检查脚本、README 和构建说明。

**检查**：`check-editorial.py` 比对生成物，`check-courseware.py` 查本地链接。

## 改稿检查

备稿时先写出本节要解决的问题、可见结果和检查方法，再对照画面读一遍。逐段看：有没有新信息，是否需要当场解释，有没有对应的文件、例子或图。然后同步页面、讲解全文、配套材料和制作说明。字数减少只说明稿子变短，节奏与时长仍需试讲确认。

改写参照：把“目标，是换一段新的介绍。范围，是 README 里的这一个段落”改为“打开 README，找到项目介绍。我们把这里换成课程网站的介绍，其他段落先保留”。把“status 不保存内容”的详细说明留在准备页，主课保留“已有改动时就先保留目录，另建练习副本”的操作提示。
