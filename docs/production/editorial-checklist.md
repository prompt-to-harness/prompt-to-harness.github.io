# 课件编辑规范与改稿清单

> 本文件是课件文案、口播稿和讲解全文**唯一的**编辑规则来源，合并了原《课程编辑与审校记录》（ED-001–003）和课程共识中的“讲述与改稿原则”。它是讲师确认过的工作规范，不是已验证的教学效果。规则服务于画面、讲述和学习判断，不是禁词表；真实信息需要标点、重复或完整解释时，以信息是否丢失为准。

## 怎么使用

- 写或改任何一节之前先读本文；改完后按“改稿检查”走一遍。
- 新出现、可迁移到多节课的问题，在这里登记一条：问题、适用材料、已确认的处理、检查方法。用户或非作者指出例外时，在对应条目补例子，不另起相似规则。
- 能机器检查的，由 `courseware/tools/check-editorial.py` 执行（随 `check-courseware.py` 一起跑）；需要判断的，由项目 skill `lesson-polish` 逐页对照本文输出问题清单，符合 `docs/reviews/README.md` 触发条件时再留存正式审查记录。两者只引用本文的条目编号，不复制规则正文。

## 规则

### ED-001 · 屏幕文案不加多余的中文句末标点

**问题**：画面里的标题、标签和短要点，句末的“。”只形成视觉噪声。

**处理**：

- 标题、章节标签、短要点、卡片标签、导航文字、单句的屏幕说明（如首页卡片描述、提示语）默认不加句号；已有箭头、冒号或分隔符能表达关系时，也不补句号。2026-10-03 确认单句说明同样适用。
- 同一元素里有多句时，句间句号保留；题干、请求、Prompt、解析、引用原文和讲解全文保留必要标点。
- 不为去句号把完整说明改成残缺短语。先判断它是标签、短提示，还是需要完整理解的说明。
- 口播稿的标点服务于朗读，不套用这条规则。

**检查**：只看屏幕文字，圈出句末标点，问“删掉后是否失去关系、条件或引用边界”。没有新增信息的删掉。脚本不检查 `.p-evidence` 阅读视图里的请求记录原文（那是引用，按原文保留）。

### ED-002 · “能读出来”包括逻辑连贯和听者接受

**问题**：朗读检查不只看发音、节奏和换气，还要让听者顺着当前对象、依据、动作和结果往下走。

**处理**：每个讲述点同时检查：

1. 听者能否说出这一段正在处理的对象或问题
2. 每个结论前的事实、例子或前提是否已经出现
3. 这一句和下一句之间的因果、转折或范围变化是否要听者自行补全
4. 术语、代词和“这里、刚才、这个结果”是否有明确指向
5. 听完后能否知道下一步要做什么，或能否独立作出题目要求的判断

必须停下来反推“为什么突然讲这个”“它指谁”“结论从哪来”，即使读得顺也要改。优先补对象、前提或过渡；补不出依据时，降低结论强度或把内容移到配套材料。不用“其实”“大家看”“对吧”之类口头填充词遮住缺口。

**补充（2026-10-05）**：结论要对应眼前的证据和具体检查对象，不用“页面对”“模型更好”这类笼统判断代替说明；没有铺垫的能力评判或设计动机问题留在讲师备注。正反对照句的检查和改写例子见 ED-010。必要的风险提醒、事实限定和失败停止条件仍按 ED-003、ED-006 保留。

**补充（2026-10-25，2.1 录制后）**：逐字稿要能一字不改地照着念（[课程设计原则](../design/course-design-principles.md)“录制形态与公开材料”）。录制时最常卡住的是四类句子：写给编辑的免责（“这只是帮我们确定一个角度，并不是它的结论”）；把刚说的话又收回去的保守说法（“只是说有这种可能，并不是说……”）；画面前后已经说过的预告（“下一页我们先……”）；还有因果写歪了的句子，比如把“累计输入是几次相加”说成“因为命中缓存，所以不等于单次长度”。前两类删掉，或者改成有信息、有观点的话；后两类改写。预告尽量不写，能帮学员转换视角、或下一页的讲述确实要它铺垫时可以留一句。

**检查**：让没参与写作的人只看画面和听稿，复述“这一段讲什么、依据是什么、下一步是什么”。复述失败时，记录卡住的原句和缺少的连接。

### ED-003 · 课程材料分层，内容同步不等于全文复制

**问题**：画面、阅读模式、逐字稿、录制说明和环境卡要一致，但各层读者和职责不同。

**处理**：

- 屏幕文字放对象、关键词、请求、差异和证据
- 口播解释当前画面变化、判断依据和下一步
- 阅读模式（`lead` 等只在阅读模式出现的文字）补足学员自己读页面时需要的上下文和逻辑转换；它是学员能读到的完整版本
- 逐字稿（讲解全文，`script.json` 渲染成的 `speaker.html`）给讲师录制用，不发布；口播里有、学员回看时也需要的解释，要在阅读模式里留下（2026-10-11 讲师确认）
- 录制说明记录镜头、真实输出、剪辑、版本和未验证状态
- 环境卡记录命令、版本、路径和排障

作者才需要知道的制作状态（时长、切点、take、未验证状态）不进入学员口播；学员完成当前判断所必需的边界，不能因为“放到配套页”而消失。

**检查**：每段标记“对谁说、要完成什么”。既不帮助学员理解、也不是录制时要执行的动作，就删掉或移到正确的层。

### ED-004 · 先有具体对象，再归纳方法

工作示范从文件、需求或可见结果开始，让学员知道眼前要解决什么。操作之后再简短点明方法；不在开场连续宣读框架、步骤名和能力承诺。必要的前置解释仍放在操作之前。

改写参照：把“目标，是换一段新的介绍。范围，是 README 里的这一个段落”改为“打开 README，找到项目介绍。我们把这里换成课程网站的介绍，其他段落先保留”。把“status 不保存内容”的详细说明留在准备页，主课保留“已有改动时就先保留目录，另建练习副本”的操作提示。

### ED-005 · 流程的分量跟任务相称

小任务的计划可以只有一句话，读取范围只覆盖当前需要的信息。为了教学拆分阅读、计划和执行时，讲明拆分的用途，并说明熟悉后哪些步骤可以合并。不要让学员误以为每次小改动都要完整套流程。

### ED-006 · 主课只讲当前需要的判断

保留会影响下一步操作的提醒、失败时的停止条件和帮助入口；当前任务暂时用不到的原理、异常分支、详细恢复步骤、未来任务的环境准备放在配套页。移出主课的内容必须可定位、可跟做，不能只说“自行排查”。

### ED-007 · 重复要带来新信息

提要求时明确范围，执行时观察动作，检查时对照结果，自检时换一种情况让学员判断。相同原则不在每一步重新解释；删去没有增加理由、观察或行动的总结句。

### ED-008 · 围绕画面讲具体变化

说清哪个文件、哪段文字、哪项输出支持了判断。“目标、范围、完成标准”可以是简短标注，不必逐项念成定义。展示示例时标明示例；实际结果按录制输出解释，不预写固定的成功台词。

### ED-009 · 学习收获与练习相称

用“能发出修改请求并看懂实际差异”这样的可观察动作描述收获。练习训练同一能力，记录要求服务于检查和下一节；版本、目录等元数据用模板承接，不逐项口播。

### ED-010 · 通过信息取舍改善口语

一句话尽量说清一个动作或判断，长句按讲解顺序拆开。检查“这样做是为了”“这里练习的就是”“既看……也看……”这类句子是否增加了信息，不把它们机械列为禁词。

**补充（2026-10-05）**：检查“能……不能……”“……不等于……”这类正反对照是否回应了前文出现的误解，或解释了当前任务确需区分的对象。不要先制造一个读者尚未提出的推论，再用否定句纠正；也不要用限制判断的套话代替具体解释。默认直接说对象、变化、证据和下一步。确有误解或需要限定证据范围时，保留必要对照并讲清依据。

**通用检查**：

- 无铺垫的否定：前文是否已有相应判断，或当前操作是否确需区分？删去这句话后，是否损失必要的操作边界？
- 笼统的证据结论：说明的是哪个检查对象、结果和完成标准？能否直接说清这些信息？

例如，“恢复对话不等于恢复文件或服务”有实验支撑，并影响是否重启服务；“最小权限不等于越少越好”有只读权限无法写入的例子。这些必要区分可以保留。

**改写参照**：2.2 P07“能看到内容差异 · 不能据此判断模型能力或设计原因”改为“换一个模型，Codex 配给它的指令内容也会变化”，口播点出具体章节；P12“能构建，不等于页面对”改为“构建流程成功完成”，口播说明视口、Tab 和 build 各自的检查对象。

**检查**：遇到上述句式，复述它正在纠正哪个判断、区分哪两个对象，以及这一区分如何影响当前操作；说不清时，检查能否改成直接描述。属于语义判断，由人工 / skill 检查，不按句式一律报错。

**补充（2026-10-24）**：抽象的概括句（“角色说明消息是谁在‘说话’，不说明文字是谁写的”）读起来像机器写的，讲师一眼就会卡住。换成画面上能指到的具体例子：“user 里有两条，一条是 Codex 加的环境，一条才是我们的问候”。2.1 p09 按这个改过。

### ED-011 · 生成物与源文件保持一致，删除要清残留引用

**问题**：有些页面由脚本生成（如 2.1 的 `lesson.js` 来自 `ch02/lessons/01-request/tools/build-lesson.py` 与本节 `script.json`；第 0、1 章 `lesson.js` 里的口播由 `rebuild-lesson.py` 从 `script.json` 合并）。只改生成物，下次生成就被覆盖；删掉一个页面或入口而不清链接、检查脚本和说明，会留下死链。

**处理**：先找到内容源再改；改完重新生成。删除页面时同步清入口、检查脚本、README 和构建说明。

**检查**：`check-editorial.py` 比对生成物，`check-courseware.py` 查本地链接。

### ED-012 · 一个对象一个叫法

**问题**：同一个对象换着叫（首页 / 个人主页 / 首页原型；工具入口 / CLI；一节课五种名字），学员会以为是不同的东西。平台 reviewer 首轮反馈把它列为最大的问题（2026-10-09，R18）。

**处理**：按 [`terminology.md`](terminology.md) 的统一叫法写；学员第一次遇到的术语，按表中“首次出现”给出解释。不要用“1.3”“1.5”这类编号代替含义，先说那一节做什么，再附编号。新出现的一物多名先登记到术语表，再改课件。

**补充（2026-10-24）**：同一组对象的分类也只能有一套。贯穿全章的分类、术语和示意图，定义只写在章文件“全章约定”里，各页只引用；反复出现的图由代码统一生成（如第 2 章 `lessonkit.anchor()`），不在页面里手写副本。外部图的分法对不上课程分类时，只画原图的顺序，不硬对。起因：2.1 p09 分六类、锚点图七块、p16b 的对应列又是另一套，三处矛盾。

**检查**：逐页列出指代同一对象的名词，超过一种就改；改完一节，再把这一节用到的分类和全章约定逐条对照；看到节号时，问学员此时是否知道那一节讲什么。术语表“已废弃的说法”一节列出的旧叫法，由 `check-editorial.py` 在章文件和课件内容源里查找（2026-10-21 起）。

### ED-013 · 每一步先写操作提示，再写口播

**问题**：录制时讲师要一边念稿一边切窗口、跑命令、开页面。操作散在折叠备注或口播里，录到一半才发现该新开标签页还是复用、命令在哪个目录跑，容易重录或念出讲师才该看的话（2026-10-11 确认，以第 1 章为范本）。

**处理**：`script.json` 里每一步以 `【操作提示｜…】` 开头，空一行接口播正文；写法见[制作手册“讲稿与转场”](lesson-authoring-playbook.md#讲稿与转场)。操作提示不念，口播正文不放舞台标注。

口播中途的窗口切换另起一段 `【切换｜目标】`，`speaker.html` 单独着色，不念（2026-10-25）。

录制要用的操作只写在操作提示和本节录前准备里，不放进折叠备注或 `teaching`；逐字稿页的组成见制作手册“讲稿与转场”（2026-10-25，第 2 章 LOG C2-102）。

**检查**：`check-editorial.py` 检查每一步都以一条操作提示开头、后面有口播正文，`【切换｜…】` 段只占一行，并对“现场演示时……”这类演示形态未定的条件句给提示；提示写得够不够具体，按制作手册逐条看。

### ED-014 · 屏幕短文字避开常见别扭说法

**问题**：节标题、卡片、label、`lead` 这类短文字，容易写成目录腔、作者行话、电报体或金句。阅读模式是学员唯一的文字版，这些说法离开口播就读不懂或读偏（2026-10-11 第 0–2 章审查，讲师确认）。

**处理**：按 [`wording-patterns.md`](wording-patterns.md) 的 W1–W8 和高频词对照，能说具体对象和动作就直接说。节标题按节的角色用稳定句式，见同文件“节标题的句式”。

**检查**：`lesson-polish` 审一节时逐页对照；另按 skill 的 `review.md` 里的“定期巡检”跨章过一遍。新模式或好例子补进 `wording-patterns.md`，不在这里加条目。

### ED-015 · 完成状态在各入口说法一致

**问题**：章 README 和节 README（已迁移的章是各节分镜的“素材状态”）都会写“首版”“只有分镜”“已审阅”“未试讲”这类状态，各自更新，时间一长就互相矛盾（2026-10-11 发现：第 2 章首页与课程首页的状态句互相矛盾，学员页面上的状态句已按 ED-016 删去）。

**处理**：状态以章 README 顶部的状态横幅为准，节 README 跟着它改；改了一处状态，同一次提交里同步其他 README。学员页面不写这类状态，见 ED-016。

**检查**：`lesson-polish` 定期巡检时，列出各章与各节 `README.md` 里的状态句，逐章比对；不一致的按章 README 改，章 README 本身过时的先问讲师。

### ED-016 · 学员页面不写制作进度和审阅状态

**问题**：课程首页和章首页容易顺手写两类状态：制作进度（“第 1 章已完成 · 第 2 章制作中”“待制作”“正在制作”），以及审阅状态（“五节均为草稿”“首版，未经讲师审阅，未试讲”“待试讲”）。它们对学员没有学习价值；哪些改过、哪些没改，讲师自己清楚，写在页面上只是每次改完都要记得同步的负担，漏改就和实际内容对不上。同一处还常配一句空泛的过渡或口号（如“先认识讲师与课程安排，再进入第一个项目”），删掉不丢信息（2026-10-11 讲师确认）。

**处理**：这两类状态只写在章 README、节 README、章 LOG 和 `docs/` 里，不上学员页面。学员页面要表达“这部分还没有”，用结构本身表达：没有课件的章不放链接，或用已有的未开放样式（如首页阶梯的 `is-todo` 虚线框），不另写状态句。节标题、导航标题也不带“草稿”“首版”。讲解全文的备课备注（`notes`、`teaching`）和操作提示同样不写排练用的时长预算（“预算 N 秒”“合计约 3 分钟”“全章合计 27 分钟”）和“未测”“待试讲”这类说明：数字没实测过，录完即过时；实测过的时间写进章 LOG 的实测记录（未迁移的章写节 README），分镜也不写时长预算（课程设计原则“章节故事线先行”）。演示里真实的等待时间（如“下载约 12 分钟”“停在 Working 超过 5 分钟就切备用材料”）要保留，它们是现场取舍的依据。

**检查**：`lesson-polish` 定期巡检时，在 `courseware/index.html`、各章 `index.html`、学员会看到的生成文字，以及各节 `lesson.js` 的 `notes`、`teaching`、`summary` 里搜“制作中”“待制作”“正在制作”“已完成第”“首版”“草稿”“审阅”“试讲”“预算”，逐条删掉；删后版面空了就一起删掉对应样式。页面由脚本生成的，改生成脚本。

### ED-017 · 已迁移的章，各层对同一节的说法一致

**问题**：同一节的信息写在章文件、分镜和页面源三层，只改一层就会对不上（2026-10-23 发现：章文件写 2.4“发布上线”、2.5“四个做法”，配套文档仍写旧标题和旧时长，2.3 的内容描述也停在旧做法）。

**处理**：每条信息只写在一层，分工见章文件“各节文件与改法”；改动从上层改起，往下同步，路由见 `lesson-polish`。报错时回到上层判断哪一侧是对的，不只改报错的那一侧。

**检查**：`check-editorial.py` 对有 `LOG.md` 的章查三项：章文件“各节要点”里的节标题、`lesson.js` 的 `title` 与分镜一级标题（去掉末尾括注）一致；分镜逐页表的页面 id 与 `lesson.js` 的页面 id 一一对应（分镜先行时，只在分镜里的新页，或分镜已撤、页面还没删的旧页，在章文件“待定”里写出 id 就放行）；分镜一级标题之后只放一段导航。旧结构首个二级标题为“素材状态”；分区结构（新写或整体重写的节，2.3 起）依次为“本节内容”“逐页安排”“素材状态与操作备注”，三部分非空，页面分镜行只在逐页区，区内小标题用三级标题。旧结构继续通过，不强制迁移。正文不在章文件、逐页区重复，属于人工检查；变更说明仍放 LOG。

### ED-018 · 来源简洁标一次，制作信息不挤进演示

**问题**：图下“据某某整理/重画”与页底原文链接重复，制作说明挤占演示画面。

**处理**：按 [外部佐证的来源标注规则](external-sources.md#来源标注)统一展示出处；制作过程留在对应材料层。规则细节只在该文件维护。

**检查**：脚本提示疑似重复来源行和重复链接，人工判断；必要的署名、改编标记与数据边界不能机械删除。

### ED-019 · 拆解真实对象时按它的实际顺序讲

**问题**：拆解请求、diff、日志、配置时，按作者觉得好讲的顺序排，和学员自己打开看到的顺序对不上（2026-10-24：2.1 p08a 原先先讲工具定义，实际请求里工具在最后）。

**处理**：页内步骤按对象的实际排列走，分组和归类放到下一页做。事实的核实按 `AGENTS.md` 的编辑底线，不在这里另立规则。

**检查**：对照真实对象逐步走一遍页面步骤，顺序不一致的改页面。

### ED-020 · 故事线押在机制上，不押在某一次运行上

**问题**：转折点写成某次排练的偶然结果（“首屏少了一层纹理”“它取到 404 就下结论”），录制当天现场结果不同，PPT 和现场就讲不到一起；还容易为凑剧情反复重跑（2026-10-25：2.3 合并两组优化时发现）。

**处理**：写故事线、页标题和转场前，把要讲的内容分成三层：

| 层 | 是什么 | 怎么用 |
| --- | --- | --- |
| 机制 | 任何一次运行都成立的事（工具返回进入请求、贴的图之后每次请求都带着） | 故事线、页标题、小结、自检题只写这一层 |
| 稳定现象 | 几次排练都出现、但不保证的事（分段读长文件、想自己起服务截图） | 可以说“通常会”“几次排练都出现过”，不当转折点 |
| 某次细节 | 只在这次运行里出现的事（具体的视觉问题、交互题内容、404、token 数） | 只在 PPT 里当例子，标明“排练这次”；转场写成通用的说法（“第一轮改完，哪里和想的不一样”） |

学员要照着用的模板（反馈句、Prompt）也写成通用的样子，用某次细节填空做示范。录制当天现场与 PPT 的对照按[课程共识“PPT 与现场演示”](../design/course-design-principles.md#7-录制形态与公开材料)。

**检查**：逐页问“换一次运行，这页的标题和转场还成立吗”；不成立的，把细节降成例子，或换成机制层的说法。

## 改稿检查

备稿时先写出本节要解决的问题、可见结果和检查方法，再按 ED-002 和 ED-007 对照画面读一遍，然后同步页面、讲解全文、配套材料和制作说明。字数减少只说明稿子变短，节奏与时长仍需试讲确认。
