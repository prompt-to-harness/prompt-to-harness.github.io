# 课件编辑规范与改稿清单

> 本文件是课件文案、口播稿和讲解全文**唯一的**编辑规则来源，合并了原《课程编辑与审校记录》（ED-001–003）和课程共识中的“讲述与改稿原则”。它是讲师确认过的工作规范，不是已验证的教学效果。规则服务于画面、讲述和学习判断，不是禁词表；真实信息需要标点、重复或完整解释时，以信息是否丢失为准。

## 按编号读取

入口负责列出本任务必读与条件补读的 ED 编号，本文只保存规则正文，不再通过公共任务表二次选路。下方分类索引仅供浏览，不是必经读取步骤。

统一使用 [读取脚本](../../tools/read-editorial-rules.py)。从仓库根目录执行，例如：

```sh
python3 tools/read-editorial-rules.py ED-002 ED-007 ED-010 ED-012
```

从其他目录执行时使用脚本绝对路径；默认规则源由脚本位置确定。跨项目使用须同时提供脚本与当前规则源，可用 `--source 文件路径` 指定，不能用旧快照覆盖当前仓库规范。

- 合并各入口需要的编号并去重；已经完整读取且未变化的规则不重复读取。四项共用原则适用于所有任务，其关联详细正文不因此全部必读。
- 脚本按 `### ED-NNN ·` 标题提取，到下一条 ED 或下一个二级章节之前停止，包含处理、例子、补充与检查，不返回其他规则或修改记录。缺号、重复规则标题、非法输入或超过输出上限均报错，不输出部分结果。
- 默认输出上限为 8,000 字符，超限按编号分批读取；这不是工具 token 上限的保证。输出最后须有 `ED-READ-COMPLETE` 标记且编号齐全；工具仍提示截断时，分批重读缺失条目，不把已发出命令当作读完。
- 正文引用其他 ED 时，当前判断依赖该规则就用同一脚本补读；术语核对、措辞修改或其他明确要求执行的配套检查，读取对应资料的相关部分。背景出处、历史例子及与当前任务无关的链接不递归展开。
- 修改后按本轮已选及因影响扩大补读的规则核对。整节审查覆盖所有涉及的内容、画面、口播、操作与交付要求，不能只核对机器检查。新增共性问题在对应条目维护，留痕按 `docs/reviews/README.md`。

## 教学目标与内容取舍

<a id="ed-005"></a>

### ED-005 · 流程的分量跟任务相称

小任务的计划可以只有一句话，读取范围只覆盖当前需要的信息。为了教学拆分阅读、计划和执行时，讲明拆分的用途，并说明熟悉后哪些步骤可以合并。不要让学员误以为每次小改动都要完整套流程。

<a id="ed-006"></a>

### ED-006 · 主课只讲当前需要的判断

保留会影响下一步操作的提醒、失败时的停止条件和帮助入口；当前任务暂时用不到的原理、异常分支、详细恢复步骤、未来任务的环境准备放在配套页。移出主课的内容必须可定位、可跟做，不能只说“自行排查”。

<a id="ed-009"></a>

### ED-009 · 学习收获与练习相称

用“能发出修改请求并看懂实际差异”这样的可观察动作描述收获。练习训练同一能力，记录要求服务于检查和下一节；版本、目录等元数据用模板承接，不逐项口播。

<a id="ed-021"></a>

### ED-021 · 先分教学单元，用学习结果确定内容深度

**问题**：备课一开始就展开文件字段、操作步骤或逐页素材，把知识点当成整节的教学单元；或者只列“了解、掌握”，无法据此判断讲多深。讲师熟悉材料，容易沿搜集、实验和制作顺序往下讲，学员却难以看出各部分解决什么问题。2026-11-06 讲师在 3.2 讨论中指出这两类问题，并要求将方法写入备课 skill。

**适用**：新设计或实质调整一节的结构、内容深度与讲述顺序。小幅措辞修改沿用已有设计，不要求重新拆分整节。

**处理**：

1. **先确定部分，再展开细节。** 先写整节目标，再分成承担完整问题的教学单元。每部分交代当前问题、学习结果和与下一部分的联系。同级部分职责清楚、粒度相当，包含关系放到下一级。概念解释、关系辨析、工作示范和案例判断都可以成为单元，不固定数量、时长或讲法，也不要求每部分都有项目操作。
2. **用可观察的结果确定深度。** 每部分先回答：“这一部分结束后，学员能用这些知识做什么？”写清学员在什么情境下、借助什么材料，能完成什么解释、判断或操作。能解释、看懂、判断、操作、迁移是可选的学习要求，不必每部分全部达到。再反推必要知识和讲解边界，少用无法判断是否达到的“了解、熟悉、掌握”。学习结果是选内容的依据，不能等内容写完再补一句口号；也不要求把备课目标逐条念进口播。
3. **把知识、材料和演示放回各自的位置。** 内部知识点服务于该单元的学习结果；文件、图、案例和演示分别承担解释、举证、示范或检查的作用。先建立必要的整体认识，再展开细节，读完例子后归纳可迁移的认识。示例帮助学员认识一类对象并作出选择，学习结果不能停在复述本例的名称和组成；写清换一个同类对象时仍可用的判断依据，并区分本例特有的实现。概念需要前置时先解释；工作示范按 ED-004 从具体对象开始，不把一种讲法套到所有单元。
4. **安排与目标相称的学习检查。** 看懂材料可让学员定位和解释，判断可让学员说明选择及依据，操作可检查实际结果。录播提供可定位的解析和继续路径，不依赖讲师现场反馈；不要求每部分都新增正式测验。观看机制演示与亲手完成主线操作按课程约定区分。
5. **结构讲通后再做下游。** 按“整节目标 → 教学单元及学习结果 → 内部知识与材料 → 连贯内容 → 逐页安排与口播”推进。现有材料可以帮助判断可行性，必要时做范围明确的探索核验；实际发现不足时回到对应层修订。内容取舍按 ED-006，复用内容按 ED-007，一次运行与通用结论的关系按 ED-020，不以制作批次或现场等待时间决定教学结构。

**例子**：“认识 Skill”是一个教学单元，名称、描述、正文和引用资源是内部知识点，打开一份 `SKILL.md` 是讲解手段。学习结果可以写成：“拿到一份 Skill，能判断它适合什么任务、提供哪些指导、还需要自己补充哪些需求。”据此选择文件片段与一个任务，让学员说明是否适用及依据，不必逐行讲完文件。这里示范备课方法，不据此锁定 3.2 的分工、页序或调用任务。

“认识 Plugin”也不能只以“说出 Game Studio 包含什么”作为结果。应通过本例，使学员能区分 Skill 的任务指导与 Plugin 的能力组织、分发，判断当前需要一份独立指导、整组相关能力还是额外工具接入，并从实际组成判断某插件能提供什么。抽象的“还需补充哪些需求”要用一次具体对照讲清，例如通用指导要求检查重开，本次任务要补充重开后哪些状态应复位；不另造一套需求模板。

**检查**：

- 隐去文件名、命令和页码，只看几个部分，能否说明整节路线？同级提纲是否混入了某部分的内部细节？
- 每部分的学习结果是否具体？知识点、材料、演示及学习检查能否支持它？必要的前提是否已出现，转场是否需要学员自行补全？
- 换一份适当的材料或一次运行，学习目的与主要关系是否仍成立？只依赖某次细节的内容按 ED-020 处理。
- 学员是否只能复述示例，还是能用已讲的依据判断一个同类情境？学习结果、例子和解析是否支持这种迁移？
- 让未参与备课的人复述“分哪几部分、各解决什么、学完能做什么”。无法复述时先修单元边界或连接，再改页面；未做这项检查时如实标明，不把作者自查当成教学效果验证。

## 解释逻辑与画面组织

<a id="ed-002"></a>

### ED-002 · “能读出来”包括逻辑连贯和听者接受

**问题**：朗读检查不只看发音、节奏和换气，还要让听者顺着当前对象、依据、动作和结果往下走。

**处理**：每个讲述点同时检查：

1. 听者能否说出这一段正在处理的对象或问题
2. 每个结论前的事实、例子或前提是否已经出现
3. 这一句和下一句之间的因果、转折或范围变化是否要听者自行补全
4. 术语、代词和“这里、刚才、这个结果”是否有明确指向
5. 听完后能否知道下一步要做什么，或能否独立作出题目要求的判断

必须停下来反推“为什么突然讲这个”“它指谁”“结论从哪来”，即使读得顺也要改。优先补对象、前提或过渡；补不出依据时，降低结论强度或把内容移到配套材料。不用“其实”“大家看”“对吧”之类口头填充词遮住缺口。

**补充（2026-10-05）**：结论要对应眼前的证据和具体检查对象，不用“页面对”“模型更好”这类笼统判断代替说明；没有铺垫的能力评判或设计动机问题留在讲师备注。正反对照句的检查和改写例子见 ED-010。必要的风险提醒、事实限定和失败停止条件仍按 ED-003、ED-006 保留。

**补充（2026-10-25，2.1 录制后）**：逐字稿要能一字不改地照着念（[课程设计原则](../design/course-design-principles.md)“录制形态与公开材料”）。录制时最常卡住的是四类句子：写给编辑的免责（“这只是帮我们确定一个角度，并不是它的结论”）；把刚说的话又收回去的保守说法（“只是说有这种可能，并不是说……”）；画面前后已经说过的预告（“下一页我们先……”）；还有因果写歪了的句子，比如把“累计输入是几次相加”说成“因为命中缓存，所以不等于单次长度”。前两类删掉，或者改成有信息、有观点的话；后两类改写。预告尽量不写，能帮学员转换视角、或下一页的讲述确实要它铺垫时可以留一句。

**补充（2026-11-01，2.3 手改稿对照后确认）**：生成逐字稿时，按讲师带着画面演示的口吻写。转场交代谁正在做什么；讲师本次的示例选择用“我这次……”说明，学员跟做用邀请语气。判断依据要能定位到具体对象，例如“拿我们 Prompt 里的约束对一下”，不只说“拿约束对一下”。删除没有新增信息的作者视角伏笔，如“我们先记住它，后面还会回来”。事实限定写清配置、次数和观察结果，不用“好像有些问题”代替具体观察；未逐项核验时，不写“一个字都没改”这类过强断言。运行差异的表达仍按 ED-020。

**检查**：让没参与写作的人只看画面和听稿，复述“这一段讲什么、依据是什么、下一步是什么”。复述失败时，记录卡住的原句和缺少的连接。

<a id="ed-004"></a>

### ED-004 · 先有具体对象，再归纳方法

工作示范从文件、需求或可见结果开始，让学员知道眼前要解决什么。操作之后再简短点明方法；不在开场连续宣读框架、步骤名和能力承诺。必要的前置解释仍放在操作之前。

改写参照：把“目标，是换一段新的介绍。范围，是 README 里的这一个段落”改为“打开 README，找到项目介绍。我们把这里换成课程网站的介绍，其他段落先保留”。把“status 不保存内容”的详细说明留在准备页，主课保留“已有改动时就先保留目录，另建练习副本”的操作提示。

<a id="ed-007"></a>

### ED-007 · 重复要带来新信息

提要求时明确范围，执行时观察动作，检查时对照结果，自检时换一种情况让学员判断。相同原则不在每一步重新解释；删去没有增加理由、观察或行动的总结句。

<a id="ed-008"></a>

### ED-008 · 围绕画面讲具体变化

说清哪个文件、哪段文字、哪项输出支持了判断。“目标、范围、完成标准”可以是简短标注，不必逐项念成定义。展示示例时标明示例；实际结果按录制输出解释，不预写固定的成功台词。

**补充（2026-11-08，3.1 讲师反馈，全课适用）**：已有对应真实素材时，直接展示真实项目、截图或运行产物，不用虚构的占位示例替代。标清素材来源与版本；不同运行的截图不能拼成同一次开发的前后结果。公开展示仍遵守仓库隐私边界。

**补充（2026-11-07，3.2 讲师反馈）**：关键知识关系必须由画面表达，不能只在口播中成立。“Plugin 包含多份 Skill，本次选其中一份”需要看见整体边界、多个部分和选中对象；只摆目录与文件头，仍把关系交给学员猜。画面说明须交代对象之间的关系、依据及学生应能作出的判断，“介绍概念”“解释用途”不算定义清楚。

**检查**：先遮住口播，只看每个实际展开状态，能否指出本段关键关系的两端、包含边界或判断依据；再对照口播，确认两者在当时同时可见。文件存在、口播映射齐全、链接和布局检查通过，不能代替这项内容检查。具体制作方法见 [course-prep 的 PPT 方法](../../.agents/skills/course-prep/references/ppt-information.md#核对前后衔接)。

<a id="ed-019"></a>

### ED-019 · 拆解真实对象时按它的实际顺序讲

**问题**：拆解请求、diff、日志、配置时，按作者觉得好讲的顺序排，和学员自己打开看到的顺序对不上（2026-10-24：2.1 p08a 原先先讲工具定义，实际请求里工具在最后）。

**处理**：页内步骤按对象的实际排列走，分组和归类放到下一页做。事实的核实按 `AGENTS.md` 的编辑底线，不在这里另立规则。

**检查**：对照真实对象逐步走一遍页面步骤，顺序不一致的改页面。

## 文案与口播表达

<a id="ed-001"></a>

### ED-001 · 屏幕文案不加多余的中文句末标点

**问题**：画面里的标题、标签和短要点，句末的“。”只形成视觉噪声。

**处理**：

- 标题、章节标签、短要点、卡片标签、导航文字、单句的屏幕说明（如首页卡片描述、提示语）默认不加句号；已有箭头、冒号或分隔符能表达关系时，也不补句号。2026-10-03 确认单句说明同样适用。
- 同一元素里有多句时，句间句号保留；题干、请求、Prompt、解析、引用原文和讲解全文保留必要标点。
- 不为去句号把完整说明改成残缺短语。先判断它是标签、短提示，还是需要完整理解的说明。
- 口播稿的标点服务于朗读，不套用这条规则。

**检查**：只看屏幕文字，圈出句末标点，问“删掉后是否失去关系、条件或引用边界”。没有新增信息的删掉。脚本不检查 `.p-evidence` 阅读视图里的请求记录原文（那是引用，按原文保留）；页面里逐字展示的原文用 `<blockquote data-quote="出处">` 包住，脚本同样跳过（2026-11-07，4.2 p14 需求笔记）。

<a id="ed-010"></a>

### ED-010 · 通过信息取舍改善口语

一句话尽量说清一个动作或判断，长句按讲解顺序拆开。检查“这样做是为了”“这里练习的就是”“既看……也看……”这类句子是否增加了信息，不把它们机械列为禁词。

**补充（2026-10-05）**：检查“能……不能……”“……不等于……”这类正反对照是否回应了前文出现的误解，或解释了当前任务确需区分的对象。不要先制造一个读者尚未提出的推论，再用否定句纠正；也不要用限制判断的套话代替具体解释。默认直接说对象、变化、证据和下一步。确有误解或需要限定证据范围时，保留必要对照并讲清依据。

**通用检查**：

- 无铺垫的否定：前文是否已有相应判断，或当前操作是否确需区分？删去这句话后，是否损失必要的操作边界？
- 笼统的证据结论：说明的是哪个检查对象、结果和完成标准？能否直接说清这些信息？

例如，“恢复对话不等于恢复文件或服务”有实验支撑，并影响是否重启服务；“最小权限不等于越少越好”有只读权限无法写入的例子。这些必要区分可以保留。

**改写参照**：2.2 P07“能看到内容差异 · 不能据此判断模型能力或设计原因”改为“换一个模型，Codex 配给它的指令内容也会变化”，口播点出具体章节；P12“能构建，不等于页面对”改为“构建流程成功完成”，口播说明视口、Tab 和 build 各自的检查对象。

**检查**：遇到上述句式，复述它正在纠正哪个判断、区分哪两个对象，以及这一区分如何影响当前操作；说不清时，检查能否改成直接描述。属于语义判断，由人工 / skill 检查，不按句式一律报错。

**补充（2026-11-01，2.3 手改稿对照后确认）**：口语化不以句子最短为目标。允许为明确主体、连接动作和转换视角保留必要的主语、连接词和缓冲语；不批量添加“其实、的话、稍微、一下”来模仿口语。改完再核对主体、术语和结论范围，不能为了顺口把“同一类内容”改成“内容一样”，或把“源码与渲染页面”的区别泛化成“数据与内容”。逐段问：“这段话能否直接用于带着学员看画面、做判断和操作？”

**补充（2026-10-24）**：抽象的概括句（“角色说明消息是谁在‘说话’，不说明文字是谁写的”）读起来像机器写的，讲师一眼就会卡住。换成画面上能指到的具体例子：“user 里有两条，一条是 Codex 加的环境，一条才是我们的问候”。2.1 p09 按这个改过。

<a id="ed-012"></a>

### ED-012 · 一个对象一个叫法

**问题**：同一个对象换着叫（首页 / 个人主页 / 首页原型；工具入口 / CLI；一节课五种名字），学员会以为是不同的东西。平台 reviewer 首轮反馈把它列为最大的问题（2026-10-09，R18）。

**处理**：按 [`terminology.md`](terminology.md) 的统一叫法写；学员第一次遇到的术语，按表中“首次出现”给出解释。不要用“1.3”“1.5”这类编号代替含义，先说那一节做什么，再附编号。新出现的一物多名先登记到术语表，再改课件。

**补充（2026-10-24）**：同一组对象的分类也只能有一套。贯穿全章的分类、术语和示意图，定义只写在章文件“全章约定”里，各页只引用；反复出现的图由代码统一生成（如第 2 章 `lessonkit.anchor()`），不在页面里手写副本。外部图的分法对不上课程分类时，只画原图的顺序，不硬对。起因：2.1 p09 分六类、锚点图七块、p16b 的对应列又是另一套，三处矛盾。

**检查**：逐页列出指代同一对象的名词，超过一种就改；改完一节，再把这一节用到的分类和全章约定逐条对照；看到节号时，问学员此时是否知道那一节讲什么。术语表“已废弃的说法”一节列出的旧叫法，由 `check-editorial.py` 在章文件和课件内容源里查找（2026-10-21 起）。

<a id="ed-014"></a>

### ED-014 · 屏幕短文字避开常见别扭说法

**问题**：节标题、卡片、label、`lead` 这类短文字，容易写成目录腔、作者行话、电报体或金句。阅读模式是学员唯一的文字版，这些说法离开口播就读不懂或读偏（2026-10-11 第 0–2 章审查，讲师确认）。

**处理**：按 [`wording-patterns.md`](wording-patterns.md) 的 W1–W8 和高频词对照，能说具体对象和动作就直接说。节标题按节的角色用稳定句式，见同文件“节标题的句式”。

**检查**：审一节时逐页对照；另按[审查方法](../../.agents/skills/lesson-polish/review.md)里的“定期巡检”跨章过一遍。新模式或好例子补进 `wording-patterns.md`，不在这里加条目。

## 产物分工与制作同步

<a id="ed-003"></a>

### ED-003 · 课程材料分层，内容同步不等于全文复制

**问题**：画面、阅读模式、逐字稿、录制说明和环境卡要一致，但各层读者和职责不同。

**处理**：

- 画面与讲述线首先回答“在什么画面讲什么内容”。HTML 大结构沿用当前有效讨论稿，在段内优化具体画面、必要操作与讲述对应；短要点或自然段按需使用，不强制展开长篇说明。格式见 [course-prep 讲述方法](../../.agents/skills/course-prep/references/spoken-script.md#先交付画面与讲述线2026-11-07讲师确定)
- 屏幕文字放对象、关键词、请求、差异和证据
- 口播解释当前画面变化、判断依据和下一步
- 学生独立使用材料在讲师确认备课成果后制作，补足独立学习所需的上下文；文件格式、阅读组织和发布范围按[交接边界](student-materials-handoff.md)另定，不默认采用现有阅读模式
- 逐字稿正文（讲解全文，来源为 `script.json`）给讲师录制用，不发布；`speaker.html` 兼作备课对照时，已有逐字稿就近对应画面，保留讲师修改，并与不念的操作提示区分。选材理由、教学分析、复用来源与核验历史放备课说明，不与正文混排，也不再写一篇重复讲法。学生独立学习所需的解释，在后续学生材料中按用途组织，不默认发布完整口播
- 录制说明记录镜头、真实输出、剪辑、版本和未验证状态
- 环境卡记录命令、版本、路径和排障

作者才需要知道的制作状态（时长、切点、take、未验证状态）不进入学员口播；学员完成当前判断所必需的边界，不能因为“放到配套页”而消失。

**检查**：每段标记“对谁说、要完成什么”。主阅读区能直接指出当前画面、对应内容与必要切换；既不帮助理解、也不是录制时要执行的动作，就删掉或移到正确的层。大结构与讨论稿一致，不能以保留大段数量为由丢掉段内对应关系。

<a id="ed-011"></a>

### ED-011 · 生成物与源文件保持一致，删除要清残留引用

**问题**：有些页面由脚本生成（如 2.1 的 `lesson.js` 来自 `ch02/lessons/01-request/tools/build-lesson.py` 与本节 `script.json`；第 0、1 章 `lesson.js` 里的口播由 `rebuild-lesson.py` 从 `script.json` 合并）。只改生成物，下次生成就被覆盖；删掉一个页面或入口而不清链接、检查脚本和说明，会留下死链。

**处理**：先找到内容源再改；改完重新生成。删除页面时同步清入口、检查脚本、README 和构建说明。

**检查**：`check-editorial.py` 比对生成物，`check-courseware.py` 查本地链接。

<a id="ed-013"></a>

### ED-013 · 每一步先写操作提示，再写口播

**问题**：录制时讲师要一边念稿一边切窗口、跑命令、开页面。操作散在折叠备注或口播里，录到一半才发现该新开标签页还是复用、命令在哪个目录跑，容易重录或念出讲师才该看的话（2026-10-11 确认，以第 1 章为范本）。

**处理**：`script.json` 里每一步以 `【操作提示｜…】` 开头，空一行接口播正文；写法见[制作手册“讲稿与转场”](lesson-authoring-playbook.md#讲稿与转场)。操作提示不念，口播正文不放舞台标注。

口播中途的窗口切换另起一段 `【切换｜目标】`，`speaker.html` 单独着色，不念（2026-10-25）。

录制要用的操作只写在操作提示和本节录前准备里，不放进折叠备注或 `teaching`；逐字稿页的组成见制作手册“讲稿与转场”（2026-10-25，第 2 章 LOG C2-102）。

**检查**：`check-editorial.py` 检查每一步都以一条操作提示开头、后面有口播正文，`【切换｜…】` 段只占一行，并对“现场演示时……”这类演示形态未定的条件句给提示；提示写得够不够具体，按制作手册逐条看。

<a id="ed-017"></a>

### ED-017 · 章级设计、讲述线与课件保持一致

**处理**：节标题、范围和验收以章级设计为准。页序、画面与口播对应按当前讲述线核对。旧 `STORYBOARD.md` 只读备查。 [内容依据](../agents/sources-of-truth.md)

**检查**：`check-editorial.py` 对有 `LOG.md` 的章核对章文件和 `lesson.js` 的节标题。制作时对照当前讲述线实际推进课件，核对页面顺序、展开状态及对应讲述。

## 证据状态与对外呈现

<a id="ed-015"></a>

### ED-015 · 完成状态在各入口说法一致

**处理**：备课状态以当前有效 Discussion、讲述线及本轮实际核验结果为依据。工作稿、材料缺口、已检查范围、讲师确认与试讲分别说明；同一成果在实际使用的入口中保持一致，不把局部完成当作整节完成。

需要后续沿用的决定与缺口写回对应内容源；日常进度、自查和构建结果随对话交付。章、节 README 与 LOG 的旧记录供查阅，不再要求按旧状态横幅逐层同步。

**检查**：核对当前有效设计、讲述页及交付说明中的状态与实际成果；已有记录冲突时定位具体依据，不因旧 README 的状态否定讲师的新决定。

<a id="ed-016"></a>

### ED-016 · 学员页面不写制作进度和审阅状态

**处理**：备课时，学生会看到的授课画面与听到的口播不出现制作进度、审阅状态或作者的时长预算。讲师使用的备课信息可保留必要状态，但须与展示和可照读正文分开。真实等待时间、失败条件及影响学生判断的事实限制仍应保留。

讲师确认后制作学生独立使用材料时，再检查最终页面、文件、导航与下载内容中的制作状态。具体载体和未开放内容的呈现由学生交付阶段确定，见[交接边界](student-materials-handoff.md)。状态保存与一致性按 ED-015，不在本条另定 README 或 LOG 保存机制。

**检查**：备课阶段检查实际授课画面和口播；学生交付阶段检查最终可见产物。按内容用途判断，不机械删除“未验证”等与教学事实有关的说明。生成页面的问题回到源文件修改。

<a id="ed-018"></a>

### ED-018 · 来源简洁标一次，制作信息不挤进演示

**问题**：图下“据某某整理/重画”与页底原文链接重复，制作说明挤占演示画面。

**处理**：按 [外部佐证的来源标注规则](external-sources.md#来源标注)统一展示出处；制作过程留在对应材料层。规则细节只在该文件维护。

**检查**：脚本提示疑似重复来源行和重复链接，人工判断；必要的署名、改编标记与数据边界不能机械删除。

<a id="ed-020"></a>

### ED-020 · 故事线押在机制上，不押在某一次运行上

**问题**：转折点写成某次排练的偶然结果（“首屏少了一层纹理”“它取到 404 就下结论”），录制当天现场结果不同，PPT 和现场就讲不到一起；还容易为凑剧情反复重跑（2026-10-25：2.3 合并两组优化时发现）。

**处理**：写故事线、页标题和转场前，把要讲的内容分成三层：

| 层 | 是什么 | 怎么用 |
| --- | --- | --- |
| 机制 | 任何一次运行都成立的事（工具返回进入请求、贴的图之后每次请求都带着） | 故事线、页标题、小结、自检题只写这一层 |
| 稳定现象 | 几次排练都出现、但不保证的事（分段读长文件、想自己起服务截图） | 可以说“通常会”“几次排练都出现过”，不当转折点 |
| 某次细节 | 只在这次运行里出现的事（具体的视觉问题、交互题内容、404、token 数） | 只在 PPT 里当例子，标明“排练这次”；转场写成通用的说法（“第一轮改完，哪里和想的不一样”） |

学员要照着用的模板（反馈句、Prompt）也写成通用的样子，用某次细节填空做示范。录制当天现场与 PPT 的对照按[课程共识“PPT 与现场演示”](../design/course-design-principles.md#7-录制形态与公开材料)。

**检查**：逐页问“换一次运行，这页的标题和转场还成立吗”；不成立的，把细节降成例子，或换成机制层的说法。

## 改稿检查

整节备稿先明确本节问题、可见结果与检查方法；局部改稿沿用有效设计。按当前任务入口列出的适用规则检查受影响内容，涉及讲述时按 ED-002、ED-007 对照画面连读，再同步本轮授权范围内受影响的产物。字数减少只说明稿子变短，节奏与时长仍需试讲确认。
