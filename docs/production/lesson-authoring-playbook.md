# 课件制作手册：从分镜到零件

> 2026-09-30，2026-10-01 补充三层内容与转场 · 把 1.2 重刷得到的做法固化下来，新小节从第一稿起按这套写，不再"先写完再重刷"。这份手册不是已验证的教学效果。视觉规范以 [visual-design-system.md](visual-design-system.md) 为准，零件与用法见 [parts.md](parts.md)，本手册只讲"按什么顺序做"。

## 1. 三条原则

1. **先有结构，再有页面。** 每页先想清楚它要表达的关系（先后、对比、归属、分类、自检），再从零件库里挑零件组合。零件拼不出来就标 `expressive`，不硬拼、不手写大段 SVG。
2. **三层内容，逐层精简。** 逐字稿最全，阅读模式其次，展示画面最精简（见第 4 节）。画面以示意图、手绘图为主，目标 60–90 字，超过 120 字就要拆（代码、diff、终端里的证据行不计）；但看懂这张图必需的文字要留——标签要能独立读懂，不缩成只有讲师才明白的简称。
3. **一页一个结构。** 每页一个断言标题，加一个结构化证据。需要两个结构就拆成两页。

## 2. 新一节的制作流程

| 步 | 做什么 | 产出 | 检查 |
|---|---|---|---|
| 1 | 对照两份大纲，抄出本节的知识点、演示、练习、验收 | 范围清单 | 与大纲逐项一致，不另起结构 |
| 2 | 写分镜：确定贯穿任务，按下文“实验与项目主线”选择主线演示或独立实验；每页写"学员面对的问题 → 看到的证据 → 需要作的判断 → 归纳的概念" | `STORYBOARD.md`（一页一行）及简短实验说明 | 抽象术语出现前，先出现它解决的问题；需要特殊条件的实验先预检，再写具体结果 |
| 3 | 给每页选结构和零件（见第 3 节）；开篇、暂停自检、涂鸦小结不可省；切到实操之前要有衔接页 | 结构序列 | 每段（5–8 分钟）以断言开场、以"暂停去做"或自检收尾 |
| 4 | 写 `lesson.js`：每页 `html`（用零件）、`steps`、`script`（口播）、`source`；需要定制的页加 `expressive` | 内容源 | `data-reveal` 最大值 = 步骤数 − 1；口播与每一步一一对应，转场与 `lead` 写法见第 4 节 |
| 5 | 打开检查：逐步点一遍，截图看焦点、溢出、遮挡、阅读顺序；按第 4 节从头到尾连读口播 | 修改记录 | 正文区不越过 y 632，不压讲师框；未试讲不写"教学效果已验证" |
| 6 | 记录验证：做了什么、没做什么 | 小节或章节 `verification.md` | 未测项如实标明 |

分镜是这套流程里最费脑力、也最不能省的一步；选零件和写 `html` 在分镜之后很快。

### 实验与项目主线

> 2026-10-05 讲师确认的课程设计目标，适用于后续新课设计和已有内容调整。第二章示例说明选择方法，具体实验尚须准备与核验；本约定不代表实验或教学效果已验证，也不新增学员验收项。

**贴近项目、前置简单、容易复现的实验优先在主线中完成；需要大量上下文、特殊状态或难以自然复现的现象，用专门设计的独立实验讲解。** 目标是让项目连续、内容容易设计、学员容易理解和复现。主体 demo 只承担交付过程与自然相关的知识，不为容纳所有知识点增加功能、堆积会话或等待 AI 犯错。

#### 怎样选择

| 判断 | 安排 |
| --- | --- |
| 当前任务已经提供所需文件和状态，几步操作就能看到相关证据，观察不妨碍项目推进 | 留在主线，直接使用本轮产物和记录 |
| 与主线有关，但需要长会话、特定历史、多个环境或反复重置；学员自己的项目未必具备条件 | 从相关检查点建立独立实验，准备最小输入和状态；可沿用项目背景，不依赖主线完整历史 |
| 已有真实记录足以解释，重新执行的成本较高或输出无法稳定重现 | 使用标明来源的固定记录对照；如提供重跑入口，说明允许变化的结果 |

独立实验切入时说明“要观察什么、准备了什么条件”；结束时说明结论如何用于当前任务，再回到主线。实验改动不自动合入项目。学员保留自己的连续项目，机制实验默认以看懂为准；必须跟做的内容仍按大纲验收，不能用观看回放替代实际交付。

#### 怎样准备与冻结

1. 先写知识问题、可观察证据和 PPT 结构草稿。需特殊条件的实验先做最小预检，能支持结论后再填写具体数字、输出和口播；结构设计可以先行，未经验证的结果不能写成事实。
2. 优先使用现有本地工具、固定文件、独立目录、少量命令和必要的独立模型配置。**当前暂不引入 Docker，也不增加统一容器环境的制作或学员前置。** 能靠一个小副本完成的实验，不搭通用实验平台。
3. 固定起点、版本与配置、任务输入、必要的人工作答和检查方法。会话实验还须记录历史如何构造；只提供代码快照不足以复现会话状态。账号与密钥不进入实验材料。
4. 保存一份真实参考记录，并区分真实运行、回放、教学示意与人工构造的条件。模型回答可以不同，观察对象与结论必须有证据；不要求重跑得到同一句摘要、同样请求次数或同一次错误。
5. 从新目录复做，条件允许时由另一位讲师仅按说明复现。写清已测环境、实际结果、未测项和无法运行时的观察入口。环境固定不代表远端模型或服务完全固定。

每个实验在已有分镜或配套材料中写一份简短说明即可，不要求另建目录体系：

| 项目 | 需要写清 |
| --- | --- |
| 问题与位置 | 解释什么；在主线还是独立实验，为什么 |
| 起点与操作 | 文件/检查点、配置、必要会话或进程状态；准备和执行步骤 |
| 观察与产出 | 看什么证据；哪些结果允许变化；学员需要留下什么（若有） |
| 验证与继续 | 已做和未做的检查；参考材料的实际入口；如何保留工作并回到主线 |

若主线没有提供合适条件，可以构造独立实验输入；若真实实验不支持原先解释，应调整解释。不为了稳定演示把准备好的故障包装成自然事故。现有章节对故障案例的明确限制仍然有效，例如第二章不准备坏 diff、错误 `base` 的约定，本原则不自动撤销这些限制。

| 内容 | 放在哪里及理由 | 输入、动作与可观察结果 | 与主线衔接 / 学员要求 |
| --- | --- | --- | --- |
| 2.1 三条反馈核对 | 主线；首页 v0 本来就是核对对象 | 用当前 v0、示例反馈卡和既有决定，按指定视口、点击与 Tab 路线核对，记录复现或未复现的证据 | 得到反馈清单，选定内容补充；跟做。无需改坏页面来保证建议成立 |
| 2.1 查看一次请求及环境对照 | 与反馈核对有关的请求就地解释；不同配置的对照独立做，避免改变主线环境 | 使用实际只读核对记录；配置对照另备同一文件与同一任务，检查两次请求中的相关差异，不要求固定 token 数 | 回到“本次回答依据什么”；机制观察，不新增验收 |

| 2.2 系统指令版本对比 | 独立材料对照；不依赖首页运行状态 | 固定源码提交、文件和对比命令，指出所选版本的具体变化；源码对比与实际请求记录分别说明来源 | 回到版本和配置对请求的影响；无需安装多个 Codex 版本即可先讲源码差异，运行时差异另行核验 |
| 2.2 内容迭代 → 2.3 Review | 主线；修改、验证和审查是连续交付 | 用人工提供的经历和完成标准，检查本轮真实 diff、页面、键盘与构建，形成评审结论与提交 | 学员在自己的项目跟做；改动干净也可以接受，不预置越界代码 |
| 2.3 回退 | 独立副本；观察撤回不应破坏即将发布的成果 | 从明确的代码与记录提交开始，核对目标后撤回代码提交，检查代码变化和记录保留情况 | 回到正常 v1 继续发布；按现有大纲解释回退点与命令，不要求主线先发生误收 |
| 2.5 重构 A/B | 独立实验；需要同一基线上的两种实现作比较 | 沿用 v1 与标明教学材料的 A/B，核对内容、点击、Tab 与视口，用行为证据判断修改性质 | 完成判断记录；无需把 A/B 合入自己的首页 |

2.4 的真实公开前检查与发布继续留在主线；固定本地输入并提前预检服务条件，发布是否完成仍以实际线上验收为准。第二章参考快照和 A/B 材料已有排练基础，请求与压缩的统一素材、操作入口仍须核验补齐。课件布局和链接检查通过不能代替实验复现检查。

## 3. 要讲的内容 → 零件

| 你要讲的 | 用 |
|---|---|
| 本节的问题和位置 | 开篇地图 `.p-map` + 手写问题 `.p-hand` |
| 一个冲突钩子（每节最多一页） | 漫画开场 `.p-comic` |
| 流程、循环、回路 | 流程 `.p-flow`，回路 `.p-back`，出口 `.p-exit` |
| 边界、范围、"有但没读到" | 集合 `.p-set`（`is-unread`、`is-wrong`）+ 对照 `.p-pair` |
| 一次工具调用、一次执行 | 操作记录 `.p-rec`，或记录贴纸 `.p-log` |
| Prompt 和回复的对应 | Prompt ↔ 回复 `.p-prompt` |
| 切去真实环境；切回来复盘 | 切到实操 `.p-handoff`，回来在同一张 `.p-watch` 上打勾 |
| 一段代码；一次改动 | 代码讲解 / diff `.p-walk` |
| "凭什么相信这句话" | 证据清单 `.p-claim`，或题卡盖章 `.p-quiz` |
| 四种性质的分类 | 2×2 `.p-quad` |
| "什么时候选哪个" | 权衡矩阵 `.p-matrix` |
| 课程主线定位 | 阶梯 `.p-stairs` |
| 失败方式与排查 | 流程 + 挂点 `.p-hang` |
| 课堂练习 | 练习任务卡 `.p-task` |
| 让学员暂停自检 | 暂停 `.p-pause` + 问答列表 `.p-qlist` |
| 本节收拢 | 涂鸦小结 `.p-sketch` |

新增零件前先问三件事：现有零件拼不出来吗；这个结构会在别的小节复用吗；能做成可组合的 HTML + CSS，而不是只服务一页的定制图吗。三个都是，再加进 `parts.css`，同时补进 [parts.md](parts.md) 和陈列页。

## 4. 三层内容：逐字稿、阅读模式、展示画面

同一页有三种呈现，信息量逐层收窄：

| 层 | 写在哪 | 给谁 | 写法 |
|---|---|---|---|
| 逐字稿 | `script`，每一步一段 | 讲师照着念，保证交付质量 | 口语，最完整，带转场 |
| 阅读模式 | 同一份 `html` 竖着往下滑，加上 `lead` | 只看材料、不听讲的人 | 书面语。`lead` 用 2–3 句（约 60–120 字）补上画面缺的上下文，可以带一点承上启下 |
| 展示画面 | `html` | 看视频、听讲的人 | 图示为主，加必要的短语标签 |

- 画面和阅读模式里出现的信息，逐字稿里都要讲到；逐字稿多讲的不必都上屏。讲师照稿念时，屏幕上不该出现他没念到的东西。
- `lead`、`.caption`、`.source-note`、题卡解析 `.p-why` 在展示模式隐藏，只在阅读模式出现；节封面页的 `lead` 两种模式都显示，保持一句话。
- 推荐顺序：分镜 → 逐字稿和画面一起写（口播说"看左边这个框"，画面就得有）→ 最后从逐字稿提炼 `lead`。
- 三层由维护内容的 Agent 保持一致即可，不为此加检查脚本。自查方式：只看阅读模式往下滑，能不能自己读懂每页在讲什么。

### 讲稿与转场

**写法**

- 每一步一段话，和 `steps` 一一对应；用口语，主语清楚（"我们""大家"），不出现"[先判断]""开场串词："这类舞台标注。
- 人称用"我/我们"的视角讲述，少用"你"：讲师和学员站在同一边做事，例如"我们把首页给熟人看""自检时各自回答"，而不是"你把首页给熟人看"。画面、阅读模式导语、自检题干同样适用。引用别人的原话、写给 AI 的 Prompt、对系统指令的转述保留原文人称（2026-10-02 第 2 章审阅确认）。
- 第一次出现、学员可能不会操作的步骤（如切换浏览器视口、启动请求查看工具），要先讲清是什么、怎么做，再切到实操；不要只给一句"后面再说"，推迟解释时也要先给一句够用的说明。
- 先讲具体例子，再归纳方法；画面上的短语要在口播里展开成完整的意思。
- 操作提醒、边界、不能宣称的事（"示意不是运行结果""不要真的去访问私人目录"）分两类处理：学员也该听到的写进口播；只给讲师看的放进 `teaching`，标题用"讲师提示"。

**转场：每一处切换都要有一句话**

| 切换 | 讲稿里要有什么 | 例 |
|---|---|---|
| 页 → 页 | 本页最后一步用一个问题或一句预告，把学员带到下一页的问题 | "权限给大一点不是更容易做成吗？下一页拆开看。" |
| 段落开头 | 先给断言，再给证据 | "多给的能力不会让结果更正确。" |
| 切到实操 / 切回 | 切走前说要看什么；切回来说用同一张清单复盘。换工具或换启动方式（如通过代理启动 Codex）要单独一页说明 | "切过去之前，先记住三件事……" |
| 节开头 | 一句话接上一节的产出，再抛出本节问题 | "上一节交付了首页 v0，这一节回头看权限。" |
| 节结尾 | 本节带走什么 + 下一节要解决的问题 | "下一节，我们把这些边界写进首页任务。" |
| 章结尾 | 回顾本章习惯，交接到下一章的起点 | "第 2 章带着本地 v0，从真实页面出发继续迭代。" |
| 暂停 / 自检 | 说清停多久、做什么，揭晓前不念答案 | "先暂停两分钟，自己起草。" |

**检查**

1. 把整节、再把相邻两节的口播按顺序连读一遍（`export-chapter-scripts.py` 导出的 `script.md` 方便连读），听有没有突然跳到下一个话题的地方。
2. 只读每节第一句和最后一句，确认节与节、章与章接得上。
3. 翻一遍展示画面：字多的页看能不能改成图或挪进讲稿；也看反方向，标签是不是缩得太短、离开口播就看不懂。

### 外部链接

（2026-10-05 讲师确认。）有些内容直接打开原网页最清楚，比如源码某个版本、官方文档。链接写成每页的 `refs`，不写进口播、讲解或手写的 `<a>`：讲解全文按纯文本渲染，那里的网址点不了，也没法被脚本找到，时间一长就忘了。

| 类型 | 判断 | `kind` | 呈现 |
|---|---|---|---|
| 现场打开 | 这个网页本身就是本页的证据 | `live` | 画面最下一行（零件 `.p-refs`），随最后一步出现；录制时讲师点开，口播说清看什么 |
| 回看 / 延伸 | 重要，但不影响学员当场的判断 | `read` | 不上画面；阅读模式本页底部、讲解全文的“原文与链接”列出 |
| 操作入口 | 学员跟做时要去的设置页、下载页 | — | 写进配套页或环境卡，不放在这里 |

- 第 2 章用 `lessonkit.ref(文字, 网址, 分组, kind=…)` 写进 `scene(refs=[…])`；渲染在 `courseware/shared/app.js` 与 `speaker.js`。
- 链接固定到具体版本（完整提交哈希、带版本的文档地址），不指向会变的 `main`。
- `make check` 离线校验 refs 格式和固定版本，口播或讲解里出现裸网址就报错；`make links` 按章、节、页列出全课链接并逐个访问，录制前跑一次。
- 第 1 章仍有直接写在 `html` 里的链接，`make links` 会一并列出，标为“页面内嵌”；改到那一页时顺手迁成 `refs`。

## 5. 把旧内容迁到零件

只在重刷已有小节时使用；新小节不需要这一步。

1. 逐页统计画面字数，标出超过 90 字的页，把解释性文字移进讲稿。
2. 为每页写映射：旧页 → 新结构 → 哪些文字进讲稿（参考[第 1 章视觉盘点](ch01-visual-inventory.md)）。
3. 先改 `html`，步骤、锚点尽量不动；步骤数变了要同步 `steps` 与 `script`。画面删掉的解释要补进口播，然后按第 4 节检查转场。
4. 拆分或合并页面时同步：页码锚点、`check-courseware.py`、各节练习页链接、大纲里引用页码的位置。说明文档里不写页数、步数这类会随改版变化的数字，以 `lesson.js` 为准。
5. 页数变化后重新核对每段时长，未试讲不写新时长已验证。
6. 和内容作者按小节交接：正在重刷的小节，内容侧先不改 `lesson.js`，避免整段 `html` 冲突。
