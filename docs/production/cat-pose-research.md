# 三猫姿态研究：头颈、猫爪与章节互动

> 2026-10-07 · 公开一手资料核查与两个流程样本。制作建议待讲师比较；不是模型成功率或教学效果的验证。

## 最新澄清（2026-10-07）

讲师澄清：标注图的问题是头扭得诡异，并不是所有稍微拟人的动作都错。角色需要展示章节任务；完全脱离内容的真实猫会变成装饰。允许动画片式简单抓握和适度夸张，猫爪不能像人手一样灵活。若细节画法难以支撑互动，可以尝试之前的卡通画风。

因此，上一轮“身体必须完全真实、主要靠视线、透明猫复用优先”的建议不作为当前制作方向；不能从公开指南推出讲师禁止拟人的偏好。当前应依次检查章节互动、头颈朝向、猫爪结构，再检查外形与画法。第 4 章新增拿两张输入卡比较的细节版和卡通版，见 [互动对照](../../demos/imagegen-pilot/interaction.html)。两稿尚待确认。

## 上一轮判断（已被讲师澄清）

我们使用 Prompt 的方式有问题，但不能把所有失败归结为一句话没写对。最明显的问题是：任务要求自然猫身体，同时锁定了“猫坐在椅子后、双爪放到书桌上”的人类办公构图。前两次又明确要求握笔、托腮或指认输入；后来虽然禁止人手，却沿用这个身体和场景继续编辑。去掉手指没有解决整体姿态。

建议停止沿着这张失败稿连续修爪。先从真实猫的完整姿态建立可复用角色，再让课程页面承担输入、对照、指向和交接；需要完整场景时另行布置符合猫身体的空间。图的画风可以细致，动作不必像人。拟人的表达可集中在表情、视线与旁边可编辑的台词，身体保持真实猫的姿态；这是本轮制作建议。

## 一手资料支持什么

1. **明确参考图角色，简化排错。** OpenAI Cookbook 建议逐张说明用途，先建立清晰基础，再用小改动迭代；长 Prompt 可以有效，重点是容易定位问题。[GPT Image Prompting Guide](https://developers.openai.com/cookbook/examples/multimodal/image-gen-models-prompting-guide)
2. **用可见构图表达目标。** Google 官方指南建议复杂姿势提供姿势参考，并用目标场景的正面描述替代单纯排除列表。这里借鉴方法，没有调用 Gemini，也不能直接移植其成功率。[Gemini image generation](https://ai.google.dev/gemini-api/docs/image-generation)
3. **姿势与风格可以分开控制。** Adobe 的 Structure Reference 控制轮廓与深度，并可搭配 Style Reference。这说明结构参考是独立制作手段，不等于多写形容词。[Firefly Structure Reference](https://developer.adobe.com/firefly-services/docs/firefly-api/guides/concepts/structure-image-reference/)
4. **有需要时使用空间条件。** ControlNet 论文研究了边缘、深度、分割与人类姿态等条件；IP-Adapter 作者展示了图像参考与结构控制组合。它们支持“外观与结构分别提供”的方向，但没有验证我们这三只猫。[ControlNet](https://arxiv.org/abs/2302.05543)、[IP-Adapter](https://ip-adapter.github.io/)
5. **生成仍需验收。** OpenAI 官方文档说明角色一致性和精确构图仍可能失败；提示指南也要求检查编辑链、保留细节和透明边缘。参考图不是确定性锁定。[Image generation limitations](https://developers.openai.com/api/docs/guides/image-generation#limitations)、[Image prompting](https://developers.openai.com/api/docs/guides/image-prompting)

查阅日期均为 2026-10-07。这里只保存链接与自述总结，不复制第三方图片。当前内置 image_gen 的可用参数没有结构权重、ControlNet 或姿势骨架接口；官方 API 或其他产品的能力不等于当前工具已暴露该能力。

## 上一轮备选做法（历史研究，不作为当前优先方向）

| 做法 | 操作 | 对本项目的取舍 |
| --- | --- | --- |
| 真实姿态参考 + 新场景 | 照片给身份和姿势，设定图只给画法；重建全身、支撑面和道具关系，允许移动或删去椅子 | 适合少量章首场景，仍逐图检查 |
| 角色素材 + 页面组合 | 先确认坐、站、趴、看向一侧等少量自然全身姿态，保存透明角色；输入卡、文字和强调由 HTML/SVG 提供 | 当前优先建议。固定角色像素复用；换章节无需重画身体。但不能随意拉伸或扭曲同一 PNG 来伪造动作 |
| 专门的结构控制 | 在支持它的工具里使用轮廓／深度参考，加外观参考；另做相同目标的质量比较 | 需要新增工具流程，暂不安装。人类骨架不是猫的四足骨架；猫可从全身轮廓参考起步，具体效果尚未试验 |

暂不推荐先训练专用角色模型，也不因这次失败直接判定应换供应商。若比较另一模型，固定照片、目标、画法与验收点，重复生成后再比较接受率；不能拿两张不同场景的好看程度作结论。

## 上一轮 Prompt 试验（仅作历史对照）

身份与画法保留，姿态与场景可调整。优先写清：猫的完整身体是否可见、身体朝向、前后爪落在哪个支撑面、道具放在何处。不要先写“像人在认真思考”，再用很多禁词纠正手。

本轮场景描述的关键部分：

> 蓝猫像真实照片一样四足站在宽桌面上，完整身体、足部和尾巴可见，躯干沿肩部到髋部水平延伸。它在摊开的本子旁自然低头关注纸张，四爪在同一桌面承重。照片给身份与站姿，设定图只给细节笔触；这是新场景，不保留旧办公构图。

保留少量有明确作用的排除项，如不生成文字、服装和椅子。正面描述不是无条件取代禁词；核心是目标与保留项不能互相冲突。

## 上一轮验收与试验边界

先看整体轮廓：是否仍像猫，前后肢与躯干是否连贯，身体由哪个面支撑，重心与接触位置是否可信。再看身份：蓝猫腮部、花色、眼色和画法。最后才看道具和章节职责。身体遮挡太多以致无法判断时，不通过姿态验收。

两个新样本各生成一次，同时改变了参考使用方式、构图与 Prompt；它们是流程探索，不是单变量 A/B 实验，不足以量化任何方法的成功率。结果与检查记录见 [本轮审查](../reviews/2026-10-07-all-cat-pose-research-codex.md)。是否采用仍待讲师比较。
