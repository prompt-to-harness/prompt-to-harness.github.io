# 屏幕短文字的常见别扭说法

> 状态：2026-10-11 建立，来自第 0–2 章屏幕短文字审查（`docs/reviews/2026-10-11-ch00-ch02-wording-claude.md`），讲师确认作为固定清单，由 `lesson-polish` 定期对照处理。编辑规则见 `editorial-checklist.md` ED-014，本文件只放模式、判断方法和例子。它不是禁词表：词本身没错，错在学员读不懂或读偏。

## 怎么用

- 看的是学员读得到的短文字：节标题、章首页与课程首页卡片、段名（`segment`，也是小标题和侧栏分组）、label、页标题、`lead`、`closing`、画面标签。口播另按 ED-002、ED-010 检查。
- 每处问题记成 `位置 · W 编号 · 原文 · 建议`，写进当次审查记录；改不改由讲师决定的，标“待讲师判断”。
- 发现新的模式或好例子，补到对应条目下（每条例子不超过 6 个，换掉最弱的），不另起相似条目。

## 模式

### W1 目录腔：概念名词并列

**样子**：“A 与 B”“A、B 与 C”，像大纲条目。

**为什么怪**：学员要先把名词翻译回动作，才知道这一节或这一页要做什么。

**检查**：问“学员读完知道要做什么、回答什么问题吗”。不知道，就改成动作或学员会问的问题。

**例**：“Agent 执行机制与 AI 协作基础” → “一句话发出去，Codex 到底做了什么？”；“模型、会话、文件与进程，各记住什么” → “关掉终端再回来，什么还在，什么没了？”

### W2 作者行话

**样子**：写作时的工作词直接上屏，以及作者自造的分类名。

**为什么怪**：在校生和初级开发者没在流程化团队里待过，读起来像公文或质检单。

**检查**：对照下面的“高频词”，每处问能不能换成具体对象或动作；必须保留的，按 `terminology.md` 首次出现时解释。

**例**：“首次闭环” → “改一句话”；“检查通过，才保存本地基线” → “检查都通过了，再提交、打 tag”；“三种处置看两个条件” → “收还是不收，看两件事”；“事实候选”“待验证主张” → “还要核对”“AI 自己说的，没证据”。

### W3 电报体：离开口播就读不懂

**样子**：为了少字砍掉主语、条件和动作，只剩名词和符号拼接。

**为什么怪**：阅读模式是学员唯一的文字版，这些短语离开讲师的声音就解不开。

**检查**：只看阅读模式，遮住口播，问“这个标签自己说清了条件和动作吗”。

**例**：“已复现记剩余；否则待核对” → “复现了：记为待修问题；没复现：写明条件，留着”；“未补 CLI 不验收” → “还没装好 Codex CLI 的，这一节先不算完成”。

### W4 用符号和对仗造金句

**样子**：“≠”“A 管 X，B 看 Y”、四字对仗、口号式收尾。

**为什么怪**：符号不说明两边是什么关系；为了对仗，说法比实际窄，学员拿去套别的情况会套错。

**检查**：把符号或对仗展开成完整的一句，看意思有没有变、有没有压掉一步。

**例**：“授权管动作，验收看结果” → “批准只让它动手；改得对不对，要看页面和 Diff”；“commit 让‘拒绝’变便宜” → “提交过的改动，收错了也能撤回”。

### W5 条文口吻，或写给讲师、AI 的指令上了屏

**样子**：“不写通过”“合规”“不能悄悄消失”这类条款句；本该在操作提示或讲师备注里的录制指令出现在画面上。

**为什么怪**：学员读到的是一张检查单或一份 AGENTS.md，不知道这句话是不是对自己说的。

**检查**：问“这句话的读者是谁”。是讲师，移进操作提示或 `teaching`；是学员，改成对学员说的话。

**例**：“请求与返回为教学示意；请对应 1.1 中真实的两条记录” → 删掉后半句；“无法验证 · 无法理解 · 需越界 → 不标通过” → “验不了、看不懂、要越权：先停下，记成‘待补做’”。

### W6 用节号、页号、段名当名字

**样子**：“1.3”“p16”“回到 请求解剖”。ED-012 已有规则，这里收集仍然出现的形态。

**为什么怪**：录播学员不记得编号指什么；段名在侧栏里找不到。

**检查**：看到编号就问“学员此时知道那一节或那一页讲什么吗”；页 id 永远不上屏。

**例**：“（2.1 p16 看过的那段文字）” → “（上一节对比只读和可写时看到的那段权限说明）”；“回到 三种状态” → 写侧栏里找得到的页标题。

### W7 同一对象在不同位置各说各的，同级句式混乱

**样子**：同一页的 label、title、段名、卡片说法不同；同一层级里问句、名词对、口号、动宾混用；数量对不上（“三种状态”下面列了四样）。

**为什么怪**：侧栏用 label、画面用 title，学员看到两套名字；数不对会让人怀疑漏看了什么。

**检查**：每节把 label 列一列，再和 title 对照（小标题由段名自动生成，不会再和进度条各说各的，见 `docs/agents/courseware-workflow.md`）；同一层级看句式是否一致（节标题按节的角色定句式，见下）。

**例**：“换一台干净的电脑”（实际是隔离 HOME） → “换个干净的 HOME 目录”；“三种状态” → “什么会留下”。

### W8 翻译腔和搭配不当

**样子**：照英文结构直译（anatomy、make X cheap），中文动宾搭配不成立，英文术语在正文里替代中文。

**为什么怪**：读得通，但不像中文母语者会说的话。

**检查**：出声读一遍，问“我会这样跟同学说吗”。

**例**：“请求解剖” → “拆开一次请求”；“迭代首页并发布 GitHub Pages” → “迭代个人主页，发布到 GitHub Pages”；“Codex 设来源，人来推送” → “Codex 改 Pages 设置，推送由我们来做”。

## 高频词

这些词不禁用，但上屏时先问能不能说具体对象。数字是 2026-10-11 第 0–2 章屏幕文字（含 `lead`）的出现次数，用来看趋势，不是配额。

| 词 | 第 1 章 | 第 2 章 | 处理 |
| --- | --- | --- | --- |
| 证据 | 54 | 22 | 讲师确认偏多（2026-10-11）。只指能拿出来检查的记录或输出，见 `terminology.md`；能说“diff”“页面”“工具返回”“命令输出”就直接说 |
| 交付 | 21 | — | 说交出什么：“提交”“打 tag”“发布” |
| 闭环 | 14 | — | 说做完了哪几步 |
| 复验 | 14 | — | “再查一遍”“修完再试” |
| 基线 / 留痕 / 处置 / 合规 / 核验 | — | — | 换成具体动作 |

## 节标题的句式

按节的角色定句式，同一角色内保持稳定，不要求全课一样（2026-10-11 讲师确认方向；具体改哪些节标题另行讨论）：

| 节的角色 | 句式 | 例 |
| --- | --- | --- |
| 跟做交付 | 动作 + 对象（+ 检查方式） | 补上项目经历，看对话怎么变长；挑一个缺陷，按证据修 |
| 机制 / 判断 | 学员此刻会问的问题 | 这条规则是谁定的；AI 交回的改动，要不要接受 |
| 工程经验 | 引 AI 的原话，或摆出现象 | AI 说“只是重构” |
