## 1. 设计理念

**吸引人的来源是"镜头"，不是"皮肤"。** 之前的 9 种风格库只换了字体和纹理，页面结构都一样，所以都显得平。真正让录播课好看、好学的，是这三件事：开场服务于本节问题，画面随讲述一步步展开，讲师和页面互相配合。视觉风格只需要一套，定下来以后全课统一。

**知识密度靠结构，不靠字数。** 演示页要承载知识，但方法不是堆文字，而是把知识做成结构：对照、分层、矩阵、带批注的代码、失败路径图。标题、证据与内容组按本页职责组织，可用正文区不要求填满。具体取舍和构图按 [PPT 方法](../../.agents/skills/course-prep/references/ppt.md)执行。

**页面代替手势去"指向"。** 讲师是坐姿会议框，手够不到内容，所以指向的工作交给页面完成：可用高亮、对齐或连线引导注意；已讲内容是否变淡，取决于后续比较是否仍需要它。

**证据要工整，气氛可以手绘。** 框、箭头、概念图用手绘线条，显得亲切，像在白板前讲。代码、终端、diff、表格属于"证据"，保持印刷体和直线，工整本身就传达可信。

**位置感放在底部，不占正文。** 学员需要知道"讲到哪了、还剩什么"，但不需要一个一直不变的侧边栏。画面最底部一条分段章节条就能回答这两个问题，实操录屏里也能保留；讲师自己需要的页面列表和计时，放在讲述者视图里。

**PPT 讲结构，实操在真实环境里做。** 演示在 Codex App、CLI、CodeSandbox 等环境里进行，PPT 不复刻实操画面。PPT 负责三件事：切过去之前告诉学员看什么，切回来之后用同一张清单复盘，把实操里的关键证据提炼成可以反复看的结构。

### 第三章：完整矩形正文与讲师覆盖层

| 区域 | 第三章制作依据 |
| --- | --- |
| 标题 | 默认从 x 56、y 82 开始，按实际行数确定高度；正文不能因预留不存在的第二行或导语而下移。标题文字仍须在摄像头叠加后可读。 |
| 正文矩形 | x 56–1224；上沿为实际标题底边加适当间距，下沿不超过 y 632。单行标题可参考 y 180，**不是新的固定上沿**；24–32px 间距可作起点，最终按截图中的可见文字和视觉平衡调整。 |
| 讲师覆盖层 | 保持 x 956–1256、y 24–249，不从标题或正文的矩形中挖去。背景、色块、装饰与不影响理解的图片局部可在其下方延伸；标题文字、关键标签、图示关系和必要操作信息不得被遮住。 |
| 字幕与导航 | 继续保留 y 640–680 的字幕区及 y 682–712 的章节条，不因正文扩大而侵入。 |

常规页把实际内容组水平、垂直居中置于正文矩形内，组内可左对齐；图文提问等页面可采用共同构图的变体。居中、留白和截图审美检查的方法由 [PPT 方法](../../.agents/skills/course-prep/references/ppt-visual.md#内容组矩形与留白)维护。讲师覆盖检查在完成构图后进行，允许背景或边框相交，判断依据是是否妨碍理解。

公共播放器与旧页面中的 `top:262px;height:370px` 是历史布局的实现值，**不再是第三章的制作边界**。后续修改对应页面时按本节落实局部布局并复验；不通过全局替换这些数值代替逐页设计。

网页品牌标识（2026-10-10）：首页、章节首页与各节播放器的右上角使用 `courseware/shared/assets/shenlanxueyuan_logo.png`，保持原图比例。专注演示保留画布上方 64px 的 logo 区，画布按剩余窗口空间等比缩放；上表坐标仍相对于 1280×720 画布，logo 不占讲师框或正文。完整尺寸检查使用 1280×784 窗口。

播放器导航（2026-10-10 讲师确认）：“课程首页”“第 * 章”“讲解全文”集中靠左排列，演示模式再接“演示设置”；logo 单独靠右。窄屏换行后仍从左侧开始排列，设置菜单完整显示在窗口内。

录屏段落（实操画面）也保持同一个讲师框位置和章节条。录制时把应用窗口里的关键区域放在左侧和中部，右上角留给讲师。

课程在深蓝学院自有播放器中播放，不在 B 站发布，因此不再为弹幕预留顶部区域。如果以后改到有弹幕的平台，再加回“顶部 180px 不放关键图形”的限制。

## 3. 视觉基调

**底色：** 课程纸色 `#F4F2EB`，所有页面一致，与 ch01 课程站的 `--color-paper`（oklch 96.5% 0.009 95）同源。任何页型都不单独换背景，漫画页和涂鸦页也不例外。

**字体：**

| 用途 | 字体 | 说明 |
|---|---|---|
| 页标题、小标题、图中主要节点、大标签与短结论（≥24px） | 站酷快乐体 ZCOOL KuaiLe | 手写感，只用于短文本 |
| 章节开篇大标题 | 长仓体 Long Cang | 只出现在每节开篇页 |
| 辅助标签、解释、例子、较长正文、批注、表格；阅读站标题 | Noto Sans SC | 印刷体；阅读站标题用粗体 |
| 代码、终端、文件名 | JetBrains Mono | 关闭连字，避免 `=>` 显示成 `⇒` |

两款手写字体都是 SIL OFL 协议，可以商用。正式制作时按全课用到的字做子集，然后自托管，不从 Google Fonts 在线加载，避免录制时回退成默认字体。字体文件、来源与选择理由见[字体说明](fonts.md)。

**线条：** 框、箭头、圆圈、概念图使用轻微手绘抖动（SVG `feTurbulence` + `feDisplacementMap`，scale ≈ 3）。以下内容不抖动：代码框、diff 框、终端、表格分隔线、勾叉图标、编号圆点。

**语义色（全课固定含义，不能挪作他用）：**

| 语义 | 主色 | 浅底 | 用法 |
|---|---|---|---|
| 我们（人） | `#243042` | — | 人的节点、结论条、头像 |
| Agent | 线条和文字 `#5A51D1` | `#EDEBFB`；大面积填充用柔和紫 `#ABA6E9`，上面配深紫字 `#2A2380` | Agent 的节点、气泡、计划 |
| Tool | `#0F8A7A`，文字 `#0B6B5F` | `#E0F3EF` | 工具调用、命令 |
| Context | `#9C8B66`，文字 `#6E6043` | `#F2EDE1` | 上下文、工具返回的信息 |
| 闸门 / 风险 | 线条 `#D9481C`，文字 `#AC3615` | `#FCE6DD` | 失败、越界、需要人拦下的地方；`#D9481C` 在纸色上只有 3.8:1，作文字时用 `#AC3615` |
| 通过 / 证据成立 | `#15803D` | `#E3F2E6` | 勾、通过、贯穿全课的检查习惯 |

大面积的深紫已经弃用，避免画面过重。深色填充只留给"我们"和结论条。

**界面框架不用语义色**（2026-10-05 讲师确认）：章节条、开篇地图的已讲状态、代码讲解的当前行色带和批注编号、课程首页的编号与标签，这些不表达"谁"的元素一律用中性色：深色 `#243042`、已完成灰 `#8E95A2`、当前行黄 `#FFF1BF`。紫色只出现在 Agent 相关的内容上，学员看到紫色就能确定那是 Agent。

**字号下限（720p，考虑手机观看）：** 页标题 40–46px；正文和批注不低于 20px，辅助说明不低于 18px；代码不低于 20px；图中标签不低于 17px。必要的标签文字要能独立读懂；内容量、拆页与各产物的分工按 [course-prep](../../.agents/skills/course-prep/references/ppt.md)处理，不设硬性字数阈值。

## 4. 一节课的页面流程

页序、展开步骤、开篇与收束按 [course-prep 的 PPT 方法](../../.agents/skills/course-prep/references/ppt.md)和当前讲述线确定；本文件不规定固定页型组合。

## 5. 进度与位置感

**录制画面里不放侧边栏。** 侧边栏会占掉约 20% 的宽度，把正文区从 1168 压到 900 左右；再加左侧边栏会压缩主体构图与留白空间；而且它在一节 20 多分钟里几乎不变，大部分时间是背景噪音。网页阅读模式（课程站）保留侧边栏，那里才是它合适的位置。

**讲师的定位信息不进录制画面。** 页面列表、每页的一句话描述、计时，都放在讲述者视图（`speaker.html`）里。

**学员的定位靠底部章节条：**

- **按段落分，不按页数分。** 段数与剪辑段落按本节讲述线确定。按页数显示进度会忽快忽慢，因为每页讲的时长差别很大。
- **宽度按计划时长分配**，段与段之间留 6px 间隙。
- **只写段落名，不加编号。** 先后顺序由从左到右的位置表达，编号是重复信息。段名尽量控制在 6 个字以内，例如"开场""三个概念""复盘证据""收尾"。
- **三种状态：** 已讲的段是中性灰满格（`#8E95A2`）；当前段的段名加粗、用深色 `#243042`，细条按讲到的页和步逐渐填充；未讲的段是浅灰空条。不用紫色，见第 3 节"界面框架不用语义色"。
- **段名字号 17px**，与图中标签下限一致；段太窄时以省略号截断，不缩小字号。
- **所有画面都显示**，包括开篇、漫画、小结和实操录屏。切到 Codex 或 CodeSandbox 时，学员同样知道自己在哪一段。
- **和播放器章节保持一致。** 如果深蓝学院播放器支持章节标记，段名和时间点与画面里的章节条一一对应。

**和字幕的关系。** 字幕由剪辑组或讲师自己在剪辑时制作并压进画面，位置可控：字幕底边放在 y 680 以上，就不会压住中间几段的段名。精简版章节条（最左侧只显示当前段名和"第几 / 共几段"，右侧是不带文字的分段细条）只作为备用，仅在将来改用位置不受控的外挂字幕时启用。

**和开篇地图的分工。** 开篇页的地图显示"本章有哪几节、这是第几节"；章节条显示"本节有哪几段、讲到哪一段"。两者层级不同，不互相替代。

**从上到下：先概览，再细节（2026-10-11 讲师确认）。** 课程设计和网页展示都按“课程 → 章 → 节 → 页”逐层展开，每一层先给学员看到全貌，再进入下一层：课程首页列出各章，章首页先放“本章路线”卡片、再放各节卡片，每节开篇页用路线条标出本节在本章的位置。不为节省篇幅删掉这些概览。章首页（网页，不是录制画面）用与小节页同款的左侧目录，列出本章各节的短名（见 `terminology.md` 节名表），顶部是“课程首页 › 第 N 章”，底部是上一章 / 下一章；窄屏隐藏侧栏，改用页头站标回课程首页。

## 6. 页型目录

以下为已有实现示例；表中的位置、数量与组合描述对应原示例，不规定新页面的教学顺序或固定形式。按内容关系选择或重组，制作方法由 course-prep 维护。

| # | 页型 | 什么时候用 | 关键规则 |
|---|---|---|---|
| 1 | 章节开篇 | 每节第一页 | 手写大标题 + 本章地图；地图全章复用，只移动当前位置 |
| 2 | 漫画开场 | 需要冲突感的开场 | 三格，角色固定为"我们"和"AI"；粗黑框加硬阴影；背景跟随全局 |
| 3 | 分层模型图（循环） | 讲流程、讲循环 | 上排概念，下排本课的具体证据，两者同屏 |
| 4 | 可见 / 不可见对照 | 讲边界、范围、容量 | 两个容器并排，用差集说明问题；最后给出"错误推断"的样子 |
| 5 | 带解读的操作记录 | 讲工具调用 | 三栏：动作、结果、这个结果能说明什么；失败行用闸门色 |
| 6 | Prompt ↔ 回复对照 | 讲 Prompt 和确认 | Prompt 分段着色，回复每一句贴上对应颜色的标签；缺失的一段用虚线框标出 |
| 7 | 切到实操 | 每次切去真实环境之前 | 列出实操环境，给 3 条"边看边找"；切回来时回到这页逐条打勾 |
| 8 | 录屏叠加层 | 实操录屏的画面规范 | 讲师框位置不变；左下角放观察清单浮层；需要看清时推近 1.5–2 倍，不缩小字号 |
| 9 | 代码讲解 | 讲一段代码 | 只高亮当前行；右侧批注一条一句，不复述代码；最后一条落在副作用上 |
| 10 | diff 对比 | 讲一次改动 | 先看文件列表和增删行数，再逐块看；用左侧括号标出当前讲的改动 |
| 11 | 正反对照 + 证据清单 | 讲验收、讲判断 | 左边是 Agent 的原话，右边是检查清单；关键越界用连线连到失败项 |
| 12 | 权衡矩阵 | "什么时候用哪个" | 行写具体情境，不写抽象优缺点；最后一列写判断依据 |
| 13 | 阶梯图（课程主线） | 每章开头定位 | 阶梯表示叠加，底部通栏是贯穿全课的习惯；全课复用 |
| 14 | 主流程 + 失败分支 | 讲失败方式、排查 | 每个失败挂在主流程的具体节点上，并写出"怎么发现" |
| 15 | 暂停自检 | 每节末尾，或难点之后 | 先只给问题并提示暂停，再逐题揭晓；每个答案都标注它回到哪个概念 |
| 16 | 涂鸦小结 | 每节最后一页 | 允许彩带、星形、图标；不讲新知识；可以直接放进阅读模式当复习卡 |

可从这些实现中取用零件，也可按当前内容设计其他表达；有可复用的新实现时再补充目录。

### 贯穿全章的示意图

一章里反复出现的同一张图（如第 2 章的锚点图），高亮、虚线、颜色各自只表示一种意思，读法写进章文件“全章约定”，由代码统一生成，不在页面里手写副本（2026-10-24）。图下一句写给学员：这一页为什么看这几块，不写“按实际记录标注”“示意”这类制作说明。某页没有新信息可指时不放这张图，换成一行结论。第 2 章的读法：粗框是这一页要看的块，这次没有内容的块画成灰色虚线并写“这次没有”，其余块画浅，列外虚线框是不在请求里的东西。

## 7. 开篇与结尾

**开篇**只做两件事：一句话点出本节的问题，告诉学员现在处在本章的什么位置。手写大标题是全课唯一大面积使用长仓体的地方，它是每节的记忆点，所以不要在其他页面使用长仓体。标题优先用本节要解决的动作，例如"把一次小改动拆开看"，不用名词堆叠。

**结尾**按本节学习结果和讲述线安排收束，不固定页数或页型组合。

## 8. 动画与节奏

- 动画形式与推进按 course-prep 的 PPT 方法确定，动画须表达关系或状态变化。
- **按需减弱背景**：可突出当前步并减弱辅助内容；比较仍需用到的证据保持可辨认。约 40% 不透明度是已有实现的参考值，是否恢复全亮按收尾画面职责决定。
- **临时标注**（高亮条、括号、连接线）：只服务当前解释的标注可在讲完后收起；后续仍需的关系与定位保留。
- 元素出现用 300–500ms 的淡入加轻微上移。不用旋转、弹跳、飞入，也不做装饰性的循环动画。尊重系统的"减少动态效果"设置。
- 步骤数由讲述线的解释与揭示顺序决定。
- 转场与画面切换按当前讲述线和 [course-prep 的口播方法](../../.agents/skills/course-prep/references/spoken-script.md)安排。

## 9. 漫画与涂鸦

**漫画与图文场景**可用于呈现冲突、动作或关系，是否采用及怎样分格按当前讲述需要判断。已有开场示例采用三格、黄色旁白框、粗黑边框与硬阴影；这些是可借鉴的表达，不限定每节数量或角色组合。角色颜色仍遵守语义色约定。

**涂鸦**可用彩带标题、星形、警示图标等形成合适的观看节奏，正文保持规定字体。已有小结示例只回顾本节内容；新页面的用途由讲述线确定。

两者的背景都和其他页一致，不单独换底色，避免整节连看时画面跳色。

## 10. 与实操环境的分工

- 实操（Codex App、CLI、CodeSandbox 等）展示"过程"，PPT 展示"结构"。PPT 里不放大段实操截图。
- 切到实操前交代观察对象和证据；可沿用当前画面或单设过渡页，按讲述线选择，不固定条数。
- 需要持续定位观察进度时，可在录屏中叠加清单浮层，留意不要遮挡实际证据。
- 需要看清细节时推近，保持 2 秒以上再拉回；整体界面和多区域面板不做自动缩放。
- 切回 PPT 以后，用代码讲解、diff 对比、验收等页型复盘刚才的证据，引用的是实操里真实出现过的内容。
- 两类代码块必须一眼分清（2026-10-11，平台 reviewer R23）：**发给 Codex 的请求**用 `.prompt`，标签“发给 Codex 的请求”并带复制按钮；**学员自己在终端运行的命令**用 `.cmd-block`，标签写“在终端运行”和运行位置（如“练习项目根目录”）。两类不混放在同一个块里，也不用无标签的裸 `pre` 给学员布置命令。代码示例（读代码用、不需要运行）不加这两种标签。

## 11. 讲师配合

- 讲到页面上的具体元素时，视线看向该元素；开场、总结、提问时看镜头。
- 手势不需要真正指到内容，指向的工作由页面的高亮和连线完成；讲师的手势用来表达强调和节奏即可。
- 讲到难点时放慢语速，多用"当前步高亮"。有研究显示讲师提示在内容难时效果更明显。
- 表情自然就好，不要每次指向都刻意配笑容。

## 12. 录制前检查清单

- [ ] 标题两行以内；第三章按覆盖层规则检查关键文字可读，其他章节沿用讲师框避让要求
- [ ] y 640 以下只有字幕和章节条
- [ ] 章节条的段名、段数与剪辑段落一致，平台章节（如果设置了）也对得上
- [ ] 字幕底边不低于 y 680，没有压住章节条的段名
- [ ] 最小字号符合下限，在手机上看过一遍
- [ ] 同时亮着、需要学员互相比较的并列项（卡片、列、选项）不超过 4 个；更多时分步揭示或拆页（工作假设，待实录验证）
- [ ] 语义色没有挪作他用（紫色只代表 Agent，红色只代表风险）
- [ ] 代码、diff、终端、表格没有手绘抖动
- [ ] 展示状态与对应讲述相符，动画推进可由讲师控制；不按一句口播拆一个步骤
- [ ] 本节有开篇、自检、小结；切到实操之前有衔接页
- [ ] 手写字体已经自托管，录制时没有回退成默认字体

## 13. 不做的事

- 不为不同页面换背景色，不用点阵、网格等底纹
- 不用手写体写正文、代码和表格
- 不在屏幕上写完整的讲稿句子（字幕已经提供了口播）
- 不做纯装饰的动画和图形
- 不在一页里放两个以上的结构化证据
- 不把讲师框缩小、隐藏或移动位置
- 不在录制画面里放侧边栏，不按页数显示进度
