## 使用方法

- 一个对象只用“统一叫法”。同一页或同一节里不再换成“不要用”一列的说法。
- “首次出现”一列是学员第一次遇到时要给的解释，屏幕和口播至少有一处讲到；之后直接用。
- 新增术语或发现一物多名时，在这里加一行，再改课件。

## 概念

| 统一叫法 | 指什么 | 不要用 | 首次出现 |
| --- | --- | --- | --- |
| Harness | 两个意思都用（2026-10-11 讲师确认）：① 包在模型外面、组装请求、调用工具、管权限的那一层，如 Codex 本身；② 课程第四层能力，为项目搭起的上下文、检查和人工门禁。指 ① 时写“Codex 这层 Harness”或“Codex 的 Harness”，指 ② 时写“项目的 Harness”；同一页不混用两个意思 | 单独写“Harness”而前后文分不出是哪一个 | ① 2.1 拆开请求时；② 第 7 章开篇，回指 ① 说明是同一个词、这次由我们自己为项目搭（两处首次出现的具体写法待改到该页时确认） |
| 对照实验使用的 Harness | 第 7 章固定下来、供第 8 章有 Harness 条件使用的项目环境 | 只写 v1、不说明它在实验中的作用 | 第 7 章冻结时：记录中标为 Harness v1，并对应实际 commit；“基线”指固定下来供后续比较的版本 |
| Harness 改进候选 | 第 9 章依据证据、只改一个因素后准备复验的 Harness | 用 v2 暗示已经更好，或要求必须交付第二个版本 | 9.1；记录可标候选 Harness v2，注明实际 commit、相对 v1 的改动与验证状态；不能证明改进时可保留 v1 |
| A / B 实验条件 | A 为无课程 Harness，B 为使用冻结 Harness 的条件；两者分别在隔离 Worktree 中执行 | 把 A / B 当作 Harness 的版本号，或把后续候选覆盖进原始 A / B 记录 | 7.1 先说明 A，8.1 回指并说明 B；A / B 表示条件，v1 / v2 表示 Harness 自身版本，commit 定位实际内容 |
| 证据 | 能拿出来检查的记录或输出：工具返回、diff、页面、命令输出、请求记录 | 把要求、意图、计划叫作证据；能说具体对象时泛称“证据” | 1.2 |

“证据”在屏幕上用得偏多（2026-10-11 讲师确认），改稿时优先换成具体对象，见 `wording-patterns.md` 高频词。
