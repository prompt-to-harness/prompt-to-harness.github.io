## 面向的客户与学习目标

面向正在进入专业开发阶段、有基础编程经验的人：一两年后毕业的高年级本科生/研究生、毕业一两年的软件工程师，以及未形成稳定 AI Coding 工作方法的学习者。学生和职场新人不分成两条课程主线。

学员可以第一次接触 Coding Agent，也可以已经用过但结果不稳定。基础方法与工程判断是人人需要的两种能力，不按“是否用过 AI”划分课程。采用一条共同主线，配基础补充与可选变化任务；共同验收底线不降低。不同起点的比例尚无招生数据。

目标：为工作与生活做出真正可用的结果，并能解释、验证、修改和迁移方法。“可用”是在明确条件下满足需求、有相应证据、能发现问题并继续修改，不自动等于企业级生产系统。用 AI 制作普通工具、网页或功能改进即可，不要求成果本身内置 AI。

## 先修条件

至少实际使用过一门编程语言；具有基本 Git、命令行与搜索排障能力；理解函数、模块、HTTP/API、测试等基本概念；能运行已有项目并修改局部代码。具体命令不要求背诵，必要操作在课内解释。

不预设学员了解 LLM、Prompt、SDD、Harness、MCP 或某个 Agent，也不预设已经装好工具、购买国外模型账号。前期提供环境与最小权限指引，并验证网络受限时的替代路径。Python、TypeScript 等可作为低配置成本候选，语言和技术栈尚未锁定。

## 学习递进与用户问题

从第一次做成，到控制修改，再到应对真实任务、独立迁移。先用最小的 Chat → Plan → Execute 走通任务，同时出现最小验证与人工确认；规格、Review、权限和 Harness 随复杂度加深，不到后期才第一次出现。

课程要帮助学员解决：怎样分配人和 AI 的职责；怎样准备代码库事实；怎样澄清模糊目标；怎样发现错误假设、上下文漂移和范围失控；怎样用证据验收；怎样复用方法。价值不以代码量、Prompt 数量或某工具熟练度衡量。

Codex CLI 为主要可复现工作流示例，App 可作较低门槛入口；其他工具按相同方法理解。实际替代组合须测试，不以“接口相似”声称全部兼容。

## 课程要达成的状态

1. 能分级一个真实任务，明确目标、AI 职责、人工把关点和不适用边界。
2. 能完成一次可解释、可验证的 AI-assisted software engineering 工作循环。
3. 能根据代码库事实准备上下文、代码地图、项目规则和计划。
4. 能把需求、约束、验收、非目标和开放问题说清；先会用轻量规格，再理解完整 SDD 的作用与代价，不要求小任务一律套框架。
5. 能小步实现、检查 diff、运行验证并复盘错误。
6. 能形成最小 Harness，解释环境、规则、检查、工具权限和人工确认分别解决什么问题。
7. 能将方法迁移到没有既有对话记忆的新任务或仓库。

成果应能说明 AI 做了什么、人确认了什么、依据何在、验证覆盖什么/遗漏什么、问题如何修正以及哪些方法可以迁移。正式提交、评分、人工评阅和证书尚未确定。

## 课程形式与边界

录播为硬约束：8～10 次、每次约 90 分钟、四小节左右，约 12～15 小时视频；跟做、暂停和课后实践另计。可以分周发布，但不依赖录制时或后续课录制前收到反馈。学员群提供异步补充，不承担主课缺失的基本解释。详见[课程共识中的录播与独立学习约定](course-design-principles.md#录播与独立学习约定)。

课程包含内容线、Projects 线和软件工程 0.5 线；后者与前两线混讲，在具体决策处点明，不另设脱离实践的理论课。“软件工程拾遗”为工作名称，保留 [概念草案](../software-engineering/software-engineering-thread.md) 与 [原始试讲卡](../software-engineering/pilots/README.md) 的讨论状态。

AI 知识不只限于项目最低需求：公开指令、上下文、工具历史、benchmark、SDK 与前沿可分为“会用/看懂/认识”三层。扩大认识范围，不扩张为完整 Agent 工程师培养、模型训练或 Transformer 数学课程。MCP 是工具边界实例，不要求独立开发完整 MCP Server。

不要求公司代码、真实业务资料和外部工作账号；不将国外账号或单一模型服务设为硬前置。环境、模型额度、镜像和远程服务的实际支持清单仍需确认。Feishu MCP、Game studio 等都是待验证候选，不自动变成必修或运营承诺。

## 尚需决定

最终 8/10 次及发布时间；Project 数量、题目、语言、必做/选做；各主题深度；评阅与答疑服务；环境与成本支持。进入编排和试跑解决，不重新打开已明确的用户、主线与录播方向。
