# AI Coding 课程设计与制作共识

> 2026-09-26 整理说明：内部设计参考，待后续课程设计重新确认。下文保留当时的讨论、候选和试验规则；课程范围以[当前总纲](../course-outline.md)为准。

> 状态：2026-09-22。本文件汇总当时的课程设计、讲述编辑、录播制作与独立学习约定；不锁定具体章节标题、Project 清单或服务承诺。早期决策缘由见[讨论汇总](../../discuss/2026-09-07-course-design-consensus.md)，录制方案原记录见[2026-09-21 录制讨论](../../discuss/2026-09-21-recording-consensus.md)，两份讨论记录均作为历史记录保留。

## 目标与成果

面向 AI Coding 初次使用者和初步使用者，保留基础编程先修。一条成长路径同时培养基础方法与工程判断：第一次做成 → 控制修改 → 真实任务 → 独立迁移。不是新手课与高手课拼接，也不假定有经验者不需要基本操作和验证。

学员带走：可用结果、可迁移方法、简短可复核记录。能够解释目标、上下文、关键决策、AI 的工作、人确认了什么、测试/Review 的依据与遗漏。生成代码量、工具数量和某次模型完成说明都不能代替成果。

## 核心原则

### 先能用，再变可靠

尽早提供环境、最小权限与可见结果，使用最小 Chat → Plan → Execute 闭环，并立即加入最小检查和人工确认。随后逐步增强规格、设计、任务拆分、测试、Review、权限和复盘。不是先讲完所有理论再动手，也不是先不管质量、后半程补救。

早期小任务允许一次生成成功；中后期通过真实变化和约束展示方法价值，不人为制造失败或堆功能来证明复杂流程必要。能够合理省略流程，也是一种工程判断。

### 人与 Agent 的边界应被看见

Agent 可搜索、草拟、编辑、运行检查与整理信息。人负责目标、范围、风险、授权、取舍和验收。证据和环境改善之后，可以增加委派；不把“模型说完成”当完成。文字规则、审批与实际执行限制需要分别解释。

### 方法稳定，但工具要讲实

Codex CLI 是主要可复现示例，App 是低门槛入口候选，不要求全员从 CLI 开始。先教会一个真实操作，再解释机制，最后展示迁移，不平铺所有产品。工具、安装、模型条件须标版本，支持组合须试跑。

### 录播不依赖讲师实时反馈

8～10 次课、每次约 90 分钟、四小节左右。学员群不保证在整套录制前产生反馈；分周发布不改变这一约束。自检题、解析、验收、主要排障和继续路径要随课交付。内部走查可用于制作 QA，不冒充真实学习效果验证。完整的录播与独立学习约定见下文。

## 三条互相支撑的线

| 线 | 职责 | 默认展示 |
| --- | --- | --- |
| 内容 | AI Coding 概念、机制、方法和边界 | 图解 PPT、讲述、局部原始材料、微实验 |
| Projects | 在实际任务中使用与组合方法 | 成果预览、标注录屏、变化、检查与交付 |
| Software Engineering 0.5 | 用真实工程问题帮助学员获得软件工程 vocabulary、看懂软件现象，并在必要时理解 trade-off；经典作者/作品作为可插拔视角 | 问题短讲、代码 diff、关系图、行为过程、Classic Lens；与正课弱耦合 |

0.5 不是课时公式，也不是一门压缩版软件工程课。它不再以“每个 Project 必须触发一个概念”或“每期讲一位人物”为默认结构，而是以**一个真实工程问题 → 2–4 个术语 → 一个可视化现象 → 0–1 个 Classic Lens → 回到 AI Coding**为基本单元。

这条线的学习深度分为：**听懂 → 看懂 → 必要时判断**。不把“工程判断”误教成“对 AI 保持敌意”；如果 AI 建议合理，理解并接受它是完全正确的结果。完整设计见 [Software Engineering 0.5 线](../software-engineering/software-engineering-thread.md)。

内容线不是项目解说词。项目最少需求之外，可以回答学员不易想到的问题：公开指令、工具变化、检索、benchmark、状态与成本等。分“会用/看懂/认识”控制深度，不把每个知识点都变成结课开发技能。

## 章节故事线先行

2026-10-02 第 2 章讨论确认：设计或重构一章时，先写本章故事线，讲师确认后再细化逐节分镜，最后才同步两份大纲和课件。直接在小节细节上讨论，容易丢掉整章的动机和前后呼应。

故事线至少包含：

1. **一句话主线**：本章把什么从哪种状态变成哪种状态，例如“把只在本机运行的首页 v0 变成可以拿给认识的人看的 v1”。
2. **这一章在做什么**：一段学员能读懂的叙述，说明会遇到哪些情况、为什么按这个顺序。
3. **学员获得**：可观察的成果和习惯，不写“了解”“熟悉”。
4. **起承转合表**：每节的情境与留下的东西。至少一个转折必须稳定发生，不能依赖 AI 碰巧出错；自然出现的失败就地使用，不出现不伪造。
5. **贯穿线索**：一两个从开头延续到结尾的具体对象（如同一条反馈），让后面的节能回指前面。

逐节分镜再按“学员此刻面对的问题 → 证据 → 判断 → 归纳的概念”展开，并标明哪些是跟做主线、哪些只需看懂。故事线和各层分镜从内容出发，不做段落或页面级的时长估算；讲述节奏由讲师录制时按自己的语速调整，整体时长在试讲或录制后再核算（2026-10-02 第 2 章讨论确认）。样例见[第 2 章提案](../outline/proposals/2026-10-02-ch02-adjustments.md)。

## 共同教学结构与变体

问题 → 知识 → 方法 → 证据 → 迁移。录播中增加自主判断、预录解析与补救入口。统一各环节的联系，不要求每个小节同序同长。

可按主题选择机制解释、工作示范、评审诊断、对照取舍。默认时间预算 20/25/30/15 分钟，可随上手和综合课调整；深挖和解析在预算内，实际跟做另计。不默认源码精读、失败案例或完整 Project 每课必有。

PPT 解释关系；录屏展示关键决策与验证；成果截图只做入口。区分真实运行、剪辑、教学重放和植入故障，保存原始依据，不把单次实验当普遍胜率。

Software Engineering 短讲采用“内容独立、教学时机相关”的方式：不解释会阻断当前课程时 inline 一句白话；需要完整 diff、关系图、行为过程或经典背景时链接独立短讲；只有与当前章节存在自然的问题级关联时才完整嵌入。10 节主课不要求正好对应 10 个 SE 小节。

## 录播与独立学习约定

### 1. 不依赖实时反馈

课程可能全部录制后才收到反馈，也可能分周发布。两种情况均按“讲师此刻看不到学员回答”设计。学员群补充个别问题与后续勘误，不补齐主课缺失的基本解释。课堂里的“现在看你的项目”指学员自主操作，不意味着讲师现场等待或查看。

共同结构：问题 → 知识/示范 → 自主判断 → 预录解析与验证 → 补救或继续 → 迁移。一个 90 分钟单元尽量闭合；不要求每个小节机械重复。

### 2. 四种讲法，共同的质量要求

| 讲法 | 适用内容 | 应留下的东西 |
| --- | --- | --- |
| 机制解释 | Prompt、上下文、工具循环 | 一张能对应实际记录的图和一个可检验判断 |
| 工作示范 | 澄清、探索、拆分、交接 | 基本方法、关键停顿点及变化时怎样调整 |
| 评审诊断 | 测试、Review、调试、权限 | 问题位置、依据、补验证或接受的理由 |
| 对照取舍 | 流程、评测、工具演变 | 输入条件、不同方案的代价、适用边界 |

没有必要每课都失败、都读源码或都启动新项目。软件工程在具体决策处点明；基础说明与深入材料均不依赖猜出讲师心中的答案。

### 3. 时间是净视频预算

默认 20/25/30/15 分钟；上手课可为 15/20/40/15，综合课可为 10/15/50/15。预录解析在预算内，暂停、实际跟做、排障与课后实践另计。平台无章节功能时，讲义提供小节与时间戳；不为了等待回应录制大段空白。

这些预算只作小节和整体层面的参考，不细分到段落或页面；内容设计不以时长为约束，见上文“章节故事线先行”。先明确每节“学完会什么”，再分配时间。扩展内容占明确预算；可跳过的拓展不能成为下一课未说明的前置。

### 4. 自检不是模拟现场互动

区分引出知识的讲述问题与需要暂停的自检问题。关键自检包含：题干和可见证据、判断及依据、完整解析、常见误解、补救入口、继续条件。答案与题目分开定位，不能只放一个正确选项。

例如：已有测试通过能否证明新增需求完成？解析须说明测试覆盖与验收的关系；“不相信 AI”也不是充分答案。允许多种合格实现，要求理由与证据一致。每个核心小节优先安排一个有价值的判断，不以题量代替学习。

### 5. 演示与实践分开承担责任

第一遍可先观察关键点，再独立重做；允许同步跟做，但叙事不假定每位学员已到相同步骤。观看和解析可帮助继续理解，不能替代核心动手能力。

正式 Project 至少提供：可启动起点、任务与非目标、验收样例、阶段检查点、参考实现、差异说明、故障入口。检查点是新目录、分支或明确下载包；恢复前保留学员工作，不通过危险覆盖“回到老师版本”。

| 状态 | 可继续的路径 | 不能宣称 |
| --- | --- | --- |
| 模型或环境不可用 | 看脱敏回放、检查固定产物，再补实际操作 | 已获得 Agent 操作能力 |
| 实现与老师不同但通过验收 | 解释差异与未覆盖项后继续 | 必须复制参考代码 |
| 行为失败或改动超范围 | 按失败项排查；保留现场后从检查点继续 | 只要能播放下一节就算完成 |
| 出现未知阻断 | 提供最小复现和证据求助；使用明确替代路径 | 群内必定即时解决 |

### 6. 材料与可信边界

上课看：图解 PPT、讲述、关键录屏和资料定位。自己做：起点、样例、检查点、检查步骤。以后查：独立讲义、方法卡、时间戳、版本和来源。PPT 导出不自动等于完整讲义。

原始 Agent 运行、剪辑回放、确定性脚本重放和人工植入故障分别标注。等待可加速，但注明省略与原始耗时；不将教学脚本标作真实模型轨迹。对照实验不预设推荐方法必胜，不把单次演示推广为成功率结论。

模型/Agent/系统版本、样例起点、权限、必要运行条件和实际检查结果应可追溯；敏感信息先移除。仅在边界内自检，测试通过不代表适用于任意真实部署。

### 7. 录制形态与公开材料

HTML 讲述页、App/CLI 实操和讲解全文可以分开录制，再按“问题 → HTML 解释 → App/CLI 实操 → HTML 复盘”连接。公开页面和讲解全文直接面向学员，也可供讲师讲述；屏幕文案的标点等编辑规则见[编辑规范](../production/editorial-checklist.md)。讲师小窗位置、会议工具、导出画质和具体 Starter Repo 属于制作试验，不在这里承诺未经验证的组合。演示页的画布分区、视觉基调与页型目录见[演示页视觉设计规范](../production/visual-design-system.md)，同样属于待实录验证的制作规范。

页面、讲解全文、准备页、逐字稿和录制说明使用同一份已确认内容，但承担不同职责：制作时长、画面切点、剪辑、take、真实输出和未验证状态留在备课材料；学员看到的是自然的课程口吻、必要证据和继续路径。

### 8. 制作与发布检查

录制前由非作者仅按配套材料走查，检查隐藏前置、跳步、误导性答案和继续路径。内部走查不等于真实用户研究，不等待招生才开始制作。

备稿与试讲按[课件编辑规范与改稿清单](../production/editorial-checklist.md)走查。

稳定概念、工具操作和时效内容分开录制；发现版本变化时可替换局部。发布前必须修复错误/危险指引和核心路径阻断。发布后按安全与正确性、学习阻断、表达改进区分勘误，不悄悄用新录屏替换旧结果而不标版本。

每课发布前必须能回答：暂时得不到讲师回复的学员，能否知道自己在哪里、结果是否达到要求，以及接下来怎么办？

## Projects 与环境

多个可独立继续的局部闭环，能力递进而非代码库强依赖。个人主页、游戏/交互、代码地图、只读工具/MCP 仍是优先候选。代码地图可为 Skill、工具或产物，至少支持一次陌生仓库理解与变更。

分别设计教学案例、微练习和正式 Project，避免题目膨胀。参考成品是合格实现之一，不是唯一答案；允许代码和界面差异，共同要求目标、约束、验收。每个阶段有干净起点与保留已有工作的恢复路径。

覆盖 Mac/Windows、网络和模型差异的意图保留，但实际支持清单待试跑。优先本地、合成/脱敏数据、最小权限与替代入口；不需要真实企业账号、公司代码或敏感资料。远程环境、token 支持和工具运营须单独决策。

## 参考与不做事项

方法参考 GSD、Spec Kit、自定义流程；Skills/Harness 参考公开资料与官方教程；RAG、SDK、Autoresearch、Kernel Ops 等按学习价值决定短演示或展望，不作核心任务前置。

AI Hero 借鉴细粒度机制与练习，陈天借鉴真实工具与工程材料，其他 refs 借鉴知识类型、判据与反例；不是照搬课程规模或宣传效果。不做 Prompt 大全、完整 Agent 工程师课程、模型训练课或云运维课；不把框架目录、测试覆盖率或文档数量作为掌握方法的唯一证据。

Software Engineering 0.5 线不做完整术语大全、设计模式大全或人物史；不要求每个词都做视频，不要求每个经典都进入课，也不为了教概念给 Project 人为制造失败。首版维护候选问题池，合并后选约 10–12 个正式短讲，后续再逐步沉淀 glossary。

## 仍需在设计与验证中解决

最终课数/发布节奏；Project 主题、数量、语言与必做边界；核心与扩展的实际分配；正式评价和服务；环境成本；引用权限；代码地图与 Harness 的具体产物。Software Engineering 0.5 线还需从候选问题池中确定最终 10–12 个短讲，并制作 Coupling / Refactoring / Idempotency 三类 prototype。
