## 2. 页面内容模型

整体层级为：

**小节 → 现有目录节点／讲解场景 → 连续讲解段 → 按时间排列的操作与逐字稿。**

| 层级 | 内容职责 | 展示方式 |
| --- | --- | --- |
| 小节 | 本节完整讲述顺序、PPT 逐页安排 | 一个讲述页入口，右侧整节连续滚动 |
| 讲解场景 | 沿用现有目录节点，例如 3.2.1.1 | 左侧目录入口，右侧场景标题 |
| 连续讲解段 | 围绕一个具体讲解目的安排画面、演示和解释 | 简短标题与画面定位，不增加整体外框 |
| 操作与逐字稿模块 | 讲师实际做什么、说什么，以及先后关系 | 按时间排列，用不同样式区分 |
| 附属内容 | 提示词、输入材料、预览、备用处理、备课说明 | 就近附着，按需要折叠 |

讲解场景是沿用现有目录的组织单位，不等于一个固定窗口。讲解段是围绕一个意思组织内容的单位；操作与逐字稿模块是页面阅读单位。三者不能混为一层。

一页 PPT 可以承载几个讲解段；一个讲解段也可以经历几个画面。段落数量不能由点击次数、窗口数量或源文件中的自然段数量决定。

最终页面保留已有的“小节 PPT 总览”：总页数、页与讲述段的对应、讲解内容、展开与切换。当前独立样例未完整展示这一项，不代表将它从正式要求中删除。

## 3. 连续讲解段的拆分标准

定义：**围绕一个具体讲解目的，安排一段能够连续完成的演示和讲述。**

“停在某个位置讲清楚一个意思”是直观理解，但画面不必静止。沿正文引用打开文件、定位示例、解释示例的作用，可以共同构成一个讲解段。

以下情况考虑拆段：

- 讲解目的或重点改变，例如从“怎样找到资源”转为“这个资源写得是否合理”。
- 讲解对象或画面状态变化后，需要独立解释一个新的意思。
- 当前单元已经难以判断哪句话对应哪个位置或动作，需要进一步分组。

仅为到达同一讲解位置而连续进行的打开、点击、滚动，可以放在一组操作中。同一目的下有多次操作与讲述交替，也不必强行拆成多个讲解段。

拆分自检：

1. 暂停录制后只看当前段，能否知道现在在哪里、接下来做什么、什么时候讲这些话？
2. 只看画面定位与操作，能否找到对象并按顺序推进？
3. 沿动作与逐字稿交替阅读，每句话所需的画面是否已经出现？
4. 有没有必须讲完才能执行的下一步被提前安排？
5. 有没有为了减少模块数量，把不同讲述位置合成一段总述？

## 4. 每段必需与可选的内容

| 部分 | 写到什么程度 | 展示要求 |
| --- | --- | --- |
| 画面与演示：必需 | 明确窗口、页面或材料位置；有动作时说明起始状态、操作、停留位置与必要返回点 | 定位常显；动作按实际顺序显示 |
| 逐字稿：必需 | 写出这一位置实际讲的话，包含理解所需的事实、解释、条件与承接 | 默认展开，可直接照读 |
| 提示词与相关材料：按需 | 实际请求原文、输入材料、文件或证据入口，以及使用方法 | 名称、用途和操作入口常显；长内容默认折叠 |

“画面定位”和“操作时序”统一归入“画面与演示”，无需为了字段分类做两个大框。定位不能只有“PPT”“Codex”或“日志”，需要具体到页与展开状态、请求与返回位置、文件标题／搜索词、运行事件或游戏状态。

材料有两种用途：

- **正在讲解的材料**：日志、文档、截图等是画面主体。具体位置和讲解范围常显，不能因为归类为材料而把定位藏起来。
- **提供给 AI 的输入材料**：截图、源码、开发说明等放在添加材料的操作附近，说明作为附件、项目文件还是其他输入提供。

这三部分是内容要求，不是三个固定大框，也不是必须执行一次的固定排列顺序。

## 5. 操作与逐字稿的时序

| 实际讲述过程 | 页面安排 |
| --- | --- |
| 静态画面已经就位 | 画面定位 → 逐字稿，无需虚构操作 |
| 连续完成几个动作，中间不解释 | 画面定位 → 编号操作组 → 逐字稿 |
| 做完一个动作，要先解释再继续 | 操作 A → 逐字稿 A → 操作 B → 逐字稿 B |
| 边操作边讲 | 操作模块注明“讲述时执行”，紧邻对应逐字稿 |
| 讲完才执行下一步 | 下一步动作放在逐字稿之后，不提前并入前一组操作 |

中间没有讲述的连续动作可以合并。有讲述意义的停留位置必须配上对应稿件。不能为整齐而把所有动作集中在前，把所有逐字稿集中在后。

同一位置连续讲述的自然段保留在同一逐字稿模块内，不按源文件自然段或编辑坐标拆成多个框。源坐标、评论及修改仍需保留。

结构示例：

> 讲解段：沿正文找到配套资源。  
> 画面：编辑器，SKILL.md 的使用步骤，左侧保留文件目录。  
> 操作：选中正文中的资源引用。  
> 逐字稿：解释为什么在这里引用，以及什么时候需要读取。  
> 操作：打开引用文件，定位对应示例。  
> 逐字稿：解释示例提供什么，以及怎样配合正文。

这是四个模块、一个讲解段。若接下来开始判断示例质量，则可以另起一段。

## 6. 画面与演示的预设形式

各形式共用视觉体系，不分别建立整套页面模板。

| 形式 | 必需信息 | 展示方式 |
| --- | --- | --- |
| 静态 PPT／截图 | 页码或图片、关注区域 | 紧凑定位行；打开入口常显，预览按需展开 |
| 分步 PPT | 页码、当前展开状态、推进时机 | 使用实际页／步定位；点击动作与对应口播就近排列 |
| 连续操作 | 顺序、必要条件、最后停留位置 | 编号列表，短说明尽量同行；附属内容挂到具体步骤 |
| 文档／源码／日志阅读 | 文件、标题／搜索词／事件、讲解范围 | 突出材料与位置；节选按需展开，保留原文入口 |
| 动态演示／试玩 | 起始状态、动作、观察目标、结束条件 | 紧凑呈现操作与观察要求，注明边做边讲或完成后讲 |
| 等待与回放切换 | 从哪里切出、回放身份、返回后查什么 | 用连续操作表达；现场／预存身份和返回点常显 |

普通窗口切换通常只是操作步骤，不必单独增加一种视觉组件。PPT 的实际页码与步骤使用现有共用定位器，不能维护一套与播放器脱节的编号。

## 7. 附属内容及折叠规则

| 内容 | 放在哪里 | 默认状态 |
| --- | --- | --- |
| 提示词／命令原文 | 对应的复制、输入或执行步骤 | 长文本折叠；名称、用途及复制入口常显 |
| 输入材料 | 添加材料的步骤旁 | 名称、用途和查看／路径入口常显；详情按需展开 |
| PPT／截图预览 | 对应画面定位或操作旁 | 默认折叠 |
| 条件与备用处理 | 可能发生分支的步骤旁 | 折叠，用“生成尚未结束时”等具体标题 |
| 备用口播 | 对应备用处理内部 | 随分支展开，不混入正常逐字稿 |
| 选材理由、来源与核验历史 | 对应段的备课说明 | 折叠，不打断主路线 |

折叠后仍要看得懂完整正常路线。关键动作、讲解位置、观察目标，以及现场／回放、预期／实际等事实边界不能被藏起来。

区分正常路线与偶发分支：

- 正常安排就是“提交后先展示预存记录”，直接写进主路线。
- 只有某条件出现才采用的处理，如生成超时或文件缺失，放备用说明。
- 录前必须完成的准备不能混成现场动作；影响能否执行的条件应可明确找到。

## 8. 视觉层级与样式绑定

| 内容 | 样式职责 |
| --- | --- |
| 场景标题 | 较大字号、清晰分隔，关联目录锚点 |
| 讲解段标题 | 中等字号、小编号，不套整体外框 |
| 画面定位 | 较小字号与次级颜色，明确具体位置 |
| 操作 | 浅绿色区域，操作标签与正文区分，多步用编号 |
| 逐字稿 | 浅色阅读区域，字号大于操作说明，保留适合连读的行距 |
| 提示词／命令 | 可展开原文，复制入口不依赖展开 |
| 材料行 | 名称、用途、查看与复制尽量同行，窄屏自然换行 |
| 预览 | 直接展示内容，不在展开后继续层层套框 |
| 备用处理与备课说明 | 次级字号、默认折叠，就近附着 |

信息密度的约束：

- 层级优先通过标题、字重、字号、颜色和小间距表达，不依靠不断增加边框和缩进。
- 只给有明确职责的操作与逐字稿模块做整体区分；讲解段不用再包一层大卡片。
- 压缩无意义的段前段后空白；短说明、材料名与按钮尽量同行。
- 不把“紧凑”等同于所有文字都缩小，逐字稿应保持可读性。
- 展开态与收起态同样需要设计；PPT、提示词、材料详情不能恢复成高留白、多重嵌套。
- 具体像素参数尚未作为跨课程标准确认；本轮确定的是层级、密度和交互关系。

## 9. 目录、连续滚动与定位

1. 左右两侧独立滚动。
2. 右侧呈现整节内容，跨场景连续向下阅读，不要求点击下一场景才能继续。
3. 左侧根据右侧当前阅读位置高亮对应目录项。
4. 点击目录跳到对应锚点，不隐藏其他正文。
5. 目录展开／收起与正文定位分开处理，避免一次点击产生意外切换。
6. 深链、刷新与浏览器前进／后退能定位对应位置。
7. 高亮更新不等于强制滚动左侧，避免打断目录查看。
8. 必须定位到真实可见内容，并展开需要的信息，避免固定导航遮住目标。
9. 保留已有的目录层级、编号和 PPT 总览；不为版式另造教学层级。

## 10. 内容源与完成状态

正式页面继续从当前唯一讲述线源、口播源和材料映射呈现。重排不丢原文、已保存编辑、评论及稳定坐标。不得把独立样例的数据副本当成正式课程新的维护源。

最终目标形态要求画面、动作、入口与可照读逐字稿齐全。现场结果仍可未知，应提供观察与判断方式，不预填成功结论。页面完成、技术检查通过、作者走查、出声试读和教学效果验证是不同状态，分别说明。

这次 3.2 样例只是快照式布局验证，包含原内容的待预跑状态，不代表 3.2 全部内容已完成。

> “每次改变讲述位置，都紧跟该位置的口播。”

## 12. 阶段二必须保留的已有经验

本节保存当时要求保留的方法。阶段二的单元、解释安排、完成依据及与制作阶段的衔接现由 [讲述设计](../../.agents/skills/course-prep/references/narration-html.md)统一维护。

| 已有方法 | 阶段二解决的问题 |
| --- | --- |
| 先明确要教的判断，再选择任务片段 | 避免直接把任务操作流程当成教学内容 |
| 对应“要理解什么—看到什么事实—为什么支持这个认识” | 保留从事实到结论的解释过程 |
| 拆出必要的中间结果 | 避免把不同事件压成一句结论 |
| 给原文、实录、实操和 PPT 分配不同职责 | 避免在多个窗口重复同一推导 |
| 切换前说明要找什么，切换后停在事实可见处完成解释 | 形成可执行、有理由的讲述路线 |
| 同一问题可以在原材料里连续定位几处，再集中归纳 | 避免每个动作之后都回 PPT |
| 返回时应新增比较、解释或核对任务 | 无新增作用的返回可以合并或省去 |
| 明确现场、回放、预期与实际 | 教学展示顺序不能改写事实先后 |
| 同时确定 PPT 总页数、逐页职责与展开状态 | 给阶段三提供制作依据 |
| 用讲述要点与已有口播走查，再完善缺少的稿件 | 阶段二不必提前写齐逐字稿，也不能用空标题代替解释 |

现有“下载网页”案例把“取回文件”和“代码片段在工具返回里出现”拆为两个可观察结果。保留中间步骤是为了让学员学会核对事实，不是为了增加操作模块。

现有 Reference 案例保留“任务请求 → 建立关系 → 阅读依据 → 对应本例 → 核对结果 → 归纳”的准备与讲述过程；它是可选路径，不是每段必须套用的六步模板。需要同时保留它对重复解释、无意义返回和预期／结果顺序的修正经验。

## 13. 新对话继续讨论的入口

本节原定的讨论已完成，后续规则与模板已归入 Skill。以下问题和维护位置表保留为历史议题；继续备课按文首当前入口执行，不再从这些问题重新启动讨论。

需要共同明确的问题：

1. 从 Discussion 进入阶段二，最先填写的是什么？每段至少需要哪些解释和依据？
2. 怎样从一个完整判断或操作过程拆出必要的观察位置，而不按点击数机械拆分？
3. 画面尚未制作、入口尚未准备、只有讲述要点时，页面怎样呈现真实进度？
4. 已有稿件与未成稿部分并存时，怎样保持阅读顺序和信息层级？
5. 什么时候细化为讲解段、什么时候定 PPT 页与步骤，怎样记录尚未确定的关系？
6. 阶段二的完成依据是什么？哪些缺口必须先解决，哪些细节留到制作阶段？
7. 从中间状态补成最终状态时，如何沿用同一内容源、锚点和材料映射，而非重建第二套页面？

当时拟议：讨论完目标与中间状态后，再提出具体 Skill 修订范围，取得讲师授权，并按以下职责归位。现行维护位置以 Skill 为准：

| 维护位置 | 应承担的内容 |
| --- | --- |
| narration-html.md | 阶段二的拆解、讲法、画面职责与讲解段组织方法 |
| narration-implementation.md | 最终页面模型、视觉层级、折叠、连续滚动及交互 |
| narration-template 配套文件 | 与规范一致的可运行通用样例，不固化本课段数与内容 |
| spoken-script.md | 口播的解释质量、承接、写作与朗读方法 |
| recording-alignment-workflow.md | 对实际画面、定位、时序和口播的验证 |
| SKILL.md | 路由、阶段职责及引用，不重复详细规则 |

需要一并核对现有编辑规范中关于录制备注的限制，与本草案中备用处理的边界；正常操作不能藏到折叠备注，偶发分支的最终呈现方式在正式修订时统一。

## 14. 验收与样例边界

最终页面应检查：

- 整节连续滚动、目录高亮、点击定位、深链和前进／后退。
- 各种画面类型，尤其多次操作与讲述交替时的顺序。
- 只看主路线能找到画面、执行动作并知道什么时候说话。
- 提示词和命令的显示／复制一致，收起时仍可复制。
- 材料链接定位到实际内容，而不只是文件首页或 HTTP 成功返回。
- PPT 页码、步骤和播放器状态一致。
- 展开与收起、宽屏与窄屏均紧凑可读，不出现横向溢出或过度嵌套。
- 正式页的编辑、评论、源坐标和保存能力保留。
- 作者走查、技术检查、试读及试讲分别报告，不相互替代。

本轮独立样例借用了 3.2 的 18 个场景和 145 段口播，完成了源文一致性、不同宽度下展开／收起、提示词复制、PPT 预览及本地链接文件存在性检查，随后验证了整节连续滚动和目录高亮。文件存在性不等于全部材料中的目标位置已逐一实测；未进行本轮课堂试讲。

样例是当前机器上的临时讨论产物，不是跨机器交付依赖。新对话即使无法打开临时服务，也应能通过本文与仓库中的正式源理解决定；不要据此修改正式课程页面。

## 16. Discussion 的组织方案（2026-11-12 讨论记录）

讲师当时认可本节组织方案，要求先保存、暂不修改实际 Discussion 或 Skill；之后已授权按分批计划实施方法与模板。组织规则现由 [Discussion 方法](../../.agents/skills/course-prep/references/discussion.md)维护，正式课程仍按各自任务范围更新。本节保留原讨论依据：阶段二不另写一份重复的完整教学逻辑稿。

### 16.1 不同层级各自承担什么

Discussion 保留讲解思路、规定格式的表格、已选材料与已定输入。不同层级只展开本层新增的关系，不重复完整教学逻辑。

| 层级 | 要回答的问题 | 3.1 的例子 |
| --- | --- | --- |
| 小节 3.1 | 各教学部分怎样共同完成目标，为什么这样排列 | 认识作品并发出任务 → 等待时分析案例 → 归纳过程与质量的关系并引出指导复用 → 回本次作品验收 |
| 节内部分 3.1.3 | 本部分内部怎样从观察形成认识 | 先看成品差异，再分析实现、设计与检查中的事实，最后归纳过程变化怎样影响质量 |
| 表格行 3.1.3.x | 当前环节讲清什么，用哪段材料支持 | 提前通关案例中区分构建通过与玩法已经验收，指出完整通关检查缺失 |
| 阶段二讲述线 | 这些认识怎样通过实际画面和讲述逐步形成 | 试玩并停在提前通关状态 → 展示计数代码 → 查看检查范围，逐处安排解释 |

上层让读者不必先读完所有细节就能理解整体。下层可以再次使用同一概念，但不重复上层完整的目标、推导与承接。

关键转折属于教学逻辑的部分，应写清在 Discussion 对应层；若缺失则指出上游缺口，不在阶段二悄悄建立另一套结论。阶段二补的是观察、呈现与讲述的具体顺序。

### 16.2 建议结构

```text
第 N 章
  当前主线、学习目标与小节分工
  章级规划表
  全章共用的未决问题（有才放）

N.1 小节
  学生收获
  讲解思路
  教学部分规划表（三列）

  N.1.1 节内部分
    讲解思路（有需要展开的关系才写）
    已选材料与已定输入
    讲解安排表（四列）
    待解决事项（有才放）
    选材依据与历史说明（按需查看）

  N.1.2 …
```

固定的是表格及信息职责，不要求机械填满所有栏目。章级已有知识覆盖、范围和分工等有效内容仍保留；上述结构是阅读组织建议，不是将未列出的现有信息直接删除。

小节开头的学生收获简短列出；讲解思路用连贯短文说明各部分为何这样连接，然后进入三列表格。不再叠加同义的总体路线、整体安排、教学逻辑、承接说明等栏目。

节内部分的讲解思路说明表格各行之间不容易直接看出的关系，不重复小节概述。关系简单时可以只有一句话；篇幅随解释需要确定，不要求各部分前言同样长。

3.1.3 的写法示意（不是对正式内容的修改）：

> 先通过成品概览看见差异，再进入具体案例，区分实现问题、设计选择与检查覆盖。案例中的局部判断分别讲清后，最后把设计、实现和检查放在一起，归纳开发过程变化怎样影响作品质量。本部分停在对这一问题的认识，下一部分再讨论可复用指导。

### 16.3 表格沿用最新 Skill 格式

小节教学部分规划表：

| 教学部分 | 学生学完能做什么 | 必要知识与讲解深度 |
| --- | --- | --- |
| 实际教学部分 | 可观察的学习结果 | 为达成结果需要教什么、讲到哪里 |

节内讲解安排表：

| 序号与环节 | 画面与动作 | 具体讲清楚什么 | 任务取段与讲解重点 |
| --- | --- | --- | --- |
| 教学环节 | 展示对象及必要动作 | 教学问题＋按顺序构成答案的知识 | 任务片段＋它支持哪部分解释、讲到哪里停 |

一行仍是教学环节，可以包含多个实际画面，不提前变成逐次点击分镜。现有 Discussion 的滞后表格后续按授权迁移到最新 Skill 格式，保留有效内容、链接、定位与待定状态，不把旧格式反过来当成标准。

讲解思路说明部分或环节为什么这样连接；表格说明各部分或环节具体承担什么。两者不重复展开同一段推导。

### 16.4 材料与已定内容

材料区承担取材清单和准备快照的职责。保留已经确定的 Skill、游戏、提示词、附件、源码、上下文、起点和运行结果；不因精简文档而要求重新准备。

| 类型 | 常显信息 | 详细内容位置 |
| --- | --- | --- |
| 已选材料：游戏、Skill、源码、截图、日志 | 名称／版本、课堂用途、入口、关键条件 | 原材料文件或材料页 |
| 已定输入：提示词、附件组合、任务起点 | 用于哪个任务、是否已实际使用、完整内容入口 | 短内容直接展示，长内容折叠或链接 |
| 已知结果：成功、超时、缺陷等 | 影响选材与讲法的结果范围 | 完整运行和检查记录 |
| 任务之间的关系 | 同一会话继续还是独立副本、输入是否改变 | 关键关系常显，不能只藏在日志中 |

共用材料在小节层集中登记一次，各部分引用稳定名称与具体片段；独有材料放在本部分。表格第四列指定采用哪个片段及其讲解重点，不重复粘贴整份材料说明。

### 16.5 其余信息的保留与阅读分层

| 信息 | 处理方式 |
| --- | --- |
| 选材和教学取舍理由 | 直接影响讲法的理由简短进入讲解思路，详细论证备查 |
| 官方依据与调研结果 | 保留支持当前判断的摘要与来源，完整调研通过入口查阅 |
| 证据缺口和待确认问题 | 明确影响哪个环节；解决后更新当前内容，清理过期提醒 |
| 最新反馈、本轮调整、承接补充 | 已确认结论合并到思路或表格的对应位置，调整过程保留历史入口 |
| 实验与运行日志 | 原记录保留，Discussion 提取起点、用途、结果边界和链接 |
| 制作进度和检查流水 | 不占教学正文，仅把影响当前使用的状态就近提示 |

例如，不同条件的游戏不能作为控制实验，这会影响课堂解释，必须容易看见；第一次截图失败、第二次成功的流水通常不必进入主阅读路线。

阅读目标：平时阅读“小节讲解思路＋规划表＋节内讲解表”，即可把握教学安排；需要核对输入和证据时查材料，需要追查取舍时看备查说明。不能要求讲师从历史修订中自行拼出当前方案。

### 16.6 与中间状态讨论的交接

阶段二从 Discussion 接走已定的教学关系、环节、材料与输入，展开成具体画面、观察顺序和对应讲述。出现推导缺口、结论错位或证据不足时，指出 Discussion 对应层的具体问题，按授权处理，不另加游离的逻辑补充。

上述原待讨论项现由 [讲述设计的单元与完成程度](../../.agents/skills/course-prep/references/narration-html.md#讲述设计的单元与完成程度)、[当前布局与交互](../../.agents/skills/course-prep/references/narration-implementation.md#当前布局与交互)及 [交接方法](../../.agents/skills/course-prep/references/preparation.md#交给其他窗口)承接。本节不再维护另一套中间阶段格式。
