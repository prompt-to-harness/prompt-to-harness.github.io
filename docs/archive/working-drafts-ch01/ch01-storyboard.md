# 第 1 章讲述 storyboard

> 2026-09-21 · 按 [深蓝课程总纲](../../course-outline.md) 的六节展开，不调整大纲。制作约定见[课程共识：录播与独立学习约定](../../design/course-design-principles.md#录播与独立学习约定)，原始讨论见[录制讨论归档](../../../discuss/2026-09-21-recording-consensus.md)。本文件是制作草案，时长与操作需试录验证。

## 贯穿的问题

从「我想做一个网站」开始，完成环境确认、任务表达、受控执行与结果检查。讲师的网站展示课程与两位讲师，学员的网站可以展示简历、作品或兴趣；内容无需一致。第一章以 Codex App 为主，CLI 只作简短对照。

第 1 节先用 README 的小改动走通协作；第 5 节再正式生成首页 v0。这样先有一段真实经历，第 2–4 节可以围绕这段经历解释机制、权限与 Prompt。

第一节按“指出要改的内容 → 发出请求 → 检查实际差异 → 判断额外改动 → 自己练习”讲述。阅读与修改分开发是第一次演示的教学安排；简单任务的计划用一句话即可。详细例外、恢复和后续运行环境放在准备页，正文保留当下必需的提醒与入口。后续备稿沿用[讲述与改稿原则](../../design/course-design-principles.md#讲述与改稿原则)。

第一节文案精简后暂沿用原试录预算，实际长度由操作和试讲确定，不用重复总结来填满时间。

## 第一节样板的八个讲述点

| 编号 | 问题与画面 | 转场 | 素材要求 |
| --- | --- | --- | --- |
| 01 | 让 Codex 改一段项目介绍 | HTML → 可选目标网站短展示 → HTML | 说明小任务与教学拆分的用途；目标示例不能标为刚生成的成果 |
| 02 | 先改一段项目介绍 | App 的原段落 → HTML 替换文字 | 显示待修改的实际段落与相邻内容 |
| 03 | 目录、已有改动、起点 | 终端逐条检查 | 大字号展示命令与结果；分支课前核对，网站运行环境另见准备页 |
| 04 | 先让 Codex 找到这一段 | HTML 请求 → App 阅读原文与简短计划 | 对照实际 README 核对回复 |
| 05 | 把新介绍发给它 | HTML 请求 → App 执行 | 无关等待可剪，实际文件变化不伪造 |
| 06 | 用 diff 核对改动 | HTML 解释 → 实际 diff 与状态 | 示例与真实结果标识明确 |
| 07 | 多改了三个文件怎么办 | HTML 题目 → 暂停提示 → 展开解析 | 不伪装成现场发现故障 |
| 08 | 换成自己的介绍再试一次 | HTML 练习与检查提示 | 记录模板给入口；给出无法使用工具时的继续路径 |

配套：[逐字稿](ch01-01-script.md)、[HTML 讲义说明](../../../courseware/ch01/README.md)。

## 从准备到正式录制

1. 按[第一节环境卡](ch01-01-environment.md)选定并验证社区 Starter Repo 的课程 fork，在 README 中准备「项目介绍」占位段落。基线 commit、包管理器、启动命令与必要依赖记录到环境卡；未完成真实试跑前，不把环境搭建说成可直接跟做。
2. 讲师按第一节稿子在真实 App 中完整预演一次，补上实际目录、版本、操作界面与结果。当前样板没有替代这次预演。
3. 用演示模式试讲，阅读模式用于学员回看。先从第一节开始，不跳到第四、五节试录。
4. 用会议工具录一小段 HTML 和一小段 App，包含讲师小窗、Prompt、代码或 diff；查看实际导出分辨率、码率、字体清晰度、声音和遮挡。1080p 可读是设计目标，不预先声称会议软件已经达到。
5. 把技术样片交课程团队确认可剪辑性，再按第一节到第六节推进。发给课程团队由讲师处理，本原型未发送任何外部消息。

## 素材粒度

每小节一个交付目录。例如 `01-01/lecture-take01.mp4`、`practice-take01.mp4`、`script.md`、`manifest.md` 与必要静态素材。manifest 标明讲述点、采用 take、插入顺序、必须保留的证据和可删除的等待。实际视频不存入本课程仓库。

逐字稿尽量完整；操作时用真实输出替换条件性说明。旁白、字幕和命令统一术语；课堂提问必须附解析，不能把讲义里的未完成内容留给群答疑补齐。
