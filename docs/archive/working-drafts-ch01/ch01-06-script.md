根据任务所需的动作与影响范围，判断应该开放哪些权限。

[录制说明与镜头证据](ch01-06-recording-notes.md) · [站内练习与参考答案](../../../courseware/ch01/lessons/06-permissions/practice.html)

真实环境、实操输出与试讲时长待核验；下面的条件性讲解不能用作已经通过的证据。

## 01 · 回看决定

**画面标题**：少几个确认，就一定更快吗

**画面要点**：读取首页入口，真的需要发布权限吗

### 口播

读 README 时，如果 Codex 提议先把所有权限打开，后面就不用反复确认了，你会怎么选？这一节用我们做过的两类任务，看看多给的权限究竟帮了什么，又多影响了哪些地方。

我们只回看记录，不再配置权限，也不执行危险命令来制造事故。先看需要完成什么，再判断允许它做什么。

## 02 · 任务 A：调查

**画面标题**：找入口，只需要读到证据

**画面要点**：读取 README、路由和状态，暂不修改或运行脚本

### 口播

任务 A 是找出首页入口和项目展示区。我们可以从 README、路由和组件引用找到证据，查看 Git 状态确认起点。这些动作本身不需要写页面，也不需要登录托管平台。

如果它说想安装一个工具方便搜索，先问现有读取和搜索为什么不够。不是任何网络访问都永远不允许，而是这张任务卡还没出现需要它的理由。若确实遇到阻断，带着具体错误再讨论最小的额外能力。

记录里写清依据：我需要读这些文件来回答入口在哪里，所以先不增加写入和发布能力。这样换一个项目时也能重新判断。

## 03 · 任务 B：生成

**画面标题**：生成首页，需要写入和本地检查

**画面要点**：能力随任务增加，范围仍要说清

### 口播

任务 B 是生成并运行首页 v0。只读范围就不够了，需要修改约定的页面文件，构建时还会写产物，开发服务器会留下一个本地进程。这些都是完成任务确实需要考虑的动作。

但能改工作区，不等于只能改我们列出的两个文件；技术权限可能比业务范围粗。所以仍要用具体文件清单和 diff 来核对。运行项目脚本之前，也要知道它会做什么，不能只看名字叫 build 就默认没有其他副作用。

这里仍没有发布需求，也不需要读取私人目录或获取部署账号。新任务确实要求安装依赖、连接服务或上线时，再逐项确认，而不是提前一次性放开。

## 04 · 给经验命名

**画面标题**：Least Privilege / 最小权限

**画面要点**：让每个参与者只得到完成当前任务所需的权限

### 口播

这项经验有一个名字，Least Privilege，最小权限。Saltzer 和 Schroeder 在系统保护原则中提出，每个程序和每个用户都应当只使用完成工作所需的权限。

把这个原则用到今天的 Agent 协作里，我们先看它要做什么动作、作用在哪些对象上，以及这次授权要持续多久。任务 A 和任务 B 的权限可以不同，不需要找到一个永远通用的配置。

这是我们用经典原则分析当前任务的方式，不是原作者针对现代 Agent 写的使用说明。它也不保证不会出错，而是帮助限制错误可能影响的范围。

## 05 · 三种保障

**画面标题**：写了“不要发布”，还要看什么

**画面要点**：文字约束、技术限制、人的检查承担不同责任

### 口播

假设 Prompt 写了不要发布，但工具持有部署凭证，网络和远端写入也已经允许。这句文字没有撤销凭证，更没有自动关掉部署能力。

请求里写了‘不要发布’，工具却还拿着部署凭证。这句话告诉它我们的要求，但没有收回它发布网站的能力。把不需要的部署权限关掉，再检查它实际做了什么。

反过来，没有弹审批窗口也不能证明什么都没发生。仍要看设置、实际动作和结果，发现范围变化就暂停。

## 06 · 暂停判断

**画面标题**：同一个建议，两种任务都合适吗

**画面要点**：“让我安装依赖，再连上托管平台”

### 口播

现在给两个任务同一个建议：先安装依赖，再连接托管平台，这样就能一次做完。任务 A 和 B 应该作出完全一样的回答吗？请先说出哪些动作没有必要，再看 B 确实缺依赖时怎么处理。

连接托管平台在两个任务里都没有必要。A 只找入口，先用只读调查即可。B 如果确实因为缺依赖无法运行，就保存错误，核对锁文件、来源和安装脚本，说明所需网络与写入范围，另行确认安装。

这并没有批准发布。需要额外权限时，把它与具体阻断对应起来；既不为了省事全部放开，也不在任务已经变化时坚持永远只读。

## 07 · 带走判断方法

**画面标题**：下一次先问这三个问题

**画面要点**：做什么、影响哪里、何时收回

### 口播

下一次拿到新任务，先问它需要什么动作，再问这些动作会影响哪里，最后想一想任务结束后哪些能力和进程不再需要。授权后仍然检查结果。

用配套的两张任务卡，各写一段判断和依据。没有真实操作记录也可以完成这项案例判断，但不要把它写成已经完成环境操作。
