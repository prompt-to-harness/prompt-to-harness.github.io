# 第 1 章第 3 节：Codex CLI、桌面端与权限边界 · 首版逐字稿

> 2026-09-21 首版。定位为知识＋操作，约 12 分钟净视频，其中 CLI 对照控制在 2–3 分钟。具体版本、登录方式、权限画面和 CLI 启动入口必须以环境卡实测结果替换。

## 本节收获

学完后，学员能够：

- 说明 App 与 CLI 是不同入口，不把界面便利当成权限证明；
- 在同一练习项目中完成一次只读 CLI 基线检查；
- 根据目标文件、动作和外部副作用判断是否需要人工确认；
- 说出为什么不使用危险的全权限或 bypass 配置。

本节不演示危险配置，不把未经核验的其他智能体、其他模型或录制快照说成 Codex CLI 的等价操作路径。

## 讲述点

### 01 · 入口改变，任务证据不变

**画面**：第 1 节 App 的项目路径、Prompt、diff 记录；旁边放 App 与 CLI 两个入口标签。

**口播**：

上一节主要使用 App。今天加入 CLI 对照，但我们先把边界说清楚：入口可以不同，任务目标、项目起点和验收证据不能因此消失。换一个界面，不等于可以少检查一次 diff，也不等于权限自然更宽。

### 02 · App 与 CLI 怎么选

**画面**：两列对照：可见性、脚本化、路径核对、权限确认、适合的任务。

**口播**：

App 适合第一次观察协作过程，能较直观看到请求、回复和权限提示。CLI 适合把目录、命令和结果放进已有工程流程，也更容易留下可复查的终端记录。选择入口时先看任务和证据需要，不要把“看起来更方便”当成唯一理由。

### 03 · 先核对 CLI 基线

**画面**：终端进入与 App 相同的练习项目，展示环境卡中的版本和路径字段。

**口播**：

切到 CLI 前，先核对它是否打开了和 App 相同的项目目录。版本、登录状态和权限设置记录在环境卡里。若这些条件没有实测，不把这段画面剪成“任何机器都能照做”的结论。

**操作**：

```bash
pwd
git rev-parse --show-toplevel
git status --short
git rev-parse HEAD
codex --version
```

实际录制时以环境卡记录的可用命令为准；如果版本检查命令或入口不同，保留真实命令并同步准备页。

### 04 · 用只读任务对照一次

**画面**：CLI 中只读检查同一 README 和当前状态，不执行修改。

**口播**：

为了比较入口，我们只做一次只读检查：确认当前目录，读取目标文件，查看状态。这里的重点不是证明 CLI 更强，而是确认同一个任务在不同入口下仍然有相同的范围和证据。

**建议请求**：

```text
请只读检查当前项目：确认项目根目录，找到 README.md 中的「项目介绍」，说明当前内容和 git 状态。
不要修改文件、运行安装、启动服务或访问外部网络。
```

若工具提出额外权限请求，先停止并查看目标动作；未确认前不允许继续。

### 05 · 权限要看动作和副作用

**画面**：三张卡片：读取仓库文件、修改工作区、访问外部系统；每张标出“可能的影响”。

**口播**：

权限判断不能只看“这个任务听起来很小”。读取文件、修改工作区、安装依赖、启动进程和访问外部系统，影响不同。我们要问三个问题：它要做什么动作，作用范围在哪里，是否会产生外部副作用。

### 06 · Prompt 里的禁止语句不是技术边界

**画面**：左侧是“不要修改其他文件”的文字，右侧是实际文件状态和审批提示。

**口播**：

请求中的“不要修改其他文件”是任务约束，帮助 Agent 理解目标，但它不是技术上的隔离。真正的边界还要由权限、工作目录、人工确认和最后的 diff 检查共同保证。文字说了禁止，不代表动作就不可能发生。

### 07 · 自检：这个请求是否可以直接批准

**题目**：

CLI 请求读取 README、查看 git 状态，并要求安装一个依赖来“顺便检查项目”。你会直接批准吗？依据是什么？

**解析**：

不应直接批准。读取和查看状态是只读检查；安装依赖会修改环境，并可能访问网络或执行安装脚本。先确认是否是本任务必要动作、目标目录和来源，再决定是否需要人工确认；如果不是必要前置，可以拒绝并继续只读检查。

### 08 · 失败路径与 1.4 转场

**画面**：App/CLI 权限请求、环境失败、外部副作用三种继续路径。

**口播**：

如果 CLI 不可用，先看脱敏回放，不能把回放算成完成 CLI 操作。如果权限请求超出任务范围，保留现场并拒绝或缩小任务。如果环境检查不一致，先回到准备页修正起点。下一节我们会把这些边界写进 Prompt，用 Goal、Context、Constraints 和 Done when 让请求更容易确认。
