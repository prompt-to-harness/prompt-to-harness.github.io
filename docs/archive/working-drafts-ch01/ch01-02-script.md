# 第 1 章第 2 节：课程主线、Agent 与通用能力地图 · 首版逐字稿

> 2026-09-21 首版。定位为知识讲解，约 10 分钟净视频。内容必须回指第 1 节的真实记录；若第 1 节尚未完成实录，画面中的对话和 diff 只能标为示例或回放。

## 本节收获

学完后，学员能够：

- 用一句话解释 Agent、Context、Tool 和 Context Window；
- 从第 1 节记录中指出输入、请求、工具动作和结果；
- 说出至少三种可能的失败方式；
- 知道下一节会把入口和权限分开检查。

本节不讲模型训练、推理架构、完整配置字段，也不要求记住代码补全、RAG 或行业发展史。行业口播最多各用一句话定位。

## 讲述点

### 01 · 回看上一节发生了什么

**画面**：展示第 1 节的 Prompt、Codex 找到的段落、实际 diff 和 `git status`；按来源标注“真实记录”或“教学示例”。

**口播**：

上一节我们没有让 Codex 直接做一个完整网站，而是先完成一个很小的修改。我们给了目标文件和范围，它读取了文件，说明准备改哪里，随后执行修改，最后由我们检查 diff 和文件列表。

今天不增加一个新项目，而是把这段经历拆开，看清楚每个角色分别做了什么。后面的 Prompt、权限和检查，都建立在这次拆分上。

### 02 · 先看一条执行循环

**画面**：

```text
人的目标与限制
        ↓
Agent 组织下一步
        ↓
Tool 读取文件 / 修改文件 / 返回结果
        ↓
Context 汇总当前可用信息
        ↓
人检查证据并决定继续、修正或停止
```

**口播**：

这里的循环不是“说一句话，机器自动完成一切”。Agent 根据当前信息组织下一步，Tool 才是实际读取、修改或执行的入口，结果再回到当前 Context。人仍然要看证据，并决定是否继续。

### 03 · Agent 是谁

**画面**：把第 1 节中“先读取、再说明、再修改”的三步逐一高亮。

**口播**：

这里把 Agent 理解成一个能根据目标和当前信息推进任务的执行者。它可以提出计划、选择下一步工具，并根据工具返回继续行动。它的完成说明是一个结果描述，不等于验收结论。

### 04 · Context 包含什么

**画面**：四格卡片：人的请求、仓库中的文件、工具返回、此前对话；旁边放一张“尚未取得的信息”卡片。

**口播**：

Context 是当前任务中可被使用的信息集合。它可能包括你的请求、已经读取的文件、工具返回和此前对话。没有被读取、没有被提供，或者已经超出当前可见范围的信息，不能因为“项目里可能有”就当成 Agent 已经知道。

### 05 · Tool 与结果不是一回事

**画面**：左侧显示 `git diff`、文件读取等工具动作，右侧显示返回的文本、状态或错误。

**口播**：

Tool 是行动入口，工具结果是行动返回的信息。例如，读取 README 是一次工具动作，读到的原文是结果；运行 `git diff` 是一次工具动作，差异文本是结果。结果也可能不完整、失败或被误读，所以我们要把“做了什么”和“看到了什么”分开记录。

### 06 · Context Window 不等于项目大小

**画面**：把“整个仓库”与“本轮可见信息”并排，标出差异。

**口播**：

Context Window 可以先理解成一次交互中能够放入和处理的信息容量。它不是项目总大小，也不保证所有文件同时可见。项目越大，越需要先找入口、分段读取和保留关键证据。

### 07 · 四层主线：能力怎样逐步叠加

**画面**：四列依次显示 Prompt、Vibe Coding、SDD、Harness；标出本章所在的第一层。

**口播**：

课程主线不是四个互相替代的工具名。Prompt 先把一次任务说清楚，Vibe Coding 把运行结果带回反馈循环，SDD 把需求和验收沉淀成持久契约，Harness 再把上下文、工具、验证和人工门禁组织成可重复的环境。

### 08 · 自检：下面哪一种说法少了一个关键判断

**题目**：

上一节中，Codex 回复“已经完成修改”，这是否足以证明任务完成？请说明还要看什么。

**解析**：

不够。至少还要核对目标段落、文件范围和 diff；如果任务要求运行或构建，还要检查对应结果。完成说明只描述 Agent 认为发生了什么，不能替代人的验收。

**常见误解**：

- “只要文件里出现新文字就完成”：没有检查位置和其他改动。
- “只要 `git diff` 有输出就完成”：有输出只说明发生了变化，不说明变化符合范围。
- “AI 能看到整个仓库”：没有证据支持时，不能这样假设。

### 09 · 三种失败方式与下一节

**画面**：三张失败卡片：找错文件、工具失败或权限不足、改动超出范围。

**口播**：

同一个循环至少有三类失败：目标或上下文不完整导致找错文件；工具或权限导致动作没执行；动作执行了但改动超过范围。下一节我们会专门看入口和权限：App 与 CLI 的选择，和一次操作到底允许做什么，是两个不同的问题。
