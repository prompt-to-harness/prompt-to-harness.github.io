# 内容分层、特色专题与展示媒介

> 内部内容选择方案。主题进入课程不等于承诺学员实现完整系统；素材事实与版本依来源表（私有，未公开）复核。每项拓展必须回答：解释哪个误解、有什么依据、改变哪个操作或判断？

## 1. 主题的首次出现与加深

| 内容 | 会用：核心动作 | 看懂：机制与边界 | 认识/参考 | 课次 |
| --- | --- | --- | --- | --- |
| 工具与最小闭环 | 启动、目标、运行、修改与检查 | 模型/Agent/环境分工 | 不同 UI 入口 | L01→L02→L10 |
| Prompt 与上下文 | 准备相关事实和限制 | 输入分层、可访问与已取得信息不同 | 公开指令与模型权重区别 | L02→L04→L09 |
| 需求与 SDD | 轻量规格、验收、计划 | 公开框架流程与取舍 | 多框架完整比较 | L03→L05→L10 |
| 代码库理解/RAG | 找入口和证据、核对地图 | 文本/符号/语义检索适用问题 | 向量索引、LSP 深层实现 | L04→L07 |
| 任务与状态 | 小步修改、复现、交接 | 会话、文件、进程、持久资料的区别 | 压缩与缓存实现 | L05→L09 |
| 测试/Review/评测 | 对齐需求与证据、补检查 | 题集、预算、尝试次数与统计口径 | 完整 benchmark 运行平台 | L01/L02→L06→L10 |
| 规则与 Skills | 外化一项重复经验 | 常驻约束、按需细节、工具与技能不同 | 插件生态 | L07→L09 |
| MCP 与权限 | 判断读写/外发/审批、核对返回 | 协议与工具边界 | MCP Server/SDK 开发 | L02→L08→L09 |
| Harness | 组织环境、检查、反馈和确认 | 为什么文件齐全不等于工作可靠 | 多 Agent、远程运行、自治研究 | L02→L09→L10 |

“看懂”内容也可有题，但不以写出 SDK/搭平台验收。“认识”内容不成为下一课隐藏前置。

## 2. 主课内的特色深挖预算

以下分钟均已包含在逐课小节中，不再额外叠加。未充分核验的素材可替换为已核验同类案例，不能因此删掉核心能力。

| 专题 | 位置/上限 | 核心问题 | 最小展示 | 制作边界 |
| --- | --- | --- | --- | --- |
| 公开 Prompt 与历史变化 | L02.2 / 12 分钟 | 除了我的话还有什么影响行动？ | 三条指令＋一处固定版本 diff | 不称为完整系统指令、不逐行读全文件 |
| 不止一种代码检索 | L04.2 / 8 分钟 | 找名字、找调用、找相似意图是否同一问题？ | 同任务下选择搜索方法 | 不启动 RAG 平台开发 |
| 交接丢的是哪种状态 | L05.2 / 8 分钟 | 新会话、文件版本和旧进程怎样区分？ | 三种状态并排＋一个定位案例 | 不宣称某恢复命令包办所有状态 |
| benchmark 读题而非追榜 | L06.2 / 10 分钟 | 分数测了什么，条件是否可比？ | 函数题/仓库题/终端题各一张任务卡 | 不把排名录成长期真理 |
| 常驻规则与按需经验 | L07.2 / 8 分钟 | 哪些信息要一直有，哪些用时再找？ | 精简规则与独立细节文件 | 不把短或长本身作为好坏标准 |
| 工具描述与实际权限 | L08.2 / 10 分钟 | 清楚工具说明与硬限制各解决什么？ | 参数/错误提示对照＋实际边界 | 不靠 Prompt 证明不可越权 |
| 反馈、持久资料与成本 | L09.2 / 8 分钟 | 哪些信息帮助继续，哪些只是重复计算？ | 任务反馈表；只读可见成本字段 | 不讲未经核实的统一节省比例 |
| 从更新中找稳定原则 | L10.2 / 8 分钟 | 更新后哪些方法继续有效？ | 一处前后变化和变更说明 | 动机事实与讲师推论分开 |

合计上限 72 分钟，是 v0.1 的保守选择，不追求每课一个“炫技点”。软件工程选段也在对应小节预算内，不能再额外加上四张 12～15 分钟试讲卡。

## 3. 软件工程拾遗如何嵌入

| 问题 | 讲清的工程经验 | 课程位置 | 最小证据 | 已有材料可用方式 |
| --- | --- | --- | --- | --- |
| “能运行”不是“按要求完成” | 验收、工作区与可复现 | L01–L02 | 目标/结果/diff | 先白话，不加史料负担 |
| 文档写了但意思没对齐 | 契约、状态、不变量 | L03 | 规格和边界检查 | SDD 验收脚本仅选当前片段 |
| 文件很多但不知为何如此 | 模块、接口、依赖、理解交接 | L04–L05 | 地图依据与交接缺口 | Naur 卡为可选史料入口 |
| 函数更短但更难读 | 命名、深浅模块、内聚耦合 | L06–L07 | 两种实现和具体 Review | Ousterhout/Martin 争论，不裁成唯一口号 |
| Agent 越多越乱 | 协作边界、集成与权限 | L08–L09 | 修改范围和反馈 | Conway 卡做当代映射，非性能证明 |
| 下次还能不能修改 | 技术债、清晰度、风险取舍 | L09–L10 | 新变化中的修改/验证成本 | 更广历史阅读进扩展 |

原始 [拾遗草案](../../software-engineering/software-engineering-thread.md) 与 [四张试讲卡](../../software-engineering/pilots/README.md) 不改写。SOLID、Clean Code 等仅在当前问题确有价值时使用；不用术语/抽象层/测试覆盖率给项目打总分。

## 4. 内容类型与媒介

| 要教什么 | 主媒介 | 学员动作 | 不采用的默认形式 |
| --- | --- | --- | --- |
| 机制 | 分层图＋对应执行记录 | 标出信息和职责 | 一页塞全套架构 |
| 工作步骤 | 标注录屏＋关键暂停点 | 独立重做局部任务 | 未剪辑长终端录像 |
| 权衡 | 同题对照＋条件卡 | 选择并解释代价 | 先指定胜者的对照 |
| 问题鉴别 | diff/测试/日志局部 | 指出缺证据处 | 只看成品截图 |
| 数量级直觉 | 可重做小实验/表格 | 先预测再核对 | 用单样本宣称普遍定律 |
| 历史/原始资料 | 版本 diff＋原文定位 | 区分事实、动机和推论 | 工具更新新闻汇编 |
| 方法回查 | 独立讲义/方法卡 | 按症状找动作 | 少字 PPT 导出即教材 |

有限交互 HTML 可以增强可见性，但任何核心练习都要有静态/可下载替代，不为第一版开发学习平台。双人 Review 可以预录；不模拟收到现场回答。

## 5. 拓展池与停止规则

Agent SDK、Autoresearch、Kernel Ops、复杂多 Agent 与更完整历史人物图谱先留作可选阅读/后续内容。放入主课前必须替换掉同等时间预算的内容，而非追加。

若某素材解释不了本课问题、只有新奇名词、依赖大量新基础、来源不可核验或版本不稳定，移到扩展/待研究。主线的操作、验证和独立继续不能为特色内容让位。
