## 1. 课程承诺与非目标

目标用户有基础编程经验，可以完全没有 AI Coding 经验。一条主线同时提供基础方法和工程判断：做出可用结果，解释依据，发现并修正问题，在新任务中复用方法。支持更多与更少经验的学习者，不把两类课程拼接，也不假定熟练工具使用者已经会验收。

“可用”是在明确条件下满足需求，有相应检查且能继续修改。成果可以是普通网站、工具或现有功能，不必内置 AI。不是生产级安全认证、就业保证或完整 Agent 工程师训练；不教模型训练、全套云运维和完整 SDK 开发。

## 2. 共同教学结构

问题 → 知识与方法 → 实际任务 → 证据与判断 → 迁移。机制解释、工作示范、评审诊断、对照取舍可以调整顺序。每个 90 分钟单元闭合，不要求每个小节重复同一模板。

内容线用图解、讲述和局部原始资料建立理解；Projects 用真实任务组合方法；软件工程在需求、接口、修改、测试和权限处混讲并点明。0.5 不是课时比例，不让项目把知识覆盖缩成操作手册。

录播不依赖实时反馈：自检答案、常见错误、恢复与继续路径预先提供。学员群只作异步增强。观看可帮助继续理解，但不替代标注为“会用”的实际操作。

## 3. 五阶段与时间预算

| 阶段 | 课次 | 主要变化 | 分钟 |
| --- | --- | --- | --- |
| 起步与认识 | L01–L02 | 第一次做成；看懂模型、工具、环境的职责 | 180 |
| 控制与变化 | L03–L05 | 澄清需求、找代码事实、分步推进与恢复 | 270 |
| 验证与复用 | L06–L07 | 用证据验收；外化重复经验 | 180 |
| 工具边界与 Harness | L08–L09 | 在明确权限和反馈下组合工作流 | 180 |
| 独立迁移 | L10 | 新任务中选择、执行并解释方法 | 90 |
| 合计 | 10 课/40 小节 | 深挖与解析均在视频预算内 | 900 |

默认每课 20/25/30/15 分钟；L01 与 L09 为 15/20/40/15，L10 为 10/15/50/15。暂停、跟做和课后实践另计。时间为制作预算，不声称是学习效果最优值。8 课方案删减 180 分钟的具体方法见交付计划，不将 900 分钟快讲成 720 分钟。

## 4. 学习结果与覆盖

| 编号 | 可观察能力 | 首次建立 | 再练/检查 | 最小证据 |
| --- | --- | --- | --- | --- |
| O1 | 在受控环境启动工具并运行一个结果 | L01 | L02、L10 | 运行条件、结果检查、未验证项 |
| O2 | 分清任务输入、运行程序、工具请求与结果 | L02 | L04、L08、L09 | 标注执行记录，不把说明当执行 |
| O3 | 将需求转成范围、验收、计划和非目标 | L01、L03 | L05、L10 | 轻量规格及一处变化的处理 |
| O4 | 用代码事实建立仓库认识与上下文 | L02、L04 | L07、L10 | 带依据的地图/入口与未知项 |
| O5 | 小步变更、调试、保护旧行为和恢复状态 | L01、L05 | L06、L09、L10 | diff、复现步骤、恢复或交接记录 |
| O6 | 用测试、运行与 Review 判断结果和遗漏 | L01、L02 | L06、L10 | 需求—证据对应，补验证或接受理由 |
| O7 | 复用规则并建立工具权限与最小 Harness | L02、L07 | L08、L09、L10 | 可重复检查、权限说明、人工确认点 |
| O8 | 在陌生任务中自主选择并迁移方法 | L04 | L05、L10 | 新任务交付卡和取舍解释 |

“首次建立”不是全部掌握；验证、版本和权限从前期出现最小版，后期增加深度。每课的预录自检提供可见证据与解析；正式评分、人工批改、证书不由本表决定。

## 5. Projects 的工作版选择

A：个人主页/实用页面，建立快速成功；B：规则可变化的交互应用，训练规格与变化；C：陌生资料浏览小站，训练代码地图与局部修改；D：只读资料查询工具，训练外部边界。T 为末课独立迁移小任务，不另建大型第五项目。

本版建议 A/B/C 构成核心实践骨架；D 的工具边界判断必须覆盖，真实 MCP 连接在支持验证通过后才列为必做。若改用受控本地工具，只能声称练过接口、权限和反馈，不能声称已掌握真实 MCP 接入。具体主题与必做范围由试跑门槛决定。

每次引用 Project 都提供独立阶段包，不依赖学员前一课代码正确。C 必须在新的会话中接手，至少有一个未在讲解中逐行展示的变更任务；L02 搜索样例不算已满足全部陌生仓库迁移要求。

## 6. 下一轮审阅与门槛

先判断课序是否合理、每课产出能否检验目标、3～4 个闭环是否过重、拓展是否遮挡操作、无群回应时能否继续。之后再定项目题目、环境组合和正式提交边界。

资料与文档校验通过，只能进入试跑/样课制作；通过试跑后才能锁定相关演示；字幕、解析、起点、检查点、引用权限和关键环境均就绪后才能发布。不得用“后面群里会解释”放行缺失教学。

所有未决项、责任角色和停止条件见 [制作与交付计划](delivery-plan.md)。已有软件工程 [四张试讲卡](../../software-engineering/pilots/README.md) 保留，按主题抽取而非全部追加到视频时长之外。
