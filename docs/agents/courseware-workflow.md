# 课件制作流程

> 从 `AGENTS.md` 拆出，设计或修改课件前阅读。规则本身没有改动。更细的制作顺序见 `docs/production/lesson-authoring-playbook.md`，页面零件见 `docs/production/parts.md`。

- 设计或重构一章时先写本章故事线（一句话主线、逐节表、贯穿线索），讲师确认后再细化逐节分镜，最后同步大纲与课件。格式见 `docs/design/course-design-principles.md` 的“章节故事线先行”。
- 每章要有一到两个明确的大知识点（2026-10-20 确认，见内部大纲 1.1）：写故事线时先写出这一两个点（同一概念可在两到三章里出现，每次换关注点，写清本章是首次点亮、深化还是重访），再检查每一节是从什么角度展开它们；展开不了的内容归入工程实践线或章末一节。
- 已迁移的章（目前是第 2 章）先读 `courseware/chNN/README.md`，它是这一章的唯一来源；新写或整体重写一节时（2.3 起），`STORYBOARD.md` 分为“本节内容 → 逐页安排 → 素材状态与操作备注”：先讨论连贯内容，再做展示与素材安排；逐页区不复述正文。已有小节保留原结构，下次整体重写时再迁移。各节不复述章级范围、验收和时长，也不写变更说明（变更写进提交说明和 `courseware/chNN/LOG.md`）。改东西先判断属于哪一层，从那一层往下改，分工见章文件“各节文件与改法”。
- 先核对该课次在两份大纲中的范围、目标、演示、练习、产出与验收，再看现有播放器和视觉约定。
- 页面引用统一用全章页面 id，写作“第 2 章 p27”（即 `lesson.js` 的 `id` 和网址 `#p27`）。id 是稳定编号：增删页不重新编号，插入的新页加后缀（如 `p27a`）；播放器的节内序号 `08/15` 只用于翻页，不用于引用（2026-10-05 确认）。
- 实验安排遵守[制作手册“实验与项目主线”](../production/lesson-authoring-playbook.md#实验与项目主线)（2026-10-05 确认）：贴近主线、前置简单且容易复现的实验留在主线；需要大量上下文或特殊条件的独立设计。优先最小本地准备，暂不引入 Docker；第二章示例与实验说明要求见该节。
- 侧边栏底部的上下节链接（2026-10-11 确认）：排成一行，向前的链接靠左、带 `rel="prev"`，向后的链接靠右、带 `rel="next"`（`shared/styles.css` 按它排左右，`shared/app.js` 按它把链接接到页脚按钮，缺了按钮就失效）。节内用「← 上一节」「下一节 →」；每章第一节用「← 上一章」，指向上一章最后一节，最后一节用「下一章 →」，指向下一章第一节；课时页工具栏放面包屑「课程首页 › 第 N 章 · 章名」和「讲解全文」，侧边栏顶部不再重复面包屑，只写节号（如「1.1」）和节标题（2026-10-11 改：工具栏在阅读、演示和手机上都显示，导航只放这一处；2026-10-13 改：第 1–3 章的节号放在节标题开头，两者使用相同字体、字号和字重，长标题自然换行）；第 0 章按单节课处理（无章首页，面包屑里的章名不做链接，侧边栏只放「下一章 →」），第 1 章第一节退回第 0 章。章首页用「← 第 N 章」「第 N 章 →」。只放这两类链接，其他入口放课程首页或章首页正文。新增或调整节时同步改相邻两节。
- 页面上的名字只有三层，每个只写一次（2026-10-11 确认）：**章**写在 `lesson.chapter`，**段**写在每页的 `segment`，**页**写在每页的 `title`。页标题上方的小标题由 `shared/app.js` 拼成“第 N 章 · N.N · 段名”（第 0 章没有节号），不再手写 `kicker`；演示模式底部进度条和阅读模式侧栏的分组标题都用段名，所以三处说法自动一致。`label` 是侧栏和页脚里的页名，只在标题太长时另写短名，不写就用标题。想换小标题，就改段名。
- 先写简短分镜：学员此刻面对的具体问题、可观察的证据、揭示顺序、需要学员做的判断、最后归纳的概念。用一个贯穿的小任务带出知识点，术语出现之前先让学员看到它解决的问题。
- 口播写在本节 `script.json`，不要写进 `build-lesson.py` 或只改 `lesson.js`；改完运行 `courseware/tools/rebuild-lesson.py <节目录>`（`make check` 会核对一致）。在 `speaker.html` 里改的句子只动口播：如果改了信息量或要增删步骤，同步改画面（`html`、`lead`、`steps`）。
- 画面只留关键证据、操作和关系；解释、追问和过渡放进讲稿或备注。动效只表达状态变化或揭示顺序。
- 流程图和结构图：节点、方向、分支条件、回路与终止条件必须先从大纲或代码核对清楚，渲染成功不代表逻辑正确。新建或实质修改时使用 `pretty-mermaid`（流程与布局）；手绘风格再用 `archscribe`，并逐项核对节点与连线，美化不得改变含义。skill 缺失或运行失败要明说，不能静默跳过。最终图示适配现有播放器与分步揭示，保留可编辑的源文件。
- 完成后实际打开页面检查画面、交互、阅读顺序、中文、遮挡溢出和离线资源，并按正常语速试读口播。没有课堂试讲，就不要写教学效果已验证；没检查的项目如实标明。
