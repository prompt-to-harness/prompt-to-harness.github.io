# 编辑约定

> 从 `AGENTS.md` 拆出，改文档、讲义、口播稿前阅读。规则本身没有改动。

- 区分**已确认的决定**、**工作假设**和**不得对外承诺的事项**；不要把讨论中的细节升级为承诺。状态横幅写明日期，并说明该文档*不是*什么（不是报名承诺，不是已验证的学习效果）。
- 保留 `discuss/` 下的讨论原文；决定写进 `docs/` 下的共识文档，不回写讨论记录。
- 优先小而可回退的文档改动，不重构结构；新增顶层文档前先确认没有现成入口，优先在 `README.md` 里链接已有文档。
- 改稿前读 `docs/production/editorial-checklist.md`（编辑规则的唯一来源）。讲义页、口播稿、准备/帮助页和录制备注保持一致；先讲清具体例子，再归纳方法。
- 不虚构 Codex 的功能、限制、命令或产品行为；不确定就说明并建议核实。区分 AI 建议、事实结论、设计假设和待验证内容。
- 示例、练习和代码必须可复现；涉及安全、隐私、版权、生产环境时写明风险与人工复核要求。每个练习明确输入、任务、产出和验收标准，避免“了解”“熟悉”这类无法验收的目标。
- 中文表达简洁、适合授课；必要的英文术语加一句解释。
