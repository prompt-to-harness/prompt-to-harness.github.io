## 对上一轮判断的补充

只删句尾总结不能解决全部问题。3.2 有些篇幅在解释文件和结果中“有什么”，而目标要求学员能判断该写什么、该改哪里、怎样知道这项修改完成了。即使全部换成顺口短句，这段教学仍可能停在认识成品。

第 2 课的目标、案例和收束之间配合更紧：选定学员最后要作出的判断，再展开这个判断需要的可见事实、因果和操作。需要消除关键误解的地方讲得细，周边技术点只解释到够用。它不要求每个知识点都完成相同的实验、练习或完整操作。

## 第 2 课怎样决定讲解深度

| 目标与定位 | 实际讲到了什么 | 在哪里收住 |
| --- | --- | --- |
| 2.3 p40b：知道给网址后模型获得的依据是什么 | 下载文件后，返回只有两个行数；随后读取文件，代码才进入请求；固定侧栏的判断能在读到的 CSS 找到依据 | 学员能分清文件已存在、代码已读入、看到渲染页面。没有继续教 curl 参数、CSS 布局或浏览器渲染原理 |
| 2.3 p40b1 → p40d：让学员知道怎样补足视觉信息 | 人看出渐变与细线的差别；解释模型此时缺什么；当前与参考两张图加一句具体偏好；在请求里定位图片；回同一位置检查修改 | 能据自己看到的差别组织反馈并检查结果。浏览器自动接入只定位后续章节，不在这里展开配置 |
| 2.2 p27：理解压缩损失细节后怎样继续工作 | 对照压缩前后，禁止读文件追问原文，发现给不出来，再允许读文件恢复原文 | 能判断摘要是否够用、何时重新读取。没有讲摘要生成算法或压缩端点实现 |
| 2.2 p28、p33：作出会话选择并说明依据 | 用请求里还剩什么比较继续、清空、压缩与新会话；回到当前任务，要求用界面可见经历说明选择理由；另以情境检查误解 | 选择有理由即可，不给唯一最佳选项，也不要求学员安装查看器后才能完成项目 |

这里的“讲透”至少有两种终点：机制内容讲到能解释现象、避免错误判断；操作内容讲到知道怎样选、怎样做和怎样检查。深度由目标决定，不按素材多少或步骤数量决定。

## 3.2 各项目标需要什么终点

| 已定目标 | 本段至少要支持的判断 | 可收住的位置 |
| --- | --- | --- |
| 读懂正文 | 从具体任务和返回中找到一条指导，解释它要求什么；分清本次需求、通用指导与模型补充 | 学员能够解释一两项真实决定，不必成为 Game Studio 使用专家 |
| 修改一项要求 | 从一个明确不足定位到负责该行为的原句，说明为什么这样改；确认读到新版，再核对目标行为 | 本次修改所针对的行为已核对，其他问题按是否影响该目标处理，不必修完整套检查计划 |
| 从零写最小 Skill | 从一项重复任务推出必要输入、做法、输出及关键例外；解释每项要求为什么值得写；调用后能针对一处失败调整 | 有一个任务清楚、能调用且已核对关键行为的最小文件；不要求提前写完所有可能边界 |
| 引用与复用 | 根据内容用途决定留正文、放资料还是拆成独立工作；能给出有读取条件的引用 | 能处理本节新情境即可，不要求在主课实现脚本、模板、素材和多份 Skill 的全部组合 |

以上是对已确认目标的解释，不新增学习目标或课程承诺。

## 当前稿的具体差距与取舍

### D1：读正文时，文件内容的解释多于决定的形成

01–05 已经对照请求、方案与正文，也区分了用户给定玩法、Phaser 默认建议和模型补出的牌数、等待时间，这是应保留的基础。问题是随后逐处解释适用条件、路由、流程、输出，容易以“这些栏目都看过”为完成标准。

这部分更应让学员跟着完成一个判断：例如方案为什么用了 Phaser，什么要求来自 Skill，用户已有技术要求时又应怎样处理。只讲需要支撑这个判断的相关段落，其余栏目说明为它服务。不能把对应关系讲成已经证明模型内部每个决定的唯一原因。

状态：待讨论；规则依据 ED-004、006、021。

### D2：修改示范需要先锁定“本轮怎样算改成了”

06–08 已有相同请求、单项修改、新版读取、结构变化的对照；这条链条比较完整，应明确肯定。目标是把检查要点展开成前置状态、操作和可见结果，而不是证明原版没有结束／重开检查。

05 已说旧方案还不够具体，但缺口可用一条原版检查项具体说明：人照着做时，还得自己补什么。这样后面三个字段的出现就回应了实际需要，而不只是照抄新增要求。

09 又展开计时器、锁定时机、窄屏牌阵三个问题，会把注意力转向检查计划质量。如果这里只要说明“采用格式仍需审阅”，挑一项能够说明边界的错误即可；没有必要把每项已发现问题都讲进主线。若改为教怎样修好这些错误，就需要对应修订与复查材料，不能只靠多念几句建议完成。现有未复测状态保持如实。

状态：待讨论；规则依据 ED-005–009、021。

### D3：从零编写展示了最终规则，还要交代怎样选出这些规则

15–16 先展示当前 v3 写法：缺少三类输入就停止、最多五问、六到十项、隐藏信息先观察、随机洗牌不要求顺序必变等；19 才回看 v2 缺失规则仍编表格的失败和修订原因。

回顾历史本身没有问题。但当前学员先看到一套已经解决多个问题的写法，容易把它们当成应当一开始写齐的固定栏目。对于“从零写”的目标，更需要显露取舍过程：任务是写手动计划，所以先确定输入规则和可执行输出；出现擅自假定玩法，就补输入不足时的分支；出现不可观察项，就补观察所需动作。

不必为此强制改成失败开场，也不必重排六环节。可在首次写到关键条件时就交代它解决哪一个实际问题，后面历史段负责核对结果。最多五问、六到十项属于本例的交付规模选择，不能让学员误认作写 Skill 的必需格式。

状态：待讨论；规则依据 ED-002、004、005、021。

### D4：掌握拆分判断，需要看到取舍理由，认识文件种类还不够

11–14 已给出界面专项工作、共享选型资料和正文取舍，21 也有迁移情境，方向与目标一致。可进一步让同一条内容在不同用途下作选择：每次写计划都必需的检查结构留正文；只有翻牌会用到的长例子按需引用；另一项能独立接受输入并交付结果的工作再另写 Skill。

重点是“为何放在这里、何时会用到”，不以读完若干路径证明学员会拆分。脚本、素材在这里解释用途即可；没有本节任务需要时，不为凑完整体系再展开实现。界面前后实录仍是材料缺口，不能用通用检查问题冒充已观察到的效果。

状态：待讨论；规则依据 ED-006、009、021。

### D5：学习检查应能检验读、改、写的目标

21 主要检查例子变长、标准共用的安排，能够支持拆分与复用；它本身不能说明学员已经会从零编写或定位修改点。17–20 的调用也主要是讲师示范，不能将“讲师演示成功”当成学员已获得能力。

不必每个小段增加测验。可以在已有文件和返回上留一次暂停判断：给出一条不足，让学员说明该改正文、补任务信息还是补资源，并指出准备核对的返回变化。若要支持从零编写的自检，可让学员先为另一项简单重复任务说出必需输入和输出，再对照解析。这些是候选做法，未新增为必做跟练或验收要求。

状态：待讨论；规则依据 ED-009、021。

## 当前最有用的调整方向

优先把三个问题落到每个教学单元：学员最后要自己判断什么；为作出该判断还缺哪一步解释；出现什么证据以后本段就可以结束。

3.2 需要一边压缩已经讲清的文件介绍，一边补足写改决定的理由。单纯减少字数、增加案例或逐项补全目录，都不能代替这一步。后续若改稿，应保留六环节与既定案例，先选“输出要求修改”或“最小 Skill 输入分支”这一段做代表性调整，再按同样标准检查全段。
