## 实验准备故障：不得当成模式差异

准备副本时，核验者使用 copytree 默认行为复制已安装的 node_modules，未保留 .bin 的符号链接。两边首次 build 都报 Cannot find module '../lib/tsc.js'。两边都开始诊断；普通模式还自行生成脚本修复 .bin，并在暂停前跑出过一次成功构建。

核验者发现后暂停两边，在各自副本按原锁文件执行 npm ci。重装前后的 tracked diff 完全相同，.bin/tsc 恢复为软链；再发送完全相同的环境说明，让两边保留页面改动、重新 build 和核对。没有改依赖声明、锁文件或应用实现来绕过问题。

因此：计划与确认前观察不受这次构建故障影响；构建之后的请求长度、耗时、自检路径带有环境故障和恢复消息，不能当作纯模式成本对照。它也不应被包装成课程主线中的自然失败，录制时先正常安装每个副本的依赖。

普通模式后续 SSR 自检出现过 React 导入配置错误并修正，也出现把“姓名”“一句话简介”字段标签当作缺失的误报，最终解释值已完整呈现；没有因此修改页面补标签。这些是本次自检路径，不证明普通模式普遍更容易出错。核验者保存临时检查脚本后，仅批准一次清理本次临时文件的命令。
