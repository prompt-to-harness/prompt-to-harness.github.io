# 课件审查记录

> 状态：2026-10-05 起采用；2026-10-24 改为按留痕价值触发。这里保存正式审查的结论，供之后的审查和修改参考。记录是审查者的观察，不是讲师确认，也不是试讲结论。

## 什么时候写

满足以下任一条件时，一次审查留一份记录：

- 整节、整章或跨章的系统审查，以及录制前验收；
- 外部审阅，或讲师明确要求留下正式审查记录；
- 存在待处理项，需要其他 agent 或之后的审查接续；
- 有重要分歧、设计取舍或核验证据，仅看最终内容和提交说明无法理解。

以下情况不在这里新建文件：临时讨论一两页的观感或措辞、作者自查、重新生成与常规验证、纯交接或并行协调，以及当场改完且没有遗留事项的小修改。形成决定时写对应的章 `LOG.md`；制作验证写章 LOG 的实测记录（未迁移的章写节 `README.md`）；其余修改和验证由提交说明承接。

不要按 agent、工作批次或页面机械拆分记录。同一次正式审查覆盖同一范围时合并成一份。

## 为什么单独存放

- **一次正式审查一个文件**：多个 agent 可以并行审查同一章，不会改到同一个文件、互相冲突。
- **放在 `docs/` 下，不放进 `courseware/`**：`courseware/` 里的 `.md` 会被字体缺字检查扫描（`check-courseware.py`），审查笔记里的新字会逼着重建字体子集。`docs/` 不发布到 Pages 站点，但仍然是公开的 git 内容，遵守 `AGENTS.md` 的公开仓库边界。
- **制作验证不另建文件**：机器能查的由 `make check` 每次重跑；实测数字、运行条件和人工复查（做了什么、还有什么没查），已迁移的章写进章 `LOG.md` 的实测记录，其他章写进节 `README.md`（2026-10-24 起，C2-91）。第 1 章现存的两份 `VALIDATION.md` 是历史记录，不再追加。正式审查发现的问题写在这里。

## 目录与命名

```text
docs/reviews/<章>/<日期>-<范围>-<审查者>.md
docs/reviews/ch02/2026-10-05-2.2-2.5-claude.md
```

- `<章>` 用 `ch01`、`ch02` 等；跨章审查放在 `docs/reviews/` 下，范围写 `all`。
- `<审查者>` 写 agent 或讲师的简称（`claude`、`codex` 等），方便区分不同来源的视角。
- 同一天同一范围同一审查者再审一次，文件名末尾加 `-2`。
- 目录不另设索引文件，按文件名排序就是时间顺序，可以避免并行写入冲突。

## 文件格式

```markdown
# <章节范围> 审查：<一句话结论>

- 日期：2026-10-05
- 审查者：Claude（claude-opus-5-5，lesson-polish）
- 范围：2.2–2.5 的页面、口播、分镜；2.1 只看共用样式
- 基于提交：afa6436（审查时的 HEAD；工作区有未提交改动要写明）
- 已参考：之前的审查记录，以及章 LOG 的实测记录；本次重复发现的问题不再展开，写“同 <文件> R3”
- 检查方式：已机器检查 / 已人工对照 / 未检查（试讲、出声试读、非作者复述……）

## 总体判断

两三句话：主线是否成立，能否进入下一步（审阅、录制），最大的阻断项。

## 问题

| ID | 优先级 | 页面 | 规则 | 问题与证据 | 建议 | 状态 |
| --- | --- | --- | --- | --- | --- | --- |
| R1 | P1 | 2.2 p32 | ED-009 | …… | …… | 待处理 |

## 未检查

## 给后续审查者
（可选）还没看完的范围、值得复测的地方、和其他记录不一致的判断。
```

- **ID**：在文件内从 R1 起编号，外部引用写成“`<文件名>` R3”。编号不重排、不复用。
- **优先级**：P1 会阻断跟做，或者遮住学员必需的信息；P2 会造成错误判断、理解断点，或明显降低呈现质量；P3 是格式与措辞问题。
- **规则**：引用 `docs/production/editorial-checklist.md` 的 ED 编号；展示问题写“展示”；事实错误写“事实”。
- **证据**：写可复现的东西，例如页面与步骤、原句、实测数字、命令输出。截图不提交，写清怎样复现。

## 状态与后续

- 状态取值：`待处理`、`已修复（<日期>）`、`不改（<理由>）`、`转登记（<去处>）`。
- 修复问题的人（或 agent）在同一个提交里把原记录的状态改掉，所以状态里写日期，不写提交号（提交前还不知道提交号）；要找具体提交，对这一行用 `git log -L` 或 `git blame`。这是对已有记录唯一允许的修改；新的判断写进新的审查文件，不改别人的结论。
- 讲师对某条有决定（采纳、否决、改范围）时，把状态改成 `不改` 或 `转登记`，决定本身仍然写进大纲或对应文件。
- 可迁移到多节课的问题，按 `editorial-checklist.md` 登记成规则，状态写 `转登记（ED-0xx）`。
- 正式审查、外部审阅、重要设计依据、实测和未决事项的记录保留。早期按“逢审必写”留下的日常修改、自查、交接、纯协调记录，以及已被后续方案完全取代的过程稿，可以在确认没有未决事项并清理引用后删除；更完整的过程仍可由 Git 历史追溯。
