## 设计取舍建议

- 独立 Review 和不可信输入判断可以补充现有主线；前者回应第 5 章的实际审查需求，后者直接服务 MCP 来源核对。是否成为核心实践，应依据本课程的产出、前提与代价决定；调研中的来源计数只能提供线索。
- 支持 Skill 在第 3 章较早出现；第一个创建案例先选已在课程环境实际验证的简单流程。不要同时让第一次创建承担浏览器工具接入、自动化测试设计、截图取证三项新前提。
- 第 3 章合并探索和调试、第 7 章吸收 Memory 都应先保留为待试讲方案。需求债务仍要保留项目中的具体证据，用它衔接第 4 章；“移到经验分享或开场”还需要指定保留的问题和判断，不能只移动术语。
- 调研报告“外部课程没有一家做到”等绝对判断超过了非系统抽样能支持的范围。建议限为“本次调研样本未发现同样完整的组织方式”；不据此推出课程独有或教学效果更好。这是证据强度提醒，本次没有复核全部外部课程。
- 第 2 章写第一条规则可以使用已经确认、确有跨任务复用价值的项目约定。调研报告所写“当 Codex 重复犯同一个错时”只能作为可选触发，不宜作为录播必现事件；沿用课程不制造失败的原则。

本次实际打开并阅读了下列相关段落，均为公开官方页面；只转述与本次判断直接相关的内容：
