## 批量润色方法

本仓库已具有大部分需要的规则：`lesson-polish` 负责课程对象、依据、学习动作和材料分层，`humanizer-zh` 负责已经确定含义的中文表达，`check-editorial.py` 负责可确定的格式及源文件一致性。增加另一份去模板表达清单不是当前重点。

推荐每次任务处理一节或一个连贯段落，由同一会话依次完成六节；一次通读全章用于发现术语和衔接问题，但不要一次无差别重写整个仓库。

```text
使用 $lesson-polish 和 $humanizer-zh，按节处理第一章。
```

humanizer-zh 默认保护代码和数据，处理本项目时必须明确上面的中文字段范围。被保护的 Prompt 或示例若确需改动，单列为教学内容修改，另核对输入与预期，不能顺手改掉。

重建命令和完整验证入口已在仓库存在：


### 其他开源工具的适用范围

- 当前本地 humanizer-zh 已基于 humanizer 与 Humanizer-zh 的模式修订，适合句子重写、重复和搭配；它是一份编辑指令，不是独立中文语法解析器，安装后不会自行扫描全仓。
- [pycorrector](https://github.com/shibing624/pycorrector) 的 README 提供中文拼写及部分语法纠错方案，可作为错字、漏字、词序等候选检查。不同模型能力不同；本次只查了说明，未安装、未对课件实测，不声称能可靠处理这些课件的术语、指代或学习步骤。
- pycorrector 等纠错结果只用于建议清单，保护 Codex、Vite、diff、命令和路径；不把模型给出的新句子自动覆盖原文。

没有必要用字数下降、风格分数或所谓“AI 检测通过”作为验收。验收是原意和事实未改变、对象指向明确、下一步可执行、材料层次一致且页面没有被改坏。
