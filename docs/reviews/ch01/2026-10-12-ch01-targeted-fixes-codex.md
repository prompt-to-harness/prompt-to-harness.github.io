## 发布衔接的必要修改

直接克隆会保留课程模板的 Git 历史；把 origin 改为新仓库地址，也不会自动清除旧的 origin/main 跟踪引用。旧的 `origin/main..HEAD` 检查会遗漏模板带来的提交，不能代表第一次向个人空仓库推送时将公开的完整历史。

因此只同步第二章 2.4 的必要部分：

- p44：先建立个人空远端、核对 origin，此时不推送；已有远端含内容时先核对，不覆盖或强推。
- p45：用 `git log --stat HEAD`、`git log -p HEAD` 和作者命令检查当前分支的完整历史，包含后来删掉的文件。
- p49：首次推送使用 `git push -u origin HEAD`，推送仍由人执行；设置来源受空仓库状态阻塞时，先推送已检查内容，再设来源并重新运行部署。

修改位于本节生成源 `tools/build-lesson.py` 和口播源 `script.json`，已重新生成 `lesson.js`。没有修改部署 Prompt 或其他小节的教学安排。
