## 总体判断

讲师的感觉成立：问题不只在节标题，屏幕短文字普遍有八种别扭的说法。其中最多的是“目录腔”（概念名词并列）、作者行话（闭环、基线、留痕、复验、处置）和电报体（为了少字砍掉主语和条件）。阅读模式是学员唯一能读到的文字版，这三类会直接影响自学。

节标题建议按节的角色给稳定句式，不要求全课一样：跟做交付用“动作 + 对象（+ 检查）”，机制 / 判断用学员此刻会问的问题，工程经验引 AI 原话或摆出现象。

顺带发现两处：

- `lesson.js` 的 `summary` 播放器和讲稿页都不读，学员看不到；1.4–1.6 的 `summary` 是从 1.1 复制的旧文字，1.2 写着“15 分钟编排预算”。学员看到的节摘要是章首页和课程首页的卡片。
- `ch02/index.html` 写“2.2–2.5 只有分镜，课件尚未制作”，`courseware/index.html` 写“2.2–2.5 为首版”，互相矛盾。已按课程首页改了 `ch02/index.html`（2026-10-11），并新增 ED-015 定期检查；`courseware/ch02/README.md` 顶部横幅原写“逐页分镜草稿”，经讲师同意已改（2026-10-11）。

## 三、待讲师判断

1. **“Harness”在第 2 章和课程路线里是两个意思。** 2.1 说“请求由 Harness 组装”，指 Codex 这层外壳；课程第 7–9 章的 Harness 指可复用的项目环境。学员会以为第 2 章已经学了第四层能力。术语表没有这个词。最需要先定。
   - 讲师（2026-10-11）：两个意思都要。已登记进 terminology.md“概念”，区分写法“Codex 这层 Harness / 项目的 Harness”是建议，改到该页时确认。
2. **“证据”要不要作为核心术语。** 第 1 章屏幕文字出现 54 次、第 2 章 22 次，已经出现“意图也算证据”这种不准的用法。登记进术语表并限定为“能检查的记录或输出”，还是一部分降成“检查结果、记录”？
   - 讲师（2026-10-11）：确实太多。已登记进 terminology.md，限定为能检查的记录或输出；wording-patterns.md 高频词里要求能说具体对象就直接说。屏幕文字尚未逐处改。
3. **改节标题要不要同步大纲。** 已确认标题不必与大纲一致；但改动幅度这么大时，章首页卡片和对外详情页的描述要不要跟着调？
4. **比喻和三分法留多少。** 1.3 的“告示牌 / 围栏 / 盖章”、2.3 的“接受 / 缩小 / 拒绝”、1.2 的“事实 / 假设 / 建议 / 决定”好记，但带了自造标签。保留框架只改词，还是少用框架、直接说动作？
5. **第 0 章访谈页上屏的作答提纲**（“当时 / 过程 / 结果”“收益与代价”）：刻意给学员看讲师怎么组织回答，就改成学员视角的看点；只是讲师提纲，就移进操作提示。
