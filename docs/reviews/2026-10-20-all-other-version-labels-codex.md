## 建议

共同原则：项目名称稳定；学员可见文字优先说明当前状态或实际差异。版本号用于定位具体代码、材料与对照条件，标题不堆叠项目阶段版本号。第三方软件 Release、具体 Git tag、路径与命令保留。

| 记忆翻牌 v0 / v1 | 3.1 实现与 3.3 修复后的对照 | 需要比较时写“修复前／修复后”；日常仍叫“记忆翻牌”。3.7 的另一份材料写“教学预备版本（未清理计时器）”，与“有计时器清理的版本”比较，不能混入自然产生的缺陷叙事。试玩链接写“试玩修复前的版本／试玩修复后的版本”，路径保留。 | 已修复（2026-10-20） |

| Harness v1 / 候选 v2 | 第 7 章冻结、第 8 章对照使用、第 9 章单因素改进 | 教学文字优先写“对照实验使用的 Harness”“改进候选”；实验表、记录和交付中保留可定位的 v1 / v2，并注明 commit。首次说明基线是固定下来供比较的版本；明确候选是否经过验证，不把 v2 当成必然改进或强制产物。 | 已修复（2026-10-20） |

“修复前／修复后”等均为针对当前比较对象的说明，不另立一套项目名称。记忆翻牌首次交回时尚未完成探索，直接叫“记忆翻牌”，不预先宣告它必然有缺陷。

Harness 的 A/B 表示实验条件（无 Harness／有 Harness），v1/v2 表示 Harness 自身的版本，commit 定位实际内容。这三层需明确区分：B 使用冻结的 v1；后续改进另行复验，不覆盖原始 A/B 记录。只增加版本号不能证明效果改善。
