只读调查

在第 3 节核对过的练习目录发送下面的请求。先确认工具处于适当的只读范围；请求文字不代替技术权限。

请只读查看项目 README、package.json、首页入口及其直接使用的样式和路由。
我们这轮只做首页首屏和项目展示区。请列出已有内容、可能要改的实际文件路径、开发启动与构建脚本；每项注明来源文件。
找不到的内容写“未知”，需要我决定的问题单独列出。先不修改、不安装、不运行项目脚本。

逐个打开它引用的文件，确认路径与内容对应。只读调查不启动项目脚本；后续启动准备见第 5 节。没有 Starter Repo 时，不在课程站目录尝试这条任务。

范围与未知项

把记录存到项目目录之外，避免它混入本轮待检查 diff。

起点：实际目录 / 完整 commit / 分支 / 当前状态
事实：结论 → 来源文件与位置
允许修改：逐项列实际文件，不写“所有相关文件”
允许新增：逐项确认；没有则写“无”
保留：已有导航、路由和其他内容
未知：问题 / 谁决定 / 决定结果 / 确认日期
确认：本轮目标、文件清单和验收由谁确认

本示例已经决定入口跳本页、卡片无外链、沿用视觉、无新增依赖。实际路径和脚本尚待仓库核对。只有影响实现的未知项已解决，才标记为“可执行”；不要求每个排版细节都先指定。

验收清单

  • Goal：说得出访客能看到什么、点击后发生什么。
  • Context：内容卡与仓库事实可追溯；未知项单列。
  • Constraints：实际文件清单、保留行为、非目标和停止条件明确。
  • Done when：检查内容、入口、两个视口、既有导航、启动、build、Console 和 diff。
  • 执行前有人确认；未填占位值或未解决未知项不能直接交给 Agent 生成。

四段不要求逐字一致；相互矛盾、把样例路径说成真实路径、将“高级”作为唯一完成标准，都需要修改。

自检与完整解析

题目：任务只说展示两个项目，Agent 计划新建详情页并上网找图片。是否批准？指出缺失的决定，并改写请求。

参考答案与常见误解

先不批准。详情页增加行为和文件，图片增加外部来源与许可问题。示例已决定只跳本页项目区、使用纯文字卡片，补回这两项再核对计划。

参考改写：“查看项目到本页项目展示区；卡片仅展示名称、简介和状态，不新建详情页，不使用外部图片。若需要扩大范围，先说明并等待确认。”

“只要好看就行”没有约定行为；“所有细节都由老师指定”也不是必要要求。关键是影响任务行为、范围和权限的决定要先明确。

补做：回看本页的范围表，找出自己的开放问题。继续条件：能说明这两项新增动作为什么不能从原句自动推出，并给出一段可检查的替代要求。

独立练习与交接

  1. 用自己的脱敏介绍与项目内容替换内容卡。
  2. 写出四段式 Prompt；把尚未核验的事实留下明确标记。
  3. 按验收清单自评，保存 Prompt、来源、未知项和确认记录。
  4. 有配套仓库时核对路径与脚本；材料还未发布时保留示例练习状态，不伪造确认。

输出是一份 Prompt 和记录；本节不提交代码。只有内容、范围与环境前置已确认，才进入第 5 节实操。不同文案和视觉均可合格，依据是完成标准，而不是复制参考代码。
