刚才找到了我们输入的问候。现在沿着同一份请求，看看前面还放了什么。这两句身份指令说明，它是编程 Agent，与用户共用工作区，一起完成目标。这一条实际标为 developer；系统指令是我们按作用给它的叫法。协作模式和团队说明也可以展开查看。

【操作提示｜推进第 2 步，定位工具定义，指 exec 名称、exec_command 与命令参数；完整工具说明可展开，不逐项读】

再看工具。这里叫 exec，说明里包含 exec_command 的用法和命令参数。工具定义告诉模型有哪些工具、怎样调用。模型提出调用以后，由 Codex 执行，再把结果带回来。后面的项目问题会把调用、返回和回答连起来核对。

【操作提示｜推进第 3 步，指 Skills 的名字、简述和文件位置；展开“对应 SKILL.md”对照，核对后收起】

Skills 列表给了名字、简述和文件位置。比如 skill-creator，列表告诉模型它能做什么。展开对应文件的片段，还能看到原则、创建和验证等详细说明。这些是另一个实际文件里的内容，没有出现在这份初始请求中；这次问候也没有读取它。当前列表来自课程 HOME 的内置目录，个人主页项目本身没有 Skills。

【操作提示｜推进第 4 步，定位环境，指 user、目录、Shell、日期与时区；不展开文件访问范围细节】

环境消息告诉模型，当前在哪个目录，用什么 Shell，日期和时区是什么。这条标为 user，但内容是 Codex 加入的，并不是我们刚才亲手输入的。

【操作提示｜推进第 5 步，定位权限，指 developer 和 workspace-write；完整审批规则按需展开；下一页进入 p09】

权限说明在 developer 消息里。本次是 workspace-write，说明允许读取文件、在指定范围写入；实际执行边界由运行时落实。现在看到了同一份请求里的几种内容，它们各有什么作用，又是谁组织进去的？下一页把这些关系归纳起来。
