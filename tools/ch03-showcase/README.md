## 构建和打开

双击本目录的 `打开游戏汇总.command`，会构建汇总页、启动服务并打开浏览器。也可以在仓库根目录执行：

```bash
python3 tools/ch03-showcase/serve.py
```

打开 `http://127.0.0.1:4397/`。21 个游戏都是已构建的静态产物或原生模块，和汇总页由同一个本地服务提供，不需要分别启动各游戏的开发服务器。服务独立在后台运行，关闭启动终端不会停止；重复启动会复用现有服务。页面会显示服务状态，加载失败时提供重新加载入口。

需要 HTTP 服务；双击 `index.html` 无法可靠加载游戏模块。重启电脑后需再次运行启动入口。查看和停止服务：

```bash
python3 tools/ch03-showcase/serve.py --status
python3 tools/ch03-showcase/serve.py --stop
```

已有构建时可加 `--no-build`；调试时可加 `--foreground`。日志在 `lab-runs/ch03-showcase/server.log`，只监听本机 `127.0.0.1`。

另一个终端可刷新真实截图并验证汇总页：

```bash
uv run tools/ch03-showcase/capture.py
uv run tools/ch03-showcase/verify.py
```

截图与检查使用 Playwright 和本机 Chrome。截图只操作归档副本中的可见控件，不改变源产物。`capture-checks.json` 保存各游戏的页面异常和 HTTP 检查；`gallery-checks.json` 保存折叠、筛选、21 个详情与试玩入口、实际翻牌或开始游戏、全部阶段、原文展开及两种视口的检查结果。测试汇总页不代表重新验收所有游戏规则。

2026-11-07 修复与实测：原 4397 服务已退出，浏览器留存的汇总页仍可见，但新的试玩请求失败。改为可重复启动的独立后台服务；以临时端口核对启动、复用同一进程与停止。当前内嵌浏览器逐个点击 19 个翻牌版本，均有实际牌面状态变化；两个躲避游戏均可开始，键盘暂停生效。窄屏下的折叠信息与翻牌也已检查。游戏原有规则与历史缺陷保留，不把这次入口修复记成完整游戏验收或试讲。

### 文字定位与逐处讲解

讲述线的记录入口须定位到支撑当前口播的具体原句、代码或输出行。`inspect-focus.json` 维护选择规则，`inspect_focus.py` 从已留存原文提取对应文字及出现次数，写入本机 manifest；匹配不到原文时构建报错。重复的断言按上下文和出现次数区分，例如重开后的归零不能定位到初始状态的同名断言。规则只负责定位，不改写源记录。

查看器用 CSS Highlight 对实际文字范围加背景色，不对整个消息、工具调用或空白区域着色。同一记录有多处对应证据时，通过“上一处 / 下一处”按讲述顺序定位；底部显示已匹配数量，缺失不能悄悄退回整块消息标记。固定难度与验证分工虽然位于同一条计划消息，也使用不同的文字定位。

### 3.2、3.3 过程原文

`build-inspect.py` 同时按 `inspect-process.json` 导入 3.2 / 3.3 的留存记录。依赖本机 selection、playtest、Plugin 目录，以及 purple 实验指针和相邻的 component-audio 实验目录；缺少原件时构建报错。完整日志和生成查看器只写到被忽略的 `lab-runs/`。

`?topic=<名称>&position=0` 表示讲述位置中的第一条记录。每条配置指定原件行号或消息 ID、要高亮的原文，构建时校验文字存在；“上一条记录／下一条记录”可以跨样本切换。系统消息合并和内联短命令按实际原文定位，不扩大高亮范围。

`python3 tools/ch03-showcase/sync-process-links.py` 同步旧节选锚点跳转，两节 `build-lesson.py` 已调用。只有过程锚点迁移，源码、真实差异、游戏和教学比较保留原入口。配置中的 `gaps` 与讲述页注明安装执行日志、短调用请求原件、E0 修改执行记录三处缺口；文件导出作为文件容器展示，不冒充助手消息。组件作者超时和后续验证边界沿用原记录。
