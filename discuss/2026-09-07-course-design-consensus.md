# 课程设计讨论汇总：从方向讨论进入总设计

> 整理日期：2026-09-07。来源：本次课程设计对话及仓库已有文档；这是整理稿，不是逐字实录，也不表示所有讨论发生在此日期。用户已确认总体方向并授权编写总设计 v0.1。本文区分已确认约束、工作假设和仍待决定事项，不把助手提出的每个细节升级为承诺。

## 一句话目标

帮助有基础编程经验、但从未使用或仅初步使用 AI Coding 的学员，为工作与生活做出真正可用的结果，并能解释、验证、修改和迁移自己的方法。

基础方法与工程判断是同一条成长路径的两种能力，不是两门课，也不是按“是否用过 AI”划分的两类人。“可用”指在明确条件下满足需求、具有相应证据、可发现并处理问题、可以继续修改，不自动等于企业级生产系统。

## 已确认的设计基线

| 编号 | 共识 | 对制作的约束 |
| --- | --- | --- |
| C01 | AI Coding 可以从零，编程仍需基本经验 | 提供工具上手与环境支持，不承担完整编程入门 |
| C02 | 先用起来，再逐步做好 | 最早就出现结果、最小检查和人工确认，不等术语讲完才动手 |
| C03 | 基础方法与工程判断共同组成主线 | 新手有补充说明，熟手有变化任务，质量底线相同 |
| C04 | 内容、Projects、软件工程 0.5 线互相支撑 | 不是三段互不相关的课；0.5 不是固定课时比例 |
| C05 | 课程是录播，准备和录制不能依赖学员实时回应 | 群反馈可以晚于整套录制；分周发布不等于可以动态调整后续课 |
| C06 | 8～10 次课，每次约 90 分钟、四小节左右 | 视频约 12～15 小时；暂停、跟做与实践另计 |
| C07 | 默认围绕问题连接知识、方法、证据和迁移 | 机制解释、工作示范、评审诊断、对照取舍可改变起点和顺序 |
| C08 | PPT 负责解释，项目录屏负责展示过程 | 截图可展示目标；保留关键决策、验证和差异，不只展示成品 |
| C09 | 软件工程混讲且在关键点显性点明 | 用模块、接口、变化、测试、Review、权限解释当前问题，不背术语 |
| C10 | 知识 scope 可以比最低操作要求更宽 | 公开指令、工具历史、benchmark 等可进入“看懂”层，不都要求实现 |
| C11 | 多个规模可控、可独立继续的局部闭环 | 不用一个项目绑定全课，不为每个知识点增加一个正式 Project |
| C12 | 录播材料必须支持独立自检和继续 | 自检有预录解析；项目有起点、验收、检查点、差异说明与求助入口 |

以上是设计基线，不是已验证的学习效果。来自用户经验的“两种起点比例可能相当”只用于考虑支持层次，不是招生统计。

## 暂用的工作假设

- 先按 10 次课编排，并保留经过取舍的 8 次课版本；10 次不是已公布的最终课数。
- 默认四小节 20/25/30/15 分钟；上手和综合课可调整，不将分段时长宣称为科学定律。
- 按四种项目角色验证 3～4 个局部闭环：快速结果、交互变化、陌生仓库、外部工具；数量、题目与必做边界尚未锁定。
- Codex CLI 为主要可复现工作流示例，App 可作为低门槛入口。替代路径按能力验证，不承诺任意模型与工具组合兼容。
- “看懂 Coding Agent 怎样工作”样课可作机制解释型参考；同意教学风格，不等于全部页码、脚本、测试或真实模型演示已通过验收。

## 讨论中修正过的理解

| 早期表达 | 当前表达 |
| --- | --- |
| 基础课面向新手，判断课面向熟手 | 同一主线，支持程度与变化任务分层 |
| 问题驱动意味着只讲项目必需知识 | 可以解释好奇、误解和取舍，但最终需连回操作或判断 |
| 每个项目都不能被一次生成解决 | 早期快速成功有价值；中后期需要变化、约束与验证空间 |
| 学员结果应该和老师差不多 | 允许不同实现，要求相同目标、约束与验收，不承诺差异一定小 |
| 课堂提问后根据学员回答继续 | 题目和解析预先准备，学员自主暂停与对照 |
| 用户 Prompt 没有交给模型 | 用户任务是输入的一部分；不能把所有其他内容统称为 System Prompt |
| 原始指令和日志揭示模型全部内部过程 | 只解释可观察、可核验的输入和执行证据，不冒充完整隐藏指令或思维 |
| Agent 完成说明、测试绿灯就是完成 | 根据任务解释覆盖、运行结果、修改范围与未验证部分 |

## 参考材料的使用结论

AI Hero 借鉴机制拆解、小练习和配套指南；陈天借鉴真实工具、工程中间产物与代码分析；其他 refs 借鉴知识分类、判据、案例和反例。它们是设计启发，不证明我们的录播课会取得相同效果。公开目录、原始项目产物与付费视频体验要分开记录；不照搬 cohort 的服务条件。

软件工程拾遗的原始研究与四张试讲卡保留。人物与争论可以做专题入口，但历史观点与当代 AI 映射须区分；不把所有候选人物都塞入必修课。

## 仍未决定，也不应擅自对外承诺

最终课数和发布时间；正式 Project 的主题、语言、数量、必做/选做；人工评阅、证书、评分及答疑响应；token 额度、远程环境和镜像服务；实际支持的系统/模型组合；代码地图是独立项目、Skill 还是项目产物。

这些事项进入总设计的决策和验证清单，不阻止开始编排，但涉及的演示、支持方案和招生文案须在正式交付前确认。
