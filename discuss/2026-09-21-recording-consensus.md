# 深蓝课程录制形式共识

> 2026-09-21 · 根据本次逐批讨论整理。内容主线采用 docs/course-outline.md；团队的深蓝制作参考（私有，未公开），不据此重排课程。

> 归档说明：这是本次录制讨论的原始整理稿，保留决策过程与待验证事项。可执行的课程设计、录播、编辑和独立学习规范已统一收录在[课程共识](../docs/design/course-design-principles.md#录播与独立学习约定)，本文件不再作为第二份规范维护。

## 已确认

- 受众沿用 v1：在校学生、初级开发者和 AI Coder，不再收窄。
- HTML 讲述录屏与独立 App / CLI 实操录屏均被课程团队接受，由深蓝剪辑、分节和承载视频。
- 全程由讲师讲解，讲师保持边角小窗，优先右上角约 12%–15% 屏宽，不安排讲师大画面。页面预留空间。
- 初步用用户所称的「微信会议」开个人会议录制，两类素材方式一致；具体客户端、实际导出分辨率与清晰度需技术样片验证，不预先等同于某种产品或画质。
- 若录制是小窗与屏幕合成的视频，后期不能无损移走小窗并恢复被遮挡内容，须在录前验证位置。
- 第 1 章 App 为主；第 2–3 章逐步穿插 CLI，第 4 章起 CLI 作为主要工程入口。第 1 章可有 2–3 分钟的 CLI 对照。
- 每节约 8–15 分钟为初步目标；按章、节顺序分别录制。第 1 章暂由缪东旭连续主讲，可后续调整，不每节切换讲师。
- 每节交付讲述与实操视频、讲稿、静态素材及剪辑说明。深蓝负责字幕制作，我们提供术语、命令和路径的准确写法。
- 真实任务从明确检查点开始；等待可剪，关键操作与结果真实。课程工作区使用脱敏示例。
- 记录项目基线、锁文件、工具大版本/入口、Prompt、关键设置和录制日期，按需要核验；不把每个工具补丁版本锁死。教学强调长期有效的思路与概念。
- 讲义、示例与代码可公开；视频交深蓝平台。课程网站纯静态，无账号、登录、进度同步或站内作业提交系统；学员以自己的 GitHub 仓库、README、截图与部署地址交付成果。
- HTML 是展示形式，可以直接编写，也可由 Markdown / MDX 等生成。本地录制不依赖在线字体、图片或 API。
- 老师展示课程项目的主页，学员可以做个人主页、简历与作品集。它们是同一类网站任务，内容不要求完全相同；不能反复以“项目主页还是个人主页”制造额外决策。
- 课程站仓库与学员 Starter Repo 分开组织，借鉴/共用设计与内容基础，录制采用可追溯的版本。课程站提前准备好；实操从可运行的 Starter Repo 起点生成或修改首页。
- 课程维护一个许可证清晰、已核验的社区 Starter Repo fork。具体上游尚未选定。学员按需替换资料、项目和视觉内容。
- 首页组织介绍与项目入口，课程与游戏可用独立路由；网页包含章/节导航、讲义、Prompt / 命令、代码入口、作业与验收。采用轻量暂停练习，不要求在线编辑器。
- 按“问题 → HTML 解释 → App/CLI 实操 → HTML 复盘”串联；无需机械切换。
- 先做第 1 章 storyboard，再完成第 1 节样板与技术试录，按顺序展开后续小节。
- 讲稿尽量做到逐字稿，以保障解释质量；实操结果与模型回复根据真实情况讲，不编造固定成功台词。

## 展示方式与公开内容

比较第一节效果后，保留阅读和演示两种模式，共享同一份内容。公开网站默认连续滚动，讲述时使用按屏翻页；切换时保留当前讲述点。

页面和讲解全文直接面向学员，也可供讲师讲述。移除制作样板、形式比较等提示，统一用自然的课程口吻；大标题、标签和短要点默认不加多余的中文句末句号，完整解释、题干与请求保留必要标点。口播试读还要检查听者能否顺着对象、依据和下一步接受内容，不能只检查发音和节奏。录制时长、画面切点和剪辑说明单独留在备课文档。人像辅助框默认隐藏，可在演示设置中打开。详见[课程编辑与审校记录](../docs/design/course-editorial-decisions.md)。
